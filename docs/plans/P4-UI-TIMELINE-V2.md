## 0. 范围、目标、取舍

- **相册优先**：启动默认看照片；统一照片、人物、地点、搜索入口，图库管理次级。保留现有纯 HTML/CSS/JS 多页架构和人工整理能力。
- **一套浏览表现、多套权威成员**：仅进入照片内容页时，全部照片/独立来源、已命名人物、人物合集、地点相册共用日期标题、照片网格、预取与滚动、年月快捷定位、空状态、错误状态及返回位置；来源过滤/人物归属/合集去重/地点归属由原服务端权威规则提供。普通待整理脸、未命名脸组、忽略/批量管理保持工作流列表，不强塞时间轴。
- 地图点位/聚合继续按当前地图成员与 viewport 查询；地图下的照片列表可另接时间浏览。搜索默认尊重相关度；纯条件查询可完整时间浏览，语义结果只能明确标为“当前候选集按时间查看”，不可冒充全部匹配。
- 不增云服务、账号、分享、第二套数据库、模型/向量建库流程、重型前端框架或第二套人物/地点身份模型。保留用户已完成的多页整理、候选头像、Esc、遮罩关闭、照片返回、图库刷新等成果，不重复实施。

## 1. 视觉与交互规范（覆盖旧版“无时间轴”条款）

桌面：左侧主导航仅照片/人物/地点、顶部唯一的全局自然语言输入框、右侧照片内容；图库管理次级；结果页复用页头搜索位置，保留 /search 路由但不在侧栏再设重复“搜索”。窄屏导航收敛成横排/紧凑模式；不用鼠标 hover 才能操作的菜单。延续原UI浅灰白、柔和青绿、暗色、可键盘操作的视觉基线。原九张静态图仅用于导航与色彩参考，其中照片网格无日期标题是**旧稿，不是最终时间轴样式**。

照片时间轴页头固定四组互不混淆的控制：
1. **时间依据**：拍摄时间（建议新默认） / 加入图库时间；可记住用户选择。不可悄悄更改原 API `time_desc`/`capture_desc` 既有含义；新默认仅在新时间轴 UI 生效。
2. **显示粒度**：按日 / 月 / 年分组；这是分组，不是筛选，也不是改变时间依据。
3. **范围筛选**：全部年份、指定年、指定年月；清除后恢复原范围，并保持所选图库/人物/地点。
4. **时间定位**：年份导航，选年后可选月，直接定位到该时间区间。**定位不缩小整个相册的筛选范围**；筛选与跳转要有不同 UI 文案、状态和 URL/返回语义。

网格按日期标题自新到旧、同日跨页合并；临近末尾自动续页，失败可手动重试。**20万以上图库必须有界管理 DOM、缩略图资源及请求**：用轻量分段/离屏区块回收或等价机制保留占位高度与滚动锚点，不能把每张曾看过的照片永久堆在 DOM 中；无需引入重型虚拟列表框架。

每个页面的照片预览能 Esc/遮罩关闭、返回筛选和滚动位置；日期信息有真实来源标签；支持“查看同一天/跳到日期”（仅合法时间键）；跨页预览不得拿未加载的局部图片列表冒充全量导航。不可改变已有合照单脸选择、地点人工更正、撤销/不可撤销等语义。

## 1.1 全站唯一自然语言搜索入口（2026-10-13 用户确认，优先于旧草图）

- **同一时刻仅有一个可见的全局自然语言搜索输入框**。桌面固定在相册外壳顶部，窄屏在页头显式展开/占行；进入 `/search` 后，结果页头仍是**同一位置/视觉组件的全局框**，下方直接呈现条件标签、结果、排序及状态。不同 HTML 文档允许复用同一外观与轻量逻辑，无需强求跨路由共用同一 DOM 实例；但**禁止顶部全局框 + 搜索内容区第二框、第二标题表单**。最新视觉入口为 [29种确认状态](../mockups/ui2-final-7ebf/README.md)；`ui2-large/` 双框图仅作历史对照，禁止照旧图恢复重复输入。
- 主导航从常驻一级入口中**去掉“搜索”重复项**，保留 **照片、人物、地点** 与次级 **图库管理**；`/search` 路由/URL/直接访问/浏览器历史与旧深链**不删除**。搜索页顶部全局框承担录入/编辑/重新提交，支持 Enter、可清空及 Esc/失焦依已有行为。首页/人物/地点等页提交后进 `/search`，只触发一次现有解析与检索；查询明确提交时优先于旧搜索快照。空输入可聚焦搜索框但**不得自动触发全库 AI 搜索**。
- 人物列表局部“筛选人物”、地点目录“筛选地名”保留，但必须有明确对象与占位/label、局限在当前目录，不得伪装为第二个全局搜图框。人物相册现有局部搜索在新 scoped 搜索完成前**过渡保留**；新 UI 的“搜索此相册/合集/地点”快捷按钮按 §1.3 传递结构化范围，不增加第二个文字检索框。非结果页普通聚焦默认全库；结果页已有固定 chip 时聚焦/改词保持范围，明确取消 chip 才解除相册限制。
- 搜索结果视图：当前输入 + 已解析可取消的条件标签 + 结果列表即可；默认相关度与语义候选限额照旧。纯条件完整分页、入库日期/日期未知查询、地图视口成员适配由 SEARCH-MAP 负责，C 不重新写搜索引擎。
- 全局框外观/焦点/返回方案由 A 做**保留可用旧搜索的导航薄壳，不显示不可提交输入**，C 接唯一输入的跨页提交与结果页单框；SEARCH-MAP 仅扩展搜索条件/结果适配。页面退出或预览返回时应恢复先前页面的独立筛选、日期锚点、滚动和搜索快照，防止因入口复用而发重复搜索。

## 1.2 人物／地点：目录卡不使用拍摄日期排序

| 层级 | 目录或照片默认规则 | 没有可信拍摄日期时 |
|---|---|---|
| 人物目录 | **唯一有效照片数降序**；同数量**最新加入图库的照片时间降序**；仍同分时稳定 person_id。对照已有 `persons/albums.py` 的 `photos_recent_desc`，只是选用现有读取模式，不扩新 API | 计入卡片总张数、封面候选不被时间筛掉；不在每张卡做额外日期未知/年月聚合 |
| 地点目录 | **有效照片总数降序**，同数量按最新加入时间降序，再稳定地名/ID。复用 `places/albums.py::_sort_albums()`；保留 CN/OSM/GeoNames 和人工归属 | 已有效归属的照片仍计入地点卡总数；不因无 EXIF 日期从地点目录消失 |
| 人物相册／人物合集／地点相册内部 | **统一拍摄时间轴**（可切入库）；成员范围内可信拍摄日期按日/月/年，日期未知和待就绪是独立直达入口 | **仍是此相册有效成员**。日期未知 / 待就绪按各自集合的入库时间 DESC、asset_id DESC 稳定分页；改为入库轴后正常归入入库年月 |

- **总数守恒**：在同一权威成员 scope、版本及有效照片资格下，`总张数 = 可信拍摄日期照片数 + 已提取无可信日期数 + 日期数据待就绪数`（每个 asset 只算一次）；**年份筛选**是子集，不能用其子集张数冒充卡片总张数。EXIF 缺失 ≠ 人脸缺失 ≠ GPS 缺失；不能互相过滤。
- 各人物、合集、地点的**年月摘要/未知/待就绪数量仅在进入对应相册时按需取**，可和首屏照片请求并行、不能阻塞它；不为首页每张人物/地点目录卡跑一份时间分布查询，也不为上千人物/地点建立永久月份计数。按 scope+相关修订+规则版本缓存，在成员、日期事实、日期规则或地点包变化时失效；不从首页已加载前50张估算。
- **时间依据与分组粒度**允许复用用户记住的浏览偏好（如“入库时间、按月”）；人物/地点**年份筛选、月份筛选、滚动位置、跳转锚点、未知入口**都属于各自 scope 的页面会话，不得切换人物或地点后错误继承。人物/地点的本地筛选也不应污染全局自然语言搜索。


## 1.3 当前相册一键搜索 → 唯一全局输入框：范围合同（2026-10-13 用户追加）

**入口与交互**

1. 人物相册标题右侧有 **「搜索此相册」**；人物合集标题右侧为 **「搜索此合集」**；地点相册标题右侧为 **「搜索此地点」**。主操作常驻可见（窄屏可收纳为仍可键盘触达的明确按钮），不埋入“更多”，不取代“整理/更换封面/更正”。人物目录“筛选人物”、地点目录“筛选地名”仍只是目录名字过滤，不能用它们来搜照片；地图当前视口“搜索当前范围”可后置，没完整成员保证先不显示。
2. 用户在非搜索结果页直接点击页头唯一全局框时，默认搜索**全部照片**；结果页已有范围时仍保持该范围，不偷偷继承当前人物、地点、合集、日期或当前已滚到的年份。只有主动点相册内快捷按钮，才将一个**身份明确、须由服务端复核成员与版本的结构化 scope** 送到 `/search`；页头同一输入框聚焦，显示可见且可取消的范围标签，例如 `张三的照片 ×`、`家庭合集 ×`、`深圳市 · 广东省 ×`。**不新增第二个文本输入框**，也不把人物/地名拼接进自然语言查询字符串。按钮点击只是“选择范围并聚焦”，空词**不自动执行**向量或全库搜索。
3. 在范围标签存在时输入「海边」只查当前相册**全部有效照片**，包含拍摄时间未知／待就绪的成员；**不隐式继承**此前所在的 2020 年筛选、入库时间偏好、滚动位置或分组粒度。用户明确输入“2020年”“2020年入库”时才增加相应已定义时间条件。搜索标签可以单独取消范围，取消后**重新搜索全图库**（非悄悄扩大已存在的搜索 session）；范围标签上的下拉可选择“全部照片”，**不默认枚举全体人物/地点**，不做每次输入的远程联想或编码器预热。
4. 范围在查询词编辑、加载下一页、结果预览、浏览器返回时保持清楚且一致；明确点击“清除范围”才能切为全库。范围改变、相册成员版本变化、时间过滤 chip 取消、从照片查看器跨页返回均按原 snapshot/revision/游标合同处理；旧会话失效需明确重搜，不允许旧 cursor 在新范围继续跑。返回原人物/合集/地点时还原原列表筛选、日期、滚动与相册入口焦点；不得重复提交一次查询。

**身份与数据资格**

- 选人物传 **canonical person_id** 和原有人物成员条件；人物合照同一 asset 去重；合集传 **collection_id + instance/revision** 并按**当前有效成员**去重；地点传 **place_kind + place_key + 父级上下文展示**，以地点相册的权威成员为准（CN/OSM/GeoNames、人工指定/排除、可用照片资格），不能将地名文案拼为普通语义词、直接混用单一 `place_id` 或从前端已加载的48张生成全集。
- scope 标签是不可由自由文本覆盖的**已选定约束**，并可与用户新输入自然语言中的其他条件取交集；如输入另一个人物/地点造成不兼容，必须明确提示冲突、要求移除原范围或更换内容，不得隐式扩大成 OR 或清除固定范围。相同身份则去重，不能导致多条件重复错误。
- 允许明确的 **`search_scope=all|person|collection|place`** 概念模型（具体请求字段以原 `SearchRequest`、`intent_plan`、`/search` 验证后最小适配）；由服务端按权限/版本重新解析真正成员，UI 参数不是资产 ID 白名单，更不得将20万个asset ID放进 URL/本地存储。仅传受控身份字段，旧 `/search` 无 scope 请求语义保持不变。非现成条件只由 SEARCH-MAP 做最小加性只读适配，不重写 FTS/向量/RRF/相关度。
- 纯条件空内容的搜索触发策略与已有 FILTER_ONLY 合同对齐：**按钮点击/聚焦**不发请求；用户明确按“搜索”、输入了条件而没有内容词时，才使用**权威 SQL 完整分页**。有内容词才走原内容召回并在召回前绑定 scope，不能“先全库检索再前端筛选”，不能把 TopK 结果说成完整相册结果。

**分卡实施与兼容门闩（A → C → CORE → B → D → E → SEARCH-MAP → F）**

- **A**：只做导航薄壳并保留可用旧搜索，页头最终输入由 C 交付，不实现相册范围协议。
- **D**：现有 `persons.html#pa-search-photos` + `persons-albums.js` 的 `person_ids` 局部搜索已能工作；C 已作为前置完成，但 D 早于 SEARCH-MAP，**不能为新外观提前删掉旧搜索表单**。仅预留相册标题快捷按钮位置/上下文；实际按钮须在真实贯通后显示并能触发，后续 SEARCH-MAP 复用 C 的交互且 PERSON_SCOPE_PASS 后才迁走旧表单。合集范围不要误用单一人物 ID。
- **E**：现有地点目录“搜索地名”不是相册内容搜索。E 在地点相册建立完整 `kind/key` 范围身份与有界分页；若 SEARCH-MAP 尚未验证此 scope，不展示一个不能工作的“搜索此地点”按钮。
- **C**：只做页头单输入、可见 scope chip、一次性跨页意图交接、取消/聚焦与返回；后端 scoped 搜索没有保证时继续沿用人物已有入口，**不虚构合集/地点结果**。不得加入第二个搜索表单、替代搜索引擎或无限 autocomplete。
- **SEARCH-MAP**：按已有 `person_ids`、`place_kind/key` 和 collection scope 入口实施/验证**服务端权威**的 scoped FILTER_ONLY/语义搜索；后端闭环定向通过后才**切换并移除**旧人物相册文字搜索输入，打开相册快捷按钮。因场景所需的加性只读合同按 B 类审核；缺任一 scope 时保留对应旧路径或记录 `DEFERRED`，不得宣称统一入口全部 PASS。
- **F**：负责范围搜索结果→预览→人物/地点/合集→浏览器返回状态与焦点，不扩大预览状态机。

**20万以上性能约束**：点击相册快捷按钮、页头聚焦与范围 chip 渲染不触发模型或额外 `COUNT/GROUP BY`；查询在服务端做权威成员筛选、稳定有界分页，地点不恢复 Python 全量成员扫描。目录/每卡不能预生成 scoped 搜索候选或月摘要。复用 CORE/E 的20万元数据夹具，搜索专项以“1人物/1合集/1地点+内容词/纯条件/分页/冲突/修订”少量定向对照和 query-plan 证明，无需新建真实大库或整套 GPU/向量基准。


## 1.4 搜索状态矩阵与操作边界

| 用户动作 | 固定相册范围 | 查询与请求 |
|---|---|---|
| 普通非结果页聚焦页头框 | 默认没有固定范围，不继承当前相册/年月 | 仅聚焦；零搜索请求 |
| 点“搜索此相册/合集/地点” | 主动选择该身份，前往结果页显示 chip | 等待输入；不自动统计/编码/检索 |
| 结果页聚焦、编辑或清空关键词 | 保留已有 chip | 编辑/清词不发请求；空词不编码 |
| 用户明确提交有文字条件的查询 | 保留固定范围，与其它明确条件取交集 | 无内容词走 FILTER_ONLY；有内容词才旧 FTS/向量 |
| “清除高级筛选” | 保留固定范围 | 仅清手动高级字段；保留 q 与未取消的解析条件，用原取消路径重建查询，不复活旧 session/cursor |
| 取消某个已解析条件 chip | 保留固定相册范围 | 沿原解析标签取消合同重建计划；不把取消词重新送回解析导致条件复活 |
| 范围 chip × / “全部照片” | 解除固定相册限制 | 保留 q 和其它明确条件；有词重开查询，无词仅等待；旧 session/cursor 失效 |
| 固定范围下切“以图搜图” | 不偷偷清除范围 | 阻止上传提交并显示“以图搜图暂不支持当前相册范围，请先取消范围”；明确取消范围后恢复原功能 |
| 网络/模型失败、预览关闭或浏览器返回 | 保留身份、q、条件及有效快照 | 显示错误/重试或恢复；不自动扩大范围或重跑编码器 |

固定范围和高级/解析条件是不同状态。身份相同先去重；不同人物只有既有合同支持时做共现 AND，不得变成 person_match=any 的 OR。合法交集没有成员是正常空结果；身份歧义、合同不支持的交集或不可表达条件才报清楚的冲突/unsupported，绝不静默扩大范围。中文输入法 composition 期间 Enter 不提交搜索；候选字确认后再明确提交仅一次。

## 2. 日期可信度与分桶规则（冻结为时间轴自己的明确合同）

- **稳定排序**：可信拍摄轴为 `taken_at_sort DESC, asset_id DESC`；入库轴、未知桶及待就绪桶为 `created_at DESC, asset_id DESC`。日/月/年只改变分组标题，不能在桶内改按另一种时间排序；游标保存完整排序键并绑定过滤与版本。
- 拍摄时间：只把有效、当前规则版本可信且来源为 `EXIF_ORIGINAL` / `EXIF_DIGITIZED` 的照片归入对应日/月/年；沿用 `taken_at_sort` 的 civil/wall-clock 本地相机时间键，不推断时区、不从 UTC 换日。
- 无可信拍摄日期细分**已完成提取但无可信日期**（`EXIF_ROOT` / `FILE_MTIME` 等）和**尚未就绪**（未抽取、规则版本不兼容）；UI 可相邻展示，查询/计数/游标必须分开，不能因规则版本失配将所有照片标为“已确认无日期”。两类都按 **`assets.created_at DESC, asset_id DESC`** 稳定排序，有独立快捷入口，不要求滚到正常时间轴底部；不能混入任何拍摄年月范围。
- 加入图库时间：沿用现有 `assets.created_at`，统一以现有服务端/浏览器约定显示的本地日历日分组；切换时间依据不会变更 stored created_at 或资产身份。若零/缺失时间值必须明确单独处理，不推断拍摄日。
- 旧 `capture_desc` 排序与 `capture_from/to_exclusive` 合同保持兼容；该排序历史上包含文件时间位置，不应直接充当**新**“可信拍摄时间轴”。新增查询须清晰区分可信时间范围、无日期桶和加入时间范围。
- 时间依据切换后所有日期导航、分组和跳转同依据；左闭右开时界遵守现有 civil 时间契约，不能因为本机时区错一天。**本轮不做用户手动编辑/补齐拍摄日期、文件名/OCR/AI 猜日期，也不增加时间覆盖表**。

## 3. 查询与分页边界

采用新增**只读**的时间轴投影/查询（接口名称由实施卡最小设计决定，候选 `GET /api/v1/timeline/assets` 与 `GET /api/v1/timeline/periods`）；尽量重用 `api/queries.py`、`taken_time/read.py`、人物/合集/地点原资格和索引。共享 API/适配器可以按现有能力合并，不强制发明第二套 source-of-truth。

- 请求限定 kind（all/source/person/collection/place，search/map 由后续卡评估）、成员标识、time_basis、group_by、year/month/range 与稳定游标/版本；不能任意字符串拼接 SQL，必须验证成员身份、权限和参数。
- 照片分页固定 48～60 左右、采用服务端权威过滤后 keyset（可信拍摄：taken_at_sort＋asset_id；入库/未知/待就绪：created_at＋asset_id）和有界查询，返回稳定时序、每张 display_date/time_source/可信标签、当前查询语义及 next_cursor。相册中的同一 asset 去重（合集、同来源重复路径、合照场景）；人工锁/活动资产、视频资格等现有过滤始终前置于分页。
- period 摘要返回**当前成员范围内**存在的年份和所选年份月份与可信统计；不得前端用首批照片计算全库比例或编造不存在的月份/总数。年月跳转直接按服务端日期区间起始定位，不能通过重复读取前面所有游标实现。
- time_basis、成员范围、修订 revision、游标、年月筛选改变后抛弃旧响应和旧游标；旧请求晚到不覆盖新视图。409/过期时给出清晰刷新/重查入口而非死循环；会员/地点/图库更新后保留合理的滚动锚点并重新获取权威行。
- 首屏行一次附带所需日期，不对每张卡额外 GET /assets/{id} 获取拍摄时间（避免 N+1）。延续缩略图懒加载、缓存和离线原图回退；不批量拉原图。
- 只在实际 SQLite 查询计划出现扫描/排序瓶颈时提出**最小索引**；若必须 schema/migration，先核对 ADR-0011、升级/兼容与 V3.1 策略并在该卡明确测试门槛，不得暗中改 schema。不能修改人工归属/识别/搜索写接口、重建模型/向量或真实图库。

## 3.1 20万以上图库查询与搜索性能合同（2026-10-13，新版优先）

- **规模**：20万张元数据级 SQLite 合成夹具为主验收；30万张仅重点 SQL / 分页退化复核。正确性仍用 20～40 张小型 fixture。无需20万真实图像、GPU、向量索引重建；不得接触用户真实 PhotoSearchData。一个可复用规模 fixture 足够，后续卡不重复生成巨量数据。
- **查询顺序**：服务端先用原权威活动照片/来源/人物/合集/地点成员（含视频/人工资格）约束，再按可信拍摄键或入库键排序，以 **keyset + LIMIT约50～60** 返回。不能先读完整 ID 列表到 Python、整库 OFFSET，再切出一页；同资产合照/多路径结果先去重后分页。可信时间轴有可靠年月，未知/待就绪是独立分区与游标，桶内用 `created_at DESC,asset_id DESC`。
- **索引计划**：现有 `idx_asset_metadata_capture(time_source,taken_at_sort,asset_id)` 对 EXIF 两来源合并的全局降序**不保证免排序**；入库 `assets.created_at` 的排序也需要核查索引。对实际关键 SQL 输出 `EXPLAIN QUERY PLAN` 和计时，若证明瓶颈才提候选部分索引 / `created_at,asset_id` 索引；若触及 schema/迁移先列兼容与 V3.1 必要审核，**不擅自加索引**。性能未测记 `PERF_PENDING`、实测未达门槛记 `PERF_FAIL`，不可用小库 PASS 覆盖。
- **年月统计**：首页先返回第一页，不必等待年月摘要；全局年份摘要仅按需取一次，在点某年后才请求当年月份；以 scope + 时间依据 + 相关 revision 为短期缓存键，成员变化失效；每滚动一页都不允许重算 GROUP BY/COUNT。不要按每个人、地点预建永久聚合表；超过目标才评估受控只读投影。
- **客户端**：一条范围至多一个续页请求，可预取邻近一页；30页连续滚动后旧离屏照片 DOM、解码图和 object URL 需有界释放/回收，保留滚动高度及日期锚点。禁止一次加载全量原图，优先已缓存缩略图。
- **地点专项**：现有非 CN `places/albums.py` 的 `_album_rows → _group_rows → offset` 可依赖全库 Python 行集，是重点优化目标。E 卡应在单个地点 scope 的 SQL 权威成员集合上做直接日期 seek 和分页，CN facet 路径同样要证明与旧成员集合等价，绝不为了速度重定义人工归属/同名身份。
- **搜索分流**：无内容词的时间/入库时间/日期未知/人物/地点/合集/图库等组合走**完整 SQLite 条件查询，不调用编码器或向量检索**；存在内容词才使用旧 FTS/Vector/RRF 并在召回前约束范围。语义结果默认相关度，只允许对**冻结且明确有限**的候选按时间浏览，不冒称全库匹配；不要每次搜索顺带计算整个年月摘要。
- **自然语言**：`2020年照片` 默认可信拍摄日期；`2020年入库/导入/加入图库` 明确使用 `assets.created_at`；`没有拍摄日期` 只指提取完成无可信日期，`拍摄日期待处理` 指尚未就绪。旧拍摄时间 `capture_from/to_exclusive` 契约不变；两种日期依据同时出现或不连续 OR 超出当期实现时，必须结构化说明而非偷偷丢失条件。相对日期首次查询冻结，之后不重新解释。新增解析/plan/model 只由 SEARCH-MAP 卡做最小加性适配，C 卡不修改后端解析。
- **20万基础性能验收门槛（尚未实测）**：隔离20万元数据、暖机后每场景≥30次同条件采样，记录机器/SQLite、P50/P95/max、查询计划、行数和请求数：全库照片页50～60条 P95≤400ms；年月直接跳转≤500ms；全局年份摘要≤800ms；人物/合集照片页≤600ms；地点照片页≤1000ms。有缓存缩略图的浏览器首图可见≤1.5s，须真实浏览器计时，不用 API 冒充。30页持续滚动后DOM/资源无单调增长；30万重点查询回归记录比率与根因。上述指标是**本批20万基础性能门槛**；缺证据记 PERF_PENDING，实测超标记 PERF_FAIL，均不能写完整 PASS。
- **轻验收**：20～40张小型数据验证真实语义 + 单次可复用20万元数据性能工具 + 30万部分复查；不要全仓/GPU/OCR/模型/打包或大规模图片制作。少样本只有探索价值，不能当形式P95。若缺浏览器或规模fixture，分别留 `BROWSER_PENDING`/`PERF_PENDING`；功能定向 PASS 不能当“大图库性能通过”。30万 AI 语义搜索的历史测速见 [P4-02X](../reports/P4-02X-block-size-15000.md)，与本时间轴耗时不同，不能互相冒用。


## 3.2 更新期间的浏览与资源预算

- **日期更新**：复用 `taken_time/extract.py` 与 ADR-0011 §6.6 已有日期事实同事务递增共享 `catalog_filter_revision`；事实相同的幂等重放不递增，不新造时间修订计数器。CORE 补验规则版本、入库、成员变化的覆盖和单请求读一致性；照片页与摘要版本不同则不合并成守恒数字，摘要重新按需取。
- **连续失效不循环重试**：旧 cursor 拒绝后保留已显示内容并标明需更新，暂停续页；多次后台变化合并成一个“照片日期已更新，重新定位”提示。用户点击后以原合法 asset/日期锚点重开一次；若再次失效仍等待明确操作，不能自动循环刷新、重复滚动加载或扫描全库。
- **空状态**：有效照片存在但可信拍摄页为空时不显示“无照片/未建库”。首页、来源、人物、合集、地点都提供本 scope 的“日期未知”“日期待就绪”“按加入图库时间浏览”；数量尚未加载/失败与真实0分开，入口不因摘要失败失效。未知/待就绪按入库排序，日期标题明确写“加入图库日期”，不生成“拍摄同一天”。
- **默认工作窗口**：最多8页照片 DOM/活动缩略图资源（包括临时焦点保留页，每页最多60条）；明细记录缓存最多10页、分页锚点描述最多64页；每范围至多1条续页和1条摘要在途请求。回收页释放图片节点/解码引用/object URL，快照只保留必要身份、条件、排序锚点和有界数据，不能持有所有已浏览页。已选 ID 独立保存且沿原≤500上限；普通人物/人脸工作流不强制回收。
- **返回**：合法旧页可按排序锚点直接 seek；同窗口/布局返回原 asset 的位置误差目标≤16px，窗口尺寸变化后至少恢复原 asset 到可见区域；焦点卡片恢复后才聚焦。第1/10/20/30页记录照片/组头节点、缓存条数、URL/图片引用、在途请求和实际误差，证明既守上限又无漏重。若预算必须调整，先在报告/规范同步新的数字与证据，不接受仅写“有界”。
- **选择边界**：回收照片 DOM 不清掉原跨页 face/person 选择，不扩大合照脸资格。“全选/反选已加载”保持原当前操作区已呈现且可直接操作口径，不扩到纯缓存/占位/未加载项目；Shift 锚点被回收或上下文改变时按原合同退化为单项。写入/对话框所需上下文不得被回收。D 补验此新增耦合，不重做已有整理协议。
- **入库日历**：CORE 实施前写明实际分组/筛选/显示使用的同一本地日历边界，并验跨午夜/月/年；不能 SQL 按 UTC 分桶而浏览器按本地显示另一日期。不改变旧 `created_at`、API 排序或 civil 拍摄时间合同，日期未知也不伪造拍摄时间。

## 6. 最少验证与升级门槛

个人相册按最少必要检查：小型合成素材（建议20～40张素材，测试 adapter 小页长覆盖两页；正式48～60条/页用≥121条元数据并复用少量缩略图，至少覆盖跨两页、同日、跨年、仅文件时间、无时间、去重、revision 失效、离线图），新增行为定向 pytest JUnit、改动 JS node --check、涉及 Python 的 Ruff/py_compile、git diff --check，受影响入口小型浏览器验证。照片来源/人工状态的写操作仍核查原协议与失败反馈；真实图库只由用户自行试用，**不得擅自访问 PhotoSearchData**。

核心卡新增 API/查询按 B 类风险面复核，但基础验收按用户本次明确指定的 §6.1 定向范围；涉及 schema/写状态须另立卡。不跑全仓、GPU、OCR、模型、真实图像20万构建；**必须**按 §3.1 运行复用的20万元数据查询基准及30万重点回归（无法运行须显式 PERF_PENDING），另保留小型定向行为/浏览器检查。不编造性能收益。

完成目标：**20万以上个人图库**日常时间轴日期直达、按范围结果准确且页面/浏览器资源有界；30万重点场景无明显规模退化，跨页不重漏、返回位置可靠；成员和纠错规则正确。此后停止扩展，不自动加 AI 回忆/分享/上传/复杂动画。

**20万性能必测的有效性**：CORE 建立一份项目内可复用夹具，使用实际 catalog schema/索引和200,000个有效唯一照片资产；失效/视频反例另加，不计入这20万基础有效照片，不用200,000份真实图片。记录生成 seed/分布/代码提交/机器与SQLite版本；覆盖多来源/重复路径、跨多年不均匀日期、同日同时间键、未知与待就绪、活动/失效/视频反例，以及大/小人物、交叠合集、大/小非CN地点和CN地点。至少一个人物/合集或地点被测相册包含≥100,000有效照片，避免20万库里只测几十张的小 scope；其它成员规模与比例在报告列实值，不强制逐种生成一份大库。

对生产 SQL/真实服务查询或隔离 API 实测首屏、深页 keyset、5年前年月 seek、按需摘要，以及 source/person/collection/place组合条件；预热后每场景≥30次采样，记录P50/P95/max、完整测试条件、返回行数、请求次数、缓存冷热和 EXPLAIN QUERY PLAN。区分SQL段与API端到端耗时；只测已缓存摘要不能证明未缓存聚合速度，摘要 miss/hit 分开记录，缺相应端到端证据明确留待验。对照少量冷读；人物/地点目录首屏也记录真实API耗时和请求数，确认没有逐卡年月N+1。代表性30万查询仅作退化复查，不跑完整30万向量/GPU基准。固定页长/过滤/并发条件后对比，禁止以小库计时、人工 sleep 或模拟耗时当规模证据。

**正确性与性能一起验**：小 fixture 对新旧成员集合完全等价、两页/同日/tie-break不漏重；规模夹具用独立SQL核对代表过滤计数及首/深页边界，纯条件证明零编码器，地点/合集无全量成员ID加载，语义有界块记录最大持有量且保持原TopK；替身向量/编码器只用于正确性和规模路径验证，其计时不得称真实模型或真实向量索引性能。浏览器用少量合成图片/缩略图测已缓存首图≤1.5s和30页资源窗口，记录真实来源、数据是否模拟及缓存状态；模拟分页可证明组件窗口行为，不能代替200,000元数据实际API分页耗时。后续卡复用同版本未漂移证据，只补本卡改变的查询/入口。

**结论分列**：FUNCTIONAL、BROWSER、PERF_200K、CHECK_300K、REVIEW分别记状态和证据；20万门槛见 §3.1，是基础需求。功能定向通过但20万或必要浏览器未测，只写 FUNCTIONAL SCOPED PASS / PERF_PENDING 或 BROWSER_PENDING，整卡保持 VALIDATION PENDING；实测超标写 PERF_FAIL并保留瓶颈，不能按功能PASS启用未验证范围。30万重点复查单列，不冒充20万结果或30万语义容量PASS。
