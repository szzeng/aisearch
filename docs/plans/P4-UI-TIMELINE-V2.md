# P4-UI-TIMELINE-V2 — 个人相册 UI 2.0 与统一时间轴规范

日期：2026-10-13。状态：**APPROVED DESIGN / 待逐卡实施**；这是原 [P4-UI-PERSONAL](P4-UI-PERSONAL.md) 的新版本增量规范。原六张任务卡仍逐卡验收，不追认旧卡已完成；不授权执行真实图库操作。

## 0. 范围、目标、取舍

- **相册优先**：启动默认看照片；统一照片、人物、地点、搜索入口，图库管理次级。保留现有纯 HTML/CSS/JS 多页架构和人工整理能力。
- **一套浏览表现、多套权威成员**：全部照片/独立来源、已命名人物、人物合集、地点相册共用日期标题、照片网格、预取与滚动、年月快捷定位、空状态、错误状态及返回位置；来源过滤/人物归属/合集去重/地点归属由原服务端权威规则提供。普通待整理脸、未命名脸组、忽略/批量管理保持工作流列表，不强塞时间轴。
- 地图点位/聚合继续按当前地图成员与 viewport 查询；地图下的照片列表可另接时间浏览。搜索默认尊重相关度；纯条件查询可完整时间浏览，语义结果只能明确标为“当前候选集按时间查看”，不可冒充全部匹配。
- 不增云服务、账号、分享、第二套数据库、模型/向量建库流程、重型前端框架或第二套人物/地点身份模型。保留用户已完成的多页整理、候选头像、Esc、遮罩关闭、照片返回、图库刷新等成果，不重复实施。

## 1. 视觉与交互规范（覆盖旧版“无时间轴”条款）

桌面：左侧主导航照片/人物/地点、顶部明显的单一全局搜索入口、右侧照片内容；图库管理次级。窄屏导航收敛成横排/紧凑模式；不用鼠标 hover 才能操作的菜单。延续原UI浅灰白、柔和青绿、暗色、可键盘操作的视觉基线。原九张静态图仅用于导航与色彩参考，其中照片网格无日期标题是**旧稿，不是最终时间轴样式**。

照片时间轴页头固定四组互不混淆的控制：
1. **时间依据**：拍摄时间（建议新默认） / 加入图库时间；可记住用户选择。不可悄悄更改原 API `time_desc`/`capture_desc` 既有含义；新默认仅在新时间轴 UI 生效。
2. **显示粒度**：按日 / 月 / 年分组；这是分组，不是筛选，也不是改变时间依据。
3. **范围筛选**：全部年份、指定年、指定年月；清除后恢复原范围，并保持所选图库/人物/地点。
4. **时间定位**：年份导航，选年后可选月，直接定位到该时间区间。**定位不缩小整个相册的筛选范围**；筛选与跳转要有不同 UI 文案、状态和 URL/返回语义。

网格按日期标题自新到旧，各标题只对应其后照片；同一日期跨两个分页必须合并成同一节。滚动接近末尾自动续页；小尺寸页面/IntersectionObserver 不工作时有明显且可用的“加载更多/重试”兜底；不要求立即实现复杂窗口化虚拟列表。先确保请求、缩略图、DOM 节点有界，数量过多时再基于性能证据引入区块回收，保留原位置与占位尺寸。

每个页面的照片预览能 Esc/遮罩关闭、返回筛选和滚动位置；日期信息有真实来源标签；支持“查看同一天/跳到日期”（仅合法时间键）；跨页预览不得拿未加载的局部图片列表冒充全量导航。不可改变已有合照单脸选择、地点人工更正、撤销/不可撤销等语义。

## 2. 日期可信度与分桶规则（冻结为时间轴自己的明确合同）

- 拍摄时间：只把有效、当前规则版本可信且来源为 `EXIF_ORIGINAL` / `EXIF_DIGITIZED` 的照片归入对应日/月/年；沿用 `taken_at_sort` 的 civil/wall-clock 本地相机时间键，不推断时区、不从 UTC 换日。
- `EXIF_ROOT`、`FILE_MTIME`、EXIF 不足、未抽取、规则版本不匹配等归入显式“无可靠拍摄时间/时间待补齐”桶；可在缩略图或详情显示文件时间来源，但不能伪称拍摄日期。拍摄日期快速筛选仅命中可信来源，不允许无拍摄日期照片被动混入某月。
- 加入图库时间：沿用现有 `assets.created_at`，统一以现有服务端/浏览器约定显示的本地日历日分组；切换时间依据不会变更 stored created_at 或资产身份。若零/缺失时间值必须明确单独处理，不推断拍摄日。
- 旧 `capture_desc` 排序与 `capture_from/to_exclusive` 合同保持兼容；该排序历史上包含文件时间位置，不应直接充当**新**“可信拍摄时间轴”。新增查询须清晰区分可信时间范围、无日期桶和加入时间范围。
- 用户主动选择时间依据后，所有导航、分组、跳转都基于同一依据。日期解析与末端 exclusive 上界遵循原精确边界，跨时区/跨月/闰日不能偏一天。

## 3. 查询与分页边界

采用新增**只读**的时间轴投影/查询（接口名称由实施卡最小设计决定，候选 `GET /api/v1/timeline/assets` 与 `GET /api/v1/timeline/periods`）；尽量重用 `api/queries.py`、`taken_time/read.py`、人物/合集/地点原资格和索引。共享 API/适配器可以按现有能力合并，不强制发明第二套 source-of-truth。

- 请求限定 kind（all/source/person/collection/place，search/map 由后续卡评估）、成员标识、time_basis、group_by、year/month/range 与稳定游标/版本；不能任意字符串拼接 SQL，必须验证成员身份、权限和参数。
- 照片分页固定 48～60 左右、采用服务端权威过滤后 keyset（日期键＋asset_id）和有界查询，返回稳定时序、每张 display_date/time_source/可信标签、当前查询语义及 next_cursor。相册中的同一 asset 去重（合集、同来源重复路径、合照场景）；人工锁/活动资产、视频资格等现有过滤始终前置于分页。
- period 摘要返回**当前成员范围内**存在的年份和所选年份月份与可信统计；不得前端用首批照片计算全库比例或编造不存在的月份/总数。年月跳转直接按服务端日期区间起始定位，不能通过重复读取前面所有游标实现。
- time_basis、成员范围、修订 revision、游标、年月筛选改变后抛弃旧响应和旧游标；旧请求晚到不覆盖新视图。409/过期时给出清晰刷新/重查入口而非死循环；会员/地点/图库更新后保留合理的滚动锚点并重新获取权威行。
- 首屏行一次附带所需日期，不对每张卡额外 GET /assets/{id} 获取拍摄时间（避免 N+1）。延续缩略图懒加载、缓存和离线原图回退；不批量拉原图。
- 只在实际 SQLite 查询计划出现扫描/排序瓶颈时提出**最小索引**；若必须 schema/migration，先核对 ADR-0011、升级/兼容与 V3.1 策略并在该卡明确测试门槛，不得暗中改 schema。不能修改人工归属/识别/搜索写接口、重建模型/向量或真实图库。

## 4. 页面职责矩阵

| 页面 | 本轮行为 | 归属任务 |
|---|---|---|
| 全部照片与来源图库 | 新时间轴默认拍摄、日分组；来源筛选与图库管理 | A、CORE、B |
| 人物相册 | 时间轴只读展示；身份勾选/纠错/封面沿用现有动作 | D |
| 人物合集 | 日期分组，唯一资产去重；成员管理不变 | D |
| 地点相册 | 全相册权威成员先筛后排序再分页；地点纠正保留 | E（如需只读 adapter 可改最小后端） |
| 搜索 | C 先统一主查询框；后续只纯条件全量或明确有界候选接时间模式，相关度是默认 | C、SEARCH-MAP |
| 地图 | 地图点/viewport/版本规则原样；仅范围照片列表可切时间 | E、SEARCH-MAP |
| 图片查看器 | 返回原滚动与年月条件，打开同日；关闭/焦点/ESC 保留 | F |
| 待整理脸/忽略人脸/批量管理 | 仍是按任务/候选分组的工作流，不接照片时间轴 | D 仅整理外观 |

## 5. 任务执行顺序（一个会话一张卡，互相共享前卡证据）

1. [P4-UI-SHELL-A](../tasks/P4-UI-SHELL-A.md)：保留导航外壳，先不造时间 API。
2. [P4-UI-TIMELINE-CORE-A](../tasks/P4-UI-TIMELINE-CORE-A.md)：做可信日期、只读查询、period 摘要、分页与前端共享渲染组件；先用合成页验证。
3. [P4-UI-PHOTOS-B](../tasks/P4-UI-PHOTOS-B.md)：首页和来源正式接入 + 来源管理排版（B 不重造后端）。
4. [P4-UI-PEOPLE-D](../tasks/P4-UI-PEOPLE-D.md)：人物/合集复用时间轴、保留全部已实现整理能力，完成视觉层级。
5. [P4-UI-PLACES-E](../tasks/P4-UI-PLACES-E.md)：地点相册复用，最小修补地点成员日期查询，原地图入口。
6. [P4-UI-SEARCH-C](../tasks/P4-UI-SEARCH-C.md)：原自然语言搜索的一个输入框/标签/结果层级（与搜索地图时间轴卡串行修改 search.js）。
7. [P4-UI-TIMELINE-SEARCH-MAP-A](../tasks/P4-UI-TIMELINE-SEARCH-MAP-A.md)：搜索结果时间模式/地图范围照片列表接入。
8. [P4-UI-VIEWER-F](../tasks/P4-UI-VIEWER-F.md)：查看器统一视觉、年月条件返回、同日跳转及受影响面收口。

C 与 D/E 若无共享文件理论上可调整先后，但默认串行，避免多任务同时改同一文件。F 可提前做视觉子项，但不得抢先假装时间轴返回上下文已经实现。每张卡自身状态独立，本设计更新不等于产品实施。

## 6. 最少验证与升级门槛

个人相册按最少必要检查：小型合成素材（建议 20～40 张，至少覆盖跨两页、同日、跨年、仅文件时间、无时间、去重、revision 失效、离线图），新增行为定向 pytest JUnit、改动 JS node --check、涉及 Python 的 Ruff/py_compile、git diff --check，受影响入口小型浏览器验证。照片来源/人工状态的写操作仍核查原协议与失败反馈；真实图库只由用户自行试用，**不得擅自访问 PhotoSearchData**。

核心卡新增 API/查询或地点成员索引时按 V3.1 正确分类审核（通常只读 B，触及 schema/写状态再提升），不能因“简单测试”跳过必要风险验证；不默认跑全仓、GPU、OCR、模型或 30 万图容量测试。仅当性能设计需要时做独立小型构造数据查询计划/分页时延核查，实测数据记录，不编造性能收益。

完成目标：2–3 千张个人试用下日常照片能用日期连续浏览、找到旧年月不必刷几百屏、跨页不重漏、返回位置可靠；成员和纠错结果正确。此后停止扩展，不自动加 AI 回忆/分享/上传/复杂动画。
