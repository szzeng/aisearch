# P2-00 — 地点分类纳入后的全项目实施路线图

日期：2026-09-13。性质：规划完成，后续功能待实现。需求：实际地点（国家／城市／景点／自定义地点），支持 GPS 和手动归类。架构基线为 V3.0 需求修订 4，执行策略为 V3.1 修订 3；决策见 [ADR-0004](../decisions/ADR-0004-place-classification-plan.md)。

## 1. 现状与要交付的产品

仓库基线 `e42c544`：P0/P1 已在状态文件标为收口，P1-06 有 16 项生命周期新增验收证据；schema_version 仍为 1。已提供扫描、资产身份、缩略图、本地 API 与静态浏览页。时间排序是加入时间；没有地点表、GPS 入库、正式搜索索引、地点 UI、remap 产品入口。这里依据代码和历史报告核对，未重新运行 P0/P1 全套验收。

最终首版闭环：添加来源 → 即时浏览 → 后台语义建库 → 地点整理与中文／图片搜索 → OCR 和人物纠错 → 备份、换盘、升级与恢复。无 GPS、无地名包、无可用 GPU 分别影响各自能力，已存人工信息与基础浏览始终可用。

| 用户需求 | 首次可用阶段 | 明确行为 |
|---|---|---|
| 给没有 GPS 的旧照片标“杭州／西湖”或“外婆家” | P2-03A API、P2-03C 页面 | 建地点并按照片指定；不修改原图 |

## 2. 地点的产品范围

首版应有六个页面，其中新增“地点”：国家／地区、行政区、城市、景点、自定义地点树；可搜索地名、查看完整层级，显示去重照片数及“无地点／待确认／手动未归类”。详情提供依据、GPS 按需查看、指定、取消、恢复自动；地点页支持最多 500 资产一批的整理及最近操作撤销。

一张照片只有一个当前最具体拍摄地。例如“杭州 → 西湖 → 某景点”只存末级归属，查询杭州展开其后代；只知道杭州就停在城市级。家／公司可独立存在，没有经纬度也可使用。同名地点可并存，显示层级和稳定 ID；不自动合并。

机器建议与有效分类分别显示。地点名字出现在路牌、截图或 OCR 文字中，不等于拍摄在那里；画面像海边也不自动产生城市。首版不做地图瓦片、全球景点自动识别、地理围栏、行程轨迹、跨照片传播和地点合并。

## 3. 数据与处理路线

处理顺序为：资产 hash 确认 → 独立 CPU GPS 提取 → 版本化 GPS 事实 → 独立 CPU 地名包解析 → 候选建议 → 用户确认 → SQLite 有效地点 → FTS／过滤投影。GPS 和语义编码互不等待。

| 层 | 权威或产物 | 更新规则 |
|---|---|---|
| 内容身份 | assets、file_locations，沿用 ADR-0002 | GPS EXIF 字节改变即新资产；目录改变不改地点 |
| 原始事实 | asset_geo_facts + 版本化 artifacts | 保留原值、坐标基准、来源和解析状态 |
| 地名目录 | places、place_aliases | 稳定本地 ID，名称不唯一；用户整理不被包更新覆盖 |
| 解析候选 | place_resolutions / artifacts | 带 extractor/resolver/dataset/input revision，允许空结果 |
| 人工归属 | asset_place_assignments、exclusions、operations/items | 人工锁、排除、幂等、期望版本、补偿撤销 |
| 派生查询 | search_documents/FTS、LanceDB 过滤投影 | 最新 SQLite 状态驱动，支持补查；不重新编码图文向量 |
| 数据包 | geo_datasets manifest + geo/datasets 只读包 | 完整校验后原子激活；任务／引用保护，缺包可手动工作 |

详细状态及筛选语义以主架构 §4.5 为准。P2-01 只冻结通用外壳；P2-01A 将上表转成精确字段／CHECK／外键、事务和 API 契约。实施按 ADR-0002 的连续编号迁移与目标 schema 校验走，不直接改 0001 或绕过校验器。

首版选择 GeoNames 城市点离线包作为解析候选方案。下载准备工具只访问公开参考数据，不提交照片或坐标。选择语言和区域后构建可复现包，记录真实体积／耗时；先校验 SHA-256、格式、许可文件、层级引用、异常记录和版本兼容。普通应用启动不联网下载，坐标不进入诊断日志或反馈。

现有地名点不能证明行政边界包含关系，因此首次交付接受的是“建议 + 人工确认”而非高精度全自动归类。未来若要自动行政区归类，单独冻结边界来源、版本、坐标基准和边界歧义；现有人工数据无须换模型或重建。

## 5. 专项验收矩阵

| 情况 | 必须观察到的结果 | 主要任务 |
|---|---|---|
| 无 GPS／(0,0)／南西半球／非法分母／越界／未知 datum | 分别解析，不误把零值当缺失；坏元数据隔离 | P2-03A |
| 文件提取时改变、原图离线、重复来源、改名移动 | 使用已验证输入；旧结果不附新资产；离线非 ABSENT；按资产复用 | P2-03A/08 |
| 城市同名、邻近国界、海上、缺中文别名 | 展示层级／原名与距离，建议可为空，不伪造行政归属 | P2-03B |
| 无包、坏 checksum、半包、升级被杀、旧解析迟到 | 旧数据和手工路径可用，包可恢复；人工状态不变 | P2-03B/08 |
| 指定→取消→重扫→恢复自动→再指定 | 锁与排除有明确语义，取消不会自动加回 | P2-03A/C/08 |

| 地点改名、深层树、父环、同名、重复文件位置 | 稳定 ID、禁止环、计数去重；旧投影不控制权威结果 | P2-03A/04/05 |
| 地点 OR + 其他条件 AND、后代、无地点、人工未归类 | API/SQLite/向量/FTS 语义一致，建议不算已归类 | P2-05/06/08 |
| 修改地点发生在搜索计算/翻页期间 | 版本复核，旧会话明确过期，重搜能补回新命中 | P2-06/08 |
| GPU 故障但地点筛选／手工整理／GPS 任务继续 | 设备资格互不阻塞；无隐式语义 CPU fallback | P2-02/08 |
| profile 回退、备份恢复、地名包缺失 | 最新人工地点／名称／排除保留；已有分类可查 | P4-04/05 |
| 普通日志、URL、反馈、静态包、外网请求 | 不含精确坐标／本机路径／私有照片，运行无地理外网调用 | P2-03B/C、P4-07 |

先用 `%TEMP%` 生成的 GPS 图片和极小合成地名表校验确定行为，再用固定公开地名包／经授权位置样本评估覆盖。不能用合成数据声称真实城市准确率，也不能以近邻命中率冒充行政边界准确率。

地点业务不变量夹具要求 100% 通过；GPS 数值允许误差在 P2-01A 固定。建议质量报告 top-k 候选命中、距离分布、无匹配率、歧义率、中文显示覆盖与样本量，阈值先在 P2-03B 卡冻结再测；本次不杜撰精度数字。

## 6. 成本、风险与取舍

- 不增加地点 AI 模型，复用 CPU 队列、Pillow、SQLite、artifacts/outbox 与已有 UI，GPU 最低配置要求不变。
- 地名点包不是第二业务数据库；catalog.db 保存唯一人工知识。是否采用 SQLite RTree 或普通网格索引在 P2-01A 定最小接口、P2-03B 用已安装 SQLite 能力验证，未验证不能扩大依赖。
- 容量预算必须分别测地名包、每资产 GPS／控制行、候选产物、FTS／投影、操作历史及保留版本。以 `资产数 × 实测每资产字节 + 地名包 + 待投影/日志 + 备份峰值` 外推，不把原始坐标几列大小当总成本。
- 元数据 I/O 与 hash／缩略图竞争；限制并发、按批提交，记录查询争用。地名包全表查最近点不得每张图全扫，需有候选索引和精确距离校验；跨日期变更线／极区另有用例。
- 一次大批量地点改名可能影响大量后代资产：目录写入短事务，持久记录投影待办，分批派生；期间读 SQLite 最新名称并失效会话。
- 不承诺日历工期。P2-01A 收口后先评估 P2-03A 的真实改动面，P2-03B 小包试验再记录吞吐与空间，随后确定规模预算。
- 现存单写者跨进程压力、媒体在事件循环、O(assets) stats/media-status、真实卷故障等继续记为欠项：调度/媒体非阻塞在 P2-02，查询统计/索引规模在 P4-01，真实卷故障和发行验证在 P4-05B/07。不能因地点加入而隐去既有风险。
