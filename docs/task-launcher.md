# 下一任务自动生成规则

每完成一个开发任务后，不要等待用户手工填写下一任务模板。

请根据仓库当前实际状态自动生成下一任务的完整执行任务卡。

## 1. 读取顺序

首先读取轻量入口：

1. `AGENTS.md`
2. `docs/development-status.md`
3. 当前任务卡和当前任务的测试报告
4. 当前 Git 状态和最近提交
5. 与下一任务直接相关的已有实现、接口和测试

然后按需读取：

6. `个人图片搜索系统_V3.1_Codex_DeepSeek_开发执行策略.md` 中用于确定依赖、模型路由、升级条件和验收等级的相关章节
7. `个人图片搜索系统_V3.0_开发主架构.md` 中与下一任务直接相关的章节

默认不读取两份当前文档全文。只有以下情况才全文读取：

* 首次进行架构对齐
* 当前或下一任务卡缺失，或与仓库真实状态冲突
* 任务需要作出跨模块架构、协议或数据语义决策
* 用户明确要求完整架构审查

不得仅根据聊天历史推断项目状态。

## 2. 确定下一任务

依据：

* `docs/development-status.md`
* V3.1 开发执行策略中的阶段依赖和任务表
* 当前真实 PASS / FAIL / BLOCKED / VALIDATION PENDING 状态

确定唯一的下一任务。

如果一个计划任务适合拆成多个独立可验收子任务，应拆成：

`P?-??A`
`P?-??B`
`P?-??C`

但保持它们仍属于原计划任务，不擅自修改总体路线。

## 3. 自动选择执行模型

依据 V3.1 开发执行策略中的任务路由和对应阶段任务表。

当前有效档位：

* DS-L → DeepSeek V4.1 Flash / 低推理
* DS-H → DeepSeek V4.1 Flash / 高推理
* DS-MAX → DeepSeek V4.1 Flash / max 推理（仅独立 DS-H 审查命中命名条件后的临时升级档）
* C0 → GPT-5.6 Luna
* C1 → GPT-5.6 Terra / medium
* C2 → GPT-5.6 Sol / high（高风险协议与数据安全边界的聚焦终审/最终冻结）

“冻结”必须区分两层：DS-H 可草拟契约、证明可实现性并给出建议冻结结论；凡涉及 V3.1 §11 高风险清单或任务表
明确要求最终冻结，必须由 Sol high 聚焦终审通过后才可写正式冻结。低风险且无语义变化的机械契约可由 DS-H
收口，但报告必须写 `SOL_NOT_REQUIRED` 和理由。

不再生成 `DS-N`。普通实现任务不得默认生成 DS-MAX；只有独立 DS-H 已做实质审查并命中下列条件之一，
才可把当前审查升级为 DS-MAX：

1. 跨多个模块的异常无法证明根因；
2. transaction / revision / undo 多状态互相影响，DS-H 后仍矛盾；
3. 测试通过但行为与 ADR 不符，无法判断测试或实现哪一方有缺陷；
4. 一次修复引发第二处或第三处相关回归；
5. 大 diff 含多个状态机耦合，需要长程整体推演；
6. Sol 聚焦终审提出问题，需要 DeepSeek 大范围反查。

任务卡/报告必须写明命中的条件编号、已有证据和待回答问题；“代码多”“测试慢”或普通单点失败不构成升级。

模型选择表示下一任务在 Codex 中推荐使用的执行模型/推理档。**模型切换始终由用户手动完成。** Codex 只负责记录和提醒，不尝试自动切换模型，也不得声称已经切换。

如果下一任务指定模型与当前模型不同，完成当前任务的报告、状态更新和下一任务卡生成后停止继续实现下一任务，并明确提示：

`下一任务建议使用 XXX，请在 Codex 中手动切换模型/推理档后继续。`

如果模型相同，则提示可以继续使用当前模型。不得要求切换客户端、启动另一个 Agent，或把 DeepSeek/GPT 描述成独立开发端。

## 4. 自动选择工作方式

* DS-L / DS-H：按冻结契约实施功能；遇到环境问题按策略推荐转 C1。
* 独立审查：新会话 DS-H 按 V3.1 §2.4 选择完整受影响面主审或有界专项审查；两者都审完所定范围的完整
  diff、任务卡验收证据与必要契约/调用链，并在报告中记录适用条件和扩大范围的判断。只按上述六类条件升级 DS-MAX。
* C1 / Terra：处理 Windows、ONNX、PyInstaller、DLL、权限、路径、驱动和固定最终集成检查。
* C2 / Sol：只接收 DS-H/DS-MAX 已收敛的高风险不变量、事务/恢复边界、ADR 差异、未决项和最小反例，做
  聚焦终审/最终冻结；不重复全量工程主审。协议冻结后的普通实现优先推荐 DS-H。

同一验收闭环同时含 DS-H 主审与 Sol 终审时，任务卡必须拆成两个独立新会话阶段，不得要求在同一会话中途
切换模型：

1. DS-H 阶段输出独立工程主审报告和压缩交接包；Sol 必选时状态写
   `ENGINEERING REVIEW PASS / SOL FOCUSED REVIEW PENDING`，停止且不得生成总任务的下一卡。
2. Sol 阶段只读 `AGENTS.md → development-status → 当前任务卡 → DS-H/DS-MAX 阶段报告` 以及报告点名的
   ADR 条款、关键 diff 和最小反例；默认不重读全仓、不重跑完整成功套件。
3. Sol 通过后才标总任务 PASS 并生成下一卡；Sol 不通过则把最小反例和修复范围交回 DS-H，修复后只做受影响
   边界短审。

压缩交接包只包含：基线/改动文件/结论表、必审或未决高风险项、ADR 预期与实际差异、关键 diff 定位、最小
反例与命令结果摘要、未验证项与禁止扩大的范围。不得复制聊天历史、完整大文档、完整 diff 或全部成功日志。

上述“转 C1 / 转 C2 / 转 DS-H / 升 DS-MAX”均表示提示用户在 Codex 中手动切换模型后继续，不表示自动切换或 Agent-to-Agent 交接。

不得为同一任务无目的地轮流尝试所有模型。

## 5. 自动填充的信息

生成任务卡前，必须从仓库中确定：

* 任务 ID
* 当前 Git 基线提交号
* 上一任务及状态
* 推荐执行模型
* reasoning 档位
* 本任务用户场景
* 需要读取的架构/策略章节
* 相关现有实现
* 允许修改的文件或目录
* 禁止修改的范围
* 本任务必须保持的数据/接口不变量
* 已存在的类型/API/迁移/协议
* 正常行为
* 异常行为
* 边界情况
* 验收等级（A/B/C/D）与验收命令
* 需要更新的测试报告
* 完成后应该进入的下一任务
* 什么失败条件需要推荐切换到其他模型
* 若任务含独立审查：V3.1 §2.4 的 DS-H 审查方式、适用条件/升级触发器与覆盖范围、DS-MAX 六类条件、
  Sol 是否必选及理由、两阶段报告路径、压缩
  交接包字段、Sol high 聚焦终审输入与边界、阶段停止点和失败回退路线

不能确定的内容必须标记为“执行时先检查”，不能凭空编造文件、接口或命令。

## 6. 任务粒度

任务必须是一个可以独立验收的闭环。

禁止生成类似：

“完成整个 P0”
“实现完整搜索系统”
“完成所有后端”

这样的宽泛任务。

如果原任务过大，先根据执行策略拆成若干最小可验收子任务。

## 7. 验收与 token 控制

任务卡必须遵循 V3.1 的最低验收等级：

- A：相关 pytest + ruff + diff-check
- B：`pytest -q tests/unit tests/integration` + ruff + diff-check
- C：B + 实际构建 + 打包 smoke test
- D：B + 对应故障注入/恢复测试；涉及打包再加 C

成功时只保留 quiet 摘要、退出码和必要计时，不把完整成功日志塞进上下文。失败时先读取失败测试和 traceback 尾部，只重跑失败目标；需要定位时再增加 `-x -vv`。

任务卡规定的必需验收尚未完成时，禁止标记 PASS。使用 `IMPLEMENTED / VALIDATION PENDING`、`BLOCKED` 或 `FAIL` 反映真实状态。

## 8. 输出位置

完整任务提示词保存到：

`docs/tasks/{任务ID}.md`

同时在：

`docs/development-status.md`

记录：

* 当前已完成任务
* 下一任务 ID
* 下一任务推荐模型
* 下一任务任务卡路径

## 9. 任务卡要求

任务卡必须已经是可以直接交给目标模型执行的最终提示词。

不得输出：

“请用户填写允许修改文件”
“请补充验收命令”
“请指定相关章节”

这些内容应由当前模型根据仓库和开发策略自行确定。

如果仓库确实没有足够信息，则写：

“执行本任务第一步先检查 XXX，并以实际结果为准。”

## 10. 完成当前任务后的固定动作

当前任务全部必需验收通过后：

1. 更新测试报告。
2. 更新 `docs/development-status.md`。
3. 保存本任务交接记录。
4. 根据 V3.1 开发执行策略确定下一任务。
5. 自动生成下一任务的完整 `docs/tasks/{ID}.md`。
6. 最终回答中仅告诉用户：
   * 当前任务 PASS / FAIL / BLOCKED / VALIDATION PENDING
   * 下一任务
   * 下一任务推荐模型/推理档
   * 下一任务卡路径
   * 模型操作：继续使用当前模型 / 请在 Codex 中手动切换至 XXX 后继续

若当前只完成多阶段审查中的 DS-H/DS-MAX 阶段且 Sol 为必选，不适用“全部必需验收通过”：只更新阶段报告和
状态，明确下一阶段为 Sol 聚焦终审并停止；不得提前标 PASS 或生成总任务的下一任务卡。

不要要求用户再次手工填写任务模板。
