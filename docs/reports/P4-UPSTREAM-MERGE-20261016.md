# 本地性能与可靠性改动

基线：上游 `b895a5c`（2026-10-16 获取，相比上一轮 `b85a17d` 新增8个提交）。本地优化已合入最新人物/合集/待整理分类、静态人脸平铺、头像预览和0.3.0版本，交付分支为 `codex/latest-performance`。最后一个提交仅新增未来任务草案，没有擅自开始该任务。合流和自动回归已完成，真实双页面冲突恢复仍待浏览器验证，因此不标记整项验收或正式发布通过。

## 改了什么

| 功能 | 修改方法与结果 |
| --- | --- |
| 大图库浏览与建库 | 用游标接续读取替代深分页，去掉重复来源查询；拍摄时间浏览利用时间索引后精确合并。人物/合集使用成员驱动查询，避免小相册也扫描全库。 |
| 地图与时间轴 | 利用现有空间索引，补充时间、有效文件位置和未确认队列的读取索引；复用同一数据版本的统计，减少移动地图和翻页时的重复扫描，保留来源、日期和资产有效性过滤。 |
| 精确文字/图片搜索 | 权威候选只查询一次，再分批读取；连续编号压缩为范围条件，向量按块读取并逐步合并最优结果，控制内存。仍检查全部候选、精确距离、稳定排序和最终成员资格，没有改成近似搜索。 |
| 来源、人物与进度统计 | 同类计数合并为一次 SQL；有效的手选头像直接验证，失效时才重新选择。文字索引状态按当前读取快照判断，修复仍有待更新内容却显示“已同步”。 |
| OCR 完整性 | 去重同时考虑文字、行位置和覆盖关系，防止尾段覆盖完整行；方向分类翻转后结果不可靠时，补试原方向。新任务统一使用 `@3`，历史 `@1/@2` 结果仍可读；过期内容正确显示待更新。 |
| 模型与图片方向 | 删除 worker 对已加载模型的第二次加载，延后不必要的大库导入；统一建库和以图搜图的 EXIF 方向处理，并隔离不兼容的向量空间。旧结果不会因更新代码自动重算。 |
| 并发与恢复 | 慢读取进入有界线程池，避免阻塞其他请求；模型通信串行配对，防止并发拿错回复。任务恢复使用条件更新，避免为每个任务展开参数而超过 SQLite 上限，并修复启动迁移和重复来源注册的竞争。 |
| 脸级合集 | 保留“动态人物照片 ∪ 静态收录人脸照片”，人脸收录不确认整个人物身份，移出合集不恢复忽略状态。改为集合查询、按需计数，同一快照返回数据、数量与版本；来源失效时整批拒绝收录。 |
| 前端交互 | 修复候选组初次展开/选择后折叠报错、普通点击误连选、跨合集残留、迟到响应覆盖、版本刷新及数量更新；修复窄窗口挤压和详情返回后筛选控件不一致。 |
| 数据库与维护 | 上游正式迁移 `0032` 不变，本地索引顺延 `0033`。结构检查仅缓存由完整迁移内容推导的期望结构，每次仍检查实际数据库。地点包兼容至 33、未知 34 仍拒绝；维护清理保护脸级合集人工引用，即使原人脸失效或图片内容变化。 |

保留 SQLite + FTS5、LanceDB、FastAPI、ONNX Runtime/PyTorch；没有更换核心组件或新增运行依赖，`pyproject.toml`、`uv.lock` 未改。向量方案试验后，保留内存开销较小的分块精确检索。

本轮合流另外修复：来源路径请求附带列表版本，拒绝过期响应，注册新来源后刷新路径；其他分类中的人物变动使合集目录缓存失效；切换合集时清理旧请求状态，成员页刷新父合集版本不再把当前人物照片替换成整个合集；返回目录恢复原位置。批量工具栏首次显示即加载完整合集选项，复用分页与缓存，失败可重试。上游头像点击预览规则保留，复选框与 Shift 继续负责选择。

## 30 万照片的合集查询对比

以下是前轮 `b85a17d` 的查询测量，本轮未重跑；相关后端查询实现未变。同一合成库含 300000 张照片、315000 张人脸、203 个合集。对比当时上游合集模块/过滤谓词和本地实现，其余依赖及索引共享本地版本；因此衡量的是合集查询差异，不是整个应用相对纯净上游的加速。交替执行 10 对暖缓存调用的中位数如下，完整响应一致。

| 场景 | 上游实现 | 当前实现 |
| --- | ---: | ---: |
| 合集目录 | 3654.071 ms | 541.139 ms |
| 纯人脸合集照片首屏 | 4115.481 ms | 152.463 ms |
| 混合集合照片首屏 | 6119.997 ms | 843.667 ms |
| 纯人脸合集人脸列表 | 0.510 ms | 0.584 ms |
| 混合集合人脸列表 | 0.514 ms | 0.618 ms |

列表两个场景略慢，仍低于 1 ms；不声称所有场景均提速。测量不含 HTTP、浏览器、模型推理和原图读取；10 对样本不作为稳定尾延迟认证。硬件为 Ryzen 9 9900X、64 GB RAM、RTX 5070 Ti 和 SATA HDD，不代表 GTX 1660 或 30 万真实照片的导入吞吐。
