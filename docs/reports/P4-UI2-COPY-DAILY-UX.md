| 真实触发条件 | 原问题 | 修复 |
|---|---|---|
| 图库为空 | 首页提示用户展开“添加图库来源”，但来源表单实际位于“图库管理”页面；旧文案还引用已移除入口。 | 指向“图库管理”→“添加图库来源”，说明填写照片目录路径后建库；不暗示文件夹选择器。 |
| 图库为空、尚未建库、正在刷新/建库、当前筛选无结果 | 多种状态共用容易误导的“没有可浏览照片/去建库”提示。 | 分别提示当前状态与可行操作；筛选无结果时建议调整/清除条件，刷新进行中时说明等待完成。 |
| 浏览或搜索结果回收早期显示节点 | “已回收”可能被理解为照片文件被删除。 | 明确仅从当前页面暂时移除，原照片没有删除。 |
| 普通搜索筛选、日期回显、FILTER_ONLY 结果 | 页面直接显示 canonical、请求字段和通道协议术语。 | 改为人物数、实际生效条件及普通语言的筛选排序说明；继续准确显示“含开始，不含结束”。 |
| 搜索摘要、智能合集规则候选 | 候选总数容易被理解为实际匹配数或可浏览数。 | 标注“候选照片/规则候选照片”，说明排除项复核后可浏览数量可能不同。 |
| 地点建议确认、固定清单、批量保存、撤销和异常 | 普通界面展示过多内部字段，地点搜索空结果还显示 `place_id`/错误码；已映射请求失败也先显示内部错误字段；编辑地点读取失败还可能被吞成“地点不存在”。 | 使用照片、地点归属、固定清单和操作记录等自然表达；已映射错误显示可操作中文并保留请求编号，未知错误保留脱敏后的诊断消息；地点空结果要求核对编号，读取失败单独提示重新加载并保留请求编号。 |
| 地图底图未配置或运行不可用 | 不同失败原因均缺少下一步，且可能让用户误以为照片不可浏览。 | 统一说明照片列表仍可用；未配置时指出地图设置中的天地图 Key，配置读取/运行故障提示检查本机地图服务配置。 |
