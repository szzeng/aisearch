## 实现

- 新增独立 `/?view=memories` 回忆页入口，卡片只在首次进入后请求生成；首页启动和普通照片浏览不会初始化回忆 runner。
- 新增一个受控只读后台线程和单待办槽，按年份增量查找。后台使用独立只读 SQLite 连接；前台 Catalog 读取繁忙、扫描/任务运行、取消或相关修订变化时暂停/中止当前范围，关闭时取消并等待线程退出。
- 只使用当前日期规则下的 `EXIF_ORIGINAL` / `EXIF_DIGITIZED`、ACTIVE 资产及仍存在的图片路径。查询显式用 `idx_asset_metadata_capture`，并以 SQLite progress handler 为单 SQL 设置 75ms 工作时间上限；超限不发布为无结果，保留已完成年份并可重试。
- 单日分4个6小时时段，每段最多60条合并候选、合计最多240；月份按日和可信 EXIF 来源各取最多1条、最多31条/来源，避免连拍密集日占满月候选。稳定规则最多精选24张。卡片张数始终是精选数量。
- 卡片缓存最多32项并绑定本地日期、图库/日期规则/收藏修订及算法版本。已完成结果按有效修订展示。普通合集保存只提交当前精选 ID，复用现有 `create_request_id` 与服务端资格校验/事务。
- 修复回忆页轮询定时器在进入精选详情后仍继续请求的问题；详情只保留精选轮询，卡片页重新进入时再启动卡片轮询。

## 状态恢复修复续验（2026-10-23）

- 复现原因：离开回忆页会无条件请求取消。若发现任务已经结束，取消接口仍会把 runner 状态覆写为 CANCELLED；前端又把 CANCELLED/STALE 当成空结果，已有卡片状态下重进也只重绘本地状态，导致看起来“没有回忆”。另 `MORE`（最近窗口结束但仍有更早年份）也落入空结果兜底文案。
- 修复：无活动或待办工作时 `cancel()` 保留当前状态；目录状态与预览任务解耦，按发现进度返回 COMPLETE/MORE/PARTIAL。中断或过期状态会作为未完成态继续轮询/重试；MORE 明确提示可继续检查更早年份，只有全部可用年份检查完成才显示最终空状态。
