# 个人试用版重评补充：30 万张与渐进式搜索

2026-09-27；基线 HEAD d370022。保留现有未提交的 P4-03A/B、全项目评估与 P4-02L 工作。本轮仅评估，不实现、不运行新性能实验、不扫描照片、不下载模型。

## 最新需求与判断

用户明确：30 万张是实际刚需，不能缩小；个人项目要控制 token、评测与开发成本；希望先快速出现一些结果，再逐步补齐。

建议保留 SQLite、LanceDB、单机、当前模型和可靠性底座。近期工作围绕真实搜索可用性收敛：第一批有用结果尽早出现，后续完成全范围精确检索。具体秒数尚未确定，也未经测量承诺。

手机相册可提前做图片分析、查询时读索引，并使用适配硬件的模型。Apple 已公开用于 Photos 等功能的端侧多任务模型与 Neural Engine 优化：[官方资料](https://machinelearning.apple.com/research/on-device-scene-analysis)。这只是公开实例，不证明用户手机的具体实现，也不能断言所有手机都使用 ANN 或云端。

## 当前项目的主要问题

本轮复核 retrieval.py 的 vector_channel、store.py 的 search_candidates：每批 5000 个权威候选，30 万约 60 次引擎调用，最终才返回；每块请求全部候选行后再取 Top-K，以保留并列距离的确定性顺序。不能直接缩小 limit 并声称等价。

[P4-02K](P4-02K-budget-and-a3-decision.md) 的合成 service 两样本中位约 5.35 秒，引擎约 4.69 秒；单次无候选约束的引擎 pass 约 0.347 秒只证明优化空间，不是具备正确性证明的产品路径。

[P4-02J](P4-02J-contention-closure.md) 同会话空闲中位约 7.73 秒，后台 drain 时中位约 15.53 秒、7 样本 P95 约 20.47 秒；另有投影未追赶时 4/9 搜索被拒，锁来源未归因。这些是既有合成/service 数据，不是本轮真实端到端测量。

API 默认 encoder_factory 可为空；实际启动的模型接线必须核对。替身编码器、历史 GPU demo 与已经可用的真实搜索工具不是同一证据。

结论：先处理重复检索调用和前后台争用，核对真实模型接线；现有证据不支持先买硬件、换大模型或重写后端。

## 渐进式搜索的最小建议

提交查询 → 有合格结果时显示“初步结果，仍在搜索” → 完整结果就绪后一次更新。用户浏览时避免卡片不断重排，可提示用户切换最终排序。

- 只编码一次查询，复用查询与筛选条件。
- 优先验证当前分块精确搜索能否提供有用的中间结果，随后继续扫描其余候选；不必先引入 ANN、多模型或第二后端。早期按 asset_id 扫描可能没有相关照片，故首批有用性必须验证，不能以早返回非空冒充体验改善。
- 后续必须扩大搜索范围；只重排最初几十张找不回起初遗漏的照片。
- 初步结果也必须满足人物、地点、日期、隐藏状态、发布资格等条件。全局 Top-K 后过滤仍可能漏掉合格候选。
- 同候选/配置/有效版本下，最终结果与现有完整精确路径对照。改条件、取消、人工事实变更或配置切换时，旧请求不得污染新结果。
- 当前同步 API 和会话/游标不支持中间状态；需要最小增量协议、执行隔离和相应回归，不能只加进度条。先少量更新加一次最终排序，不做逐张推送、永久任务平台或复杂消息系统。
- “完整”是当前可检索范围计算完成，不是全部相关照片保证：未建库照片、模型识别遗漏和有界 Top-K 截断仍须分别说明。当前默认通道 Top-K 为 200；全范围扫描不等于返回所有相关照片。

渐进式展示不代替总耗时优化。如果精确路径修复后等待已经可接受，就可以推迟中间状态协议，避免为形式增加复杂度。

## 控制投入

保留：30 万容量、原图只读、人工知识、筛选正确性、故障恢复、现有单体与存储。

优先：单模型真实启动→查询→结果→缩略图闭环；一处主要检索瓶颈；后台写入争用与搜索失败。

建议后置：完整模型升级/回退管理、复杂设置、多模型、大型 ANN 参数曲线。已有 P4-03A 冻结成果保留；P4-03B 与 P4-02L 不因已经立卡自动成为个人试用的最优下一步。本报告只调整建议，不撤销旧任务或改写其状态。

验证采用少量固定查询（建议 20～30 条）做个人体验冒烟，记录预期目标是否出现、首批有用结果时间、最终完成时间及失败；它不能证明总体 Recall。只使用已授权样本和登记模型，无授权不扫描照片。

复用现有 30 万合成夹具测容量与精确结果等价，小夹具做正确性回归；真实语义质量另用授权样本。保留空闲、后台建库、重启恢复场景，不新建多规模/多模型/多参数评测平台。涉及筛选、排序、取消、旧请求污染、人工事实与写入恢复时，直接回归和适用策略要求的检查不能省。测试输出 quiet + JUnit；本轮无代码变更，不重跑全量测试。

建议把第一批有用结果和最终完成时间分开定目标。用户未指定秒数；原 §12.2、最低 GPU 发行承诺和未通过记录不在本轮改写。个人本机试用与跨机型正式发行应分开记录，不能将未验证说成支持。
