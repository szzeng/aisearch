# 2026-09-20 剩余任务审查路由与 token 优化对齐（修订 2）

## 结论

从 P3-06 起，剩余任务采用统一审查链：

```text
独立新会话 DS-H 全量工程主审
  → 仅命中六类条件时手动升 DeepSeek max
  → 压缩交接包落盘并停止当前会话
  → 必选时由独立新会话 Sol high 对高风险不变量、ADR 差异、未决矛盾和关键反例做聚焦终审
```

这次调整只改变模型分工与审查输入，不改变任务顺序、产品架构、冻结协议、验收等级或 PASS 门槛。模型切换
仍由用户在 Codex 中手动完成。

“冻结”分成两层：DS-H 负责契约草拟、可实现性证明和工程预审；V3.1 §11 高风险协议及任务表明确要求的
最终冻结，只有 Sol high 聚焦终审通过后才能正式冻结。低风险机械契约没有语义变化、没有未决项时，可由 DS-H
记录 `SOL_NOT_REQUIRED` 后直接收口。

## DS-H 全量工程主审

主审必须在独立新会话中核对完整 diff、任务卡允许/禁止范围、相关 ADR/contract、跨模块调用链、迁移与状态机、
测试/JUnit/打包/浏览器证据和未验证项。实现者自检不能替代这一步。

DS-H 阶段结束时生成独立工程主审报告和压缩交接包；若 Sol 为必选，状态只写
`ENGINEERING REVIEW PASS / SOL FOCUSED REVIEW PENDING`，不得提前 PASS 或生成总任务的下一卡。

## DS-H 升 max 的唯一条件

1. 跨多个模块的异常无法证明根因；
2. transaction / revision / undo 多状态互相影响，DS-H 后仍矛盾；
3. 测试通过但行为与 ADR 不符，无法判断测试或实现哪一方有缺陷；
4. 一次修复引发第二处或第三处相关回归；
5. 大 diff 含多个状态机耦合，需要长程整体推演；
6. Sol 聚焦终审提出问题，需要 DeepSeek 大范围反查。

升级报告必须记录命中的条件编号、已有证据和待回答问题。“代码多”“测试慢”“想更稳”或普通单点失败
不构成 max 条件。

## Sol high 聚焦终审输入

Sol high 默认只读取 DS-H/DS-MAX 主审结论、未决问题清单、相关 ADR/contract、关键 diff、最小反例与受影响
测试。除非发现证据缺口，不重复全仓逐文件主审或全部成功日志。需要最终冻结的协议仍由 Sol high 作最终裁决，
但工程证据先由 DeepSeek 收敛。

压缩交接包只保留：基线/改动文件/结论表、必审或未决高风险项、ADR 预期与实际差异、关键 diff 定位、最小
反例与命令结果摘要、未验证项与禁止扩大范围。完整 diff、完整成功日志、无关大文档和聊天历史不进入 Sol 输入。
Sol 不通过时只给裁决、最小反例和修复范围，普通实现修复退回 DS-H；修复后 Sol 仅短审失败边界。

## 任务卡生成约束

后续任务卡必须明确 Sol 是否必选及理由。含 DS-H + Sol 的闭环必须写出两个阶段各自的会话、输入、输出报告、
停止点和失败回退路线；不得用一份模糊的“综合审查报告”掩盖实际执行模型，也不得要求在同一会话中途更换
DS-H 与 Sol。Sol 非必选且 DS-H 已证明无高风险语义变化/未决项时，不为形式完整增加一次模型调用。
