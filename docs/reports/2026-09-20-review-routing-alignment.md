# 2026-09-20 剩余任务审查路由对齐

## 结论

从 P3-06 起，剩余任务采用统一审查链：

```text
独立新会话 DS-H 全量工程主审
  → 仅命中六类条件时手动升 DeepSeek max
  → Sol high 对高风险不变量、ADR 差异、未决矛盾和关键反例做聚焦终审
```

这次调整只改变模型分工与审查输入，不改变任务顺序、产品架构、冻结协议、验收等级或 PASS 门槛。模型切换
仍由用户在 Codex 中手动完成。

## DS-H 全量工程主审

主审必须在独立新会话中核对完整 diff、任务卡允许/禁止范围、相关 ADR/contract、跨模块调用链、迁移与状态机、
测试/JUnit/打包/浏览器证据和未验证项。实现者自检不能替代这一步。

## DS-H 升 max 的唯一条件

1. 跨多个模块的异常无法证明根因；
2. transaction / revision / undo 多状态互相影响，DS-H 后仍矛盾；
3. 测试通过但行为与 ADR 不符，无法判断测试或实现哪一方有缺陷；
4. 一次修复引发第二处或第三处相关回归；
5. 大 diff 含多个状态机耦合，需要长程整体推演；
6. Sol 聚焦终审提出问题，需要 DeepSeek 大范围反查。

升级报告必须记录命中的条件编号、已有证据和待回答问题。“代码多”“测试慢”“想更稳”或普通单点失败
不构成 max 条件。

## Sol high 聚焦终审输入

Sol high 默认只读取 DS-H/DS-MAX 主审结论、未决问题清单、相关 ADR/contract、关键 diff、最小反例与受影响
测试。除非发现证据缺口，不重复全仓逐文件主审或全部成功日志。需要最终冻结的协议仍由 Sol high 作最终裁决，
但工程证据先由 DeepSeek 收敛。
