# P4-02Y-V — `top_k` 性能测试

日期：2026-09-30
性质：纯测量 / 决策；未修改产品代码与产品参数。

## 结论

1. K=200→500 的 Service P50 增加 **1.3%**，到 K=1000 增加 **6.1%**；Vector P50 分别增加 **1.8%**、**7.6%**。
2. 到 K=3000，合并样本中位数比 K=200 慢 **11.4%**，是本次合并中位数的最大上升点；K=5000 却低于 K=200 和 K=3000。两轮中 K=5000 都较快，结果不呈单调增长，因此本轮**没有测出可信的明显拐点**。原始数据保留供后续复测判断。
3. 纯性能角度，`MAX_TOP_K=1000` 有一定保守性：合法上限内 K=1000 只比 K=200 慢约 6%；K=2000/3000 中位数增加约 7%/11%。但这不足以据此变更上限，尤其 K=5000 的反常结果需要独立复测。K>1000 均为进程内诊断数据，不代表 API 契约通过。

## 条件与核对

- 固定夹具：`tmp/p402f-阶段0/scale-300000-wave/data`；300,000 assets / 300,000 index entries；同一 generation、查询文本 `西湖 sunset 全家福`、deterministic encoder 和 query vector。
- `SCOPE_BLOCK_SIZE=15000`；每个 K 每轮 warmup 1 次、正式样本 5 次；两轮按任务卡交错顺序，总计 60 个正式搜索。无后台任务。
- 当前进程将服务内存中的 `MAX_TOP_K` 临时放宽至 5000；未改 `src/**`，没有 API 契约结论。
- 全部样本均为 20 blocks、300,000 scanned assets、`truncated=false`、0 fallback。每块返回行数分别为 K+1：201 / 501 / 1001 / 2001 / 3001 / 5001。
- 五项向量前缀检查均通过；对比了完整顺序的 `asset_id` 与未舍入 `distance`：K500→K200、K1000→K500、K2000→K1000、K3000→K2000、K5000→K3000。
- Peak RAM 是搜索期间每 10 ms 采样当前工作集，并纳入调用前后读数；采样线程会带来少量扰动。此处是采样峰值，不是系统级内存统计。
- 原始 60 个样本、逐块行数、完整向量页、前缀检查、设备信息和采样顺序见 [`test-results/p4-02y-v-top-k.json`](../../test-results/p4-02y-v-top-k.json)。
