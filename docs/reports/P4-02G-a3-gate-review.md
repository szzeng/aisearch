# P4-02G — A3 架构闸门评估

**裁决：进入 A3 契约与隔离实验；当前产品继续使用 SQLite 权威候选块路径。此裁决不授权 A3 产品实现，不修改 §12.2 的 30 万资产暖机普通文字搜索 API P95 ≤1 s 目标，也不授予 P4-02B/P4-02F 性能 PASS。**

评估基线为 `f083023`，工作树在评估前干净。本文仅记录架构判断；未改 `src/**`、测试、迁移、既有 ADR、状态或性能目标，未运行新基准。这里的 A3 专指“无额外用户筛选时，试图以一次全局向量 Top-K 或等价的少候选访问取代整代候选块物化”，与 P4-02C 的同名“审计幂等 A3”无关。

## 1. 证据和口径

- [P4-02D 归因](P4-02D-attribution.md)证明 F3 主因是 `asset_id_idx` 覆盖率；同表重建索引使 10 万波次档约 14.90 s 降至 2.44 s，未改变返回页。
- [P4-02F 实测 §6、§7、§13–§17](P4-02F-retrieval-latency.md)显示：30 万全覆盖、未截断块路径在块大小 1,000/5,000/20,000 下分别约 15.13/7.05/6.42 s；阶段 1 更大块的**已测最优**为 50,000 候选×6 次、7.378 s（单样本），整代一次物化为 10.431 s（单样本）。同表 `replace` 将默认 5,000 块路径 209.44 s 降至 8.80 s，页逐项相同。表句柄复用的估计收益约 0.55 s/60 块，不足以消除量级差。
- 同一 30 万合成代上，单次无候选约束 `limit=20` 的引擎查询中位 346.96 ms（5 样本），**仅是诊断值**。P4-02F 将它与 `pending_projection_page` 359.0 ms、权威复读 28.7 ms、其他约 78.8 ms 相加得约 813 ms；未计真实中文 CLIP 文本编码、HTTP 与余量，且不是 A3 端到端实测或严格数学下界。现有测量有明显跨运行漂移。
- [主架构 §7.2、§9.2–§9.5、§12.2](../../个人图片搜索系统_V3.0_开发主架构.md)和 [ADR-0003 §8–§9](../decisions/ADR-0003-p2-processing-runtime-and-search-profile-contract.md)、[ADR-0005 §10](../decisions/ADR-0005-place-facts-assignment-and-search-contract.md)要求 SQLite 决定资格、Lance 仅作派生检索、查询绑定 profile/generation/space、发布前复核，并在投影滞后时补查或诚实报告。过滤后的全局 Top-K 不能冒充完整结果。

这些是替身编码器、暖缓存、单会话的 service/引擎证据。真实文本塔、HTTP P95、GTX 1660、冷缓存、并发维护和长时分布仍未验证；不能把上述中位或少量样本 P95 当正式容量验收。

## 2. A：当前精确路径继续优化

当前 `vector_channel` 从 SQLite 的 `(generation_id, space_id, state='CONFIRMED')` 候选流按 `asset_id` 分块，逐块调用 Lance `search_candidates`，最后按 `(distance, asset_id)` 合并。后者为保住完全并列距离的全序，向引擎请求**块内每个候选的行**，再在 Python 截到 `top_k`；因此无筛选且 30 万均已确认时，现有实现必须读取约 30 万候选 ID、构造约 30 万项的块约束，并跨各块物化至多约 30 万行。`MAX_VECTOR_BLOCKS` 若截断，结果就不能宣称完整；P4-02F 的 250 候选块/30 万例已实际截在 25 万且页不同。

在**仅**允许完整标量索引覆盖、句柄复用和块大小/块数调整的闸门 A 参数内，最佳已测 7.378 s，距 1 s 约 7.4 倍；因仅测离散参数和少量样本，它不是所有参数的数学性能下界。计算量方面，若继续让引擎返回每个候选并在 Python 物化，这一路径保有 Θ(N) 行传输/物化成本；单纯减少重复编码、索引重建或调整块大小无法消除该项。没有证据支持它在目标机上达到 30 万 API P95 ≤1 s。

仍保持**精确语义**的后续研究方向是：把 SQLite 权威资格变成 Lance 查询前可证明等价的成员谓词/快照；或在引擎内部完成带 `(distance, asset_id)` 全序的精确 Top-K 与候选资格交集，仅返回 K 行及完整性证明；同时单独优化 `pending_projection_page` 的 359 ms 级成本、索引覆盖维护与句柄复用。前两者已经改变检索策略和跨存储一致性证明义务，不属于闸门 A 的“常数项优化”。是否能达 ≤1 s 必须端到端实测，不能从 Θ(N) 或一次无约束 pass 推断。

## 3. B：A3 协议候选与冲突

### 3.1 资格和结果定义

A3 只可考虑**有绑定且无额外权威筛选**的语义请求：固定请求的 `profile_id`、`generation_id`、`space_id`、dimension 与查询向量，来源、地点、人物、拍摄时间等条件均为空，`availability=any`；纯筛选、带任一条件、跨代/跨 space、旧/不可用 generation 均不合格。“无用户筛选”只消除了 `scope_condition` 中的额外限制，**不等于** Lance 全表都是可搜索行。资格集合 `C` 必须由同一 SQLite 权威视图定义为该绑定代/空间内当前有效的 `CONFIRMED` 项，且与当前资产可见性、确认的工件/投影 revision 相符；Lance 查询所见每个行须恰好对应 `C` 中一个最新、可读、同 space 的行。当前 `vector_channel` 的 SQL 明确以 `index_entries.state='CONFIRMED'` 决定入口，而 `search_candidates` 没有对无约束全表提供这一资格证明。

A3 的输出契约不是“尽量多拿一些相近结果”，而是：对于同一稳定权威视图及 Lance 版本，向量通道的前 K 项及顺序与现行**完整、未截断**候选块精确路径逐项相同，排序为 `(distance, asset_id)`；随后 FTS、RRF、`pending_projection`、权威复读、会话/游标和错误语义保持原状。并列距离时，不能先让引擎只截 K 行，再在 Python 排序；P4-01C 已证明该做法依赖写入顺序并改变命中 ID。`top_k` 可能为 1～1000，不能只验证 20。

### 3.2 与 SQLite 权威模型的冲突窗口

Lance 写入与 SQLite 的 outbox/index_entries 确认分两步，故可存在“Lance 已写、SQLite 未确认”；修复可以令 `index_entries=PENDING_REPAIR`，旧 `projection_revision` 行可能尚在 Lance。资产可见性、用户筛选事实与活动 profile 是 SQLite 权威；Lance 的 `visible` 等派生列不自动成为资格凭证。请求执行中还可能发生发布、撤销、修复、代切换或 revision 变化。即使开头某一时刻两库计数相等，也不能证明 ID 集合、revision、行内容相等，更不能保证查询到发布之间持续相等。现有 `catalog_filter_revision` 和发布前复核保护其既有语义，不能未经证据把它当成覆盖所有向量确认/修复变化的跨库原子版本。

最小反例（无用户筛选、同代/space、`top_k=1`）：SQLite 中 B 为当前 `CONFIRMED`、距离 0.20；Lance 另有已写未确认的 A、距离 0.10。现行权威候选检索只比较 B，结果为 B。一次全局 `limit=1` 得 A，第二阶段 SQLite 删除 A 后变空，**漏掉 B**。把 A 改成 `PENDING_REPAIR`、旧 revision 或当前隐藏/移除的行，同理；若 A 与 B 距离相同且 A 的 `asset_id` 更小，先按引擎未定义的并列截断也可能漏 B。反方向是 SQLite 已确认 B，但 Lance 行暂缺或为旧 revision：一次全局查询根本无法找到 B，事后核验已返回行也无法补回。

**二阶段校验的能力边界**：对已返回 ID 作 SQLite 复读，可以剔除失格项，不能从被引擎截掉或根本缺失的行中补回正确 Top-K。只有下列任一机制同时成立，才可能保持精确性：

1. 查询前具有可验证、在整个查询/发布窗口有效的“Lance 可查询行集及 revision = SQLite 资格集合”证明，并使用同一全序；或
2. 把资格约束**推入排序之前**，且证明谓词与该 SQLite 视图逐项等价；或
3. 逐次扩大检索范围直到具有严格的停止证书：已取得 K 个合格行，所有未检查行在 `(distance, asset_id)` 全序上均不可能排在第 K 行之前；无法取得证书就执行完整权威候选路径。固定倍数 overfetch、固定重试次数、全局 Top-K 后过滤、仅凭计数/采样/索引存在性都不构成证书。没有跨库快照或写者栅栏时，须在发布前按现行 revision/资格门禁重新验证；若窗口已变且不能重建完整结果，回退/重搜或按现有契约报告状态，不发布缺项页。

第三种机制最坏情况下会退化为完整候选扫描，所以 A3 的性能收益不能作为必然保证。带筛选场景继续走已有权威约束路径，不能将此无筛选实验泛化到人物/地点/来源/时间。

## 4. C：决策

| 选项 | 本次裁决 | 理由 |
|---|---|---|
| 保持当前协议并结束性能工作 | 不选作最终路线；当前产品仍保持该协议 | 精确性基线可用，但已测闸门 A 与 1 s 差距数倍，F2 未关闭。 |
| **进入 A3 契约与隔离实验** | **选择** | 候选减少是唯一已观测到可消除大规模行物化成本的方向；单次 pass 量级值得验证，但正确性和端到端达标尚无证据。 |
| 修改 §12.2 性能目标 | 本次不选 | 真实文本塔、HTTP、最低配置和 A3 可行性尚未测完；修改承诺需要单独 ADR 与用户裁决。 |

“进入实验”只授权制定协议、用合成隔离夹具做反例/等价性与性能可行性研究；**不是**发布路径切换、产品实现授权或性能目标放宽。若无法给出资格/并发/全序证明，实验必须判失败并保持旧路径；若证明正确却端到端 P95 仍超标，提交独立性能目标决策，不暗改目标。

## 5. D：实验准入、验证与禁止范围

### 5.1 ADR 与冻结前置

先提交新的 ADR 或现行检索 ADR 的正式补遗及机器可读 companion，冻结：A3 无筛选资格谓词和 `C` 的精确定义；绑定的 profile/generation/space/向量维度；SQLite/Lance 视图或写者栅栏、outbox 确认/修复/旧 revision 的状态矩阵；引擎过滤和并列全序保证；`top_k=1..1000` 与补页/RRF/会话语义；失败、回退、重试、发布门禁；最坏性能与维护预算。特别要判明“当前 SQL 的 `CONFIRMED` 入口”与“可见、最新 revision”的期望关系，不能悄悄改写现有业务语义。冻结前由独立 DS-H 做完整受影响面工程审查，再由 Sol high 聚焦终审协议与最小反例；任何实现须另行立卡、按冻结结果再审。

### 5.2 必须交付的指标

- 10 万和 30 万、突发/波次、完整/部分标量索引覆盖、无筛选与含筛选回退：service 与 HTTP **P50/P95**、真实文本编码/排队、Lance 查询、资格验证、`pending_projection_page`、融合/权威复读、总时延；同时记录样本数、冷/暖缓存、磁盘读写、CPU、RAM/VRAM 峰值及长时分布。正式 30 万普通文字搜索用 [主架构 §12.2](../../个人图片搜索系统_V3.0_开发主架构.md) 的 **API P95 ≤1 s 且包含文本编码**判断；后台维护同时 P95 ≤1.5 s 单列。RTX 4060 与 GTX 1660 6 GB 分别验证，缺一不得宣称最低配置 PASS。
- 资格证书的生成/核对成本、命中率、拒绝率、回退率、回退时延 P95/最坏值；一次搜索读取/物化的 ID 与向量行数、Lance 调用次数、资格变化时的重搜次数。A3 快样本不能掩盖大量慢回退，P95 必须按真实混合负载报告。
- 证明任何新增索引、成员快照或栅栏的增量写入成本、重建时间、磁盘空间、崩溃恢复和 outbox 吞吐影响；不得用一次性静态全覆盖库代表持续维护。

### 5.3 Recall 与正确性

以同一查询向量、同一绑定、同一稳定权威视图的**现行完整候选块精确路径**作 oracle（确认 `truncated=false`），逐项比较向量 Top-K 的 `(asset_id, distance)`、并列全序、FTS/RRF 融合页、`pending_semantic`、会话/游标和错误；按 `top_k=1,20,200,1000`、随机查询及人为制造的大量并列距离分别统计。A3 作为精确路径，要求对受支持状态 **Top-K 集合与次序 100% 相同、Recall@K=1.000**；§12.3 的 ANN Recall@20 ≥0.95 是另一个质量口径，不能用于放宽 A3。

注入并交错验证：未确认 A/已确认 B 的 `top_k=1`、`PENDING_REPAIR`、Lance 缺行、旧/重复 `projection_revision`、隐藏/离线与来源变化、并列距离、空间/代切换、Lance 写入后 SQLite 确认前、确认/修复/可见性变化发生在查询和发布之间、崩溃重启及回退。每例断言候选资格、结果/缺失项、`pending_semantic`、revision 和是否回退，不能只断言 HTTP 200。随机对照只能补充，不能替代这些最小反例。

### 5.4 实验及后续实现的禁止范围

本次 P4-02G 只交付本文档。后续隔离实验不得改 `src/**`、现行搜索 API 信封、`query_hash`/游标、RRF/BM25/距离、人物/地点/拍摄时间权威谓词、P1～P3 人工事实、现有 `0001`～`0016` 迁移内容或既有 ADR 条款；不得接入真实照片库、引入 ANN/第二向量后端/云服务，或以固定 overfetch、后过滤、修改测试 oracle、放宽 §12.2 掩盖缺项。若实验结论需要改这些边界，先停下提交新 ADR/任务范围，经过独立审查后再决定是否授权实现。
