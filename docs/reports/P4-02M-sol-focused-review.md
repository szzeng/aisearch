## 2. F1 裁决：现有约束不需要放宽

**采纳主审提出的行为等价解释，F1 闭合。** 这里裁决的是已冻结条款对当前访问优化的适用关系，不修改 ADR/companion，不新增 A3 资格或证书机制，因此不触发 §11 的契约修改流程。

1. **§5.2 的禁止情形是先取 K 行，再仅在这些行中排序并当成完整答案。** 当前取 K+1 行作为边界探测；`search()` 已按 `(distance, asset_id)` 排序。若 `d[k] > d[k-1]`，精确引擎未返回行的距离均不小于 `d[k]`，故所有可能进入该块前 K 的行都已返回。证明覆盖任意合法 K（含 K=1）；实际行数不超过 K 时是穷尽返回。这里 K+1 不是固定倍数 overfetch 的经验保证，而是严格距离间隔的可判定证明。
2. **§6 第 5 行的前提是第 K 与 K+1 距离相同。** 当前正是在这个输入下 `resolved=False`，舍弃探测结果并回到旧 `search_candidates`：取该块所有候选行、全序后截断。没有把被引擎切掉的并列组直接作为答案。若删去回退，30 个同距离且逆序写入资产、K=2 的既有形状即可产生错页；主审变异记录确实检出了这种错误。
3. **§5.5 的 oracle 语义保留。** `_CONFIRMED_BLOCK_SQL`、generation/space 绑定、revision-blind 行为、块大小、max_blocks/truncated、权威补查与最终排序均未改。旧 `search_candidates` 实现逐字保留，可通过只暴露该方法的代理作为独立对照。局部前 K 与旧路径相同，则未进入局部前 K 的行不可能进入全局前 K；合并后完整有界页相同。返回额外的第 K+1 行不影响最终全局前 K。
4. **§8 不能断章取义为禁止一切 oracle 实现优化。** 原文是“不得用固定 overfetch、后过滤、修改 oracle 或改测试来掩盖缺项”，首项也明确限定不得改检索语义。当前没有改 oracle 的成员、全序或发布语义，也没有通过替换预期答案掩盖缺项；对照仍用旧穷举实现。将“现行实现”理解为永久冻结每一条访问语句，会与本卡和主架构 §7.3 明确允许的精确检索执行优化冲突。
5. **不把这个块内证明迁移成 A3 授权。** 当前过滤在排序前限定到同一权威块，不是全代 Top-K 后过滤。A3 的 `C_strict == C_sql`、机制对应引擎门禁和发布窗口复核仍必须全部成立；本轮不改变 §9 的隔离实验及独立实现卡前置。任何未来将此解释推广到 ANN、全局候选或变更 oracle 语义的方案，仍按 §11 正式变更控制。

证明前提是当前已验证的精确引擎、排序前成员过滤及同输入/有效版本；不授予未来 ANN 或跨版本写窗等价性。主审已在锁定版本复现并列回退、300k 块对照及整页一致，本轮没有发现推翻该前提的新产品改动。
