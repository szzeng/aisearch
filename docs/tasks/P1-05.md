## 任务定位

P1-04 已经把已验收的图库能力（来源、扫描、资产、缩略图/预览/原图字节、job 状态）暴露为本机 `/api/v1` API，
但调用方目前只能看 JSON。P1-05 交付**第一个可用的本机前端闭环**：来源页、按时间浏览、图片详情、离线提示。

前端**必须**建立在不改动 P1-04 安全边界的前提下：会话与 CSRF 仍由 cookie/头部承担，文件字节仍只经资产 ID 获取，
页面不得成为绕过边界的新入口，也不得把本机路径、令牌或个人数据渲染进 DOM。

本任务仍然**不做**：搜索/以图搜图、人物与人脸、OCR、模型/索引世代/升级回退 API、outbox、FTS、调度器
pause/resume、P2 全量任务协议、重复/断盘/重映射验收（P1-06）。

## 用户场景

- 用户拿到启动器打印的一次性链接，打开后直接进入页面；页面显示来源清单，可新增来源、触发扫描并看到进度；
- 用户按"加入时间"从新到旧浏览图库，网格按需加载缩略图，滚动翻页不重不漏；
- 用户点开一张图片，看到预览、全部文件位置、每种产物的状态与原因；
- 原文件离线/被删除时，用户仍能看到已生成的缩略图，并被明确告知"原文件不可用"，而不是破图或空白。

验收一律使用 `%TEMP%` 下的临时夹具，**不得**读取真实照片库。

## 开始前必须先检查（不得凭空假设）

1. **静态服务与打包**：确认 `src/photo_search/api` 的现有路由前缀（`/api/v1`）与安全中间件只保护
   `/api/v1/*`（`UNPROTECTED_PATHS`）；确认 P1-04 已把 `tools/packaging/build_onedir.py` 改为
   `--collect-data photo_search`，从而包内 `web/**` 会随包分发。若实际仓库缺少该项，先补上再继续。
2. **会话引导**：`GET /api/v1/session` 目前是 200 + JSON + 两个 cookie。确认在**不带 `next`** 时该行为与
   P1-04 既有测试完全一致（本任务只允许加性扩展），并确认 `ps_csrf` 是非 HttpOnly cookie（前端读得到）。
3. **分页现状**：`GET /api/v1/assets` 是 `asset_id` 递增 keyset，游标为 `base64url("v1:<asset_id>")`
   （`src/photo_search/api/queries.py`）。确认新增 `order=time_desc` 时游标必须换一套编码，且两种游标互不兼容。
4. **数据语义**：`assets.created_at` 是**入库时间**（`upsert_asset` 写入时刻），不是 EXIF 拍摄时间。
   **本任务不得**新增 `taken_at` 列或迁移（需要按 ADR-0002 §7 加列 + C2 决策，属于其他任务）。
   页面必须把该维度如实标注为"加入时间"。
5. **离线语义**：`GET /assets` 的 `availability`、`GET /assets/{id}` 的 `media[*].state/code`、
   缩略图响应的 `X-Original-Available` 三者含义不同，页面必须分别使用：列表用 `availability`，
   详情用 `media`，图片请求用 `X-Original-Available`。

## 必须交付

### 1. 服务器端（最小加性扩展）

- `GET /`：返回 HTML 外壳；`GET /web/{path}`（或等价路径）：返回包内静态资源。
  两者通过 `importlib.resources` 从 `src/photo_search/web/` 读取（打包后同样可用），
  **不需要会话**（外壳与脚本不含任何个人数据），但所有数据请求仍必须走受保护的 `/api/v1/*`。
  `index.html` 明确 `Cache-Control: no-cache`（或 `max-age=0, must-revalidate`），静态脚本/样式可用短 `max-age`。
- `GET /api/v1/session?token=...&next=/`：带 `next` 且 `next` 是安全本地路径（以单个 `/` 开头、不以 `//` 开头、
  不含 scheme、不含 CR/LF）时，交换成功后返回 `303 See Other` + `Location: <next>` 并照旧设置 cookie；
  不带 `next` 时保持 P1-04 的 200 JSON 行为**逐字节不变**；不安全的 `next` 必须拒绝（结构化 422），不重定向。
- `GET /api/v1/assets` 增加加性参数 `order`：
  - `order=asset_id`（默认）：与 P1-04 完全一致（同一 SQL、同一游标编码、同一行为）；
  - `order=time_desc`：按 `(created_at DESC, asset_id DESC)` 稳定排序的 keyset 分页，游标自带排序标识；
  - 两种游标互不兼容：把 `time_desc` 的游标用于默认排序（或反之）必须返回 422 `INVALID_CURSOR`，不得静默混用。
  响应中明确回显实际生效的 `order`。
- `src/photo_search/__main__.py`：启动器打印的会话 URL 追加 `&next=/`，使用户打开后直接进入页面
  （凭证仍只出现在控制台引导行，`uvicorn.access` 脱敏规则不变）。

### 2. 页面（四块，纯静态、离线可用）

- **来源页**：`GET /sources` 清单（显示名、根路径、状态、计数、`last_successful_scan`）；
  新增来源表单（`POST /sources`，`root_path` 由用户输入/粘贴，前端**不得**枚举本地文件系统）；
  "扫描" 按钮（`POST /sources/{id}/scan`，接受 202 与复用语义）→ 轮询 `GET /jobs?source_id=` 显示
  `state`/`attempts`/`progress`/`last_error_code`；扫描结束后刷新资产列表。
- **时间浏览**：`order=time_desc` 的网格分页（默认 50/页，滚动或按钮加载下一页），缩略图
  `loading="lazy"` + `IntersectionObserver` 按需加载；可按来源筛选；**必须**把该维度标注为"加入时间"
  （`assets.created_at`），不得暗示是拍摄时间；空库、加载中、错误三态都要有明确文案。
- **详情**：预览（`/preview`，失败回退 `/thumbnail`）、全部位置（来源显示名、相对路径、`availability`、
  `size`、`mtime_ns`）、每种产物状态与结构化 `code`；"打开原图" 指向 `/api/v1/assets/{id}/original`
  （同源导航天然带 cookie 并支持 Range）。
- **离线提示**：`availability=missing` 或 `X-Original-Available: false` 的资产必须显示已有缩略图并标注
  "原文件不可用"；未生成产物且原图不可用时显示 `SOURCE_FILE_MISSING` 结构化原因，**不得**显示破图或空白占位；
  `DECODE_FAILED`/`FORMAT_UNSUPPORTED` 同样以可见文本给出 code。

### 3. 前端会话与安全

- CSRF 从 `ps_csrf` cookie 读取并放入 `X-CSRF-Token`；所有请求使用 `credentials: "same-origin"`；
  变更请求带 `Origin`（同源自动带，无需伪造）。
- **不得**把令牌写入 `localStorage`/`sessionStorage`/URL hash/控制台日志；不得内联任何令牌；
  不得渲染任何绝对本机路径（只用来源显示名 + 来源相对路径；`root_path` 仅出现在用户自己填写的输入框）；
  不得引用任何 `http(s)://` 外部资源（离线可用、无 CDN、无在线字体）。
- 收到 401 `SESSION_REQUIRED`/`SESSION_INVALID` 时显示"请使用启动器打印的一次性链接建立会话"，
  不自动重试、不隐藏错误；任何结构化错误都把 `code`/`message`/`request_id` 显示出来。

### 4. 明确不做

- 不做搜索/以图搜图、不做人物与人脸、不做 OCR、不做模型/索引/outbox/升级回退 API。
- 不做调度器 pause/resume、不做 P2 全量任务协议、不做重复/断盘/重映射验收（P1-06）。
- 不新增 Python 依赖、不引入 Node/npm/打包链、不做服务端渲染、不新增表/迁移、不改 `schema_version`。
- 不开放局域网、不放宽 CORS、不提供任意路径文件接口、不写入任何来源目录。

## 正常行为 / 异常行为 / 边界情况（验收时逐条覆盖）

**正常行为**

- 打开页面 → 用一次性链接建立会话 → 注册来源 → 触发扫描并看到进度直到 `SUCCEEDED`；
- 时间浏览（`time_desc`）分页遍历 N 个资产不重不漏，缩略图按需加载；
- 详情显示预览、位置与媒体状态；"打开原图" 返回与源文件一致的内容。

**异常行为**

- 无会话 → 页面显示引导提示（不是空白页或无限重试）；缺 CSRF/Origin → 403 可见提示；
- 注册重叠来源 → 显示 409 `SOURCE_OVERLAP` 及提示；数据目录在来源内 → 409 `DATA_ROOT_INSIDE_SOURCE`；
- 原图缺失 → 缩略图仍显示 + "原文件不可用"；未生成产物 → 409 `SOURCE_FILE_MISSING`；
- 损坏/不支持格式 → 显示 `DECODE_FAILED`/`FORMAT_UNSUPPORTED`，不显示破图；
- 更高 `schema_version` 的库 → 页面显示 `SCHEMA_TOO_NEW` 结构化提示，不显示空列表误导用户。

**边界情况**

- 空库（0 资产）、单资产、`>200` 资产的多页遍历、`limit` 上限与非法 `limit`/`cursor`；
- 多个资产 `created_at` 相同（按 `asset_id` 稳定次序，翻页不重不漏）；
- 中文、空格、`>220` 字符的来源名/相对路径；只读原图；来源目录被删除（离线）时列表仍可用；
- 页面在窄窗口与 200% 缩放下可用；键盘可达（Tab/Enter）与图片 `alt` 文本。

5. 详情与离线：删除原图后缩略图仍 200 且 `X-Original-Available: false`，`original` → 409 `SOURCE_FILE_MISSING`；
   未生成产物的离线资产显示 `SOURCE_FILE_MISSING`；不得出现空白图。
6. 坏图/不支持格式的可见 code（沿用 P1-03 失败记录）。
7. 空库、单资产、多页、中文/空格/长路径、只读原图：页面与接口均正常，来源树未被修改。
8. 真实浏览器 smoke：真实端口启动应用，用**真实浏览器**（Codex 内置浏览器或系统浏览器）完成
   "建立会话 → 新建来源 → 扫描并看到进度 → 时间浏览翻页 → 打开详情 → 看到离线提示" 闭环，
   在报告中记录实际步骤、观察结果与失败原因。**若本会话确实没有可用浏览器工具，必须把该场景标记为
   `VALIDATION PENDING` 且不得标记 PASS。**
9. 更高 `schema_version` 的库：页面显示 `SCHEMA_TOO_NEW` 结构化提示（读接口不再产生写副作用）。

成功时只保留 quiet 摘要、退出码与必要计时；失败时先读失败测试名与 traceback 尾部，只重跑失败目标。
任一必需场景未真实完成，不得标记 PASS（可用 `IMPLEMENTED / VALIDATION PENDING`、`BLOCKED`、`FAIL`）。
