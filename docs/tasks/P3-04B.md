## 用户场景

用户在“爸爸”的照片里只选中一个误识别人脸取消归类，同图妈妈/孩子不变；随后把待手动归类的一张脸
明确指定为“叔叔”，后台重算不能覆盖；用户也可恢复自动，但已有排除保留。每一步支持网络重试、批量原子
提交和无冲突补偿撤销。

## 本任务范围

1. **连续迁移 0012**：安全重建 0011 的 `person_operations` / `person_operation_items` 闭合 CHECK，加入
   ADR-0007 的四个脸级 type、`FACE_CONTROL` 与互斥 `entity_id/entity_key`；逐列保留全部既有 operation、
   item、undo、alias/last_operation 引用。schema_version 11→12；0001～0011 逐字节不变。
2. **脸级服务**：实现 GET state、单脸 assign/unassign/restore_auto、1～500 mixed batch、canonical person
   解析、无控制行 revision 0、模式/排除矩阵、唯一 MANUAL/CONFIRMED 与建议保留边界。
3. **幂等与快照**：全局 request_id gate 必须早于 revision 检查；canonical payload hash；FACE_CONTROL
   before/after bundle；同 key replay、异 payload 冲突；no-op 有 operation 但无权威/派生 revision。
4. **补偿撤销**：扩展既有 `/person-operations/{id}/undo` 支持 FACE_CONTROL；live after bundle 冲突时
   整批拒绝；无冲突按 before 语义恢复且所有 revision 向前；不允许 undo an UNDO。
5. **自动路径门禁**：自动提交读取 logical control revision；MANUAL 两态或排除命中零覆盖；晚到结果零写
   权威链接。不得把建议自动提升为确认。
6. **权威→派生**：changed operation 在同一事务内恰好一次 `PERSON_CHANGED` filter revision、资产
   projection queue、受影响 face candidate `PENDING_REPAIR`；事务内不做模型/文件/Lance；no-op/replay
   不排队，不新增 queue cause，不写图片索引 namespace。
7. **API 与错误**：实现 ADR-0007 §6 的四条路径、envelope、FACE_* 错误及 HTTP 映射；复用既有 session/
   CSRF/Host/Origin/脱敏。响应不含路径、geometry、向量、confidence 或内部快照。
8. **只读计数**：`face_summary` 增加 ADR-0007 的四个计数，canonical exclusion pair 去重，未知/坏 schema
   保持现有只读诊断边界。

## 必须保持的不变量

1. SQLite 是人物权威；机器 artifact/候选索引可重建且不覆盖人工知识。
2. 最小单位永远是明确 face_id；不得由 asset_id 暗中扩张到合照其他脸。
3. MANUAL_ASSIGNED 恰有一个 MANUAL/CONFIRMED，MANUAL_UNASSIGNED 没有 CONFIRMED；每脸总计至多一个
   CONFIRMED。
4. 无控制行等价 AUTO_ALLOWED revision 0；实际人工变化 current+1；no-op/replay 不推进。
5. assign 回排除目标只解除目标排除；restore_auto 不清空任何排除、不采用 suggestion。
6. request_id 全局幂等；batch 先全量验证后单事务；任一失败零部分写。
7. undo 是向前补偿，后续人工编辑冲突时整批拒绝。
8. changed 操作 filter revision 最多 +1，cause 复用 PERSON_CHANGED；投影/index 追赶不在权威事务内完成。
9. API/日志/错误/普通诊断不含路径、bbox、landmark、向量、confidence/单对相似度。
10. 不改依赖；0001～0011 与冻结文件逐字节不变。
