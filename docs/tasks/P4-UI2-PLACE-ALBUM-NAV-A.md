# P4-UI2-PLACE-ALBUM-NAV-A — 地点目录→独立地点相册视图与导航闭环

> **状态**：READY / 待实施；2026-10-14 建卡，尚未修改产品代码或执行验收。
> **优先级**：P1 / UI 2.0 日常使用体验修复（地点相册进入/返回不应表现为同页尾部追加）。
> **建议执行**：GPT-6 High（由用户在 Codex 手动选择）；前端原生 HTML/CSS/JS 导航与状态修复，不默认引入后端改造。
> **施工原则**：个人图库，以小型定向测试、真实产品合成浏览器 2～3 条核心路径为主；不访问真实 `PhotoSearchData`，不跑全仓、模型/GPU 或重新生成 20万/30万规模夹具。
> **读取顺序**：`AGENTS.md` → `docs/development-status.md` → 本卡 → 涉及的代码与测试。执行前先核对最新 HEAD 以及可能已实施的其他 UI 任务；不要用建卡时的旧文件整体覆盖后来提交。

## 1. 症状、原因与明确目标

用户反馈：在“地点相册”点击城市/省份/区县/国家卡片后，照片出现在原地点管理长页面后面，体验不符合“进入某个地点的照片相册”。

已核对的现状：
- `src/photo_search/web/places.html` 的 `#panel-albums` 内并列 `#album-cards`、`#album-current-title`、`#album-photos`；同一 `main` 仍有地名包、地点目录、建议/批量与操作日志等管理 `section`。
- `src/photo_search/web/places-albums.js::openAlbum()` 仅将卡片隐藏/照片显示并调用 `currentTitle.scrollIntoView()`；没有真正将浏览模式与管理内容分离，也没有完整 pushState/popstate 导航；“返回地点目录”仅手动切换局部 DOM。
- `places.css` 对 `.album-cards {display:grid}`、`.album-current-title {display:flex}` 有显式展示规则，需确认 `hidden` 是否被 CSS 覆盖；不能仅修改 `scrollIntoView` 掩盖底层显隐缺陷。
- 当前已有 `/places?album_kind=city&album_key=...` 深链、`SearchScopeEntry` 中 `place_kind/place_key` 范围搜索、`PhotoTimeline.mount()` 共享时间轴、地点更正与照片查看器。应复用，而非重建。

**目标体验**：`地点相册列表 → 某地点独立照片视图 → 点击照片弹窗 → 关闭回同地点/原时间位置 → 返回地点列表/原筛选与滚动位置`。仅一层主要内容可见；地点的成员规则和照片数量均不变。

参考：[最终 UI 2.0 可点击原型](../mockups/ui2-interactive/demo.html#place/shenzhen)、[P4-UI-PLACES-E](P4-UI-PLACES-E.md)、[UI 2.0 总规范](../plans/P4-UI-TIMELINE-V2.md)。本卡纠正产品页面层级与导航，不另起一版全站视觉。

## 2. 页面/URL 合同（本卡主交付）

| 页面状态 | 可见内容 | URL 与行为 |
| --- | --- | --- |
| 地点列表 | 原有地点封面卡、城市/省份/区县/国家切换、地名筛选；管理工具可按原入口访问 | `/places`；无合法选中地点时**不得**显示“搜索此地点” |
| 具体地点相册 | 统一页头/左侧导航；“← 返回地点列表”、地点名、父级/来源/有效照片总数，独占主内容的共享时间轴 | 维持现有 `/places?album_kind=<kind>&album_key=<key>` 参数协议；点击卡片产生可后退的历史条目 |
| 地点相册内看照片 | 沿用已有或在后续 Viewer 任务中统一的照片弹窗 | 关闭/Esc/遮罩等依查看器已生效能力回到该地点时间轴，不转去全库或管理页 |
| 从搜索/照片详情等打开地点深链 | 直接进入正确地点照片页，显示有效范围 | 刷新与浏览器直接访问恢复；无效/已失效地点给出可见错误和“返回地点列表”，不可静默显示错误地点/全部图库 |
| 地点列表内管理 | 地名包、普通地点目录、建议、批量操作、日志及撤销继续可用 | 管理面板只属于列表/工具层，不应被移动到地点相册照片下方，也不能因隐藏而删除其操作 |

UI 结构优先采用**现有 `/places` 文档内的两套互斥浏览视图**（列表/详情），不新建前端框架、新业务路由或第二套相册数据模型。地点管理模块可保留现有 DOM/ID 与惰性加载；只在详情视图隐藏非照片管理区域。侧栏“地点”仍为当前页；顶部全局搜索框始终存在。地点目录“筛选地名”不是照片搜索。

## 3. 实施细则（按优先级）

### A. P0 — 真实视图切换与视觉

1. 在 `places.html` 将**地点相册列表**（卡片、种类、地名筛选）与**单个地点照片详情**明确包成两个互斥的容器；`#album-current-title`、`#album-photos` 及原照片纠错入口可保留。进入详情后列表控件、地点工具、地名包/目录/建议/批量/日志和页内管理导航不显示、不参与键盘 Tab；页头/侧栏/全局搜索保留。
2. 详情顶端放**明确的返回入口 + 地点名称 + 完整父级语境/来源 + 实际有效照片总数**，下方直接是共享 `PhotoTimeline` 日期筛选/分组/网格。标题为“深圳市 · 地点相册”之类，不把内部 `place_key` 当名称；不能重复显示列表“筛选地名”、管理表单或说明长文。
3. 修复目标元素的 `[hidden]` 与 `display:grid/flex` 冲突，隐藏必须真实生效（计算样式、可见性、焦点/交互）。仅为本页做局部样式，不改全站 `[hidden]` 规则、配色和容器风格；桌面、窄屏、浅/暗色复用现有 token。
4. 点击地点卡进入详情时滚动到照片内容顶部、聚焦标题或返回入口（`preventScroll`），**移除以长页面 `scrollIntoView()` 作为“进入相册”的假导航**。完整内容可直读，空相册/读取中/失败/重新尝试均有明确状态。

### B. P0 — URL、Back、深链与返回状态

1. 以 `album_kind + album_key` 为**唯一地点选择身份**，复用现有深链。卡片点击使用单一导航函数更新 URL（`pushState`）及视图；`popstate` 读取 URL 反向恢复。禁止仅用地点名、列表序号或 `place_id` 推断详情，尤其是同名不同上级/来源。
2. 页面初始加载/刷新若携合法参数，**直接渲染相册详情**；不能先显示原页面尾部或闪现整页管理工具。旧入口 `search-place-entry.js` 的 `/places?album_kind=...&album_key=...` 继续生效；非法 kind、缺 key、无结果、活动地点包/归属变化后已不存在的 scope 显示可见错误和目录返回，不执行全库 fallback。
3. 点击“返回地点列表”以及浏览器 Back/Forward 均能恢复正确模式；内部由列表进入时不重复压入历史、避免循环 `popstate`；直接深链进入时按钮安全导航至 `/places`，不可无条件 `history.back()` 跳到不相关网站。多次地点 A→列表→B 后退不能出现 A 照片/B 标题。
4. 进入详情前保存地点列表的**城市类型、局部地名筛选、已渲染卡片、可见锚点/滚动位置**。从相册返回尽量直接恢复原列表 DOM、位置和卡片焦点，不必无条件重新请求整个地点列表。正常同页往返必须恢复；刷新/失效导致精确锚点不可恢复时保留可恢复筛选并给出合理退化，不能无限重放分页或无提示跳顶。
5. 照片预览闭合后优先恢复原照片 `asset_id`/时间轴锚点；使用共享 `PhotoTimeline` 已有作用域记忆/恢复 API，不自建第二套时间轴缓存。年份/月/可信日期/未知/待就绪按当前 `kind/key` 隔离，切换地点不得串状态。地点成员变化、旧 revision/游标过期时服从原时间轴 409 处理，不复用不可信旧页。

### C. P1 — 异步请求、整理操作与跨卡兼容

1. 切换地点/返回/`popstate` 时取消或以 generation 拒绝旧的卡片、照片/时间摘要、范围等迟到响应；离开详情调用 `timeline.dispose()`，断开 observer/listener；同一详情不得挂两个时间轴。隐藏视图不可继续后台无限续页。
2. 保留地点相册内每张照片的“更正地点”、`assign/unassign/restore_auto` 与现有受 CSRF/revision 保护的写协议。操作成功后**刷新当前 scope 的成员/计数与照片**，尽量保持相册标题、URL、时间选择和当前照片附近锚点；修正导致资产离开当前地点时给出正常更新，不应自动返回目录或每次跳到页面顶端。失败保留原视图并有明确提示。
3. 顶部“搜索此地点”按钮仅在**有效且可见的地点详情视图**出现，仍使用 `SearchScopeEntry` 的结构化 `kind/key` 与现有单次 `scope_entry` 交接。`全库搜索/Enter` 仍按已经实现的 UI2.0 范围搜索合同；返回目录立即隐藏范围按钮，旧地点不能残留。
4. 与 `P4-UI2-SEARCH-SCOPE-UNIFY-A`、`P4-UI2-SCROLL-LOAD-A/B` 及照片查看器统一任务**串行处理共享文件冲突**；不改搜索结果分页、照片浏览滚动器、地点/人物成员 SQL、地图 viewport、照片弹窗放大缩小的独立实现。原 `PhotoTimeline` 自动续页和资源回收不能回退。
5. 地点目录卡封面、排序、有效照片数、CN/OSM/GeoNames 来源、同名上级、人工归属/排除与照片去重完全按当前后端真值；不加入按地点卡计算年月摘要的 N+1 调用。不读原图完成导航；不增加前端缓存全部资产 ID 的结构。

## 4. 实施文件与最小变更边界

- 主要：`src/photo_search/web/places.html`、`places-albums.js`、`places.css`；必要时仅小范围调整 `places.js` 的目录/管理区显隐协调，保留旧 DOM ID、按钮绑定、数据请求和 `IntersectionObserver` 语义。按项目惯例更新修改过的 JS/CSS 的静态缓存版本。
- 复用：`photo-timeline.js`、`search-scope-entry.js`、`photo-info.js`、现有 `/api/v1/places/albums` 与 `/api/v1/timeline/{assets,periods}`。**原则上不改 Python/SQL/数据库**；若当前完整列表接口无法可靠定位合法深链，先调查精确 kind/key 的可用只读能力，提出最小兼容处理并补测试；不得静默“未见于当前页 = 地点不存在”。
- 测试优先查看 `tests/unit/test_p4_place_unified_ui.py`、`tests/unit/test_p4_place_cn_ui.py`、`tests/unit/test_p4_ui_timeline_core.py` 及相关前端测试；可增 `tests/unit/test_p4_ui2_place_album_nav_a.py`。不要为本卡扩大跨模块回归。
- 没有理由因本卡纯导航改动执行 OCR/模型、重新解析 GPS、重建地名包、迁移数据库或重跑 20万/30万图库。继承 `P4-UI-PLACES-E` 尚未完成的 `PERF_200K/CHECK_300K=PENDING`，不能在本卡“补签通过”。
