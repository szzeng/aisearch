# P4-UI2-SEARCH-TOOLS-PLACEMENT-A — 搜索辅助入口布局优化

**日期**：2026-10-19
**状态**：IMPLEMENTED / ACCEPTANCE PARTIAL
**建议执行模型**：GPT-6 Medium（由用户手动选择）
**需求来源**：本任务用户提供的完整任务卡；仓库此前无该 ID 的落盘卡。
**范围**：`search.html/css/js` 与必要前端 UI 契约测试；不改 API、后端格式校验、数据库、搜索协议或排序。

## 目标与不变量

- 固定搜索栏增加「以图搜图」和右上角「索引状态」入口；上传及覆盖率统计置于按需打开的原生对话框中，移除结果区底部重复面板。
- 上传沿用 `/search/image`、来源/可用性/地点过滤及现有分页会话；仅当前请求成功后替换结果。失败/缺文件时保留旧结果与会话；世代变化时丢弃旧响应。图片文件在成功后绑定图片会话供续页使用。
- 拒绝当前固定范围、收藏、人物、拍摄时间及文字/意图条件下的图片搜索，避免静默扩大范围。前端 accept 列表与既有后端支持格式一致。
- 覆盖率仍复用现有四项统计和口径，打开时不请求，点击读取才请求，成功后允许主动刷新；并发请求去重，不轮询。
- 保留搜索结果预览、收藏、多选、合集操作及自动续页行为；不做全站搜索栏改造。

## 性能设计与验收

- 链路与风险：只移动本页工具入口；新增请求仅为用户显式读取/刷新既有覆盖率，上传仍为单次首查与既有续页。
- 做法与边界：按需加载，不重绘结果网格；复用请求世代、图片会话、分页与原统计函数，不新增后台工作。
- 验证与停止：受影响前端单测 + 真实内置浏览器关键流程；不做 30 万规模测试或延迟承诺。浏览器不可用/模型缺失的必要链路记 PENDING，不以静态测试替代。
