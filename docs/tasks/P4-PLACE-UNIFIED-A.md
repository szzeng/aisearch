# P4-PLACE-UNIFIED-A — 统一地点选择与人工归属（OSM 优先 / GeoNames 兜底）

日期：2026-10-08。状态：**DRAFT — 仅任务卡，尚未实施**。基线：master `5d7bc139b2b73de5f30c77fbee9e6a1cc648f108`。
定位：个人 PhotoSearch 一张功能卡；基于现有 P4-PLACE-CN、P4-PLACE-SEARCH-A，不重做地点系统。
前置：建议 P4-PLACE-CN 独立受影响面审查先收口；旧包与中国复合包实际安装/更新由用户另行决定，本卡不操作真实图库。
推荐实现：GPT-6 Luna / High；独立 DS-H 核对本卡**全受影响面**（非全仓），Sol high 仅在高风险身份/人工契约仍有问题时聚焦复核；模型用户手动切换。

## 1. 用户目标

普通自然语言搜索**自动优先识别 OSM 地点；已安装 OSM 目录找不到时才用 GeoNames**。无需强制先选地点；仅当同名且不能可靠消歧时显示带完整上级区域的选项。

| 输入/操作 | 期望 |
|---|---|
| “深圳的海边照片” | 识别深圳；若活动包有相应 OSM 行政区则选 OSM；只在该地点成员内检索“海边” |
| “东京夜景” | 当前 OSM 数据无东京、GeoNames 有东京，则用 GeoNames 城市范围 |
| “南山区” / “南山区的海边” | OSM 区县归属；GeoNames 最近城市不得冒充区县 |
| “朝阳区的夜景” | 不同地区同名时显示北京市／吉林省长春市等完整上级路径，选定才搜索 |
| 给无 GPS 照片指定“南山区” | 从真实来源地点中选中 OSM 区县，保存、搜索、取消和撤销都生效 |
| 输入数据源不存在的地点 | 不允许以任意文本创建或手工指定该地点；地点明确但不存在时提示未找到 |

OSM 指**当前活动、已验证数据包的行政区目录**，不是联网查询整个 OpenStreetMap；当前 OSM 仅中国省/市/区县，GeoNames 是已安装的亚洲城市点。地区覆盖以实际有效包为准，不宣称全球覆盖。

## 3. 最小实现

### 3.1 一个共享地点选择层

优先新增一个小型只读适配层（例如 `places/choices.py`），同时供普通搜索、同名消歧和人工指定调用；必要时增加 `GET /api/v1/places/choices?name=...`。

候选至少包含：来源 `OSM/GEONAMES`、稳定来源 ID、数据包/版本、真实行政类型、规范名/别名、完整上级区域、供后续读取成员和人工指定使用的受控 key。不能把客户端展示名或任意数字 ID 当作来源证明。

1. 只搜索活动且已验证的来源目录；名称/别名按既有规范化方式识别，最长有效匹配优先，不能误把“巴黎风格”等普通描述转成地点。
2. 可靠判明同一实体（来源映射、行政层级＋已验证父级等充分证据）时，OSM 优先并折叠 GeoNames 候选；**仅同名或近似名称不足以合并**。
3. 多个不同 OSM 地点同名、或无法证明等价的跨来源同名候选，保留消歧；不静默取第一条。完整上级区域来自目录，而非猜测。
4. OSM 目录不存在请求地点时才使用 GeoNames；**OSM 地点存在但没有照片/尚未跑完 GPS 行政解析时，不能改用 GeoNames**。给出无照片或待更新状态。
5. 明确地名表达式无法识别时，提示地点未找到；无法确定是地名的普通文本继续走原有搜索，不退化为随意新建地点。

### 3.2 搜索和相册共用权威成员

保留 `POST /api/v1/search/place-aware`、原照片查询服务/FTS/向量/RRF/分页，不复制检索器：
- 纯地点搜索走 SQLite keyset；地点＋内容先套用地点权威成员，再进行语义/FTS 检索，不允许全库 Top-K 后过滤；
- OSM 省/市/区县沿用 `cn_facets.members_sql`；GeoNames 城市沿用最近城市阈值、歧义与有效 GPS 检查，**不可**把附近城市解释为 Polygon 包含；
- 单照片只计一次；保留来源/人物/时间/可用性过滤、人工指定/取消/排除优先；搜索和地点相册看到的同一地点成员必须一致；
- 搜索结果显示地点全名与来源，支持取消地点条件；旧会话/游标绑定地点来源 key、活动包、人工修订和 GPS 成员版本，变化后明确要求重新搜索；
- 搜索时仅查询 SQLite 已存归属，不每次加载 OSM 几何或重新计算 GPS；OSM 未完成后台更新时不把“未处理”误判“地名不存在”。

### 3.3 手动指定只选真实地点

统一将“指定地点”改为：输入名称 → 查统一地点选择层 → 看完整上级区域和来源 → 点选 → 保存。不要再要求普通用户填 `place_id`，普通界面隐藏自由创建地名、自由重命名和任意文本保存。

服务器必须校验**所有新增人工指定写入路径**（单张与批量），包括旧 API 的绕过方式：目标来源 ID/有效数据包/地名实体真实存在且可选择。不得只做 UI 限制。对普通自由创建/改名接口的行为收紧属于既有冻结契约变化，先在实现报告写明最小兼容方案；不默默改变旧响应结构或破坏历史读取。无包或仅旧 USER 地点不得允许任意新建/新指定。

**重点：当前 `asset_place_assignments` 保存旧 `place_id`，而 OSM 区县是 `cn_admin_ids`；现有 `manual_district_assignment=false`。** 开工先写半页映射决策：优先复用有效 `place_external_refs`／`cn_legacy_links`，必要时增加一个仅承载来源身份的加性映射，使 OSM 省、市、区县可通过现有人工归属/历史/撤销体系保存。旧 `Place.kind` 不含 district，**不得把区县伪装为 city**，也不得建立第二套彼此竞争的人工 assignment 状态机；若使用合法本地代理 Place，行政类型必须由真实 OSM ID/映射决定，且用户不能自由制造代理。

`cn_facets.members_sql` 和地点成员读取必须识别新的 OSM 人工指定：选区县后可按区县及可信父级市/省查到，同张照片不能再从 GPS 补入与人工指定冲突的地点。恢复自动/取消/撤销/排除与 revision 一律沿用旧事务语义。

历史 USER/custom 地点、旧人工归属、排除与操作历史**不删除、不批量迁移**；仍能查看并对旧操作撤销，但新选择必须绑定来源证明。遇既有协议无法安全兼容时，记录具体阻塞和最小替代，不扩写整套 Place enum/旧迁移。

## 4. 仅做个人使用的最小测试

约 15～20 张合成照片＋小 OSM/GeoNames 地名包；使用受控假 encoder/FTS，不访问私人照片库：

1. 深圳两来源同实体：OSM 优先、无重复；东京只有 GeoNames：正常兜底；不存在的地名：不虚构。
2. 北京朝阳区／长春朝阳区：展示父级并选择；同名不同实体不能乱合并；普通“巴黎风格”不误判地名。
3. OSM 南山区：纯地点分页、地点＋“海边”检索与相册成员一致；附近城市不得充当区县；地点存在但无照片不回退。
4. 无 GPS 照片人工指定 OSM 区县与 GeoNames 城市：可搜索、取消/恢复/撤销；人工改上海不能同时自动落入南山区；排除不被重加。
5. 任意名称或伪造 ID 的前端/单张/批量新指定均拒绝；旧 USER/custom 只读与历史操作保留；包切换/修订使旧游标过期。
6. 一次简单网页闭环：普通输入→同名选择（如触发）→展示来源→给照片选定地点→再搜索→取消/撤销。

只运行相关定向 `pytest -q --junitxml=...`、受影响 Ruff、`node --check`、`git diff --check`。不得以测试收集代替通过；不追加全量 pytest、30 万压测、真实模型、大规模区域准确率、多浏览器或 exe 构建。真实图库须用户单独授权。

## 5. 交付和停止条件

在 `docs/reports/P4-PLACE-UNIFIED-A.md` 记录半页身份/人工契约决策、实际修改路径、定向测试命令及 JUnit 结果、网页闭环、未覆盖项，更新 `docs/development-status.md` 和本卡状态。高风险 ID/人工操作写路径由独立 DS-H **全受影响面**审查（不重审全仓）；需要时由 Sol high 仅看映射身份、人工排除与未关闭问题。按完成的证据标注状态，不因小样本测试声称全地区准确。

达到“OSM 优先、GeoNames 兜底、可靠消歧、真实来源人工指定、旧历史不坏、最小测试通过”即停止；不自动扩大全球 OSM、引入在线逆地理、改模型或重新建库。
