# P3-07B — 人物 all/any × 地点 AND 组合搜索实现（canonical 解析、权威补查、缓存/会话失效）

本卡按已冻结的 **ADR-0009** 实现 `POST /api/v1/search` 的人物筛选协议：加性接受
`person_ids`/`person_match`，把「有效成员脸」权威谓词与地点、来源、可用性、语义条件组合成一条
`AND` 检索，并把 canonical 解析、会话/游标摘要、响应回显、错误面与投影/补查语义落实为可验证的行为。

执行模型：**DS-H（DeepSeek V4.1 Flash / 高推理）**。模型切换由用户在 Codex 中手动完成；不得自动切换或
声称已切换。实现完成后必须由**独立新会话 DS-H** 做全量工程主审（完整 diff、测试证据、ADR/任务卡一致性、
跨模块影响）；**只有命中 V3.1 §2.2 六类具名条件之一**才把该审查升级为 **DeepSeek max**，卡内必须写明
命中的条件编号与待回答问题。**canonical / revision / 缓存失效**这三条边界在 DS-H 收敛后交
**C2 / GPT-5.6 Sol / high 聚焦终审**（只审这三条，不重复全量 diff）。

## 必须实现的内容

### 1. 请求形状（ADR-0009 §2.2 判定表逐行）

- `SearchRequest`（`search/contracts.py`）与 `SearchRequestModel`（`api/models.py`）加性增加
  `person_ids`、`person_match` 两个**可选**字段；既有字段、默认值、上下界与
  `contract_version = "p2-contracts.v1"` 一字不改；
- 判定表：缺省/空 = 无人物条件（不是「没有人物脸」）；`all` + 空/缺省 = 422
  `INVALID_PERSON_FILTER`（`reason=person_match_all_requires_ids`）；非数组/非整数/`<1`/原始重复 =
  422 `VALIDATION_ERROR`；元素数 > 100 = 422 `INVALID_PERSON_FILTER`
  （`reason=person_filter_too_large`、`max_person_ids=100`）；非法 `person_match` 值 = 422
  `VALIDATION_ERROR`；未知字段继续被拒绝。全部拒绝零写、零会话。

### 2. 权威谓词与 AND 组合（ADR-0009 §3）

- 复用 `persons/members.py` 的 `MEMBER_PREDICATE` 构造「照片级有效成员」谓词
  （`CONFIRMED` + 无 `MANUAL_UNASSIGNED` + 无 `active=1` 排除），**不得复制第二份口径**；
- 谓词进入 `retrieval.scope_condition`/`SearchScope`，与 `source_id`、`availability`、地点谓词一起被每个
  通道与提交前复核使用；`all` = 对每个 canonical 人物都有有效成员（存在性交集），`any` = 至少一个；
- `place_ids`/`place_state` 的既有拒绝矩阵（只有 `any`/`assigned` 可与 `place_ids` 组合）不变；
- 人物**不得**成为命中原因或排序通道：`hit_reason` 仍只有 `TEXT`/`SEMANTIC`/`TEXT+SEMANTIC`/
  `FILTER_ONLY`，`matched_by` 键仍只有 `fts`/`vector`/`filter`；纯人物/纯筛选请求不绑定 profile、不需要
  GPU，走既有权威列表与 `FILTER_ONLY` 行形状。

### 3. canonical 解析与去重（ADR-0009 §4）

- 每个 id 用 `persons/identity.resolve_canonical_person_id` 在同一只读快照解析；不存在 404
  `PERSON_NOT_FOUND`，成环/悬挂 409 `PERSON_REDIRECT_CYCLE`，任一失败即整请求拒绝（不丢 id、不部分返回）；
- 不同原始 id 折叠到同一 canonical 人物时静默去重，`all`/`any` 命中集不因重复计数改变；canonical 集合
  升序用于摘要与回显；原始重复仍是形状错误（与去重是两件事）。

### 4. 会话/游标与摘要（ADR-0009 §6）

- `sessions.query_hash` 纳入 canonical、去重、升序的 `person_ids` 与规范化 `person_match`（连同既有
  `text`/`source_id`/`availability`/`place_ids`/`include_descendants`/`place_state`/`top_k`/`page_size`），
  使两个不同人物条件不能被同一会话续页接受；
- 续页继续比较**同一个** `catalog_filter_revision`：不同即 409 `CATALOG_FILTER_REVISION_STALE`
  （`reason=CATALOG_FILTER_REVISION_CHANGED`，details 仍是既有四个键，**不加** `cause`）；
- 进程重启/TTL 到期 → 409 `SEARCH_SESSION_EXPIRED`；损坏/跨会话/越界游标 → 422 `INVALID_CURSOR`；
- 不新增第二套 revision；`place_state=suggested` 仍额外绑定既有 `suggestion_revision`。

### 5. 响应回显与隐私闭集（ADR-0009 §7）

- `filters` 回显**始终**包含 `person_ids`（canonical 升序，无人物条件时 `[]`）与 `person_match`
  （无人物条件时 `"any"`），其余键集合不变；
- `POST /api/v1/search/image` 不新增 multipart 字段，其 `filters` 回显固定为 `person_ids: []`、
  `person_match: "any"`；
- 响应/错误/日志不得含路径、姓名/`name_key`/别名文本、bbox、landmark、向量、相似度/confidence、
  幂等 payload/hash 或 before/after 快照；`INVALID_PERSON_FILTER` 的 details 只允许
  `reason`/`person_match`/`person_ids`/`person_id`/`max_person_ids`。

### 6. 错误面（ADR-0009 §7.3）

- 在 `catalog/errors.py` 新增 `INVALID_PERSON_FILTER`，并在 `api/errors.py` 映射 422；
- 其余失败复用既有码：`VALIDATION_ERROR` 422、`PERSON_NOT_FOUND` 404、`PERSON_REDIRECT_CYCLE` 409、
  `CATALOG_FILTER_REVISION_STALE` 409、`SEARCH_SESSION_EXPIRED` 409、`INVALID_CURSOR` 422、
  `SCHEMA_TOO_NEW`/`SCHEMA_INCONSISTENT` 409、`INVALID_PLACE_FILTER` 422；不得给既有码新增 details 字段。

### 7. 投影与补查（ADR-0009 §5）

- `search_projection` 与 `pending_semantic` 的**字段集合与上界不变**（权威候选页 1000、补查 200、
  `reason ∈ {GENERATION_NOT_READY, ENTRY_NOT_CONFIRMED}`）；`SYNCED` 仍当且仅当 `queued_assets == 0`；
- 提交前的权威复核谓词**必须包含**人物条件（旧投影不得复活已不满足条件的照片）；人物事实不进入
  `search_documents`，不得新增列/表/cause/migration。

## 必须保持的不变量

- 人物/控制/操作仍是 SQLite 唯一权威；不引入第二份状态或第二套 revision；
- `face_id` 仍是最小人工单位；有效成员口径与 P3-06 的 `face_count`/`asset_count` 一字不差；
- 同名合并、拆分、单脸纠错、`request_id` 幂等与撤销冲突矩阵不变；`MANUAL_UNASSIGNED` 与活动排除的脸
  不因任何搜索条件被当作有效归属；
- 只读与错误响应继续遵守隐私闭集（无路径、无坐标、无几何、无向量、无相似度）；
- `p2-contracts.v1` 既有字段语义、地点筛选矩阵与 `space_id`/profile 隔离不变。

必须真实完成的专项证据（ADR-0009 §8 的十条，逐条不得省略）：

1. 判定表逐行（缺省/空/重复/非正数/非整数/101 项/非法 `person_match`/未知字段）零写、零会话；
2. `all`/`any` 与地点、来源、可用性、语义条件的 AND 组合矩阵，`|P|=1` 时两模式等价；
3. canonical 的旧 id、折叠重复、不存在、成环、悬挂五种结果；
4. `person_ids=[p]` 命中集合与 `GET /api/v1/persons/{p}` 的 `asset_count` 同源同值（真实夹具）；
5. `MANUAL_UNASSIGNED`、活动排除、`SUGGESTED` 都不命中；同图 sibling 不受影响；
6. 纯人物/纯筛选请求无 GPU、无 profile、`FILTER_ONLY` 且无人物原因值；
7. 改名/合并/拆分/纠错/撤销后旧会话续页 `CATALOG_FILTER_REVISION_STALE`，重搜（同一旧 id）正确；
   人物条件不同但同 `search_session_id` 的续页被摘要拒绝；
8. `search_projection`/`pending_semantic` 字段与上界逐字符合 ADR-0009 §5.4/§5.5；投影滞后不漏召回、
   不复活已移除命中；
9. 隐私负向扫描通过（无路径/姓名/别名/`name_key`/bbox/landmark/向量/相似度/confidence/payload）；
10. `p2-contracts.v1`、四个既有 companion、`0001`～`0013`、依赖与既有测试断言原样通过。

`.pytest-tmp` 受限令牌 ACL 若再次出现 `WinError 5`，按 P3-05B/P3-06 的方式改用已授权的正常 Windows
