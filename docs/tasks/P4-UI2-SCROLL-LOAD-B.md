- **核对基准**：`szzeng/aisearch`，`master` HEAD `e3c42d75a665f01f4f4517533f98757baf9934db`，2026-10-14；实施前重新核对最新代码。

- **依赖/串行顺序**：建议先完成 `P4-UI2-BATCH-SELECT-UNIFY-A` 和 `P4-UI2-SEARCH-SCOPE-UNIFY-A` 对同一文件的修改，再开始本卡；`P4-UI2-SCROLL-LOAD-A` 的通用滚动 helper 若实际完成，可直接复用，否则只建立最小观察器。**禁止多个任务并行覆盖 `persons-albums.js`**。

## 1. 目标、具体范围与明确不做

用户浏览人物和合集时，接近页面底部自动追加下一批，而不是点击「再看一些」。**仍然是服务端游标分页，不一次性读取全部人物、合集或其照片。**

| 场景 | 当前代码 | 本卡目标 |
| --- | --- | --- |
| 人物列表、未命名人物列表、已隐藏人物目录（共用人物列表组件） | `persons-albums.js loadPeople()`，40/批，`#pa-more` 手动按钮 | 当前可见的**列表**自动续页；隐藏/未命名视图也只在用户实际打开时自动 |
| 人物合集目录 | `loadCollections()`，40/批，`#pa-collections-more` | 展开合集面板后按该面板/页面实际可见区域自动续页，不主动把全部合集取完 |
| 合集内“人物”成员列表 | `loadCollectionPeople()`，40/批，`#pa-collection-people-more` | 自动续页；保留批量勾选、Shift/全选已加载、合集修订身份 |
| 人物/合集照片普通网格：局部查询、封面选图等**仍然存在的入口** | `loadPhotos()`，60/批，`#pa-photos-more` | 若最近 `SEARCH-SCOPE-UNIFY-A` 已取消局部搜索，**不要恢复旧入口**；只对最新版本实际仍存在的普通网格加自动续页 |
| 人物/合集默认照片时间轴 | 已共用 `PhotoTimeline` 自动续页 | **只做回归，不重写** |

**明确保留手动加载**：待整理人脸总览与候选组内部、已忽略人脸、每张脸的整理/确认、人物操作历史、合并人物候选选择框、维护/清理类分页。理由是它们包含写入、复杂候选展开、快照或独立复核语义；自动翻页可能使选择范围不清晰。搜索结果高级筛选的人物选项列表继续手动，不在本卡范围。

**暂不覆盖**：地点管理目录及建议、地点相册目录（现为无分页整目录响应）、地图 bbox/cluster 列表、地点操作日志和历史维护。地点相册内部照片已自动续页。若发现真实 UI 仍有其他照片浏览入口，只在报告记为 `FOLLOW_UP`，不要本卡无限扩展。

## 2. 核对事实与风险

- `loadPeople()` 当前保存 `peopleBinding`、`peoplePages`、`peopleLoadPromise` 和 `listCursor`，刷新同一列表时会调用 `readLoadedPages()` 重放已经打开的分页。引入自动滚动后，**不能因为浏览得深而在刷新或返回时自动逐页重读数十/数百页**。
- `loadCollections()` 同时写合集卡片和 `<select>` 选项。自动续页只追加新 ID；过滤重置/版本失效必须删除旧卡/旧 option，防重复；不能在用户选择合集时自动改变已选项。
- `loadCollectionPeople()` 使用合集 `collection_id`、`instance_token`、`revision`，并维护 `collectionSelectedPeople`。不能因续页或列表变化而把其他合集成员混入本次操作。
- 待整理的人脸分组与批量管理使用不同的身份：`person_id`、`face_id`、`asset_id` 不能互换。现有 `P4-UI2-BATCH-SELECT-UNIFY-A` 规定**Shift 仅已加载、全选仅已加载、操作批次上限不变**；自动加载绝不能改成自动选中新增项目。
- 现有人员列表和封面/相册页面复用了返回位置、滚动锚点、选择状态和弹窗导航；自动请求会改变 DOM 长度，必须使用稳定 ID 还原并在隐藏面板时暂停。

## 3. 产品及前端状态合同（P0/P1）

### 3.1 加载体验

1. 人物/合集/成员列表分别有自己的 observer、sentinel、`loading/hasMore/cursor/viewKey` 状态；只有当前**可见**且允许交互的板块接近底部（建议 600–900px）才允许自动取下一页。合集面板未展开、切到其它 tab、正在操作写入、页面已离开时均停止观察/请求。
2. 各使用原 40 人/合集的服务端分页；`loadPhotos` 若仍存在使用原 60，不擅自提高接口上限。首次加载只取 1 批；首屏不足时最多有限次补足，不允许 observer 在短列表中无用户滚动就扫描完 1 万个人物。
3. 一次只发一个续页请求；批次按后端原序追加，去重以权威 ID；加载失败显示「重试加载」，不会不断请求；到末尾显示已到底。`IntersectionObserver` 不可用时退化为原「再看一些」按钮。
4. 视图切换（人物/未命名/已隐藏、合集面板开合、合集切换、排序、搜索人物名称、选择归属）立即失效原请求代次、cursor 和 observer；旧响应不能插入新视图。刷新列表与新排序后必须重新基于服务端权威顺序显示。
5. 不能用 `total` 或“页面不足一屏”推断 `has_more`；严格以服务端 cursor/has_more 决定。停止时不在后台偷偷加载隐藏 tab 或已关闭候选组。

### 3.2 多选与写入隔离（阻断级正确性）

1. 进入人物批量管理后：勾选一个人物、再 Shift 点击已加载列表中的另一个人物，只按**当前已加载同域顺序**取范围；滚动自动出现的新人物不被自动勾选。
2. “全选已加载”“反选已加载”“清空选择”只作用于当时 DOM/已加载数据，不为选择而触发额外分页；原人物/人脸 500 上限、合集成员移出协议和 pending write 防护原样保持。
3. 已选项目跨单纯续页保持；切换合集实例、视图身份/排序或发生 revision stale 时按现有合同清锚点并处理选择。不能复用旧 ID 集执行新的集合写入；合照人脸整理行为完全不受影响。
4. 手动展开候选人物组、看已忽略人脸和执行人员历史操作时，不启动背景自动续页；不能将待整理流程误当照片浏览，不能为自动滚动引入新的写 API。

### 3.3 1 万人目录性能与返回

1. 列表必须按页读。优先复用 A 卡已有轻量 observer/helper、可见缩略图懒加载与布局；目录卡数量增长到数千时需有**有界 DOM 或可靠节制机制**，不能一直创建所有头像 DOM。
2. 先分析 `readLoadedPages()` 与 `peoplePages` 回放。返回/刷新优先恢复可见 `person_id`、合集 ID 与少量邻页/当前排序，不要因打开 100 页就在一次刷新里重读 100 次 API；若无法安全定位，明确保留筛选并回到当前可信首屏，不宣称完整深页恢复。
3. 对列表回收要保护 checkbox、已选 ID Set、Shift 范围锚点和当前聚焦对象。凡采用虚拟 DOM 的页面，“已加载”应有明确的**数据页集合定义**，不能让被卸载 DOM 的已加载项目从业务选择范围中无提示消失；若暂时达不到，优先仅在纯浏览模式回收，不在批量选择期间丢失任何可操作的已加载卡片。
4. 不能在打开人物/合集后同步拉取所有头像、全人物 ID、全合集成员；卡片头像继续懒加载/浏览器原有机制。监控 observer、listeners 与分页状态是否在面板关闭时解除。
