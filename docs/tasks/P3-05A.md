# P3-05A — 人物拆分、通用撤销与 revision 冲突契约冻结

本卡只冻结 P3-05 的高风险数据语义，不实现生产服务、API 或 migration。目标是先把人物拆分的身份、成员、
快照、幂等、冲突、补偿撤销和派生提交顺序写成可审查契约，再把机械实现交给 P3-05B。

不得自动切换或启动其他 Agent。若冻结完成，P3-05B 推荐 **DS-H / DeepSeek V4.1 Flash / 高推理**。

## 用户场景

用户发现一个人物分组混入了另一人，选择这个分组中的若干明确脸，执行“拆分”。拆出的脸形成一个可继续
命名、合并、逐脸纠错的独立人物；源人物保留未选成员。网络重试不重复拆分，撤销不回滚后续人工整理，
重启、重新关联和投影追赶后权威结果仍一致。

## 必须冻结的决策

### 1. 拆分对象与身份

- 拆分最小输入是否为 `source_person_id + 明确 face_ids`，以及 canonical source 的解析规则。
- 新人物 ID 的创建时点、是否必须为未命名活动人物、revision 初值、创建失败的回滚边界。
- 选中脸必须满足的当前归属/decision/assignment_kind；建议、无归属、MANUAL_UNASSIGNED、来自其他人物、
  已消失 face_id 分别如何拒绝。
- 空集合、重复 face_id、超过 500、选中源人物全部有效成员、源人物没有剩余成员分别是拒绝、no-op 还是
  合法拆分；不得留给实现自行猜测。
- 拆分不得复用或改变检测 `face_id`；新旧检测 `face_id` 可审查映射明确留给 P3-08。

### 2. 人工控制、排除与人物属性

- 被拆脸的 `face_assignment_controls`、`face_exclusions`、`face_person_links` 如何前进；不得丢失人工否定。
- 拆分是否把被移动脸设为 MANUAL_ASSIGNED，如何处理对新人物/源人物的既有 canonical 排除冲突。
- 源人物/新人物的名称、别名、头像、revision、merged_into 和未命名分组语义；禁止隐式复制姓名造成同名
  自动合并后立刻把拆分抵消。
- 同图多人冲突的拒绝/人工覆盖边界；不能靠拆分绕过“每脸至多一个 CONFIRMED”。

### 3. 幂等、快照与操作权威

- 继续使用全局唯一 `person_operations.request_id`，冻结 `SPLIT` 的 requested-payload canonical hash；同 key
  同 payload replay 必须早于 revision 检查，同 key 异 payload 零写拒绝。
- 必需的 expected revision：至少源人物、每脸 control/link，以及是否需要目标/目录 revision；明确缺省和
  stale 错误。
- `PERSON_BUNDLE` 与 `FACE_CONTROL` 是否足够表达 before/after，还是需要新 entity type；只能保存本次影响的
  最小权威快照，不能复制全库。
- operation type、source/target 字段、item 排序、after_revision、响应 envelope 与隐私字段闭集。
- 需要扩展 0012 CHECK 时，只冻结下一 migration 的目标语义；P3-05A 不修改历史 migration。

### 4. 补偿撤销与跨类型冲突

- 撤销拆分必须创建新的 `UNDO`、递增 revision、恢复哪些人物/脸/控制/排除/头像事实。
- 拆分后发生 rename、merge、face assign/unassign/restore_auto、第二次 split、自动关联或人物新增成员时，
  哪些构成整批冲突，哪些不属于旧快照而保持原状。
- 源人物或新人物随后被合并、redirect 链改变、脸消失时的闭合错误码；禁止模糊恢复到错误人物。
- 通用 `/persons/operations/{operation_id}/undo` 如何按 operation family 分派且 replay envelope 稳定；
  禁止 undo an UNDO，失败必须零写。

### 5. 权威到派生与读取

- 单次 changed split/undo 对 `catalog_filter_revision` 的“最多 +1”规则、`PERSON_CHANGED` 搜索队列、人物/头像
  cache、face candidate `PENDING_REPAIR` 的目标集合与提交顺序。
- 明确不得因人物拆分重新编码图片、写图片向量 `index_outbox` 或更改 face embedding space。
- no-op/replay（若允许 no-op）必须零派生副作用；提交后 SQLite 权威查询立即正确，滞后投影不得漏召回。
- 人物列表、face_summary 和旧 canonical ID 的读取口径；是否新增只读计数必须明确，没有必要则保持现有契约。

### 6. API、错误与隐私

- 冻结唯一的 split 路径、请求/响应 JSON、contract version、HTTP status 和稳定错误码；不得同时留下多个候选
  路径给 P3-05B 选择。
- 继续沿用 session、Host/Origin、CSRF、稳定 request_id 和路径脱敏；响应/错误/日志不得暴露文件路径、
  bbox、landmark、向量、单对相似度、置信度或原始幂等 payload。
- companion 使用 `additionalProperties: false`，覆盖请求、成功、replay、冲突和 undo 响应。

## 契约反例测试至少覆盖

1. 同 request_id 同 payload 在 revision 变化后 replay；异 payload 零写冲突。
2. source/person/face revision 任一 stale 时整批拒绝。
3. 重复脸、空集合、501 个脸、跨人物脸、建议脸、无归属脸、消失脸的闭合结果。
4. 拆分不会移动未选 siblings，不会复制姓名后自动回并，不会写图片向量 outbox。
5. MANUAL control 与 canonical exclusions 在拆分/撤销前后不丢失。
6. 撤销前发生 rename、merge、单脸纠错、再次拆分、新增自动成员时逐类判定。
7. undo an UNDO、重复 undo request、脸/人物消失、redirect 环/坏 schema 的零写拒绝。
8. filter revision、operation/item、搜索队列、face repair 在同一事务全成或全回滚。
9. 响应 schema 不接受额外字段，错误码/HTTP 映射闭合且无敏感字段。
10. 与 ADR-0006/0007 的 rename/merge/face undo replay envelope 兼容，不破坏既有 operation family。

契约测试必须读取 ADR/companion 并断言实际冻结值，不能只检查文件存在或复制常量后自证。
