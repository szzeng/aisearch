## 唯一闭环（新版时间轴优先）

- 全部照片与单来源照片使用 CORE 的**同一时间轴**：默认可信拍摄时间+按日、可切换入库时间和按月/年分组；年/月筛选与直接跳转是不同控件，侧边年月导航窄屏可收纳。
- 服务端权威日期标题，跨页同日合并、稳定 cursor/时间成员修订；滚动接近底部自动续页、失败时“加载更多/重试”，切时间/来源/年月必须抛弃过期响应。跳到旧年月不能逐页遍历。
- 无可靠拍摄时间/只有文件时间/未抽取分桶且不伪称拍摄；旧 `time_desc/capture_desc/asset_id` 的 API 合同不改，旧高级条件仍可找回；照片日期直接在分页结果中获取，避免逐图 `GET /assets/{id}`。
- 管理 UI 延续“看照片、建库/刷新”优先，改名/移除/完整扫描次级；所有原权限/CSRF/任务状态、查看器原图能力和返回滚动位置保留。无来源/未建库/筛选空/请求失败明确区分，不虚构照片总数。
- 旧静态 PNG/SVG 仅留档，当前视觉以最后版演示为准；不因此重造 CORE API、人工整理或第二套网格组件。

## 大图库浏览器性能必须项（20万+）

- 首屏数据与年份/month 摘要分开请求，页面不因全量 `COUNT/GROUP BY` 阻塞照片第一页。不要对每张图多发详情请求；页数据随带日期来源，缩略图走原有懒加载和缓存。切换来源、日期依据/范围与“未知/待就绪”快捷入口均须产生新 generation，旧响应不能回填。
- 50～60 张一页，仅在临近视口触发下一页，同一范围至多一条续页 in-flight；失败时可手动重试；切回旧年月直接通过 API seek，不连续扫几十页。分组头跨页合并；连续超过30页后有界**回收离屏 DOM/图片解码对象/URL**并留锚点与占位高度，不引入重框架、不损坏键盘焦点/预览返回。
- **未知拍摄日期**在拍摄视图中有直接入口，按入库时间倒序；**日期待就绪**单独标识；切换入库视图后正常并入按年月的入库时间轴。没有手动修时间控件，也不推断年份。
- 20万图库性能依 CORE 元数据 API 基准证据，不重复生成大数据；B 做轻量浏览器可见时间测量（已缓存缩略图首张出现目标≤1.5秒，仅目标，未测不可宣称达成）与 30 页模拟数据连续滚动的 DOM/资源趋势检查；真实20万原图不需要。

## 浏览偏好与相册范围隔离（2026-10-13）

用户全局偏好只记 `time_basis=capture|added` 与 `group_by=day|month|year`（沿用现有或最小本地 UI 偏好载体）；默认可信拍摄+按日。来源库选择、筛选到某年/月、滚动/日期跳转锚点绑定**当前 source scope**，返回仍可恢复；打开另一个人物/地点相册不得突然带入首页某一年的筛选。所有照片总数与可信/未知/待就绪均按相同资产资格，不能因为无 EXIF 时间漏照片。

## 补充空状态与回收验收

首页/来源存在有效照片但可信拍摄页为空时，显示“当前没有可信拍摄日期的照片”，保留本范围“日期未知”“日期待就绪”“按加入图库时间浏览”；不得误显示无来源/未建库。未知与待就绪桶的标题明确为“加入图库日期”，年份筛选/跳转也使用此依据。摘要加载或失败时入口仍可用，数量使用待加载/重试状态，不伪造0。

按 [规范 §3.2](../plans/P4-UI-TIMELINE-V2.md#32-更新期间的浏览与资源预算)记录30页节点、缓存、资源、请求和返回误差；分别检查从页30返回已回收的页1、连续日期修订、摘要迟到与窗口缩放。两页 fixture 可以测试小页长；正式页长需≥121条元数据验证，复用少量合成素材即可。
