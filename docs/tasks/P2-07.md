## 用户场景

用户在主页面输入中文查询，看到一页**有界**的图片网格；每张图旁能看到它**为什么命中**（文件名/有效地点
文本命中的文字通道，还是图文向量通道，或纯筛选）；当语义索引仍在追赶或本进程没有查询编码器时，页面
**明确说明**而不是给一个看似正常但没有语义结果的空页；用户能用地点、来源、可用性筛选收窄，并能在
一个页面上看到**分类别的覆盖率**（例如已投影文本资产数 / 已确认向量条目 / 已归类地点），据以判断
"为什么结果不全"。用户还可以上传一张本地图片找相似图；没有图像编码器时得到明确的结构化拒绝，
而不是拿文本通道假装成功。

## 冻结实现范围

### 1. 搜索页（静态前端，不引入 Node/npm）

- 新增 `src/photo_search/web/search.html` + `search.js` + `search.css`，与 `places.*` 同风格：
  零依赖、无外链、无绝对本地路径、窄视口可重排、键盘可达。
- 功能：查询框（`{request_id, text}`）、来源／可用性／地点（复用地点页的选择方式，含
  `include_descendants` 与 `place_state`）筛选、`page_size` 分页与**游标续页**（同一
  `search_session_id`，`next_cursor` 续页）、按需缩略图（`GET /assets/{id}/thumbnail`）、
  命中原因的**逐行**展示（`hit_reason` 取值 `TEXT`/`SEMANTIC`/`TEXT+SEMANTIC`/`FILTER_ONLY`）、
  `matched_text` 与 `semantic_ready` 的如实呈现（后端字段直接展示，不新造文案结论）。
- 必须显式呈现的**非成功**状态（不得静默降级）：
  - 本进程没有查询编码器 → 409 `RUNTIME_CAPABILITY_UNAVAILABLE`（`reason=QUERY_ENCODER_UNAVAILABLE`）
    的提示（占位文案必须说明"语义通道未运行"，不得显示成"无结果"）；
  - 会话/游标类拒绝（`SEARCH_SESSION_EXPIRED`/`INVALID_CURSOR`/`PROFILE_GENERATION_MISMATCH`/
    `CATALOG_FILTER_REVISION_STALE`/`PLACE_SUGGESTION_REVISION_STALE`）→ 提示并保留查询、提供重搜入口；
  - `search_projection.state=LAGGING` 与 `pending_semantic.entries` → "语义索引仍在追赶"的提示与计数；
  - `candidates_truncated`/`channels.*.truncated` → 说明结果被上界截断。
- 页面顶部导航与 `index.html`/`places.html` 互相可达（沿用现有链接风格）。

### 2. 上传搜图（`POST /api/v1/search/image`）

- 端点接受一张本地上传图片（`multipart/form-data`），字段与筛选条件显式声明；接入既有
  session/Host/Origin/CSRF 边界与错误信封。
- **硬限制**（必须在服务端执行，且逐项实测）：字节上限、像素上限、格式白名单（与 P1-03 的
  `supported_input_formats` 一致）、解码时间/解码失败分类；临时文件在**成功与失败两条路径**都被回收。
- 绑定规则：上传图必须与 `SearchRequest` 同一套绑定语义（显式 `space_id`/`image_generation_id`/
  `dimension` 或激活 profile），并复用 P2-05 的双通道/RRF/权威复核路径；**不得**为上传图另造一套排序。
- 没有图像编码器时返回结构化 409（沿用 `RUNTIME_CAPABILITY_UNAVAILABLE`，`reason` 写明
  `IMAGE_ENCODER_UNAVAILABLE`；如新增码必须在报告 §6 说明），**不得**用文本通道或"零命中"假装成功。
- 上传图不得写库：不新增资产、不写 `index_*`/`artifacts`/`search_feedback`，查询结束后不留临时文件。

### 3. 地点筛选与命中原因

- 搜索页必须支持 P2-03A/B 的地点筛选语义（`place_ids`、`include_descendants`、`place_state`、
  `suggestion_revision`），并如实显示"待确认建议不参与有效地点过滤"的现状。
- 命中原因只展示后端字段：不得把向量距离/BM25/精排分数显示成"准确率/百分比"，也不得把
  `reranker_score` 与 `hit.score` 相加或并列成同一含义（P2-06B 的分离由契约保证）。

### 4. 分项覆盖率（分类别，不共用准确率）

- 新增一个**只读**覆盖率视图（优先复用 `GET /api/v1/places/coverage` 与
  `/capabilities` 的 `search`/`documents`/`indexing` 摘要；如需新增端点，必须是纯读、无写、
  只返回 id/计数/状态、绝不含路径或坐标），至少区分：文本投影覆盖（`search_documents` 与
  `search_projection_queue`）、语义索引覆盖（绑定 generation 的 CONFIRMED `index_entries` 与
  `pending_semantic` 滞后）、地点覆盖（GPS 事实/已归类/未归类/待确认）、来源可用性。
- 页面把每一项单独列示并说明口径；**不得**合成一个"整体 AI 准确率"。

### 5. 明确的非目标（本卡不得实现）

- 不得实现 P2-08 的综合故障验收（恢复、过滤、增量、后台竞争、地点人工锁/投影/缺包联测）。
- 不得实现自然语言条件解析（年份/日期/人物别名/显式筛选语法，属 §9.1 的后续卡）；查询文本仍原样
  交给后端。
- 不得实现 OCR、人脸/人物页面、图片详情页的人工备注与 VLM 描述。
- 不得引入 Node/npm/前端构建链，不得新增运行时依赖或云服务。
- 不得改动：ADR-0001～0005 与冻结 JSON schema、`0001`～`0008`、五字段 job 身份、lease/attempts/
  迟到提交、资产/位置/缺失判定、P2-03A/B 人工锁/排除/幂等/批量/撤销语义、P2-04 tokenizer 世代/
  MATCH 策略/`place_text` 来源规则、P2-05 RRF 公式/并列规则/`hit_reason` 语义、P2-06A 会话/游标/
  profile 绑定语义、P2-06B 反馈幂等与精排分数分离、`space_id` 语义、`ingestion/**`、`workers/**`、
  打包入口、`pyproject.toml`、`uv.lock`。
