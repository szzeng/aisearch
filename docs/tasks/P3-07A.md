# P3-07A — 人物 all/any 与地点 AND 搜索契约冻结（ADR + companion + 契约用例）

本卡只冻结 P3-07 的**筛选协议**，不实现检索：把人物的 `all`/`any` 条件与地点、时间、来源、
可用性、语义条件组合成一条可判定、可失效、可补查的契约，并把它写成 ADR 与机器可读伴随物。
**本卡不修改任何生产代码、migration、`schema_version`、依赖或既有测试**；实现留给 P3-07B。

执行模型：**DS-H（DeepSeek V4.1 Flash / 高推理）**。模型切换由用户在 Codex 中手动完成；不得自动切换或
声称已切换。若本卡要求的冻结与 ADR-0003/P2-06A、ADR-0005、ADR-0006～0008 出现无法调和的冲突，
停止冻结，把差异、最小反例与待决问题交独立新会话 **DS-H 做全量工程主审**；只有命中 V3.1 §2.2 六类
条件之一才把该审查升级为 **DeepSeek max**。**canonical / revision / 缓存失效**这三条边界在 DS-H
收敛后交 **C2 / GPT-5.6 Sol / high 聚焦终审**（只审这些边界，不重复全量 diff）。

## 必须冻结的内容（本卡的唯一交付）

### 1. 条件形状与组合语义

- 新增人物条件的**闭集**字段（建议 `person_ids: [int]`、`person_match: "all" | "any"`），并明确：
  `person_ids` 为空/缺省时**不产生**人物条件（不是「匹配没有人物的照片」）；`person_match` 缺省为
  `any`；`all` 与 `any` 的判定对象是**有效成员**（ADR-0006 §5：`CONFIRMED` 且非
  `MANUAL_UNASSIGNED`、非活动排除），口径必须与 `GET /api/v1/persons` 的 `face_count`/`asset_count`
  完全一致；
- 与既有条件的关系：与 `place_ids`/`place_state`/`availability`/`source_id`/时间/语义条件一律
  **AND**；`person_ids` 内部才是 `all`/`any`；`any` 去重后仍然是 1..N 个 canonical 人物；
- 与 `place_ids` 的互斥/校验规则照抄 ADR-0005（`place_state=unassigned|manual_unassigned|suggested`
  与 `place_ids` 的组合拒绝），并明确**不得**允许 `person_match=all` + 空 `person_ids`、
  `person_ids` 含重复/非正数等形状错误；
- 是否允许「照片级」与「脸级」两种口径：默认只冻结**照片级**（一张照片属于某人 = 该照片至少有一张
  该人物的有效成员脸），并写明脸级口径不在本阶段。

### 2. canonical / 旧 ID 语义

- 查询入口把每个 `person_ids` 解析到 `canonical_person_id`（复用 `persons.identity` 的唯一解析器）；
- `all` 模式下**合并后的重复条件必须去重**（`person_ids=[3, 7]` 且 7 已合并进 3 时等价于 `[3]`），
  `any` 模式同理不得因重复计数改变命中集；
- 已合并的旧 id、以及指向不存在/成环 id 的行为：不存在 → 结构化 404/422（按既有 `PERSON_NOT_FOUND`/
  `PERSON_REDIRECT_CYCLE` 口径冻结到本协议），成环 → 拒绝而不是猜一个端点；
- 明确「旧筛选可继续使用」的含义：一个在合并前建立的搜索会话/分页游标在合并后如何失效（见第 4 条），
  而不是静默换一套结果。

### 3. 权威补查与投影滞后

- 人物条件是**权威 SQLite 判定**还是派生投影：必须写明如果实现选择把人物放进
  `search_documents`（例如复用现有的 `user_text`/`caption_text`/`tag_text` 之一或新增列），
  投影滞后时**必须**按架构 §4.5.3/§9.3 用权威候选集补查，不能让旧投影漏掉新归类、也不能继续显示
  已移除的命中；
- 必须写明本阶段**不新增 migration** 时的可行实现路径与**需要 migration**时的判定条件（若确实需要
  新列/新表，本卡即失败并转 DS-H 全量主审，不得在本卡顺手加迁移）；
- 「补查」的上界、失败语义与 `search_projection` 状态字段（`SYNCED`/`LAGGING`、`queued_assets`）
  如何随本协议扩展，必须写成可测试的字段级描述。

### 4. 失效与缓存

- `catalog_filter_revision`：改名/合并/拆分/单脸纠错/撤销一律只 +1 且 cause 仍是 `PERSON_CHANGED`
  （ADR-0006～0008 已冻结）；本卡要冻结的是：**搜索会话/分页游标在人物条件存在时**如何把
  `catalog_filter_revision` 纳入绑定，以及过期时的稳定错误码（复用既有
  `CATALOG_FILTER_REVISION_STALE` 还是新码，必须二选一并给理由）；
- 人物数量/头像等**可重建缓存**（`cache/face-crops`、人物计数）在合并/拆分/纠错后的失效边界：哪些是
  派生缓存（可重建、允许短暂滞后）、哪些必须立即一致（页面与关系查询读 SQLite 权威）；
- 明确「地点条件 + 人物条件同时存在」时的绑定顺序与单一 revision 集合，避免两套 revision 各自为政。

### 5. 隐私与错误面

- 请求/响应闭集：新增字段必须 `additionalProperties: false`，且**不得**把 bbox/landmark/embedding/
  similarity/confidence/`name_key`/本地路径带进任何搜索响应；命中原因词表（`TEXT:`/`SEMANTIC:`/
  `TEXT+SEMANTIC`/`FILTER_ONLY`）是否需要新增人物原因值必须显式冻结（默认不新增，人物只作为
  **筛选**而非命中原因）；
- 结构化错误：形状错误、`all` 空集、canonical 冲突、revision 过期、会话过期各自一个稳定 code。

## 必须保持的不变量

- 人物/控制/操作仍是 SQLite 唯一权威；本卡不引入第二份状态；
- `face_id` 仍是最小人工单位；有效成员口径与 P3-06 的 `face_count`/`asset_count` 一字不差；
- 同名合并、revision、`request_id` 幂等、拆分与撤销冲突矩阵不变；
- `MANUAL_UNASSIGNED` 的脸不因任何搜索条件被当作有效归属；活动排除不计入 `all`/`any`；
- 只读与错误响应继续遵守隐私闭集（无路径、无坐标、无几何、无向量、无相似度）。
