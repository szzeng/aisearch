## 1. 已证问题（输入证据，不要重新归因）

- 30 万档、投影未追赶（`search_projection_queue` 非空）+ 后台 drain 在场时，**合法**前台搜索被拒：
  `CATALOG_UNREADABLE: cannot start a catalog write transaction: database is locked`（各等满 5 s busy timeout）。
  P4-02U 复现：线程臂 **5/6 被拒**、进程臂 **4/6 被拒**；无 drain 对照 0/4。
- **持锁者 = drain 自己的 `claim`/`apply` 写事务**（`IndexCoordinator.process_batch`）；单条事务并不长
  （30 万档 max 467 ms / 692.6 ms），但**批间几乎无让步**（间隙 p50 1.58 ms、p95 3.47 ms），
  线程臂自身最长连续不可用 **32 449.4 ms**（进程臂 6 295.8 ms）⇒ 占空比 **98.96%**（窗口 `acquire..end` 口径），竞争者在 5 s busy timeout 内抢不到锁。
- 已排除：WAL checkpoint（≤62 ms、busy=0、WAL ≤4.24 MB）、未计时写路径（进程内写窗口数与 `write_phases` 完全一致）、
  第三方外部写者（无 drain 时 0 次被拒）。**R2 更正（2026-09-27，见 [R2 报告](../reports/P4-02U-lock-attribution.md) §5 与 [复审报告](../reports/P4-02U-dsh-capacity-evidence-rereview.md) §5 R5）**：可回溯证据里单条事务最长 **692.6 ms**（30 万进程臂）/ 465.7 ms（线程臂）/ 538.0 ms（6 000 重跑）/ 608.3 ms（交错臂）；旧「6 000 档单条 `apply` 持锁 3 150.7 ms」出自已被覆盖的首轮 JSON、已不再引用。旧表述
  「单条事务也可能持续数秒」据此不成立 ⇒ 修复**可以**依赖「单条事务 < 1 s」，但**不能**依赖「批间一定有可用空隙」（实测有效空闲 ≈ 间隙 − COMMIT ≈ 0）。
- 违反的验收条款：主架构 §12.2 后台档「API 样本 P95 ≤ 8 秒；**不得因内部争用拒绝合法验证请求**」
  与最小口径「存在非预期的合法请求失败时该场景不通过」。

## 2. 目标与边界

- 目标：同一夹具、同一脚本下把「4/6 拒绝」变成「0 拒绝」，**结果页与修复前逐项相同**（除被拒→成功），
  不新增错误码/信封字段/游标语义，不放宽 §12.2。
- 允许：`src/photo_search/search/**`（投影追赶的失败处理与有界退避）、必要时 `src/photo_search/indexing/**`
  （drain 批间让步）、其直接测试、最小诊断驱动、本报告/卡/状态。
- 禁止：把「加大 busy_timeout」当作唯一手段（必须给机制论证）；改 schema/迁移/依赖/`uv.lock`；
  改 §12.2、ADR/companion、错误码集合、`query_hash`、信封/游标/total；改 outbox/claim/revision 语义
  （P4-01C A1 的「supersede 检查 + 引擎写 + 确认同一 `BEGIN IMMEDIATE`」不得拆开）；A3/ANN/第二后端；
  扫描真实图库或下载模型；改 ACL。

## 3. 候选方向（只选一个，并在报告里论证取舍）

1. **搜索侧降级**：投影追赶拿不到写锁时，跳过本次追赶并以既有「语义索引仍在追赶」语义返回
   （`pending_projection_page` 已表达该状态）；不得静默丢待补项，必须保持可观测。
2. **搜索侧有界退避重试**：仅对 `CATALOG_UNREADABLE` 且命中 busy 标记的拒绝做有限次短退避
   （例如 2 次 × 500 ms），仍失败按现行错误返回；需证明不放大 P95、不与 §12.2 冲突。**审查输入（2026-09-27）**：实测连续不可用为进程臂 6.30 s、线程臂 32.45 s 量级，而每次拒绝都已等满 5 s busy timeout ⇒「2 次 × 500 ms」在算术上不足以把 4/6 拒绝变成 0 拒绝；若选此方向，退避预算必须按饥饿时长上界重算并给出 P95 代价，否则改选方向 1/3。**R2 补充（2026-09-27，宿主 P4-02U 报告 R2）**：同状态交错臂显示「暂停 drain ≥1 s」后 held 段 **0/4 被拒**、running 段 2/4 被拒，且线程臂最长连续不可用为 **32 449.4 ms**、有效空闲 ≈「间隙 − COMMIT」≈0 ⇒ 方向 2 的退避预算必须按 32.45 s 量级上界评估，方向 3 的让步量级必须显著大于该有效空闲并给出建库吞吐代价。
3. **drain 批间让步**：批与批之间主动让出写锁以降低占空比（代价：建库吞吐下降），需给出吞吐代价数字。

选择必须服从「保持结果与现有精确路径一致」与「不改事务/恢复边界」；不得同时改多条。
