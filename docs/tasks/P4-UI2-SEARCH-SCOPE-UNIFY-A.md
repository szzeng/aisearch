# P4-UI2-SEARCH-SCOPE-UNIFY-A — 顶部搜索栏一键执行当前范围搜索

> 状态：PLANNED / 未实施。创建日期：2026-10-14。基于 `master` HEAD `856b07a1` 分析；执行前复核最新 HEAD。建议执行：GPT-6 / High。**本卡仅调整 UI2.0 搜索入口、范围交接及相关前端状态，优先不改搜索后端。**
>
> **用户 2026-10-14 确认的新交互是本卡最高优先级要求**：在人物/合集/地点（以及明确选定单一图库）页面，`搜索此XXX` 按钮直接出现在顶部唯一搜索框旁；用户填词后点击它，**立即以该词在当前范围搜索，并跳转搜索结果页**。空词点击该按钮也应执行当前范围内“全部照片”查询。旧任务和旧演示中“标题旁 CTA → 进入搜索页 → 由用户再输入/提交”只作历史参考，不再是本卡验收标准。

## 1. 目标与边界

解决“搜索此相册”按钮分散在标题处、进入结果页还要再输/再搜、人物相册仍有第二个局部文字框、合集/地点/图库行为不一致的问题。

- **唯一关键词输入**：非搜索页复用现有页头 `.global-search-form` / `#global-search-query`；搜索页复用 `#search-form` / `#query-text`。每个页面只有一个自然语言搜图输入和一套提交处理，保留高级筛选及独立的目录名称筛选。
- **两个明确动作**：页头默认 `全库搜索`（Enter 在非结果页同义）；有合法的当前照片范围时，在输入框紧邻位置额外显示 `搜索此相册 / 搜索此合集 / 搜索此地点 / 搜索此图库`。两按钮读取**同一**关键词，选择范围由用户点击的按钮决定；当前范围按钮是执行操作，不是范围选择开关。
- **结果页持续限定**：从当前范围按钮进入 `/search` 后立即发送一次查询、显示范围 chip，后续修改关键词/点击结果页提交/Enter 继续在该范围内搜索，直到明确取消。结果页顶部应一眼可见当前固定范围，提交按钮文案可用 `搜索当前范围`；取消后变回 `全库搜索`。
- 不修改人物/地点/合集的人工归属，不扫描或改动真实 `PhotoSearchData`，不重写自然语言解析、FTS、向量检索、RRF、TopK、时间轴、地点 SQL 权威成员筛选或搜索服务端 session 机制。
- 地图“当前视口内容搜索”**明确不在本卡实现**：现有 viewport 时间浏览不是可直接复用的全文/语义范围查询；不做假按钮。若要做需单独设计 bbox 权威成员、版本和候选策略。

| 地图页面 | 全库搜索 | 本卡不新增 viewport CTA | — |

注：`搜索此相册` 指所有属于该人物的有效照片，而非当前屏、时间轴日期桶、分页窗口、被勾选的照片或其中某张脸；图库、合集、地点亦同。来源身份以 `source_id` 为准，不按显示名查找。进入范围搜索**不暗带**相册当前年月、拍摄时间偏好、滚动位置、人物列表筛选、地点目录名称筛选；后续在结果页主动设置的高级筛选可以再与固定范围 AND。

## 4. 实施顺序

### A. P0 — 统一页头范围动作与单次交接

1. 复用各页面现存唯一 `global-search-form`。在页头输入框**旁边**增加可随当前视图更新的范围操作按钮；普通 `<button type="button">` 必须避免触发表单默认 submit；全库按钮保持正常提交 `q`。不要添加第二个自然语言搜索输入、二套全局 listener 或从 DOM 标题文字反推范围。
2. 人物/合集使用 `person_id` 或 `collection_id + instance_token + revision`；地点使用 `place_kind + place_key`；图库使用 `source_id`。显示名称仅用于 chip。切换相册、回目录、切换图库、集合成员 tab、加载中/无身份/过期实例时，范围按钮必须及时按**当前有效视图状态**更新，禁止旧按钮带上一个对象搜索。
3. 点击 `搜索此...` 时**原子携带** `q(0..256)`、正确结构化范围和 `execute=true` 跳至 `/search`；允许最小兼容扩展现有一次性 `scope_entry` / `sessionStorage`（或同等可靠的一次性交接），不得传递资产 ID 列表、敏感本地路径或把范围转为关键词。消费一次、跳转前失败可见、刷新/返回/旧 `/search?q=` 深链兼容。**范围交接失效不得静默回退成全库查询**；明确报错并让用户手动选择重新搜索。
4. 有 q：落地后**恰好一次** scoped 文字查询；空 q：因为用户已显式点击范围按钮，仍**恰好一次** `FILTER_ONLY` 查询，按权威成员完整分页、零编码器调用。仅聚焦框、打开空 `/search`、清空全库搜索框、按 Esc 均不应意外发空查询。输入法组合态 Enter 不重复提交。
5. 默认全库按钮/非结果页 Enter 永远不因当前相册而暗带 scope（即使它们与范围按钮紧邻）；不能在跳转时先发全库查询再替换成 scoped 结果，也不能同时触发两次请求。

### B. P0 — 搜索结果状态与安全边界

1. 在搜索结果页**顶部输入附近**显示明确可取消的固定范围 chip（人物名、合集名、地点名+父级、图库名）。若保留原 `#result-intent-scope` 用于其他解析条件，避免重复范围标签、相互矛盾的状态或重复监听。
2. 已固定范围时，编辑 q、点击结果页提交/Enter、高级筛选、续页、预览与返回，均保留相同权威身份和版本约束。空 q 有效的 `FILTER_ONLY` 分页与非空词现有 FTS/向量/RRF/TopK 行为区分，不把语义有界候选说成完整范围。
3. 取消固定范围：作废旧 request generation、session/cursor、binding、旧列表/计数/预览、快照；只清**这个固定范围身份**，保留与之不冲突的显式筛选及关键词，显示“已取消范围，点击全库搜索重新查询”；**不自动展示或发送范围扩大的全库结果**。遇条件冲突时给出提示而非默默丢条件。若有旧异步请求迟到，不得覆盖新状态。
4. 一切服务端身份/修订异常（人物合并、合集重建或成员变动、地点活动包/成员变化、图库删除）需有可读错误，并要求重新进入有效范围/刷新；不能静默忽略 scope 而查全库，也不能恢复已失效的旧命中。
5. 已固定 scope 时，上传图片检索若无完整服务端 scope 支持，就屏蔽 scoped 上传搜索并解释“当前范围仅支持文字/条件搜索，请取消范围后以图搜图”；非 scoped 以图搜图功能完全保留。

### C. P1 — 去重与视觉小收口

1. 仅在对应人物 scoped 新流程通过定向验证后移除 `persons.html#pa-search-photos`、`#pa-photo-query`、`#pa-all-photos` 及**仅服务于旧表单**的监听/状态；不能误删人物整理、筛选人物、时间轴、分页与照片操作。若新范围行为未闭环则保留旧入口、整卡记 PARTIAL，不假称完成。
2. 删除人物/合集标题旁原 `#pa-search-scope` 的可视 CTA，地点标题原 `.album-search` 迁移到页头；不要为了保持旧 ID 把按钮隐藏两份并双绑。具体实现可重用 DOM/函数，但可见动作唯一。
3. 采用已有 UI2.0 设计 tokens、字体、浅深色与控件高度；桌面搜索框、全库搜索、范围搜索同排，移动端/窄屏可换行或紧凑收纳，但两个动作语义可辨、键盘可触达、无横向溢出、200% 缩放不遮挡输入。不要重做全站视觉。
4. 更新受影响的 UI2.0 搜索交互说明/示例，**尤其纠正旧 `docs/mockups/ui2-interactive/demo.html` 中与“点击只跳转等提交”冲突的演示逻辑**；实现者不可只按旧效果页接线。无需重绘全套 mockup。
