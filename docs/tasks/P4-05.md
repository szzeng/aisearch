## 1. 目标与用户收益

停机状态下能生成一份**一致性备份**，并能在**空数据目录**上恢复出一套**可直接搜索**的运行环境：
- 人工知识不丢：人物/人脸归属、地点归属与排除、手动 hidden、操作历史（撤销链）等以 SQLite 为准的事实全部保留；
- 派生状态可判定：语义（Lance 向量/`index_entries`/generations）与文字投影（`search_documents(_fts)`/待投影队列）
  在恢复后**与备份时刻一致**，不需要重扫真实照片目录、不重新编码全库；
- 恢复后**离线可用**：不依赖云、不依赖网络、不依赖重新下载模型（模型是否随备份携带由本卡测量后裁决，见 §3）。

## 2. 允许 / 禁止

- 允许：新增备份/恢复实现模块与其 CLI 子命令（沿用既有 CLI 家族与 JSON 输出风格）、其直接测试、
  最小诊断/校验驱动、报告/状态/本卡；必要时在 `config.py` 增加只读路径解析。
- 禁止：改 §12.2、ADR/companion、搜索信封/游标/错误码语义；**新增迁移或改 schema 版本**（迁移保护是"拒绝不匹配"，
  不是"自动升级"）；改 outbox/claim/revision 协议；新增依赖（若确需须先向用户申请并说明）；Docker/云/第二后端；
  **扫描、修改或移动真实照片库**（除用户明确授权）；改 Windows ACL；把本卡扩成增量/云同步或发行级 remap 工作。

## 3. 必须保持的不变量

原图目录**只读**（备份/恢复只读照片、只写数据根）；SQLite 与派生物的一致性边界（备份必须是"停机/静止"状态，
不得在同一时刻既读到旧 catalog 又读到新向量）；恢复后的目录布局与运行时不变量（`catalog/`、`vectors/`、`artifacts/`、
缩略图缓存、`runtime/` 的相对关系）与产品启动路径一致；`SUPPORTED_SCHEMA_VERSION` 与迁移编号不变。

## 4. 验证与验收（D 级：B + 故障注入/恢复测试）

1. **一致性备份**：在合成夹具上生成备份；断言备份集合与清单（每个成员的相对路径 + 大小 + SHA-256）完整；
   备份在**停机**状态下完成（无并发写入脚本参与）；对照"迁移前单库备份"说明本卡新增的是一致性集合而不是复制单库。
2. **空目录恢复**：把备份恢复到**空**数据目录 → 启动产品入口 → 语义搜索与文字搜索各自返回与备份时刻**逐项相同**的页面
   （同一查询、同一 top_k、逐 asset_id 比对）；SQL 断言人工知识（人物/地点/排除/hidden/操作历史）行数与内容摘要一致；
   派生状态不需要重扫（记录恢复耗时与是否触发任何重扫/重编码）。
3. **迁移保护**：把备份恢复到 schema 版本**更高/更低**的目标目录时必须**结构化拒绝**（错误码/JSON 状态可判定），
   不得静默降级、自动迁移或留下半个可用目录。
4. **失败注入**：备份中途失败（例如目标盘空间/Z 点注入）不得留下会被误认为完整的备份（原子提交或显式标记 + 拒绝使用）；
   恢复中途失败不得留下"看起来完整"的数据根。
5. **仓库级**：`pytest -q tests/unit tests/integration`（JUnit XML）+ `ruff check .` + `uv lock --check` + `git diff --check`；
   全部命令与退出码写入报告。
6. **未授权项**：真实照片目录的任何扫描/写入都需要用户单独授权；本卡默认只用合成夹具与已授权样本。
