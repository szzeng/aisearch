# P4-02Y-K — Face 检测 CUDA/CPU 混合执行

**状态：READY**

执行模型：**C1 / GPT-5.6 Terra / medium**。完成后仅需 **DS-H 窄受影响面复核**；若必须改变 ADR-0001 的全局设备语义，停止并转 **C2 / GPT-5.6 Sol / high**。

## 目标

本机已确认 `buffalo_l/det_10g.onnx` 不能 strict CUDA：大部分节点可跑 CUDA，少量节点只能由 CPU EP 执行。当前禁用 CPU EP fallback 会导致 Face GPU probe 报错并整条降级 CPU。

本卡只修 Face：

- **det_10g detection**：允许 `CUDAExecutionProvider + CPUExecutionProvider` 混合执行；
- **w600k_r50 recognition**：继续 strict CUDA；
- `auto` 下 mixed Face 可用时应优先使用，不再整条 Face 降级 CPU；
- mixed 状态必须显式记录，不得伪装成纯 CUDA。

## 边界

不要改：

- Chinese-CLIP strict CUDA；
- OCR；
- 全局 device policy；
- Face 权重、阈值、向量空间、聚类逻辑；
- 调度器或其他无关架构。

优先只改 `src/photo_search/face/engine.py`，确有必要再动 `face/service.py`。

## 最小验收

使用现有 Face smoke，确认：

1. `det_10g` session 成功，实际存在 CUDA + CPU EP；
2. `w600k_r50` 仍为 CUDA only；
3. Face smoke 结果与当前 CPU 基线一致；
4. `qualified_devices` 包含 `gpu`；
5. 建库不再因 `session.disable_cpu_ep_fallback=1` 触发该 Face 报错；
6. 记录一次 CPU Face 与 mixed Face 总耗时，仅用于确认无明显反向退化，不设性能门槛。

完成后更新本卡结果与 `docs/development-status.md`。
