# P4-PHOTO-RANDOM-BROWSE-TIME — 随机浏览时间来源修正

状态 **SCOPED PASS / USER ACCEPTED**（2026-11-26）。定向测试已通过，用户确认实测通过并豁免独立只读复核。详见[执行报告](../reports/P4-PHOTO-RANDOM-BROWSE-TIME.md)。未访问真实图库。

## 目标与当前原因

随机浏览缩略图目前显示「加入时间」，原因是 `web/app.js::buildTile()` 使用了 `asset.created_at`。它代表资产入库时间，不是照片拍摄时间，也不是文件创建时间。

随机摘要由 `POST /photo-random-summaries` / `api/queries.py::random_asset_summaries()` 提供，每次最多处理 50 张。项目已有 P4-00B 拍摄时间数据，可直接复用；`file_locations` 只有文件修改时间，没有单独保存文件创建时间。

**目标显示规则：**
1. 有可信 EXIF 拍摄时间：显示「拍摄时间」。
2. 没有可信拍摄时间：显示 Windows 文件属性中的真实「创建时间」。
3. 两者都无法取得：显示「时间未知」。
4. 随机浏览不再显示「加入时间」；普通列表原有「加入时间」保持不变。

## 实施要求（尽量小改）

- 只改随机摘要与随机卡片时间展示，不改其它浏览模式。
- 拍摄时间沿用 `taken_time` 现有规则：仅可信 `EXIF_ORIGINAL` / `EXIF_DIGITIZED`（`label == "capture"`）作为拍摄时间；不改 P4-00B 规则。
- 无可信拍摄时间时，复用 `api/files.py` 现有受控文件位置解析，对当前随机页的照片读取文件创建时间。Windows 可按项目现有做法使用 `st_birthtime_ns`，必要时在 Windows 平台回退 `st_ctime_ns`。
- 不得把 POSIX 的 `st_ctime_ns`、文件修改时间、`EXIF_ROOT`、`FILE_MTIME` 或 `assets.created_at` 当作创建时间；确实没有创建时间就显示未知。
- 每次只处理当前最多 50 张摘要，不增加逐图 HTTP 详情请求，不扫描全图库。优先使用一条批量查询读取本页拍摄时间；仅对没有拍摄时间的照片读取文件系统元数据。不要为了提前优化而新建通用框架或大范围改造路径解析。
- API 只返回显示所需的时间和来源标签，不返回绝对路径、原始 EXIF 文本或其它文件隐私信息。
- 同一照片有多个位置时，沿用现有受控解析顺序，使用第一个可安全访问且能提供创建时间的位置；无法取得则显示未知。

## 明确不做

- 不新增数据库 migration，不改 `assets.created_at`、`asset_metadata` 或 P4-00B 时间契约。
- 不重新扫描照片、不重提取 EXIF、不重建图库、不打开或解码原图；文件创建时间只需读取文件系统元数据。
- 不改普通列表、时间轴、搜索、地图、地点、人物、合集等页面。
- 不改随机抽样、分页、换批、近期避重、收藏、查看器和返回恢复逻辑。
- 不构建或发布 Windows 安装包，不访问真实照片或真实 `PhotoSearchData`。
- 如果发现必须新增 schema 或全库回填才能实现，先停止说明，不擅自扩大范围。

## 开工性能与验证选择

- **链路与风险**：随机摘要页增加时间读取；逐图查询或遍历整库会增加首屏工作。
- **做法与边界**：沿用本卡每页 50 张预算，按主键一次批量读取可信拍摄时间，仅缺失者依既有受控位置顺序读取文件元数据；不解码照片。
- **验证与停止**：运行随机浏览及 UI 定向测试、一次隔离浏览器检查；检查页内工作量和顺序。无需全仓回归或新增 30 万容量结论；若必须改 schema 或回填则停止。
- **影响面及全量触发**：随机摘要 API 与随机卡片；未涉及依赖、迁移、全局协议或广泛合流，不触发全量回归。完整变更面需独立只读复核。
