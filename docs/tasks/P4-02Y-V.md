# P4-02Y-V — `top_k` 性能测试

**状态：READY**

性质：**纯测量 / 决策卡。产品代码零改动。**

目标只回答：

> 当前 30 万图库下，`top_k = 200 / 500 / 1000 / 2000 / 3000 / 5000` 分别需要多少搜索时间，性能从哪里开始明显下降？

执行：**DS-L / DeepSeek V4.1 Flash / 低～中推理**；**GPT-5.6 Luna 亦可**。  
本卡无需 DS-H / Sol；若出现正确性异常或必须修改产品代码，停止并另行分析。

## 1. 固定条件

复用现有 30 万稳定夹具和当前检索实现：

- `SCOPE_BLOCK_SIZE = 15000`
- 同一 query / query vector
- 同一 generation / index
- 暖缓存、无后台任务
- deterministic encoder

只改变：

```text
top_k = 200, 500, 1000, 2000, 3000, 5000
```

优先复用 `tools/diagnostics/p4_02f_stage0.py`，不要另建大型测试工具。

## 2. `top_k > 1000` 的实验边界

当前产品 `MAX_TOP_K = 1000`，因此：

- 200 / 500 / 1000：当前产品合法范围；
- 2000 / 3000 / 5000：仅用于诊断性能。

不得修改 `src/**` 或正式 `MAX_TOP_K`。允许诊断工具在**当前进程内**临时放宽限制到 5000，使六档继续走同一现行检索链；输出必须标记为实验测试，不得宣称 2000～5000 已通过产品 API 契约。

## 3. 测试方式

两轮交错：

```text
Round 1:
200 → 1000 → 3000 → 500 → 2000 → 5000

Round 2:
5000 → 2000 → 500 → 3000 → 1000 → 200
```

每档每轮：

```text
1 次 warmup（不计）
5 次正式样本
```

每个 K 共 10 个正式样本，总计 60 次正式搜索。

本卡只看趋势和拐点，**不宣称正式 P95 验收**。


不要求不同 K 的最终 RRF 融合页完全一致。

## 6. 最终只回答三个问题

报告结论只回答：

1. `top_k` 从 200 增大到 500 / 1000 的性能成本；
2. 2000 / 3000 / 5000 从哪里开始出现明显性能拐点；
3. 当前 `MAX_TOP_K=1000` 从**纯性能角度**是否明显偏保守。

不要在本卡修改默认值或上限。
