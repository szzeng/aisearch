# P3-06 — 人物页、同名提示、待归类、脸框、最近操作和撤销 UI

本卡只交付人物整理的本地网页闭环：让用户能够看到人物与待手动归类脸、保存名字并明确处理同名、
选择单脸/多脸执行指定、取消、恢复自动和拆分，并从最近操作中执行补偿撤销。不得改变 P3-03～P3-05C
已经冻结的人物、单脸控制、拆分、幂等或撤销语义。

执行模型：**DS-L（DeepSeek V4.1 Flash / low）**。模型切换由用户在 Codex 中手动完成；不得自动切换或
声称已切换。若只读 API 必须改变 ADR-0006/0007/0008 语义，停止并转 **C2 / GPT-5.6 Sol / high**；
Windows/PyInstaller/浏览器运行环境疑难转 **C1 / GPT-5.6 Terra / medium**；复杂跨事务状态机实现转 DS-H。

## 必须交付

### 1. 人物只读列表

新增 `GET /api/v1/persons`，只返回 active canonical person，使用稳定 keyset cursor，支持有界 `limit` 与
至少 `kind=all|named|unnamed`。每项仅返回页面需要的安全字段：`person_id`、可空 display name、revision、
可空 avatar face id、去重 `face_count`/`asset_count`。排序和 cursor 绑定字段必须确定，redirect 人物不重复列出。

不得返回 `name_key`、alias 原文列表、内部快照、路径、bbox、landmark、向量、相似度或 confidence。

### 2. 脸列表与安全裁剪

新增 `GET /api/v1/faces`，用稳定 keyset cursor 支持两类互斥视图：

- `person_id=<id>`：解析到 canonical person 后列出当前有效成员；
- `assignment_state=manual_unassigned`：只列 `MANUAL_UNASSIGNED`，用于“待手动归类”。

每项只返回页面需要的 `face_id`、`asset_id`、control mode/revision、有效 person id、assignment revision、
是否有建议和一个受控脸图 URL。不要返回人脸几何、landmark、embedding、候选分数或原始路径。

提供受会话保护的 `GET /api/v1/faces/{face_id}/thumbnail`：服务端使用权威 face 几何从既有安全预览生成
有界裁剪图，复用现有解码/方向/像素与缓存安全边界；客户端不能提交路径或 bbox。源离线、坏媒体和不存在
必须返回稳定错误/占位状态，不能泄露路径。若现有媒体层无法在不改变协议或持久化语义的情况下安全复用，
停止并转 C2，而不是暴露 bbox 给浏览器。

### 3. 最近人物操作列表

新增 `GET /api/v1/person-operations`，用稳定 keyset cursor 返回最近 committed/undone 人物操作摘要，至少包含
operation id/type/revision/status/undo target/changed/created time，以及安全的受影响数量或 ID；不得回显
request payload/hash、name/name_key/alias、before/after snapshot、face geometry 或内部错误。

列表只提供已有共享 undo 所需的 operation id/revision；能否撤销仍由服务器冻结冲突矩阵决定，前端不得本地
猜测成功。读取 API 均必须闭合 OpenAPI schema，拒绝未知查询组合，并遵守现有 session/Host/Origin 边界。

### 4. `/persons` 页面

在既有 dependency-free 静态前端中增加人物页及导航入口，至少完成：

- named、unnamed、manual-unassigned 三个明确视图，空态/加载/失败/分页状态清楚；
- 人物卡显示安全头像裁剪与去重计数；脸框选择精确到 `face_id`，不能把同图 sibling 自动带入；
- 保存名字前显示同名提示；服务器返回 merge 时明确展示 canonical 结果，不在前端复制一套 name_key 规则；
- 显式批量合并选择；单脸/多脸 assign、unassign、restore_auto；从一个人物选 1..500 脸拆分；
- 所有写请求生成 request_id 并携带当前 revision；冲突时刷新相关人物/脸/操作，不静默覆盖；
- 最近操作展示状态并调用共享 undo；undo 冲突展示服务器 code/reason，不把失败显示为成功；
- 所有用户可见文本、DOM、日志和 URL 不出现本地路径、内部快照、bbox/landmark、向量或相似度。

使用现有 HTML/CSS/JavaScript 风格，不新增前端框架、构建链或 CDN；键盘可达、焦点可见、表单有 label，
在窄窗口可用。若图像加载失败，显示占位而不是暴露原路径。

### 5. 状态与能力

只有上述只读 API 与页面真实可用时才暴露人物页面入口/能力；缺模型不应阻止已有人物数据的浏览和人工
整理。UI 不直接等待模型加载，不写模型文件，不触碰真实照片库。

## 禁止修改

- ADR-0001～0008、既有 companion、`0001`～`0013`、人物写接口的请求/响应/错误闭集；
- `pyproject.toml`、`uv.lock`、`PhotoSearch.spec`（除非确有打包资源缺失且报告说明）；
- face_id 生成、检测/质量阈值、embedding/space/generation、候选与自动关联规则；
- P1/P2/OCR/place/search/profile/feedback 语义；云服务、外部 CDN、第二套前端框架；
- 真实私人照片或真实照片库。只用 `%TEMP%` 下的合成/公共领域夹具。

## 必须保持的不变量

- SQLite 仍是人物/控制/操作唯一权威事实源；列表与页面不能创建第二份状态。
- `face_id` 是最小人工单位；siblings 不联动。
- MANUAL_ASSIGNED/MANUAL_UNASSIGNED、exclusion、每脸至多一个 CONFIRMED、redirect/canonical 规则不变。
- 同名是否合并、revision、request_id 幂等、split 与 undo 冲突全部由服务器决定。
- 人工操作只触发既有 PERSON_CHANGED/face repair 边界，不写图片向量，不改变 embedding/space/generation。
- 只读与错误响应遵守隐私闭集；页面永不获得路径、bbox、landmark、向量、score 或内部快照。

必需自动验证（项目内 `.uv-cache`、`.pytest-tmp`，JUnit XML；成功仅保留 quiet 摘要）：


等级：**B + C + 真实浏览器闭环**，并对写操作执行相关 D 级拒绝/回滚回归。

至少验证：

1. persons/faces/operations 三个 keyset 列表的排序、分页无重无漏、canonical/redirect、非法 cursor/查询组合；
2. face thumbnail 的正常、源离线、坏媒体、不存在、超限、安全响应头、无路径泄露与同图 sibling 隔离；
3. OpenAPI request/response `additionalProperties: false` 与隐私负向字段；
4. 页面从 named/unnamed/manual-unassigned 到 rename/同名 merge、显式 merge、assign/unassign/restore_auto、
   split、最近操作 undo 的端到端数据刷新；
5. stale revision、request_id replay/冲突、undo conflict、401/Host/Origin/CSRF、服务重启后的页面恢复；
6. 真实浏览器手工 smoke：窄/宽窗口、键盘、错误态、空态、分页、脸图失败占位；记录步骤和结果，
   不把手工 smoke 称为自动 DOM 覆盖；
7. 真实 `pyinstaller --noconfirm PhotoSearch.spec` onedir 重建，在全新 D 盘中文/空格目录运行 packaged smoke，
   验证 `/persons` 静态资源、四个新只读面、既有写/undo 路径、schema 13、bundle `0001`～`0013` 连续且
   0013 与源码 hash 一致。

任何必需验证未完成时不得标 PASS；写 `VALIDATION PENDING` 或 `FAIL` 并列出缺口。不得因缺少模型权重
下载大模型；页面可用性应由合成/迁移夹具验证，真实模型链路沿用已记录边界。
