# P4-00A — 拍摄时间/时区/回退来源/新 order 契约

本卡冻结「拍摄时间」进入产品所需的唯一契约：源事实与列、（时区与排序键）、回退来源与「文件时间」规则、
新的拍摄时间 order/游标，以及时间范围条件与既有 AND 集合、单一 revision、会话摘要的关系。

这是一个**只写契约**的任务（A 级）：**阶段 A** 由独立 DS-H 会话草拟 ADR、机器可读 companion 与契约测试并
做工程预审；**阶段 B** 必须由独立 **C2 / GPT-5.6 Sol / high** 会话聚焦终审并冻结。V3.1 §9 的 P4-00A 行明确
要求 Sol 最终冻结，属 §2.3 的「Sol 必选门禁」，不可跳过；两阶段必须分别在两个**新会话**中完成。

推荐执行模型：**阶段 A — DS-H / DeepSeek V4.1 Flash / 高推理**；**阶段 B — C2 / GPT-5.6 Sol / high**。
模型切换始终由用户在 Codex 中手动完成；不得声称自动切换，也不得在同一会话中途换档。命中 V3.1 §2.2 六类
具名条件时才建议升 DS-MAX，且必须写明命中编号、已有证据与待回答问题。

## 契约必须冻结的内容

1. **列与表形态**：`asset_metadata`（或经证据支持的等价表）的 `taken_at_raw`、`taken_at_sort`、
   `time_source`、`time_confidence`、`timezone_offset`、`camera` 的稳定列名、类型、可空性、单位与时基、
   闭集 CHECK，以及与 `assets`/`file_locations` 的权威边界（不得与 §4.5 的 GPS 事实形成双权威）。
2. **时区与排序键**：本地墙上时间与 `taken_at_sort` 的关系；缺失/非法 `timezone_offset` 时的确定行为；
   夏令时与歧义本地时间的处理；不得把无偏移的本地时间当成 UTC；排序键必须可比较且与展示值一致。
3. **回退来源与「文件时间」**：`time_source` 的**闭集**与优先级顺序（EXIF 拍摄时间族 → 次选 EXIF → 文件
   时间等，具体成员由证据确定）、`time_confidence` 口径、来源不可靠时界面必须显示「文件时间」而不得伪装成
   拍摄时间、缺字段/坏值/时区矛盾时的确定性回退；**禁止**用扫描时间或「现在」兜底。
4. **新 order**：新增独立 order 值（例如 `capture_desc`）及其**独立游标空间**（前缀/arity，既不解释也不被
   既有 `asset_id`/`time_desc` 游标解释）；排序键与 tie-break；缺失拍摄时间的资产在新 order 中的确定位置；
   分页稳定性（不重复、不跳行）；**既有 `time_desc`＝加入时间的语义与游标必须逐字不变**。
5. **时间范围条件**：左闭右开区间；进入哪个信封（`GET /api/v1/assets` 查询参数与/或 `POST /api/v1/search`
   的新可选字段）与字段名；按 ADR-0009 §3.5 的要求进入同一个 AND 集合、同一个 `catalog_filter_revision`
   绑定与同一个 `query_hash`，不新增第二套 revision；时间来源不可靠的行是否参与时间过滤必须显式规定。
6. **失效与投影**：时间事实变化是否新增 cause、是否影响 `search_documents`（若影响，必须写明 P4-00B 需要的
   migration 与重投影路径）；不得给既有错误码新增 details 键；会话/游标失效只复用既有码。
7. **隐私闭集**：公开面允许出现的时间字段形态（例如是否只给排序用时间与 `time_source` 枚举，是否公开
   `camera`）；不得暴露绝对路径、GPS、原始 EXIF 全量、设备序列号等 P3 §7.2 同类禁止项。
8. **迁移与兼容契约（为 P4-00B 提供可实现性证明）**：新 migration 编号（按实际下一个空号，当前应为
   `0015`）、`SUPPORTED_SCHEMA_VERSION` 递增、旧库升级与失败回滚路径、`0001`～`0014` 逐字节不变的承诺、
   只读兼容检查、以及未提取拍摄时间的旧库在 API/UI 上的逐字不变行为。本卡**不实现**迁移。
9. **P4-00B 的验收前提清单**：把 D 级（迁移/回退/故障注入）、必要时 C 级（是否改打包资源）、以及记录式
   浏览器步骤写成可直接执行的清单。

判定表、闭集、字段默认值、边界（等于区间端点、空值、极值时间戳）必须逐条写进 ADR，并在 companion 中以
`additionalProperties: false` 的公共 object 与逐值 `oneOf`/`enum` 表达。

## 契约测试与必测反例（A 级）

`tests/unit/test_p4_time_contracts.py` 至少固定：

1. companion 是合法 JSON、SHA-256 与 ADR 记录一致、每个公共 object 都 `additionalProperties: false`；
2. `time_source` 闭集逐值接受、未知值拒绝；`time_confidence` 形状（含空值与非法值）逐条拒绝；
3. `timezone_offset` 的合法范围/缺省/非法值判定，含「无偏移本地时间不得当 UTC」的负例；
4. 新 order 值闭集：未知 order 值拒绝、既有两个 order 值仍被接受；
5. 三个游标空间互不解释：任一 order 的游标被另一个 order 使用时被拒绝（用真实编解码函数或契约层断言）；
6. 时间范围左闭右开：区间两端相等、等于左端、等于右端、跨天/跨时区的正反例；
7. 回退优先级：每个来源成员的正例与「跳过坏值继续回退」的反例，禁止扫描时间/当前时间兜底；
8. 时间条件进入同一个 AND 集合与同一个 `query_hash`/`catalog_filter_revision` 的契约断言（与 ADR-0009
   §3.5/§6 一致），并断言未新增第二套 revision 或错误码 details 键；
9. `time_desc`＝加入时间的既有语义与既有游标空间未变（对既有 frozen companion/常量的只读断言）；
10. 隐私闭集：ADR/companion 中没有路径、坐标、设备序列号等禁止字段示例。

环境无第三方 JSON Schema validator 时，测试对 companion 实际使用的关键字子集执行正反例，并**不得**因此
声称已做完整 JSON Schema 校验。
