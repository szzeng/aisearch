## 用户场景

用户在本机页面上输入一句中文/英文关键词并（可选）选定地点、来源、可用性条件，得到一页结果；
继续翻页时结果必须来自**同一个查询、同一个 profile、同一个 catalog 版本**。期间若用户整理地点、
切换搜索配置或应用重启，继续翻页必须得到一个**可识别的过期状态**并提示重搜，而不是悄悄换一套
排序或混入两个版本的结果。

## 冻结实现范围

### 1. `SearchRequest` / `SearchResult` 协议（新增 `src/photo_search/search/contracts.py`）

- 两个不可变信封，`contract_version = "p2-contracts.v1"`，**拒绝未知字段**（与 P2-01 的
  `JobRequest`/`JobResult` 同风格），时间为 UTC epoch 毫秒，ID 为非空字符串。
- `SearchRequest` 至少包含：`contract_version`、`request_id`、`text`（可空 = 纯筛选查询）、
  `profile_id`（可空）、显式绑定 `space_id`/`image_generation_id`/`dimension`（仅在未给
  `profile_id` 时允许/必需，规则见 §3）、`source_id`、`availability`、`place_ids`、
  `include_descendants`、`place_state`、`top_k`、`page_size`、`search_session_id`（可空）、
  `cursor`（可空）。
- `SearchResult` 至少包含：`contract_version`、`request_id`、`search_session_id`、
  `profile_id`、`image_generation_id`、`space_id`、`dimension`、`catalog_filter_revision`、
  `suggestion_revision`、`fusion_config`、`query`（回显文本/词项/MATCH 表达式）、`filters`、
  `hits`（本页，逐行含 `asset_id`/`rank`/`score`/`matched_by`/`hit_reason`/`matched_text`）、
  `page_size`、`next_cursor`、`has_more`、`total_candidates`、`channels`（两通道的候选数与
  是否被截断）、`pending_semantic`（滞后摘要，不得泄漏坐标/路径）、`search_projection`、`state`。
- 协议对象只做**形状**校验：不解析自然语言（年份/人物别名/显式筛选语法属后续卡），不把 `text`
  拆成条件；`text` 原样交给 P2-04 的 `build_match`。

### 2. 搜索会话与游标（新增 `src/photo_search/search/sessions.py`）

- 一次搜索最多缓存 `MAX_SESSION_IDS = 1000` 个**有序** `asset_id`（architecture §9.5），
  `SESSION_TTL_MS = 600_000`（默认 10 分钟），会话数有上界（常量写进报告），LRU 淘汰过期/最旧会话。
- 会话绑定：查询哈希、`profile_id`、`image_generation_id`、`space_id`、`dimension`、
  `catalog_filter_revision`、`suggestion_revision`、创建时间。
- `cursor` 是**不透明**令牌（建议 base64；形如 `s1:<session>:<offset>`），并且必须与会话绑定：
  别的会话、别的查询、别的位置组合的 cursor 一律 `INVALID_CURSOR`，绝不被重新解释。
- 存储是**进程内**的：应用重启后会话不存在，必须返回可识别的过期状态（不是空结果、不是新排序）。
  多线程访问需加锁（API 可能在工作线程里继续翻页）。
- 每页返回前，仍按当前 SQLite 权威条件复核该页 `asset_id`（可见性/地点/来源/可用性）；被排除的行
  直接不出现在页里，但不得因此把后续 id 顺序改变或跳页。

### 3. `profile_id` / `image_generation_id` / `catalog_filter_revision` 绑定

- 新增 migration `catalog/migrations/0007_search_profiles.sql`（连续编号，**不改** `0001`～`0006`），
  `SUPPORTED_SCHEMA_VERSION` 推进到 **7**：
  - `search_profiles`：字段与冻结 `$defs/SearchProfile` 逐项一致（`profile_id` 主键、
    `embedding_processor_id`、`space_id`、`image_generation_id`、`query_preprocess_version`、
    `query_parser_version`、`fts_tokenizer_version`、`fts_generation_id`、
    `reranker_processor_id` 可空、`fusion_config_json`（`json_valid` + 形状 CHECK）、
    `runtime_package_id`、`created_at`）。**创建后不可变**：内容列的任何 `UPDATE` 都要被触发器
    拒绝（新配置必须发布新 `profile_id`）。
  - `active_search_profile`：单行（`state_id = 1`）保存可空 `profile_id`（未激活时为 NULL）
    与 `updated_at`；`profile_id` 用 `ON DELETE RESTRICT` 外键，禁止物理删除被引用的 profile。
  - **执行时先检查**：伴生 schema 的 `fts_tokenizer_version` 是字符串，而 P2-04 的
    `search_documents.tokenizer_version` 是整数；DDL 按冻结 schema 存字符串，映射规则必须写进报告，
    不得改冻结 schema（要改就先报 C2）。
- 激活（新增服务入口 + `POST /api/v1/search-profile/activate`）在**一个** SQLite 事务内核对
  profile、其 embedding processor 的运行能力/设备资格（复用 P2-02 已记录的事实）与所有引用的
  generation 均为 READY，再同时维护 `index_generations.is_active` 与活动指针：不允许「分别切换
  模型和向量表」出现编码器/索引错配的可见状态，也不允许物理删除或改写 `state`。
- 未激活（`active_search_profile.profile_id IS NULL`）时，请求**必须**自带显式绑定
  `space_id`/`image_generation_id`/`dimension`（P2-05 的路径），否则结构化拒绝；一旦给了
  `profile_id`，请求中的显式绑定必须与该 profile 一致（不一致 → `PROFILE_GENERATION_MISMATCH`）。
- 会话与游标绑定 profile/generation/`catalog_filter_revision`（`place_state=suggested` 时额外绑定
  `suggestion_revision`）：继续翻页时任一不同 → 对应的结构化过期码（见 §5），保留查询让客户端重搜。
- 每次请求开始时固定一个 profile，查询向量、候选缓存与会话都不得中途换 profile；激活后的**新**
  请求才使用新配置（architecture §9.5/§11.3.5）。

### 4. API（`POST /api/v1/search` 等）

- 新增 `POST /api/v1/search`：正文为 `SearchRequest`，响应为 `SearchResult`；首屏返回
  `search_session_id` + `next_cursor`，续页请求带 `search_session_id` + `cursor`（其余字段必须
  与首屏一致，否则 `INVALID_CURSOR`）。
- 新增 `GET /api/v1/search-profile`（当前活动 profile 的只读投影，未激活时 `profile_id = null`）
  与 `POST /api/v1/search-profile/activate`（幂等：同一 `profile_id` 重复激活返回同一结果）。
- 全部走既有 session/Host/Origin/CSRF 边界；无 session → 401；参数/协议错误 → 422；过期/冲突 →
  409；不得出现本机路径、坐标或 `request_id` 之外的内部标识。
- `GET /api/v1/capabilities` 的 `search` 块可加性补充：活动 `profile_id`、`image_generation_id`、
  `fts_generation_id` 与 `pending_projection` 摘要（复用 P2-05 的
  `scheduler.projection.pending_projection_summary`，只读、无路径、无 asset id）。

## 必须保持的不变量

1. `0001`～`0006` 与冻结 ADR/JSON schema 逐字节不变；migration 连续到 `0007`；
   `schema_version = 7` 且既有无 `0007` 对象行为不变。
2. 权威判定仍只在 SQLite：搜索返回的每一行都必须满足当前地点/来源/可用性条件；投影/向量只能是
   加速，不得成为权威；「全库 Top-K 后过滤」仍然禁止。
3. `catalog_filter_revision` 只在产生权威变化的同一事务 +1；搜索/翻页**不写** revision，
   也不写 `assets.created_at`、不重算向量、不改 `space_id`。
4. 会话/游标绑定 `profile_id` + generation + `catalog_filter_revision`；跨版本继续翻页必须报过期，
   不得返回混合版本页。
5. 未激活 profile 时显式绑定路径与 P2-05 行为完全一致（既有 P2-05 测试原样通过）。
6. 隐私：响应与错误里没有绝对路径、坐标；引擎错误只带异常类型名。

## 验收（B + C + D）

必需命令（沙箱内 `uv` 缓存/pytest basetemp 会被拒绝时在沙箱外执行，并在报告里记录）：

```text
uv run --no-sync pytest -q -p no:cacheprovider tests/unit tests/integration
uv run --no-sync ruff check .
git diff --check
uv run --no-sync uv lock --check
uv run --no-sync python tools/packaging/build_onedir.py          # C 级：本次改了 API 导入图
uv run --no-sync python tools/diagnostics/packaged_api_smoke.py --bundle dist/PhotoSearch --work-dir <D 盘目录>
```

**C 级证据（必须）**：bundle 内新增模块（`photo_search.search.contracts`/`sessions`）与
`0007_search_profiles.sql` 都在包内；`packaged_api_smoke.py` 新增检查至少覆盖
「未激活 profile 时显式绑定的 `POST /api/v1/search` → 200 且 `state=OK`」「带 `cursor` 续页
→ 同一 `search_session_id`、无重复 id」「`GET /api/v1/search-profile` → 200，
`profile_id = null`」「无 session → 401」；smoke 结束后删除本次创建的 bundle 工作目录，
并在报告里写明 C 盘余量/清理结果。

**D 级故障注入（必须，逐项记录实测）**：

1. v6→v7 迁移：备份先生成（备份内 `schema_version=6` 且无 3 张新表）、单事务推进、旧行逐列
   不变；注入损坏 `0007` → `MIGRATION_FAILED` 且版本仍 6、无半成品对象；缺件 →
   `SCHEMA_INCONSISTENT`；过新库 → `SCHEMA_TOO_NEW` 且零写。
2. 激活中断：在激活事务中途注入异常 → 活动指针与 `index_generations.is_active` 全部回滚，
   旧 profile 仍可查询；被引用的 generation 不是 READY 或 runtime 不健康 → 结构化拒绝且零写。
3. 切换后旧会话：激活新 profile 后，用旧会话继续翻页 → `CATALOG_FILTER_REVISION_STALE` 或
   `PROFILE_GENERATION_MISMATCH`（按实现并写进报告），不得返回混合版本页；新查询使用新绑定。
4. 会话过期/重启：超过 TTL 或新建进程后带旧 `search_session_id` 续页 → `SEARCH_SESSION_EXPIRED`；
   过期后重搜得到完整第一页。
5. 翻页期间人工改动：翻页前改变地点归属（revision +1）→ 续页报过期；重搜能补回新命中。
6. 游标隔离：另一个会话/另一个查询/另一个位置组合的 cursor → `INVALID_CURSOR`；被篡改的
   base64 → `INVALID_CURSOR`（不是 500）。
7. `page_size` 上界、`page_size=0`、`top_k` 越界、未知字段、缺 `profile_id` 且缺显式绑定、
   `text` 不可用（P2-04 的 422）逐项断言。

**会话/游标对照**：同一查询两次请求（不翻页）结果逐项一致；首屏 + 逐页遍历 ≤1000 个 id 时
无重复、无遗漏、顺序与首屏 `hits` 一致；`has_more`/`next_cursor` 语义与 P1-04/P1-05 的
`GET /assets` 分页一致（`page_size` 达到上界时 `has_more=true`）。
