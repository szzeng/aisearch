用户希望：人物批量管理或逐脸整理时按 Esc 退出；照片预览弹窗可按 Esc 或点击弹窗外的遮罩关闭，且内部点击不误关。

- [P4-PERSON-SELECT-RANGE-A](P4-PERSON-SELECT-RANGE-A.md) 已实现 Shift 连选、多页选择与清空操作。本卡只补退出快捷键，不改选择算法或 500 项上限。

## 2. 修改要求

### A. 批量管理支持 Esc

范围：
1. 已命名/未命名人物列表，以及“整理一下”的待整理/已忽略人脸：Esc 调用已有退出批量模式语义。
2. 人物相册“整理照片”：Esc 等效“完成整理”。
3. 退出只清空本次临时选择、选择锚点和相关 snapshot / UI 标记；**不撤销已提交操作**，不产生业务写请求、不刷新/重建已加载列表、不折叠分页、不改变滚动位置。
4. **“清空选择”仅取消勾选、不退出模式**；“退出批量管理/完成整理”才退出。现有 `pa-batch-cancel` 文案改为与行为一致，并避免和 `pa-batch-toggle` 形成两个重复“退出批量管理”按钮：优先复用原切换按钮作为唯一明显退出入口，删减/隐藏冗余入口即可，不另造控制条。
5. 写入中、可见性写入中、结果未知待重试等已有保护仍有效；不能用 Esc 绕过 busy / pendingWrite / revision / 撤销边界。
6. 保留现有 Shift、分页选择、最多 500 项和人物合集成员的原选择逻辑。

### B. 照片预览弹窗的关闭行为

检查入口：
- 搜索结果 `search-preview`
- 人物/人物合集 `pa-preview`
- 共享 `AIPhotoInfo.open()`
- 地点相册共享查看器及旧式降级预览

原则：
1. Esc 或点击弹窗真正的**外部遮罩**关闭；关闭按钮不变。
2. 点击图片、弹窗内部空白、信息面板、人物头像和上一张/下一张等控件**不能误关**；拖动/选择内容也不能因释放在遮罩上误关。
3. 沿用既有 `close` 清理：预览 mount、关联请求版本、图片状态和需要恢复的焦点；保留搜索结果、已加载列表、原滚动位置。
4. 现有 `event.target === dialog` 若真实浏览器中误判弹窗内部空白区域，应在必要入口补充点击坐标与弹窗边界判断；不要全站替换已正常的实现，也不引入第三方依赖。
5. 编辑人名、指定人物、合并确认等**可能含未保存操作的弹窗**，不扩大“点击遮罩自动关闭”；保留原 Esc/cancel/保存防护。

### C. Esc 优先级

每次按 Esc 只关最上层一层：
- 有原生模态 `<dialog>` 打开：先遵循其 `cancel`/原生 Esc；**不同时退出底层批量管理**。
- 无弹窗时才允许 Esc 退出批量管理或“整理照片”。
- 普通浏览、搜索输入候选或其他控件自身已消费 Esc 时，不额外执行；避免重复监听、重复关闭或 Esc 长按重复动作。
- 示例：批量管理中打开照片，第一次 Esc 关照片，第二次 Esc 才退出管理。若内层编辑被写入保护拦截，外层保持原样。

## 4. 最小测试与验收

只需四项定向合成 UI 验证：
1. 人物批量管理选几人后 Esc：退出，选择清空，已加载卡片/分页及滚动状态不重置；“清空选择”不退出。
2. 人物相册选择几张脸后 Esc：相当于“完成整理”，已保存动作不回滚。
3. 搜索、人物/合集、地点、共享照片查看：模拟遮罩点击或 Esc 能关闭；模拟内部点击不关闭；正常 `close` 清理继续执行。
4. 先打开批量管理，再打开照片弹窗：第一次 Esc 只关闭照片，第二次退出管理；忙时与编辑弹窗保护不被绕过。

优先复用 `tests/unit/test_photo_view_info_ui.py`、`test_search_person_album_link_ui.py` 及现有人物 DOM 小测试；只对新增行为补少量断言，按仓库约定输出 `test-results/P4-UI-DIALOG-ESC-A.xml` JUnit。对改过的 JS 运行 `node --check`，执行 `git diff --check`；修改 Python 测试则只检查该文件 Ruff/编译。**不跑全仓 pytest、不要求 Playwright/完整真实浏览器自动化、GPU、真图库或 30 万性能测试**。旧遮罩测试只验证事件目标，真实浏览器效果未覆盖时标为待用户手工检查，不能写“已实测”。
