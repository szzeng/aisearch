## 任务定位

P1 交付了可靠图库基础：内容身份、位置、来源映射、扫描、媒体产物、受控本地 API 与前端。
P2 要做中文搜图、以图搜图和可恢复索引，而**这些能力的协议边界必须先冻结**，否则实现期会出现
「隐式设备回退」「同维不同 space 混用」「profile 半切换」「迟到结果覆盖新结果」这类难以回滚的错误。

V3.1 §11 明确规定：`ProcessorSpec.device_policy`、requested/resolved device、RuntimeCapabilities、
禁止隐式 fallback 的设备资格契约，以及同维不同 embedding space 的隔离，**必须先由 C2 明确不变量或
独立审查**。本卡就是这一步：把 P2 的最小稳定协议写成可执行、可校验、无 `{placeholder}` 的契约，
让 DS-H 之后按冻结协议实现，不再自行决定语义。

本任务**不做**：调度器/worker/lease 实现（P2-02）、产物提交与 outbox / LanceDB 写入（P2-03）、
FTS（P2-04）、召回融合（P2-05）、搜索会话与 API（P2-06）、搜索页（P2-07）、恢复与竞争验收（P2-08）。
也**不做**：任何 `taken_at`/EXIF 拍摄时间列、人物/OCR 能力、模型下载或真实推理。
也不实施地点表、GPS 解码、地名包下载／解析和地点界面。下一任务是地点详细契约 P2-01A，
其后才进入调度实现 P2-02，不在本卡中扩成整个地点模块。

## 用户场景

- 用户装的是 GTX 1660 6 GB。系统在**没有可用 GPU** 时必须把需要 GPU 的任务显式 `BLOCKED`（带原因），
  而不是偷偷用 CPU 跑一遍给出效果不同的结果。
- 用户手动指定 CPU 跑一次编码。系统必须只对这一次使用 CPU，并且运行记录里能查到
  `requested_device=cpu` / `resolved_device=cpu` / `runtime_provider=cpu`，不会污染其它任务或索引。
- 用户升级了模型或运行时包。旧 profile 仍在服务；新 profile 只有构建、校验、健康检查全部通过，
  才能在一次原子切换后生效；不存在「新模型 + 旧向量表」的错配窗口。
- 用户查询中文。查询编码必须使用与索引用同一个 `space_id` 的编码器；若两者的 space 不同，
  请求必须被拒绝而不是给出无意义的相似度。
- 运维排查一次「模型缺失」。系统必须能回答：这个 processor 的权重 revision/SHA-256、
  预处理版本、维度、度量、backend、device/precision、批量上限、取消与 CPU/GPU 能力分别是什么。

   存在 CPU provider **不得**触发隐式 fallback；显式请求 GPU 失败不得静默换 CPU；
   `CPU_PREFERRED` 默认 CPU 且只有该 processor 通过专项 GPU 验收才可选 GPU；

   设备不进入逻辑任务唯一键，**除非**输出语义空间因此改变（此时必须产生新的 `processor_id`/`space_id`）。
4. **RuntimeCapabilities**：provider 清单、可用 device、precision、运行时包与驱动版本、
   健康检查语义、能力失效如何让任务阻塞与恢复，以及「能力声明必须有实测依据」。
5. **EmbeddingAdapter / RerankerAdapter**：`spec()/load()/encode_queries()/encode_images()/health()/close()`

   业务层禁止顶层 import 重型框架（架构 §11.3.4）。
6. **SearchProfile**：不可变 profile 字段（含 `embedding_processor_id`/`space_id`/索引世代/
   预处理与分词版本/`fusion_config`/`runtime_package_id`）、单行 `active_search_profile` 的**原子**切换、
   查询向量/候选缓存/分页会话绑定 `profile_id`、`index_generations` 与 profile 引用不得分别切换形成错配、
   人物与人工知识与 profile 回退解耦（架构 §11.3.5、§11.3.6）。
7. **space 隔离**：`space_id` 由影响表示空间的不可变配置确定（不由模型昵称或维度单独确定）；
   同维不同 `space_id` 的写入/查询/缓存混用必须被拒绝；向量空间版本与设备/运行库兼容性必须由验证证明。
8. **与冻结基线的边界**：明确 `schema_version = 1` 现状、本卡不改 ADR-0002 语义、
   后续实现卡需要新增表/加列/迁移时必须先有 ADR-0003 依据并由 C2 复核。
9. **无模型处理器与非向量结果**：ProcessorSpec 用明确类型分支区分模型与普通 CPU 处理器；
   版本化 processor_id/task_type/config_hash 对所有分支必需，模型权重、dimension/metric/space_id
   仅适用于对应模型／向量分支，不给 GPS 或地名解析伪造它们。JobResult 支持结构化非向量 artifact

10. **权威筛选变化**：CatalogFilterRevision 为单调可变目录版本，独立于 profile 和向量 space；

    地点改名／有效归类变更不能只过滤旧结果而漏掉新命中；机器候选更新不等于有效归属改变。

## 正常行为 / 异常行为 / 边界情况（契约必须逐条回答）

**正常行为**

- CPU 任务在 CPU provider 上运行，运行记录保留 `requested_device/resolved_device/runtime_provider`。
- 已通过专项 GPU 验收的 processor 在 `CPU_PREFERRED` 下可选择 GPU；未通过验收的只能 CPU。
- 一次查询固定一个 `profile_id`；查询编码与索引 `space_id` 一致时结果可用。
- GPU 不可用时 `GPU_REQUIRED` 任务进入 `BLOCKED`（不消耗普通重试次数），恢复后重新可调度。

**异常行为**

- CUDA 不可用或运行时不健康时，`GPU_REQUIRED` **不得**静默改用 CPU（必须 `BLOCKED`）。
- 显式请求 GPU 失败时不得静默换 CPU；必须显式失败或阻塞并记录原因。
- 同维不同 `space_id` 的编码/查询/缓存混用必须被拒绝（结构化错误码）。
- 迟到/过期执行结果（旧 `lease_token`、旧 revision、错误 processor/device 语义）不得写入任何持久结果。
- profile 半切换（新编码器 + 旧索引世代，或活动指针与引用关系不一致）必须不可能出现。

**边界情况**

- 同一 processor 同时声明 CPU 与 GPU 能力时的解析规则必须唯一且可测。
- `auto` 在没有可用 GPU 时的取值规则必须明确（不得靠实现者猜测）。
- `resolved_device` 与实际 provider 不一致时必须报错而不是记录成功。
- 取消发生在批次中间、模型加载失败、显存不足、运行时包版本不匹配时的分类必须明确。
- `space_id` 的组成必须能回答「换 device/precision 后是否还是同一空间」。
