## 1. 目标与成功边界

**目标**：让已完成的 UI 2.0 在“照片、人物、地点、搜索、地图、图库管理、照片查看”之间具有统一的、接近最终 demo 的个人相册观感；修正字体、颜色、层级、间距、卡片、控件、留白、窄屏及对话框的明显不一致，让用户日常操作直观、文字可读、控件不被遮挡。

**本卡不是**重新定义产品使用流程，也不是要求精确复制演示中的模拟照片、示例计数、按钮顺序或非真实业务动作。实际业务合同、可访问性及用户确认的功能优先于效果图。尤其不重新开发人物整理、地点归属、时间轴 SQL、搜索解析、范围恢复、查看器切换机制。

**最重要的验收规则**：拆分“代码与布局已检查”“内置浏览器实际看到”“截图是否真实落盘”“浏览器无法测量的项目”四种事实。即使内置浏览器不能切换系统主题、不能设置真实 200% 页面缩放、无法导出截图，仍应完成安全可实施的视觉修正并交付可复核的分项结果，但**不得把未验证项记为 PASS**。

## 3. 视觉施工范围：一套设计，七类常用画面

### A. 公共外壳与主题（优先级 P1）

负责：`src/photo_search/web/styles.css` 及受影响页面的 HTML 引用。

- 统一侧边导航、品牌、顶栏**唯一全局搜图框**、内容主区域、页面标题与副标题、面包屑/返回按钮、菜单选中、滚动条、分隔线和留白；必须保持管理入口、人物/地点导航及响应式收纳的既有可用性。
- 依现有 `--bg / --panel / --fg / --fg-muted / --line / --accent / --tint / --danger / --space-* / --radius-* / --shadow-soft` 语义变量修正有证据的硬编码差异，维护亮暗色一致的层级。保持系统字体、OS 字号偏好和默认根字号，**禁止为了匹配 demo 的 14px 而将根字号强制改为 14px**。
- 主要文字与操作保持可读：普通文字原则上对实际底色 **≥4.5:1**，大型文字/粗体 ≥3:1；禁用、占位等特殊状态有清楚区别；危险操作不能与普通链接/成功状态只靠颜色区分。保留 `:focus-visible`，不要复活先前整页大焦点框；也不要隐藏真实可键盘操作控件的焦点。
- 桌面没有无故空出一整屏的顶部空白；窄屏导航、页头搜索和主内容不相互覆盖。检查实际 `vh / dvh / grid / overflow` 层级，谨慎修改共享滚动容器。
- **明确合并缓存版本**：共享 CSS 或 viewer/timeline 等跨页资源更新后，核对 `index.html`、`persons.html`、`places.html`、`search.html`、`map.html` 中对应链接；避免浏览器缓存使“改了却看不到”。

负责：`web/styles.css` 内相关组件 + `web/photo-timeline.css`，有必要时极少量 `index.html`/`app.js` 显示接线。

- 时间轴日/月/年组头、拍摄/入库依据切换、日期未知/待就绪入口、来源切换、卡片间隙与网格密度，与 demo 保持同一视觉语法；不更改时间归类、API 或翻页。

- 图库管理常用操作突出、危险/低频操作次级显示；保留原有所有确实需要的管理能力及权限提示，不“为好看”移除按钮。

### C. 搜索结果（优先级 P1）

- 人物目录和人物相册的照片时间轴保持各自正确定位，不把目录变成年月照片时间轴。

### E. 地点相册与地图（优先级 P1）

负责：`web/places.css`、`web/map.css`，必要时少量页面 HTML。

- 地点目录卡、地点相册标题/父级地名/照片总数、人工更正与“搜索此地点”的视觉优先级一致；地点名和完整地区层级不要被不合理截断。
- 地图与照片侧栏比例清楚，地图加载失败/无瓦片时仍有可读的照片侧栏和状态提示；时间排序入口、卡片选中和滚动条与全站匹配。

- **离线瓦片不可用时，仅验地图容器、提示和现有列表布局**，地图真实渲染状态记 `MAP_TILES_PENDING`，不需要联网补瓦片。

### F. 照片查看器与通用弹窗（优先级 P1）

负责：`web/photo-info.css`、相关 `search.css` / `persons.css` / `places.css` 及既有查看器 DOM。

- 当前已经存在的照片详情页与弹窗按**各自原有入口和行为**修正视觉：大图主体优先、`object-fit: contain`、信息面板可折叠/滚动、照片标题/文件信息清晰、关闭按钮可见、遮罩与背景对比合理、竖图长图不裁切或溢出。
- 同一类弹窗统一按钮尺寸、圆角、背景遮罩、可读字体及焦点样式；在内置浏览器能点击时抽查 Escape/关闭按钮和原焦点恢复，但**不重写这些行为的状态机**。
- **本卡明确不实施**“把所有入口改成同一种弹窗”、照片 100% 实际像素/缩放/平移手势、新的上一张/下一张机制。用户关于统一查看入口与放大缩小的需求属**另行功能设计**，本卡不能暗自当作视觉微调实现。

## 4. Codex 内置浏览器专属验收方案（此节优先于旧卡对 Chrome 的要求）

### 4.1 允许的工具与有效证据

**唯一浏览器观察工具是 Codex 内置浏览器**。施工不依赖另一浏览器或驱动。优先在现有合法本机服务和**隔离合成图库**中运行产品 UI；同一内置浏览器能访问最终 demo 时再对照。`file://` 被内置浏览器限制时，只在原工具许可、可明确验证地址和来源的前提下，使用项目内允许的本机 `127.0.0.1` 静态服务浏览 demo；不更改正式产品路由、不绕过浏览器 URL/认证安全检查。若工具无法安全打开该地址，记录 `DEMO_BROWSER_PENDING`，改用**源 CSS/结构逐项对照**并保留这一限制。

| 检查项目 | 首选证据 | 内置浏览器做不到时 |
| --- | --- | --- |
| 产品页面结构与实际布局 | 在内置浏览器进入已授权的真实产品页面，实看并点击；记录页面/数据/状态 | `BROWSER_ACCESS_PENDING`；继续源码/CSS/DOM 定向检查，不伪造产品截图 |
| demo 与产品视觉对照 | 同一内置浏览器打开 demo 与产品，对照导航、网格、色彩、层次、间距 | `DEMO_BROWSER_PENDING`；依据确认版 demo 源码与已实现 CSS 做可审查的差异清单；不宣称目测完全一致 |
| 截图与项目落盘 | **仅当内置浏览器实际提供截屏与可合法导出能力**时保存；记录真实路由、数据、主题、视口 | 若只能看不能保存，写 `SCREENSHOT_FILE_PENDING_TOOL_LIMIT`，附交互记录/代码检查结果；**不生成冒充产品浏览器的图片** |
| 窄屏布局 | 使用内置浏览器**实际可调的视口/窗口**观察小窗口；记录可观察 CSS 宽度（若工具提供） | 通过媒体查询/布局静态检查及已有证据复核，记 `NARROW_BROWSER_PENDING` |
| 暗色 | 仅当内置浏览器可实际切换 `prefers-color-scheme` 或其系统环境时观察 | 计算/审核暗色 token 和组件覆盖，记 `DARK_BROWSER_PENDING`；不得把 CSS 强制覆写等同系统暗色切换 |
| **真实浏览器页面 Zoom 200%** | 仅当内置浏览器明确提供页面级 Zoom 并能确认实际达到 200% 时判定 | 标记 `ZOOM_200_NATIVE=PENDING_TOOL_LIMIT`；用**窄 CSS 视口作布局压力替代检查**，另记 `ZOOM_LAYOUT_PROXY=CHECKED/FAILED`，**两者绝不等价** |
| 长图、竖图、无结果/错误等状态 | 使用已有合法隔离样本在内置浏览器实看 | 样本缺失只补极少量合成数据；未观察的状态逐项标 `STATE_PENDING` |
| 地图与瓦片 | 内置浏览器可访问现有瓦片时看真实布局与地图侧栏 | 无瓦片时验证容器/回退文案，不绕过网络规则；`MAP_TILES_PENDING` |

特别禁止：把 `window.devicePixelRatio`、`visualViewport.scale`、缩小浏览器视口、操作系统显示比例、CSS `transform: scale()` 或截图后放大**当作已确认浏览器页面 Zoom 200%**。它们最多是辅助诊断，不是同一个验收对象。

### 4.2 最小内置浏览器实看路线（不跑大量重复组合）

**最多覆盖 7 类页面，每类 1 个代表状态**，复用现有合成数据：

1. **照片 / 时间轴**：首页 + 可见日期组头与照片卡，观察导航、大片留白、文件名两行，点击一个已有照片弹窗并返回。
2. **搜索**：一个 `FILTER_ONLY` 有结果页；范围 chip + 高级筛选展开（若可用），以及一次错误或空态。
3. **人物**：目录卡 → 人物相册/合集，打开一个缩略图；已忽略/待整理仅抽看一处易错对比区域。
4. **地点**：地点目录 → 地点相册，检查父级、照片网格与更正按钮排布。
5. **地图**：地图容器 + 右侧照片区，瓦片失败时仍保留状态说明。
6. **图库管理**：入口、主要操作与低频管理区，检查是否有异常页面高度/焦点框。
7. **照片查看器**：选一张宽图/竖图（至少一种长图），检查大图容器、信息面板、关闭按钮、小窗口可读性；这是对已有第1～4项查看器的集中复用，不必分别截图每一种。

如果内置浏览器允许控制窄视口，只挑**照片/搜索/查看器/地图**四种布局压力较大的状态复看；不强制 1440、640、暗色、Zoom 200% 做笛卡尔积组合。优先确保照片、搜索、人物、地点及查看器这五种高频画面有真实产品实看；其余页面若因能力/数据问题无法进入，按页面记 PENDING，不拿静态断言填充浏览器通过数。

**内置浏览器故障预算**：每类待验能力最多做一次合理尝试，若明确不支持（例如真实 zoom、主题切换、截图落盘、`file://`），记录“操作—现象—能力限制/权限限制”即停止；不要循环尝试快捷键、插件、私有调试端口或变更浏览器安全设置。可继续完成不依赖该能力的 CSS 施工与源码对照。

### 4.3 验收证据等级与收口判定

- `STATIC_CHECKED`：源码、CSS tokens、响应式规则、缓存版本、HTML 引用和焦点/可访问性静态断言有效。**不是**浏览器视觉 PASS。
- `BUILTIN_BROWSER_VERIFIED`：当前 HEAD、当前隔离产品服务的真实页面已在 Codex 内置浏览器看到并完成所记录的操作；只覆盖表中具体路由/状态。
- `SCREENSHOT_SAVED`：只能在**内置浏览器实拍且能够导出**时填写文件相对路径；截图看不出真实浏览器 Zoom 比例时不写 Zoom 已验。
- `PENDING_TOOL_LIMIT`：工具不能切主题、设真实 Zoom、落盘截图或进入某个会话；如实列出，**不是产品缺陷，也不是 PASS**。每项保留其本来对应的验收结论，不因为工具限制自动给整卡放行。
- `FAIL`：**确实在可访问的产品界面复现**遮挡/溢出/不可读，或定向回归失败；这是产品缺陷，不能混写成工具限制。
- `PENDING_FIXTURE`：产品页面可打开，但没有该状态的有效隔离样本，例如无人物头像/有效地点/搜索结果；不能写已实测通过，也不必为了纯视觉大量造数据。
- `USER_TRIAL_PENDING`：只有用户在日常使用设备上能最终观察的感受/真实 Zoom/真实图库素材展示；由用户自愿体验，**不强制用户截图才能完成代码收口**。

**可宣布的结论**：只有 P0 阻断已消除、主要 P1 差异已经处理或给出合理保留理由、定向测试通过，且**实际能访问的主要页面**已经由 Codex 内置浏览器观察，才可写 **`VISUAL_SCOPED_PASS / TOOL-LIMITED_ACCEPTANCE`**。需附实际已观察的页面清单与未观察项：这只意味着受限工具下的**本卡有限视觉验收**，不是全站/所有主题/所有缩放通过。真实 Zoom 200%、暗色切换、缺少的截图与性能等各自继续 `PENDING`。若浏览器完全无法进入产品或只能看到单一不具代表性的页面，则最多写 `IMPLEMENTED / STATIC_CHECKED / BROWSER_PENDING`，不写 `VISUAL_SCOPED_PASS`，也不能把工具限制说成产品失败。

## 5. 施工保护与防止重做

1. **只改显示层**：优先 `styles.css`、`search.css`、`persons.css`、`places.css`、`map.css`、`photo-timeline.css`、`photo-info.css`；HTML 仅改必要布局/类名、样式引用版本，JS 仅在展示 class/交互遮挡实证必要时做最小改动。

3. 不自行修改 `PhotoSearchData` 或真实照片；全部浏览器样本来自现有隔离数据。无权访问/安全路由不确定时直接停止浏览器测试，保留 `BROWSER_PENDING`。
4. 不新增另一套 CSS 主题文件、UI 框架、图标/字体依赖、第二套照片查看器或全站应用状态机；页面选择器尽量具备作用域，避免人物/地点/搜索 `.panel/.chip/.filters` 之类同名规则相互污染。

7. 若发现涉及全站导航语义、统一弹窗入口或交互模式的“更佳设计”，列为后续建议，不借本卡无审查改成新功能。
