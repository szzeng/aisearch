## 必须交付的环境证据

### 1. 包内组件清单

- 真实重建 onedir（`uv run --no-sync python tools/packaging/build_onedir.py`）；
- 证明 `pillow-heif` 的 Python 扩展与 libheif 运行库**确实在包内**：列出包内相对路径、字节数与 SHA-256，
  并说明它们与 `.venv` 中来源文件的对应关系（同源哈希一致）；
- 反向清单：包内 `photo_search` 的全部数据资源（css/html/js/sql/json/svg）与源码逐字节一致；
  若发现任一陈旧资源（P4-00B 出现过的 `web/app.js` 类问题），必须修复并记录。

### 2. 打包后的 HEIC 端到端闭环

用**打包后的可执行文件**（不是源码进程）对一份合成 HEIC 完成：

1. 注册来源 + 扫描入库（`/api/v1/sources`、`/api/v1/sources/{id}/scan`）；
2. 缩略图与预览 READY（媒体状态接口），且与同等 JPEG 的方向/尺寸结论一致；
3. 详情页 `taken_time` 与 GPS 事实按 A 段冻结的语义发布（含一条有偏移或无偏移的对照）；
4. 一条损坏 HEIC 与正常照片同批：坏文件结构化失败、好文件全部 READY，进程不崩。

### 3. 降级反例（fail closed）

在**独立可丢弃副本**里移除或改名包内的 libheif/ pillow-heif 组件后：

- 程序仍能启动；
- HEIC 得到结构化 `FORMAT_UNSUPPORTED`（不是启动失败、不是 `DECODE_FAILED`、不是空图）；
- 其它格式（JPEG 等）与既有缓存不受影响；
- 反例结束后只清理该副本。

### 4. `packaged_api_smoke.py` 扩展

- 加入 HEIC 断言（包内组件存在 + 打包进程对 HEIC 的真实结果）；
- 加入 R1 的「全部数据资源与源码逐字节一致」断言；
- 保持既有断言（schema 版本、person 词表、taken-time 层、migrations 连续性）不削弱。
