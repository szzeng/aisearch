# P4-PERSON-IGNORE-STATE-A — 人物忽略状态细分与管理优化

## 背景

当前人物整理流程中存在「已忽略」状态，但实际包含两种不同需求：

1. 暂时不知道是谁，希望以后继续处理；
2. 明确不要管理该人物，例如路人、背景人物。

单一「已忽略」状态无法区分，导致：

- 暂时不处理的人可能永久沉默；
- 明确排除的人仍可能参与人物推荐；
- 人物整理列表长期积累无效状态。

## 目标

将现有「已忽略」状态优化为两个明确状态：

- 暂时忽略
- 明确排除

本任务不修改人脸识别算法，不改变人物识别流程。

---

## 功能要求

### 1. 暂时忽略状态

含义：当前无法确认，但未来可能处理。

保留：

- 人脸记录；
- 候选人物关系；
- 相似度信息；
- 历史推荐信息。

支持后续：

- 查看候选人物；
- 确认归属；
- 选择其他人物。

示例：

```
暂时忽略

可能人物：张三 85%

操作：
- 确认是张三
- 选择其他人物
- 继续保持暂时忽略
```

---

### 2. 明确排除状态

含义：用户确认该人物不需要进入人物管理。

行为：

停止：

- 出现在待整理；
- 自动人物推荐；
- 人物匹配提示。

保留必要历史信息，兼容现有撤销或维护机制。

---

## 3. 已有数据兼容

现有状态：

```
已忽略
```

默认迁移：

```
已忽略 → 暂时忽略
```

原因：历史数据无法判断用户真实意图，避免误永久排除。

---

## 4. UI 调整

位置：

```
人物管理 → 待整理
```

调整为：

```
待整理
├── 暂时忽略
└── 明确排除
```

用户执行忽略操作时，需要明确选择：

- 暂时忽略：以后可能处理；
- 明确排除：不再推荐。

---

## 5. 与候选人物系统兼容

暂时忽略：

继续保存已有候选关系：

- candidate_person
- similarity
- 推荐信息

明确排除：

不参与：

- 候选排序；
- 人物推荐；
- 自动提示。

---

## 性能限制

禁止：

- 页面打开重新执行人脸识别；
- 批量重新计算相似度；
- 重建人物关系。

只处理：

- 状态字段；
- 查询逻辑；
- UI 展示。

---

## 简单验收

### 测试1：旧数据兼容

已有旧「已忽略」人物。

结果：

进入「暂时忽略」。

---

### 测试2：暂时忽略

选择暂时忽略后：

- 出现在暂时忽略列表；
- 保留候选人物信息。

---

### 测试3：明确排除

选择明确排除后：

- 不再出现在待整理；
- 不再生成推荐。

---

### 测试4：恢复处理

暂时忽略人物存在候选张三时：

可以确认归属张三。

---

## 实现范围

本任务仅处理：

- 人物状态设计；
- 数据兼容；
- UI 入口；
- 状态流转。

不涉及：

- 人脸算法优化；
- 相似度模型调整；
- 人物聚合重构。

## 推荐执行模型

中高级代码模型。

重点避免重构人物识别系统。
