# P4-PERSON-IGNORE-STATE-A — 人物忽略状态细分与管理优化

## 背景

当前人物整理流程中存在「已忽略」状态，但实际包含两种不同需求：

1. 暂时无法确认是谁，希望以后继续处理；
2. 明确不希望该人物进入人物管理，例如路人、背景人物。

单一「已忽略」状态无法区分用户意图，导致：

- 暂时不处理的人可能永久沉默；
- 明确排除的人仍可能参与人物推荐；
- 人物整理列表长期积累无效状态。

---

## 目标

将现有：

```
已忽略
```

优化为：

```
暂时忽略
明确排除
```

目标：

- 保留用户人工判断；
- 减少重复推荐干扰；
- 保证历史数据安全；
- 不修改人脸识别算法；
- 不改变人物识别流程。

---

# 状态定义

## 1. 暂时忽略

含义：当前无法确认，但未来可能继续处理。

保留：

- 人脸记录；
- 候选人物关系；
- 相似度信息；
- 历史推荐信息。

支持后续：

- 查看候选人物；
- 确认归属；
- 选择其他人物；
- 恢复整理流程。

示例：

```
暂时忽略

可能人物：张三 85%

操作：
- 确认归属
- 选择其他人物
- 保持暂时忽略
```

---

## 2. 明确排除

含义：用户确认该人物不需要进入人物管理。

行为：

停止：

- 出现在待整理列表；
- 自动人物推荐；
- 人物匹配提示。

注意：

明确排除不是删除。

必须保留：

- 原有人脸记录；
- 照片关联关系；
- 必要历史信息。

支持后续维护或撤销（如果已有机制）。

---

# 数据安全与兼容要求

## 旧数据迁移

已有状态：

```
已忽略
```

默认迁移：

```
已忽略 → 暂时忽略
```

原因：历史数据无法判断用户真实意图，避免误永久排除。

## 数据安全限制

禁止：

- 删除已有已忽略人物数据；
- 删除人脸记录；
- 删除照片关联关系；
- 重新生成全部人物关系；
- 重新执行全部人脸识别。

如果需要数据库结构变化：

要求：

- 提供明确迁移逻辑；
- 保留原数据；
- 支持失败恢复；
- 优先提供迁移前后的数量校验。

# UI 调整

位置：

```
人物管理 → 待整理
```

调整为：

```
待处理
├── 暂时忽略
└── 明确排除
```

用户执行忽略操作时，需要明确选择：

- 暂时忽略：以后可能处理；
- 明确排除：不再推荐。

---

# 与候选人物系统兼容

本任务只负责状态设计。

候选展示和归属操作由：

```
P4-PERSON-IGNORED-CANDIDATE-A
```

负责。

暂时忽略：

继续保存：

- candidate_person；
- similarity；
- 推荐信息。

明确排除：

不参与：

- 候选排序；
- 人物推荐；
- 自动提示。

# 性能限制

禁止：

- 页面打开重新执行人脸识别；
- 批量重新计算相似度；
- 重建人物关系。

实现范围仅包括：

- 状态字段；
- 查询过滤；
- UI 展示；
- 状态迁移。

# 简单验收

## 测试1：旧数据兼容

已有旧「已忽略」人物。

结果：

进入「暂时忽略」，原数据完整。

---

## 测试2：暂时忽略

选择暂时忽略后：

- 出现在暂时忽略列表；
- 保留候选人物信息。

---

## 测试3：明确排除

选择明确排除后：

- 不再出现在待整理；
- 不再生成推荐；
- 原数据仍存在。

---

## 测试4：恢复处理

暂时忽略人物存在候选张三时：

可以继续确认归属张三。
