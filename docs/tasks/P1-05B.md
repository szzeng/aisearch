## 任务定位

P1-05 交付了本机前端，但它的正确性目前依赖两类证据：

1. `tests/unit/test_api_frontend.py` 里的**静态契约断言**（资源内容、无外部引用、无令牌存储、关键文案、
   端点使用），分散在若干断言里，没有明确列出「契约清单」；
2. **手动浏览器 smoke**（P1-05 报告 §6 的 10 步），只存在于报告里，下一次要复现得重新设计夹具与步骤。

本任务把这两类证据固化成可重复运行的资产，同时**明确记录**本仓库不做自动化 DOM 断言这一限制及其理由，
避免后续会话误以为「前端已有自动化回归」。

本任务仍然**不做**：修改页面行为、新增前端功能、引入 Node/npm/无头浏览器/新依赖、
EXIF 拍摄时间维度（`taken_at` 属 C2 决策）、任何后端改动。

## 用户场景

- 维护者在改动前端（或后端返回结构）后，能用一条命令知道「静态契约是否仍成立」，
  而不是靠肉眼读 `app.js`。
- 维护者需要重跑 P1-05 记录的浏览器闭环时，有一条命令生成全部 `%TEMP%` 夹具并打印逐步期望观察，
  不需要重新回忆 2000 文件、corrupt.jpg、schema_version=2、断盘删文件这些细节。
- 下一位接手者能一眼看到：哪些必须人工确认、哪些限制已被接受、为什么没有自动化 DOM 测试。

3. 读 `tools/diagnostics/packaged_api_smoke.py`，沿用其「argparse + `%TEMP%` 工作目录 + 打印 JSON/路径」

4. 读 `docs/reports/P1-05-local-frontend-sources-browse-detail-offline.md` §6（10 步）与 §8（限制清单），

## 必须交付

### 1. 静态契约断言的集中化与补齐

- 在 `tests/unit/test_api_frontend.py` **追加**（不重写、不删除既有断言）一组显式契约断言，至少覆盖：
  - 三个静态文件都不含 `http://`/`https://`；
  - `app.js` 不使用 `localStorage`/`sessionStorage`/`console.`；
  - 所有数据请求都指向 `/api/v1`（页面上不出现数据库、来源目录或任何非 `/api/v1` 的数据端点）；
  - CSRF 只经 `ps_csrf` cookie + `X-CSRF-Token` 头，且请求使用 `credentials: "same-origin"`；
  - 页面守卫仍在（`PATH_LIKE` 与「错误详情包含本机路径」文案），不得因为 P1-05A 修了服务端就删掉；
  - 关键中文文案存在：`加入时间`、`原文件不可用`、`请使用启动器打印的一次性链接建立会话`；
  - 时间维度只声明为入库时间（页面出现「不是 EXIF 拍摄时间」之类的既有说明）。
- 断言写成「一个契约一条断言」并有简短注释说明它防的是什么回归；必要时用一个辅助函数读取三个文件，
  避免重复读盘。

### 2. `%TEMP%` 夹具脚本

- 新增 `tools/diagnostics/frontend_smoke_fixture.py`（纯 stdlib + 已装 Pillow；不启动服务器、不启动浏览器）：
  - 参数（建议）：`--work-dir`（默认 `%TEMP%\P1-05B 前端验收`）、`--photos N`（默认 60 个独立 JPEG）、
    `--bulk N`（默认 2000 个 bulk JPEG，用于让扫描**慢到可以观察 RUNNING 进度**）、`--corrupt`、
    `--too-new`、`--offline <相对路径…>`（删掉指定原图以演示离线提示）；
  - 生成：中文 + 空格路径的来源库与数据目录、独立 JPEG、bulk JPEG、1 字节 `corrupt.jpg`、
    可选的 `schema_version=2` 库；
  - 打印：绝对路径、真实端口启动命令（`uv run python -m photo_search --port <p> --data-root <d>`）、
    需要打开的启动器链接形状（`?next=/&token=…` 在控制台）、以及 §6 的 10 步期望观察；
  - 明确打印「只使用合成夹具，不读取真实照片库」。
- 脚本必须可重复运行（重复执行不报错；已存在的目录按参数重建或跳过，行为要写在输出里）。

### 3. 浏览器 smoke 核对清单

- 新增 `docs/diagnostics/frontend-smoke-checklist.md`（新建 `docs/diagnostics/` 目录）：
  - 逐条固化 P1-05 报告 §6 的 10 步：步骤 / 期望观察 / **不满足即不得标 PASS** 的判据 / 常见失败原因；
  - 写明夹具生成命令与真实端口启动命令（与本卡第 2 项一致）；
  - 写明本仓库**不做**自动化 DOM 断言的限制与理由（不引入 Node/npm/无头浏览器；如需改变需单独 ADR 与
    依赖决策）；
  - 写明已知限制：窄视口 ≠ 真实 200% 缩放；`time_desc` 只按入库时间；
    `taken_at` 需要 ADR-0002 §7 加列 + C2 决策；
  - 写明「页面不得渲染绝对路径」这一条要在核对时用 `document.body.innerText` 的正则
    `/[A-Za-z]:\\|\/Users\//` 之类方式人工确认（清单里给出可复制的检查方法）。

## 正常行为 / 异常行为 / 边界情况

**正常行为**

- `uv run pytest -q tests/unit/test_api_frontend.py` 全绿，且断言条数与契约条数一致、可读。
- 夹具脚本在干净机器上一次运行即可产出全部 `%TEMP%` 夹具，并打印可直接照做的下一步。
- 清单里的每一步都能在不查历史报告的情况下执行并判断通过/失败。

**异常行为**

- 若发现前端行为与 P1-05 报告描述不一致（例如某一步骤现在不再成立）：不修改实现，
  在该卡报告里作为「发现」记录，并把清单中该步标为 `VALIDATION PENDING` 或按实测更正描述。
- 若夹具脚本在无 Pillow 的环境运行：给出明确错误信息，不静默失败（Pillow 已是项目依赖）。

**边界情况**

- `%TEMP%` 路径含中文/空格；夹具目录已存在；`--bulk 0`；`--photos 0`；`--offline` 指向不存在的相对路径；
- 只跑清单中的部分步骤（清单要允许「按需执行 + 逐条记录结果」）。
