# P4-03 — UpgradeRun / targets、预算、暂停恢复与 profile 原子激活

本卡在 30 万正式容量口径已建立（P4-02B）之后，实现**模型/索引升级运行体**：一次 UpgradeRun
把「目标 profile、目标资产集、预算、进度、暂停/恢复/取消、失败分类」变成持久状态，并让
`search_profiles` 的切换保持**原子激活**（旧 profile 在切换前后始终可服务，切换后旧代不
回滚新的过滤事实）。

推荐执行模型：**DS-H / DeepSeek V4.1 Flash / 高推理**（按 V3.1 §9 的 P4-03 行：DS-H 契约/工程主审
→ 条件式 DS-MAX → Sol high 聚焦终审并冻结）。命中 §2.2 六类条件才建议升 **DS-MAX**；
无法解释的 Windows/权限/驱动异常建议转 **C1**。**Sol 必选**：本卡直接命中 V3.1 §11 的
「profile 原子激活、升级、回退、引用保护」高风险清单，不得记 `SOL_NOT_REQUIRED`。
模型切换由用户在 Codex 中手动完成。

## 必须交付

1. **UpgradeRun 契约**：一个运行体绑定「目标 profile_id、目标 generation、资产目标集、预算
   （数量/时间/并发）、状态机（PLANNED/RUNNING/PAUSED/CANCELLED/FAILED/SUCCEEDED）」，状态转换
   只允许闭集；`upgrade_targets` 每资产一行且可幂等重放。
2. **预算与暂停/恢复**：达到预算后不再领取新目标但不丢已完成进度；暂停必须让在途批次可重放、
   重启后从持久状态恢复；取消不清空已完成产物、不删除人工事实。
3. **profile 原子激活**：只有目标 generation 达到 READY 且其引用完整时才允许激活；激活是
   单行事务；激活后旧查询缓存/旧会话按既有语义过期；失败不得留下半个 profile。
4. **引用保护**：被活动 profile、在途查询、UpgradeRun 目标或回退任务引用的 generation
   不得被清理/退休。
5. **失败分类**：模型缺失、来源离线、显存不足、租约过期、产物缺失各自有闭集错误码与可读详情；
   不得隐式降级到 CPU 或另一个 profile。
6. **D 级注入证据**（逐条给前后计数）：升级中杀进程后重启；暂停→恢复；预算耗尽中断；
   激活失败原子回滚；旧 generation 在切换期间继续服务；引用中的 generation 清理被拒。
