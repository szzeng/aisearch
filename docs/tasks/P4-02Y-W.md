## 1. 产品口径

调整：

```text
DEFAULT_TOP_K = 5000
MAX_TOP_K = 5000
MAX_SESSION_IDS = 5000
```

产品固定最多 5000 个结果，不做动态 `top_k`。

继续使用现有：

```text
FTS + Vector
→ RRF
→ 现有排序
→ 最终 Session 最多保存 5000 条
→ 前端分页 / 滚动浏览
```

用户不需要配置 `top_k`。

## 2. 高度匹配定义

内部只保留一个常量：

```python
STRONG_MATCH_MAX_DISTANCE = 1.3
```

当前 Chinese-CLIP embedding 为 L2 normalized，当前 Lance distance 为 squared L2：

```text
distance = 2 - 2 × cosine
```

所以 `distance <= 1.3` 等价于约 `cosine >= 0.35`。

`0.35` 只写在注释/文档中作为依据，**不要再维护第二个产品常量**。

## 3. 高度匹配只统计 Vector

定义：

```text
strong_match_count =
当前 Vector Top5000 中 distance <= 1.3 的数量
```

不得根据 RRF score、FTS rank、OCR、文件名或最终融合 rank 计算高度匹配。

边界：

- `vector candidates < 5000`：直接得到实际 `strong_match_count`。
- `vector candidates == 5000` 且第 5000 条 `distance <= 1.3`：`strong_match_more_possible=true`。
- 其他情况：`strong_match_more_possible=false`。

## 4. API 最小改动

不要修改 `SearchResult` 顶层字段。

在现有 `channels.vector` 增加：

```json
{
  "strong_match_count": 327,
  "strong_match_more_possible": false,
  "scan_truncated": false
}
```

不要向 API 暴露 `0.35`、`1.3`、similarity 百分比。

`scan_truncated` 必须直接来自 `vector_scan.truncated`，含义只允许是“向量候选空间没有真正扫描完整”。

禁止继续用：

```text
vector_count >= top_k
```

推断扫描不完整。

## 5. 5000 是正常产品容量

Session 最多保存前 5000 条，这是正常产品上限，不是运行错误。

修掉当前边界误判：

```python
len(entries) >= MAX_SESSION_IDS
```

不得导致“恰好 5000 条”被标记为截断。

统一遵循 `SearchSessionStore.build_session()` 现有语义：

```text
len(entries) <= 5000
→ candidates_truncated=false

len(entries) > 5000
→ 保存前5000
→ candidates_truncated=true
```

UI **不要因为正常产品容量达到 5000 就弹错误警告**。

## 6. UI

语义搜索结果顶部显示：

普通情况：

```text
约 327 张高度匹配
```

若 `strong_match_more_possible=true`：

```text
5000+ 张高度匹配
```

不要显示“327 张匹配结果”、匹配率、相似度百分比或准确率。

第 N 张以后照片仍继续正常显示，最多 5000 张。高度匹配门限不得影响继续滚动。

## 7. 警告语义

只有：

```text
scan_truncated = true
```

才显示：

> 向量扫描未完整完成，本次结果可能不完整。

以下情况均不应显示异常警告：

```text
vector candidates = 5000
session results = 5000
strong_match_count = 5000
candidates_truncated = true（RRF 融合结果超过产品 5000 容量）
```

其中高度匹配达到 5000 时只显示“5000+ 张高度匹配”。
