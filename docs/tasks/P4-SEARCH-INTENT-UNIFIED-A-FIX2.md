# P4-SEARCH-INTENT-UNIFIED-A-FIX2 — 同名 GeoNames 父子候选默认范围修复

**状态：修复完成 / 定向验证通过 / 真实活动目录未读取**

**关联：** [统一搜索主卡](P4-SEARCH-INTENT-UNIFIED-A.md)、[前序重复候选修复](P4-SEARCH-INTENT-UNIFIED-A-FIX1.md)

## 问题与根因

用户现场仍看到“地点：香港（GEONAMES）”和“地点：香港（香港 · GEONAMES）”两个选择。标签表现为两个同名 GeoNames 记录，其中一个的父级也叫香港。地点解析器此前只实现 OSM 对 GeoNames 的来源优先；同来源、同跨度的父子地点被当作两个独立歧义。

未读取用户的活动地点目录，以上实际记录关系依据按钮上的父级标签推断。实现只对目录能提供并验证父记录身份的候选应用默认范围。

## 范围与验收

- GeoNames 搜索候选可按需携带内部父记录 ID；手动地点选择的公开选项契约保持不变。
- 无地区限定且同名候选明确是同一活动包、同一来源中的国家/城市直接父子记录时，解析到国家范围。
- 仅名称或显示父级相同不能触发合并；不同身份、无父身份凭据的同名候选仍要求选择。
- 解析器返回给 API/UI 的选择项不包含内部父身份字段。
- 覆盖地点解析、统一意图计划和真实合成目录的父 ID 投影；运行受影响的最小 pytest、Ruff 与 diff-check。

不改变地点身份/数据包、来源折叠、GPS 归属、地点相册成员规则或搜索排名；不读取真实图库和现有服务。
