## 任务定位

P1 的第一个任务，也是整个图库数据模型的地基：把“来源 / 位置 / 资产 / 扫描”从概念变成
**有版本化迁移、有唯一约束、可中断恢复的最小持久任务**。本任务不实现完整扫描算法、不做 AI、
不做搜索、不做界面。P1-01 的契约一旦冻结，P1-02 起只在契约之上实现，不再重排数据身份。

## 用户场景

用户把本机的照片目录（含中文、空格、长路径；可能是外接盘）添加为“来源”，系统能：

- 记住来源身份，而不是记住某个盘符；
- 记录每个文件位置，并把同字节内容的多个位置归到同一个资产；
- 文件被改名或被移动到同盘其他目录时，不改变资产身份，也不误判为删除；
- 扫描中断、断电、程序被杀之后，重启能接着做完，不产生半成品资产或重复任务；
- 不安装/不运行任何 AI 模型，也能看到“来源有几千张图、库里有几个资产”这类真实状态。

本任务不要求用户开始正式导入自己的图库；所有验收使用临时夹具目录，且**不得**读取真实照片库。

## 必须交付

### 1. 版本化迁移与 schema 版本（架构 §11.2）

- `src/photo_search/catalog/migrations/0001_initial.sql` 起的递增迁移文件，配一个可复用的迁移执行器。
- `metadata` 表保存 `schema_version`；迁移在受控事务内执行，重复运行幂等。
- 迁移前检查可用磁盘空间；迁移前停止写入并创建数据库备份。
- **程序遇到高于自身支持的 `schema_version` 必须拒绝写入并说明版本要求**，不得静默丢表重建，
  不得用“重新扫描一下”代替保护已有身份与人工信息。
- 迁移中断留下的状态必须可诊断、可恢复，不得留下“部分应用但版本号已前进”的假状态。

### 2. 最小数据契约（架构 §4.1、§4.2、§5.1～§5.3）

只建本任务需要的表，字段名与语义按架构 §4.2，不得提前创建人物、向量、outbox、索引世代等后续阶段表：

- `source_roots`：`source_id`、`display_name`、`root_path`、`volume_hint`、`status`、`last_successful_scan`。
- `scan_runs`：`scan_id`、`source_id`、`started_at`、`finished_at`、`state`、`error`。
- `file_locations`：`location_id`、`source_id`、`relative_path`、`path_key`、`asset_id`、
  `size`、`mtime_ns`、`last_seen_scan_id`、`availability`。
- `assets`：`asset_id`、`sha256`、`byte_size`、`width`、`height`、`format`、`created_at`、`state`。
- `jobs`（最小子集，架构 §6.2）：`job_id`、`subject_type`、`subject_id`、`input_revision`、
  `task_type`、`processor_id`、`state`、`priority`、`attempts`、`max_attempts`、`run_after`、
  `lease_token`、`lease_expires_at`、`worker_id`、`progress`、`last_error_code`、
  `last_error_message`、`created_at`、`updated_at`。
- `metadata`：`key`、`value`。

**不可动摇的约束（C2 冻结，DS-H 不得改写）：**

| 约束 | 内容 |
|---|---|
| 资产内容身份 | `assets.sha256` 唯一；完整 SHA-256 才构成内容身份 |
| 位置唯一性 | `UNIQUE(source_id, path_key)`；`file_locations.asset_id` 在内容确认前允许为空 |
| 待确认状态 | 未算完完整 hash 的文件只能停留在位置层，**不得**用部分 hash 创建永久资产身份 |
| 多位置共享 | 同字节内容的多个位置指向同一个 `asset_id` |
| 移动/改名 | 不改变 `asset_id`；文件名与目录属于位置属性 |
| 同路径内容替换 | 该位置重新指向对应内容的资产；**旧资产与人工信息不被覆盖、不被删除** |
| 来源身份 | 不等于盘符；目录重映射显式记录，不靠替换绝对路径字符串 |
| 缺失判定 | **只有完整成功扫描**才能对该范围做缺失判断（本任务只需让 schema/状态机支持该规则） |
| 人工与机器分离 | 机器结果不得写入人工知识字段；不可合并的语义边界（资产/位置、人工/模型输出）不得合并成一张表 |
| 原图只读 | 扫描、hash、格式探测全部只读；任何情况下不修改、不删除用户原文件 |

### 3. 路径与来源边界（架构 §5.3）

- 规范化 Windows 分隔符、驱动器与比较键，生成稳定的 `path_key`，同时**保留展示路径**。
- 支持空格、中文、超长路径；用真实临时夹具验证，不靠单元测试里的纯 ASCII 路径。
- 重叠来源默认拒绝并给出合并提示，避免同一棵树被扫描两次。
- 默认不递归跟随目录联接与符号链接；显式添加其目标才是来源。
- 数据目录不得位于照片来源内部（避免索引自身被再次扫描）。
- 数据根解析沿用 P0-04 已验证的做法（`%LOCALAPPDATA%\PhotoSearchData`，打包视图下同样解析到
  用户数据目录），运行数据不写入 `dist/PhotoSearch`。

### 4. 最小持久扫描任务（架构 §6.2、§6.3）

- 任务唯一逻辑键：`(subject_type, subject_id, input_revision, task_type, processor_id)`，**五要素全部非空**；
  无模型任务也使用固定的版本化 `processor_id`，避免 SQLite 的 NULL 唯一性语义放过重复任务。
- 状态集合：`QUEUED / RUNNING / SUCCEEDED / RETRY_WAIT / BLOCKED / FAILED / CANCELLED`，
  合法迁移按架构 §6.2 与 ADR-0002；非法迁移必须被拒绝而不是静默接受。
- 领取在**短 SQLite 事务**内完成：选中任务 → 置 `RUNNING` → 生成新 `lease_token` + `lease_expires_at`。
- 心跳续租；租约过期后可重新领取；**迟到提交必须校验 `lease_token`、输入 revision 与 `processor_id`，
  过期结果不得覆盖新结果**。
- 重启后能收回过期租约并继续调度；进程退出丢失内存队列不丢逻辑任务。
- 本任务只需实现让上述规则可验证的最小扫描闭环；完整的稳定等待、hash 前后校验、移动/缺失判定算法
  属于 **P1-02**，不得在本任务提前实现，也不得用一次性脚本替代正式入口。

### 5. 内部入口与错误行为

- 本任务**不新增 HTTP 业务 API**（sources/assets API 属 P1-04）；`GET /api/v1/health` 保持 P0-01 行为。
  若需要展示 schema 版本，只允许在健康信息里增加只读字段，且不得引入数据库写入路径。
- 提供一个可测试、可观测的内部服务入口（模块函数或 CLI 子命令），至少支持：注册来源、
  发起最小扫描、查询来源/资产计数、以 `--json` 输出结构。
- 结构化错误至少区分：来源不存在、来源离线、路径重叠、权限/访问拒绝、磁盘空间不足、
  schema 版本过高、租约冲突/迟到提交。错误不得只打印到 stdout 后返回成功。

## 正常行为 / 异常行为 / 边界情况（验收时逐条覆盖）

**正常行为**

- 空库首次运行自动迁移到最新版；重复运行迁移不改变结果。
- 注册一个临时来源、扫描后：`assets` 数 = 去重后的内容数，`file_locations` 数 = 实际文件数，
  同字节两文件共享一个 `asset_id`。
- 重命名文件后再次扫描：`location_id` 关系更新，`asset_id` 不变。

**异常行为**

- 迁移中断：重跑可继续或安全回滚，`schema_version` 与实际表结构一致。
- 扫描中途被终止：重启后继续，不产生半成品资产，不出现重复逻辑任务。
- 租约过期 / 迟到提交：被拒绝并记录原因，不覆盖新结果。
- 来源离线（目录不可访问）：来源状态标记，**不**把整批位置判为缺失。
- 磁盘空间不足：停止提交并报告，不删除任何已有身份或人工数据“自救”。

**边界情况**

- 中文目录名、含空格目录名、超长路径、只读文件、0 字节文件、损坏/非图片文件、同名不同内容。
- 两个来源重叠（父目录 + 子目录）→ 拒绝并提示。
- 同一内容在两个来源（两个盘）→ 共享资产，移除其中一个位置后另一个仍可用。
- `path_key` 大小写/分隔符差异不得造成重复位置，也不得把不同文件合并成同一位置。

## 验收等级与命令

本任务涉及数据库、唯一约束与租约恢复，按 **D 级** 验收（B 级 + 对应故障注入/恢复测试；不涉及打包，故不加 C）。

```text
uv run pytest -q tests/unit tests/integration
uv run ruff check .
git diff --check
```

必须真实执行的故障注入/恢复场景（对应架构 §12.4 中属于本任务的部分）：

1. 迁移：空库 → 最新版成功；重复运行幂等；`schema_version` 高于程序支持时在任何写副作用前拒绝写入；版本号与核心 schema 不一致时报 `SCHEMA_INCONSISTENT`。
2. 扫描中断后重启：继续完成，无半成品资产、无重复逻辑任务。
3. 租约过期后可重新领取；迟到提交（旧 `lease_token` / 旧 revision）被拒绝且不覆盖新结果。
4. 同路径内容被替换：生成新资产，旧资产与人工信息不被覆盖。
5. 同字节两位置共享资产；移除其中一个位置后另一个仍可用。
6. 中文 / 空格 / 长路径来源可扫描；重叠来源被拒绝。
7. 来源离线不导致整批位置被判定缺失。
8. 正常 catalog 数据库使用 WAL；`BLOCKED -> QUEUED` 恢复不会在真正领取前把 `scan_run` 提前标为 `RUNNING`。

成功时只保留 quiet 摘要、退出码和必要计时；失败时先读失败测试名与 traceback 尾部，只重跑失败目标，
需要定位再用 `-x -vv`。任一必需场景未真实完成，不得标记 PASS（可用 `IMPLEMENTED / VALIDATION PENDING`、
`BLOCKED`、`FAIL` 反映真实状态）。
