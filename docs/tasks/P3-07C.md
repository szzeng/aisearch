## 主审范围（必须逐条给出结论与证据）

1. **完整 diff 走查**：`src/photo_search/{search,catalog,api}` 的 7 个改动文件与 4 个新增文件，逐处说明
   它落实了 ADR-0009 的哪一条，以及是否引入未冻结形状、未冻结错误码或未冻结字段。
2. **判定表一致性**：ADR-0009 §2.2 的每一行（缺省/空/`all` 无 id/非数组/非整数/`<1`/原始重复/`>100`/
   非法 `person_match`/未知字段）与实现、测试三方对照；特别是「原始重复 = 形状错误」与
   「canonical 折叠 = 合法去重」是否真的分开，以及传输层是否**故意不设** `maxItems`（保证
   `INVALID_PERSON_FILTER` 带 `max_person_ids`）。
3. **唯一谓词复用**：`search/retrieval.py` 是否真的只用 `persons/members.PREDICATE`，检索层是否存在
   第二份「有效成员」口径；`any`/`all` 的 SQL 组合是否与 ADR §3.2 等价（`|P|=1` 时等价）。
4. **AND 组合与通道边界**：`source_id`/`availability`/地点谓词/文本与语义通道/精排是否全部 AND；人物
   条件是否**未**成为命中原因、排序通道或 RRF 输入；纯筛选与纯人物请求是否仍走权威列表与 `FILTER_ONLY`。
5. **canonical 解析**（高风险边界 ①）：唯一解析器复用、同一只读快照、任一失败即整请求拒绝、
   去重升序、回显与摘要使用同一集合；悬挂/成环的注入方式是否只改测试夹具而不改生产语义。
6. **revision 与续页**（高风险边界 ②）：单一 `catalog_filter_revision`（无第二套）、人物五类编辑各 +1、
   **`_continue_session` 中 revision 检查早于 `query_hash` 比较这一顺序收敛**是否与 ADR-0005 §10、
   ADR-0009 §4.4/§6.2 一致，是否引入任何「本应答 `INVALID_CURSOR` 却答 stale」或反向的回归
   （这是本卡最需要回答的问题）。
7. **缓存失效**（高风险边界 ③）：ADR-0009 §6.3 的「必须立即一致 / 允许滞后」清单是否被这次改动
   违反；`cache/face-crops` 的键是否仍不含 `person_id`；`GET /persons`/`/persons/{id}`/`/faces`/
   `/person-operations`/`face_summary` 是否仍直接读 SQLite；`avatar_face_id` 是否仍取当前值。
8. **投影与补查**：`search_projection`/`pending_semantic` 的字段级冻结与上界（1000/200）、
   `SYNCED ⇔ queued_assets == 0`、`reason` 闭集；人物事实是否**未**进入 `search_documents`；
   投影滞后不复活已移除命中是否有真实反例。
9. **隐私闭集与错误面**：响应/错误/日志不得含路径、姓名/`name_key`/别名、bbox、landmark、向量、
   相似度/confidence、幂等 payload/hash、before/after 快照；`INVALID_PERSON_FILTER` 的 details 只允许
   `reason`/`person_match`/`person_ids`/`person_id`/`max_person_ids`；既有码未新增 details 键。
10. **冻结件与依赖**：ADR-0009、companion、四个既有 companion、`0001`～`0013`、`schema_version == 13`、
    依赖 95 包、`PhotoSearch.spec`、前端资源是否一字未改；既有测试断言是否只有「新增」而无删改
    （`tests/unit/test_p3_person_search_contracts.py` 只允许附加用例与文档字符串更新）。
11. **P3-07B 报告 §6 的越界发现核实**：独立复现「合并目标 id 大于源人物时 undo 触发
    `face_person_links` 唯一索引冲突」，确认它确实与本任务改动无关、且未被本任务掩盖或误修；
    给出「留在后续人物任务处理」还是「需要立即开卡」的结论。
