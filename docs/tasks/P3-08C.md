## 阶段 B — C2 / Sol high 聚焦终审（必选）

**Sol 为必选**，理由：本任务改写了人工知识在 `face_id` 变化后的权威转移与保持、revision/幂等/补偿撤销、
失效与队列生命周期，并扩大了一处 P3-06 读取边界；这些属 V3.1 §11 高风险语义面，任务表也要求最终冻结。
阶段 B 只能在**独立新会话**中进行，输入为阶段 A 报告的压缩交接包。

### 只审这些边界（不重复全量主审）

1. 临时保持是否真的接在 `_reconcile_asset()` 的自动关联写事务内、与人工锁/活动排除同一时点读取；
   `human_controlled_face_ids()` 是否仍只表达检测行保留；`undo → OPEN` 是否恢复保持且不是释放。
2. 人工知识转移矩阵：双向继承基数、保守 `MANUAL_UNASSIGNED`、exclusion 并集、肯定/否定冲突、
   目标已被人工编辑拒绝；`NO_CANDIDATE` 只允许 reject；服务端永不自动确认。
3. revision / 幂等 / 撤销：`request_id` 门先于 revision；`max(before,live)+1`；不允许 undo an undo；
   `changed` 与 `catalog_filter_revision` 两种事实是否诚实。
4. 失效与队列：失效先于保持；被删除候选不得被保持钉住；保持期保留队列、释放后重排队、
   决策事务不替用户选人。
5. 公开闭集与隐私：12 码 `details` 逐码闭集、`limit` 1..200、`fm1` 游标、`FACE_NOT_FOUND` 至少一个 ID、
   `INVALID_CURSOR` 空对象；响应/错误/日志不含几何、向量、路径、快照。
6. 报告 §7 未验证项的处置是否诚实（不得把未执行步骤写成 PASS）。
7. `media/face_crop.py` 读取容忍与 `persons/operations.py` 链接恢复收窄是否引入静默掩盖（给出最小反例）。
