## 实现要求

### 1. 格式策略与失败闭集

- `HEIC`/`HEIF` 进入**支持**闭集；`AVIF`/`JXL`/`TIFF`/`MPO`/`RAW`/`PSD`/`PDF` 等继续拒绝；
  capabilities/`as_dict()` 的 `supported_input_formats` 必须与真实可解码集合一致，不得把「能识别」写成「能解码」。
- Pillow 插件注册只有**一处**、幂等；插件或 libheif 运行时不可用时必须 **fail closed**：
  HEIC 得到结构化 `FORMAT_UNSUPPORTED`（既有 details 键），不得是 `DECODE_FAILED`、不得静默空图、不得崩溃。
- 坏文件（损坏/截断/不支持的 HEIC 变体）⇒ 每文件 `DECODE_FAILED`（既有 details 键），
  **不得**中断扫描或整批缩略图，不得写伪产物；沿用 P1-03 隔离语义。

### 2. 方向、缩略图与预览

- HEIC 走与其它格式**完全相同**的解码路径：方向归一化先于 resize；长边/质量/输出格式沿用
  `media/contract.py` 冻结值；缓存分片与 READY 标记语义不变。
- `THUMBNAIL_PROCESSOR_ID`/`PREVIEW_PROCESSOR_ID` 是否递增必须由证据裁定：既有格式产物在改动前后**逐字节
  相同**则不递增（给出证据）；任一既有格式产物变化则必须递增，不得让新旧语义共用同一 artifact 身份。
- 大图 HEIC 的解码内存/耗时沿用 P1-03 的硬上界，不得为 HEIC 放宽既有上限。

### 3. GPS 与拍摄时间一致性（对照组证据）

- 用**同一组坐标**的 JPEG 与 HEIC 做对照：`asset_geo_facts` 的 `status`/`datum_status`/归一化结果必须一致；
  `(0,0)`、缺块、坏分母、未知基准的既有决策不得改变。
- 用**同一墙钟时间与同一 `OffsetTime*`** 的 JPEG 与 HEIC 做对照：ADR-0011 的来源链、civil key、confidence
  与「文件时间」诚实性必须一致；无偏移不得写 UTC；`EXIF_ROOT`/`FILE_MTIME` 不得参与时间过滤。
- 确认 HEIC 上 `0x8825` 与 `0x8769` 子 IFD 的标签可见性（`0x9003/0x9004/0x9011/0x9012/0x9291/0x9292/0x0132/0x9010`）。
  若某标签在该版本不可读，必须在报告写明并列入未验证项，**不得**把缺标签解释成通用的「无 GPS/无时间」结论。
- 缩略图/预览/GPS/拍摄时间都只使用已发布事实，不得为 HEIC 新增第二套判定。

### 4. 上传面（必须显式裁定，不得默认漂移）

`POST /api/v1/search/image` 有独立白名单与字节/像素/解码时间上限（P2-07 冻结）。

- 若让上传面跟随库内能力（接受 HEIC），必须同步更新 P2-07 的静态与集成断言、保持三类上限不变，
  并在报告写明这是一次**加性**协议变更（该情形下最终 Sol 聚焦终审改为必选）；
- 若本卡不动上传面，必须在报告 §裁定 明确「上传仍拒绝 HEIC」及理由，并留下一个真实 HTTP 结构化拒绝样本，
  不得让不一致处于未记录状态。
