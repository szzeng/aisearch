## 1. 用户问题与最终验收行为

### Bug 1：100% 预览下，照片下半部分显示不全

- **适合窗口**：整张照片可见，不裁掉上下边缘。
- **预览 100%**：显示的是**加载的预览产物**的 1:1 CSS 像素比例（不是 JPEG/RAW 原图像素 1:1）；超出舞台的区域允许裁切，但必须可以拖动到图片的**上、下、左、右实际边缘**。尤其是竖图、长竖图，拖到最下方要能看到最后一行像素；不应出现底部永久不可达。
- 图片刚打开、100% 按钮、双击、放大/缩小、Ctrl+滚轮缩放、下一张/上一张、横竖图切换、窗口改变后保持坐标正确。舞台始终裁切溢出内容；**弹窗外框尺寸只受视口和响应式断点影响，不随图像比例变化**。
- 鼠标拖动必须可用；触屏如该入口支持拖动，也必须能上下移动，不可由浏览器默认 `pan-y` 吃掉；舞台外的页面/信息栏仍能正常滚动。不误选文字，不遮挡工具栏和关闭操作。缩放模式下 resize 应夹紧平移位置，而非强行改为适窗。

### Bug 1b：双击放大到 100% 后，再双击不能稳定恢复适合窗口

- **明确交互**：整张照片以「适合窗口」显示 → 在照片上双击一次 → 切换到「预览 100%」并保持图片可拖动 → **再在照片可见区域双击一次 → 立即恢复「适合窗口」并让整张照片完整居中可见**；可连续重复切换，不需要点击工具栏按钮。
- 从工具栏点击「预览 100%」进入时，再双击照片也必须恢复适窗；若经 +/−、Ctrl+滚轮或拖动后处于非适窗缩放，双击应统一回适窗；下一次双击才切到 100%。仅双击**图片实际可见区域**，不要双击舞台空白、人物头像、工具栏或图片信息区就触发切换。小图适窗比例本来是 100% 时，两次双击可视觉相同，但缩放模式与按钮状态仍要一致。
- 双击不能误触图片拖动、残留 `pointercapture`、选中文字、触发导航或改变 viewer 外框尺寸；回适窗需清空平移量并重新按当前舞台空间计算。发生实际拖拽而不是点击时不得触发双击缩放。

### Bug 2：照片中点击已识别人物头像，跳入人物相册后出现“没有可用人脸”

- 同一人物从**人物目录点击进入**或从**照片查看器中的人物头像进入**，标题头像的有效展示规则应一致。
- 数据库 `persons.avatar_face_id` 为 `NULL`、保存封面已失效／已移出／被有效排除，但人物仍有有效成员时，使用已有只读有效成员头像投影；不能将“没有手工存储封面”误显示为“没有可用人脸”。
- 手动设置且仍有效的封面优先；自动补选**只作显示**，不悄悄保存数据库，也不得选择其他人物、失效世代、待确认映射或明确排除的人脸。
- 合并后的旧人物 ID 必须解析为 canonical ID；相册标题、照片范围、后续封面更换使用同一 canonical 人物，不因同名或合照随意合并。
- 确实不存在有效人脸时允许明确空态；接口失败应显示错误／重试，不要假装人物没有人脸。保留从照片跳转的现有返回语义。

## 3. 最小施工方案

### A. 预览舞台几何修复

1. **先测再改**：用可复现的隔离合成预览图（800×600 舞台，1200×1600、1600×1200、600×2400 与小图）分别操作 fit、100%、任意缩放。记录 `stage/img.getBoundingClientRect()`、`clientWidth/Height`、图片 `naturalWidth/Height` 与 `transform`；确认加载的预览图本身完整，区分**媒体预览已截断**和**前端显示不可达**。用真实几何判断上/下边缘能否进入裁切窗口，容许约 1 CSS px；仅对 `style.transform` 字符串作断言不算修复。
2. 重点核对 `place-items:center` 与超出舞台尺寸的 `<img>`：grid 隐式轨道的尺寸/布局中心可能不等于 `clampPan()` 假定的舞台中心，**这是待证假设而非已确认根因**。如果测量成立，优先为图像定义明确、与平移公式一致的**舞台中心定位基准**（例如绝对定位 + 明确中心基准），并避免 transform 次序导致中心被重复偏移；否则按实际测量最小修正。四边夹紧应满足刚好见到边缘，不允许额外空白和漂移。
3. 检查 `pointerdown/move/up/cancel/lostpointercapture`：只在有可移动图片且按下有效指针时启动，结束时释放捕获并清理 dragging；单轴溢出只允许该轴移动，未溢出轴居中。特别复核 `.photo-viewer-stage { touch-action:pan-y; }` 对**纵向触控拖动**的竞争；必要时仅在舞台内用 `touch-action:none`（或等价有界策略），不能禁止页面其他区滚动。对触摸主指针、取消及失焦做安全回退。
4. resize、侧栏/扩展区占用变化后：`fit` 模式重新适配；`zoom` 模式保留选定倍率、重新夹紧并在可用区变大时维持合理中心。照片 A→B 或关闭时清空旧缩放/拖动/指针捕获，旧图加载回调和旧 `ResizeObserver` 不得覆盖 B。
5. **双击真实事件链修复**：在现有 `stage.dblclick` 与 `pointerdown/up/cancel/lostpointercapture` 上最小修改，先查清真实双击由 `image` 还是 `stage` 接收，以及单击是否被指针捕获重定向。优先避免普通点击过早捕获（需要拖动时再正确捕获），或使用可验证的图片命中判定；**禁止单纯删掉 `event.target === image` 保护而使舞台空白也能放大**。双击与拖动通过移动阈值、指针状态及捕获释放互不干扰；第一次 fit→100%、第二次 100%→fit，按钮进入 100%→双击 fit，任意其他 zoom→双击 fit 都要成立。不要重复添加全局监听或自造延时双击识别器。
6. 不删除 `overflow:hidden`，不恢复“图片撑大弹窗”的旧行为；不以 `object-fit:contain` 强制 100% 永远缩小来掩盖不可达问题。保留 viewer 的 Back/Esc/完整详情、焦点返回与 10%～800% 范围。

### B. 人物直接跳转头像修复

1. **优先路径**：直接深链 `openPersonById()` 尝试用**一次**有界 `GET /persons/{requestedId}/photos?limit=1` 替代首次 `GET /persons/{id}`；用响应中的 `page.person` 统一取得 canonical `person_id`、revision、名称、计数与 `thumbnail_url`。该额外返回的 1 张照片**仅是接口副产物**：不得预加载整页、将其直接加入时间轴、借此推断全相册或发第二次封面请求。人物目录的正常 `openAlbum(person)` 保持原样。
2. **编码前先核成本**：`/photos?limit=1` 会执行排序分页、时间与人脸投影，不是轻量“只取头像”。核对该接口在**大人物相册**下的查询计划/已有索引与一次深链 HTTP/SQL 次数；与原 `/persons/{id}` 请求作小型有界对照，并区分人物标题可用与时间轴首批照片可见。如果已有接口明显带来不必要的全范围工作或显著变慢，应改为**复用已有单人物展示摘要的最小只读适配方案**，且不更改冻结的 `PersonRecord` 对外字段/语义；如避不开协议或高风险 SQL 变动，记阻断并先评审，不以双请求临时绕过。
3. 初始化相册使用服务端可信 `person.thumbnail_url`，而不是只拼存储的 `avatar_face_id`；沿用 `picture()` 既有 URL 验证、错误占位和 cache-bust。**不把照片查看器当前人脸缩略图直接缓存为该人物的封面**，避免选到不属于人物或后来被排除的脸。
4. 深链成功/失败、无图/无有效脸、redirect canonical、快速点击不同人物、网络晚到响应均不得串人。把**确无有效成员**、**有成员但头像缩略图加载失败**、**接口读失败**分开提示；不要把 404/401/网络错误变成“没有可用人脸”。时间轴模式首次进入、刷新和从照片返回后也须显示当前有效头像。
5. 保留普通人物卡片进入 `openAlbum(person)` 的现有复用路径、头像 DOM 复用及写后刷新；封面更换、合并、移出、人工排除后读取可信有效摘要，不新增自动写入。**不改** `GET /persons/{id}` 旧契约和 URL 返回 `from_photo` 行为；对于缺少人物的深链，原路由与回退控件须可用。

### C. 改动范围与禁止项

- **预计修改**：`src/photo_search/web/photo-info.js`、`photo-info.css`、`persons-albums.js`；必要时仅更新真正引用这些资源的 HTML 缓存版本及直接测试。若只用旧只读接口，后端生产代码不需要改。
- **优先不改**：Python 后端 API/schema、`persons` 权威成员 SQL、缓存/索引和批处理；只有诊断证明无法沿用现有摘要时才评估最小只读接口改动，并先记录原因与协议边界。
- **禁止**：迁移数据库、修改 `PhotoSearchData`、重跑人脸识别／RAW 解码／索引、改变 AI 模型与阈值、自动保存头像、为人物目录或每张照片追加请求、改动时间轴分页/搜索会话/地图范围、重写 viewer 状态机或历史跳转。

## 4. 性能设计与停止条件（PERF-BOUNDED）

- **链路与风险**：用户打开**一张照片**及从该照片点**一个人物**时，风险主要在 UI 重复重排、图片重复下载，以及人物直接跳转新增高成本照片分页／成员聚合；禁止按照片数量 N 或同图脸数 K 的新逐项请求。
- **做法与边界**：查看器几何纯本地、有界；人物直接跳转最多一次必要的权威摘要读取（不得原详情 + 新 1 图请求叠加）。进入人物相册后沿用既有时间轴分页，不新增全局统计、后台循环或持久缓存；若修改高频 SQL，先查 N/K/P 扇出与索引、必要时比较 query plan。
- **验证与停止**：定向断言人物跳转请求数、相册有效头像和实际预览边缘可达；1～2 条隔离浏览器闭环观察流畅度和意外请求。发现明确退化再做小型同输入对照；**本卡不新增 30 万照片或 GTX1660/4060 的性能认证，也不据小样本承诺毫秒延迟**。
