## 必须保持的不变量

1. **失败关闭、无静默丢失**：任何不可读/校验失败的工件都不得产生一条被确认的派生行；
   事件在修复前只能处于未确认状态，并始终可在库中被读到（含 `last_error_code`）。
2. **旧 revision 不回滚最新状态**：`_is_superseded` 与「检查/引擎写/确认同一 `BEGIN IMMEDIATE` 事务」
   两条 P4-01C 纪律原样保持；本卡不得放宽、不得把引擎写移出该事务。
3. **重执行必须逐字节等价**：`ArtifactStore.prepare` 的 payload 校验（canonical JSON 的
   `checksum_sha256` + `byte_size`）是重执行的唯一准入口；重执行得到的向量若与工件记录不一致，
   必须结构化拒绝（`ARTIFACT_INVALID`）而不是覆盖语义。
4. **确认语义不变**：`semantic_ready` 仍只由 `index_entries.state='CONFIRMED'` 加 READY generation 决定；
   本卡不新增任何绕过确认的写入路径。
5. **审计幂等**：在 drain 被卡住的同一状态上重复执行审计，未确认事件数不得增长；
   确有新事实（条目确认丢失、Lance 行缺失、工件被换）时仍必须能重新排程。
6. **一个坏工件不得阻塞其余事件**：隔离只作用于「工件已 `RECLAIMED`（等待重执行）」的事件；
   「工件 PUBLISHED 但内容损坏」仍然失败关闭并把结构化错误交给运维，不静默跳过。

## 必须交付

### 1. A3：审计幂等

`_schedule_existing` 的**审计路径**（`projection_revision is None`）在分配
`MAX(projection_revision)+1` 之前，先检查同一 (space_id, asset_id, generation_id) 是否已存在
**未确认的 `UPSERT_VECTOR` 事件、且它指向同一 artifact_id、且其 revision 就是当前最大值**；
若是则**复用**该事件（不再插入新行、不再抬高 revision），同时仍把 `index_entries` 的
`state` 归到 `PENDING_REPAIR`（诚实反映「尚未重新投影」）。
`schedule_projection_refresh`（显式 revision 的权威投影补查路径）语义**保持不变**。
交付证据：同一卡住状态连续三次审计后 `PENDING` 计数不增长（例如 3 → 3 → 3），
且首次审计时真正缺失的确认仍能被重新排程。

### 2. A2-a：不可读工件的隔离与结构化可见性

领取条件收紧为：**不领取工件处于 `RECLAIMED` 的事件**（`process_next` 与 `process_batch` 用同一条
谓词，避免两套纪律）。语义与边界必须写进代码注释与报告：

- 这**不是**「跳过坏工件」：`RECLAIMED` 只由 P2-03 的修复审计或 `reclaim` 写入，代表
  「该工件已判定需要重执行」；事件本身保持未确认（`PENDING`/`last_error_code`），不丢行、不报成功。
- 「工件 `PUBLISHED` 但内容损坏/缺失」的事件**仍会被领取并以结构化 `ARTIFACT_MISSING` 失败**，
  即失败关闭不变；运维必须先跑审计（`drain --repair`）把它判为 `RECLAIMED`，隔离才开始生效。
- drain 报告新增机器可读块（不改变 `status` 与 `index_summary` 的既有键集）：
  `awaiting_reexecution`，至少含 `count`、有界 `sample`（`event_id`/`artifact_id`/`asset_id`/
  `space_id`/`generation_id`/`projection_revision`/`attempts`/`last_error_code`）与
  `sample_truncated` 标志。
- 重执行发布后，**同一条**事件必须能被正常领取并确认（不依赖新事件），
  即 `semantic_ready` 恢复且 `index_entries.confirmation_revision` 与 Lance
  `projection_revision` 一致。

### 3. A2-b：受支持的生产恢复入口

新增 `photo_search.indexing.maintenance.reexecute_reclaimed_artifacts(catalog, *, encoder, limit, now_ms)`
（名字可微调，报告写明），职责单一：

1. 只读列出 `artifact_type='embedding'` 且 `lifecycle_state='RECLAIMED'` 的工件（确定性顺序 + `limit`）；
2. 经 `jobs` 取 `subject_type='asset'`；经 `file_locations`（优先 `availability='PRESENT'`）+
   `source_roots.root_path` 解析媒体绝对路径；
3. 调用 `encoder.encode_image(path)` 得到确定性重执行输出，校验为**有限数值、长度等于工件 dimension**
   的向量（不足/超长/非有限 → 结构化拒绝，绝不裁剪或补齐）；
4. 走既有 `ArtifactStore.republish_reclaimed`（payload 必须是 `{"vector": [...]}`），
   由 `prepare` 的 checksum/byte_size 校验兜底「非确定性重执行」；
5. 返回逐工件结构化结果（`republished` / `refused` + 错误码 + 原因 / `skipped`），
   一个工件的失败不得中断其余工件；
6. 支持 `dry_run`（只列目标、**不做编码、不写库**）。

`encoder` 是 **ADR-0003 §7 适配器边界的图像半边**：生产由既有的中文 CLIP ONNX 适配器提供
（AI worker 现用 `adapter.encode_image(path)`，本卡沿用同一表面），测试/诊断由确定性注入编码器提供。
**不得**在本卡内引入第二套模型加载路径或改变设备资格契约。

同时给 `python -m photo_search.indexing.cli` 增加受控子命令 `reexecute`
（`--data-root`、`--limit`、`--dry-run`、`--device`、`--device-policy`、`--model-dir`、`--manifest`、
`--json`）：JSON 输出、退出码 0/1/2 与既有命令一致；真实模型路径必须**显式**指定
`--model-dir`/`--manifest`，缺失时给结构化错误且**零写库**；不得默认静默回退到 CPU。

## 必做注入与验收（B + D）

D 级注入（逐条给前后计数，全部走生产入口/生产函数，不自建 replay 循环）：

1. **A2 复现→隔离→恢复全链**：3 个待确认事件，损坏其中一个工件的字节 →
   `drain` 结构化 `ARTIFACT_MISSING` 且零进展 → `drain --repair` → 再次 `drain`：
   健康事件**全部确认**、被回收事件进入 `awaiting_reexecution`、坏工件零派生行 →
   `reexecute`（注入编码器，payload 与原件逐字节等价）→ `drain` 收敛：
   该事件确认、`semantic_ready` 为真、`confirmation_revision == Lance.projection_revision`。
2. **A3 幂等**：同一卡住状态连续三次 `--repair`（或直接调审计）+ 单独调用一次审计，
   未确认事件数**不增长**；同时「删除 `index_entries` 行」这类真实缺失仍必须被重新排程（不得因幂等而漏修）。
3. **非确定性重执行必须被拒**：注入编码器返回与记录 checksum 不等价的向量（例如长度正确但数值不同）
   → `ARTIFACT_INVALID` 结构化拒绝，工件仍 `RECLAIMED`、事件仍未确认、库内零污染。
4. **P4-01C 纪律不回归**：旧/新 revision 交错、并发重领同一事件、`after_lance` 崩溃窗口重放
   三条既有注入在新领取谓词下仍然成立。
5. **前台写不静默丢失**：维护期间的真实前台修订写与 `catalog_filter_revision` 计数逐一相等
   （沿用 P4-02A 判据）。
6. **重启一致性**：中途中断 drain 后重启到的派生状态指纹与不中断一致（沿用 `state_digest` 口径）。
