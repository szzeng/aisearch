## 4. 问题分级：只有 S0 / S1 阻止 RC

### S0 — 数据安全 blocker

任一出现即 **NOT READY**：

- 原图被程序修改、覆盖、移动或删除；
- catalog/index 明显损坏且无法按既有恢复路径恢复；
- 快速刷新造成错误 asset 绑定或大面积错误 MISSING；
- 备份/恢复最小流程无法恢复到可启动状态。

### S1 — 核心使用 blocker

任一系统性出现即 **NOT READY**：

- 应用无法稳定启动/重启；
- 新照片正常刷新后仍长期无法搜索；
- 普通搜索频繁 500/崩溃/完全不可用；
- Web 基本浏览明显无法使用；
- 后台刷新导致应用长时间完全不可搜索；
- 用户当前明确的核心功能存在系统性错误。

### S2 — 可接受限制

不阻止个人试用，进入 Known Limitations：

- 某些操作偏慢但仍可正常完成；
- 个别图片/格式异常；
- 个别查询相关性不理想；
- 可选 face/OCR/GPS 不可用或较晚完成；
- 历史后台正式性能指标略高于目标；
- 浏览器首屏缺自动 P95 证据。

### S3 — 体验/外观问题

例如：

- 文案；
- 布局；
- 状态提示不够漂亮；
- 少量交互不顺手。

直接记入后续 UI issue；**不得阻止 RC**。

## 5. 只跑 5 个真实用户旅程

优先使用用户已经明确授权的真实图库做**只读/非破坏性**操作。

删除、替换、离线、恢复等破坏性场景只在独立小型测试来源/副本执行。

### Journey 1 — 启动、浏览、重启

执行：

1. 正常启动应用；
2. 打开 Web UI；
3. 浏览已有图库、缩略图、详情；
4. 做 2～3 次普通搜索；
5. 正常退出；
6. 再次启动；
7. 重启后再次搜索同一批内容。

通过条件：

- 不需要重新建库；
- catalog/index/profile 保持；
- 页面没有持续白屏/卡死；
- 已有图片仍能正常浏览和搜索。

---

### Journey 2 — 日常增量刷新闭环

使用小型测试来源：

1. 先做一次 no-op “刷新图库”；
2. 增加约 **20～50 张真实图片**；
3. 再刷新；
4. 观察 SCANNING → INDEXING → SEARCH_READY → ENRICHING/COMPLETE；
5. 一到 SEARCH_READY，立即搜索其中若干新增图片；
6. 等待增强阶段自行继续。

只验证真实产品体验，不重做 P4-02Y 30 万实验。

必须确认：

- no-op 没有明显重新跑全库 AI；
- 新照片不需要用户手工再跑 semantic build；
- 到 SEARCH_READY 时已经可搜；
- face/OCR/GPS 等不阻塞 SEARCH_READY；
- 增强阶段失败时核心搜索仍可用。

---

### Journey 3 — 搜索、浏览、上传

使用约 **8～12 条用户真实会输入的查询**，覆盖：

- 人物/关系；
- 场景/物体；
- 时间；
- 地点；
- 中文自然语言组合。

检查：

- 搜索正常返回；
- 第一屏图片正常出现；
- 连续查询不频繁报错；
- 结果整体有实际使用价值；
- 滚动/翻页/详情/preview 正常。

不做 Recall/nDCG，不要求每条 top1 正确。

再做最小上传 smoke：

- JPEG；
- HEIC/HEIF；
- MPO（手头有则测）。

已有格式和性能证据直接继承；这里只验证当前 RC 没回归。

---

### Journey 4 — 后台工作与来源异常

启动一次小批量刷新/增强，同时继续普通搜索。

确认：

- 搜索仍能使用；
- LAGGING 可以接受；
- 不出现持续几十秒完全不可用；
- 不频繁出现合法请求 500/409。

随后对一个可安全操作的测试来源做一次临时离线：

1. 来源暂时不可访问；
2. 浏览/搜索已有内容；
3. 恢复来源；
4. 再次快速刷新。

确认：

- 整源不会被错误判成删除；
- 应用不会因为离线源整体失效；
- 恢复后能继续刷新。

**注意：**
历史 P4-02W D 的 8144.9 ms vs 8000 ms 继续保留为正式性能未闭合事实；本卡不因此自动判个人试用失败，也不得改写成正式 PASS。

---

### Journey 5 — 最小备份恢复

只使用测试 data root：

1. 正常停机；
2. 创建一致性备份；
3. 恢复到新的空目录；
4. 用恢复目录启动；
5. 打开图库；
6. 做 1～2 条普通搜索。

只证明当前 RC 没破坏 P4-05 已经闭合的恢复能力。

不得覆盖主个人图库。

- 某类查询明显搜不准；

- A3；
- ANN / FAISS；

- P4-03B；
- 40 万以上优化；

> **没有 S0/S1 blocker，核心日常流程成立，就开始用。**
