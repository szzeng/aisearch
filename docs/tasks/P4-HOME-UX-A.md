## 1. 用户问题与交付目标

1. **打开首页就很慢，必须解决**：首页先显示可操作的图库入口，不能等待所有来源的完整进度统计；不能只改加载提示。
2. **图库来源不清楚**：首页和照片浏览能直观看出来自哪个图库，不靠资产编号猜测；名称重复仍能区分。
3. **操作不方便**：点击图库直接进入该来源照片；“全部图库”明确可选；管理和分析明细不占据日常浏览主区域。
4. **照片点进去预览很小**：正常详情使用可用视口宽高等比放大显示，横图、竖图和小屏都能完整看图；从首页和搜索进入详情行为一致。

一个主要性能瓶颈：`GET /sources` 把基本来源信息和逐来源全套统计/进度捆绑，首页必须等整个返回。先测这条调用链；若不是实际主要瓶颈，以证据选择同一首页调用链中的真正原因，不扩大到搜索性能专项。

## 3. 先定位，再最小实现

### 3.1 简单定位与前后对照

复用项目内独立合成图库，2～3个来源、约50～100张照片即可；包含横图、竖图和一个重名来源。不连接真实照片目录或 `PhotoSearchData`，不下载或运行模型。

同一环境修复前后各打开首页3次，记录来源接口耗时、图库入口何时可点击，以及照片详情预览可见耗时；记录每次结果和失败，报告中放一张小对照表即可。不要求P95、冷暖多轮矩阵、30万catalog或单独开发benchmark工具。已有计时工具可复用小规模参数，不继续扩大工具范围。

重点核对首页是否仍等待所有来源的完整统计，以及详情是否仍受12rem限制。只有耗时仍解释不清时再查看相关SQL或缩略图生成链路，不做全仓性能调查；基线太快不能宣称已证明真实大图库加速，但仍须证明轻量入口不调用全套统计、明细慢不阻塞首页。

### 3.2 首页轻量读取

- 优先新增受原会话/Host/Origin边界保护的轻量来源读取，例如 `GET /api/v1/sources/summary`；静态路径必须在 `{source_id}` 动态路由前正确匹配。执行时在实现报告先写最终路径/参数/响应字段。
- 轻量返回复用来源行基本字段，不调用 `get_source → catalog_counts` 或全套 `source_progress`，不加载模型、不探测所有原文件。状态只表示来源记录，不能冒充实时磁盘在线证明。
- 原 `GET /sources` 和 `/sources/{id}` 的完整计数/进度语义保持兼容；详情明细按所选来源读取，不在轻量返回后又立即自动发出全部来源重请求。
- 首屏先出图库名称和“查看照片”；照片数、语义资格、扫描状态在取到权威结果后更新，未取得时显示“读取中/待加载”，不得伪造0、完成或可以搜索。
- 每个图库明细独立 loading/error/retry；一个统计慢或失败不能隐藏其他图库。请求数量有界，不能把一次大响应变成无界并发风暴。
- 只在实测有必要时优化直接相关只读SQL，要求结果等价；禁止改schema、写路径、revision、claim、outbox和设备资格。
- 不给“刷新图库”偷偷附加扫描动作；浏览/查看明细本身不扫描或改动原图。若改后台统计调度，先核对SQLite连接与线程归属，不直接跨线程复用连接。

### 3.3 来源可辨识与操作

- 每个图库保留用户显示名，补安全的来源说明（已有 `volume_hint` 有值时使用，不能编造）；重名可附来源编号消歧。
- 卡片提供“查看照片”，绑定该 `source_id`，显示当前图库与可取消筛选；“全部图库”显式入口，切换清理旧游标，拒绝旧请求回写新筛选。
- 照片卡片显示来源名称＋相对路径；可用 `current_location.source_id` 配合轻量来源映射，不为每张照片请求详情。不能把一个 current_location 当成全部来源。
- 多位置继续提示位置数；详情保留全部来源名、相对路径和可用性，不丢掉跨图库重复资产的来源事实。
- 默认不回显绝对路径，保留 `PATH_LIKE` 和错误脱敏。若来源辨识仍需“查看完整根目录”，先写最小展示契约（受保护页面、明确展开、字段/位置、错误脱敏仍有效）及现有路径测试变更理由；不得只删除历史测试绕过边界。本卡不扩展权限/隐私契约；优先用已有名称和相对路径解决辨识。
- 详情返回恢复当前来源、排序、已加载照片与滚动位置；同页状态优先保存在内存，凭证不得进URL或storage。本卡不增加永久浏览历史、自动相册或推荐系统。
- 首页保留清楚的搜索入口，管理动作集中到展开明细/管理区域；不强行重写搜索/地点/人物页面。

### 3.4 预览按视口适配

- `drawDetail` 当前复用 `.thumb-frame`，图像继承 `max-height:12rem`。改为独立详情预览容器/明确限定的样式，解除缩略图高度上限，避免影响网格缩略图。
- 使用视口可用高度（扣除导航/返回按钮及合理间距）和容器宽度，等比 `contain`，默认完整显示图片；不裁剪、拉伸或因固定48rem上限在大屏留出过大空白。
- 浏览器缩放、窗口调整与横竖屏变化后自动适配；竖图宽度由比例决定，不能要求横竖图都铺满宽度。低分辨率原图允许按容器显示，但不声称提升清晰度。
- 继续优先 `/preview`，失败再回退 `/thumbnail`，明确标记回退质量及离线/失败原因，不把缩略图当高清预览，不绕过受控ID读取原图。
- 核对媒体长边1600px和EXIF归一化沿用既有规则；不为CSS问题重建全库预览或修改processor/cache版本。
- 首页浏览及搜索结果详情链接都进入同一修复后的详情。地点相册弹窗只有实际修改时才补查；不扩展地点更正功能。

### 一次浏览器走完使用闭环

用上述合成图库，在普通桌面窗口操作一次：

1. 打开首页，图库名称和“查看照片”先可用，来源信息能辨认；检查一个来源明细加载慢或失败时，其他图库仍可打开。可以用浏览器延迟/受控夹具，不引入大型故障注入工具。
2. 点击一个图库只显示该来源照片，切回全部图库；翻一页，打开照片再返回，筛选和浏览位置保留。
