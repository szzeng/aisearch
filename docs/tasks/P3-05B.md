## 用户场景

用户在一个人物分组中选择若干明确脸并拆分。系统创建一个未命名活动人物，把所选脸作为人工确认成员，源组
保留未选成员与名字。网络重试不重复创建。无后续相关编辑时可补偿撤销；后续改名、合并、脸级纠错、第二次
拆分或新增有效成员时，旧撤销整体拒绝而不覆盖新事实。重启与投影追赶后结果一致。

## 唯一实现目标

实现且只实现：

- `POST /api/v1/persons/{source_person_id}/split`；
- operation type `SPLIT`、item type `SPLIT_GROUP`，以及 split-family 的共享 undo/replay envelope；
- migration `0013_person_split_operations.sql`；
- source/new 人物、所选 face 控制/排除/link、头像、revision、幂等、快照与补偿撤销；
- `PERSON_CHANGED`、搜索投影、face candidate repair；
- 冻结错误码/HTTP/隐私与 OpenAPI；
- `%TEMP%` 或项目测试临时目录内的诊断/故障证据。

不实现人物页、选择器、新旧检测 `face_id` 映射、模型重跑、图片向量重编码或 P3-06/P3-08 功能。

## 数据与 migration

只新增连续 `0013_person_split_operations.sql`，`schema_version 12 → 13`：

- `person_operations.type` 加 `SPLIT`；旧类型和值逐列保留；
- `person_operation_items.entity_type` 加 `SPLIT_GROUP`；`SPLIT_GROUP` 与 `PERSON_BUNDLE` 都用正整数
  `entity_id`/NULL `entity_key`，`FACE_CONTROL` 仍用 NULL `entity_id`/非空 `entity_key`；
- 不新增事实表，不改 `persons`、link/control/exclusion、队列表，不新增 queue cause；
- 按 0012 已证实的 FK 安全重建范式停放/恢复 alias 引用，逐列保留 P3-03/P3-04 operation/item/UNDO；
- `0001`～`0012` 逐字节不变；缺件、损坏脚本、过新库、提交失败均单事务零残留；
- 更新 `SUPPORTED_SCHEMA_VERSION` 与所有必要的 schema-version 耦合夹具；地名示例兼容上限如需机械
  12→13，必须用现有 dataset tool 重建/核对并在报告说明语义未变。

真实 v12→v13 迁移夹具至少含：RENAME/MERGE/FACE/BATCH/UNDO、PERSON_BUNDLE/FACE_CONTROL、alias
`last_operation_id`、original/undo 相互引用，并逐列比对迁移前后。

## 拆分事务与不变量

严格按 ADR-0008：

1. shape/contract/1..500/重复检查后，使用 requested source ID 与排序 face revisions 计算 digest；
2. 全局 request_id gate 在 source/face/revision 检查前；同 payload replay，异 payload
   `PERSON_IDEMPOTENCY_CONFLICT`；
3. 同一写事务重新 canonicalize source，检查 source/control/assignment revision、唯一有效成员、归属、
   MANUAL_UNASSIGNED/exclusion 和 source 至少剩一个有效 sibling；
4. 写 operation 占位，创建 name/name_key NULL、无 alias、revision 1 的新人物，再补 target；
5. source revision 只 +1；新人物不复制名字/alias；头像只在同一 processor/space 的有效成员内选择；
6. 每个所选 face 使用 ADR-0007 assign 的同一规则：MANUAL_ASSIGNED + MANUAL/CONFIRMED 新人物，激活 source
   exclusion，保留其他 exclusion；同图未选 sibling 不变；
7. item 固定为 source SPLIT_GROUP、created SPLIT_GROUP、按 face_id 排序的 FACE_CONTROL；snapshot 为 ADR
   冻结的最小字段，不把 suggestion 纳入 group fingerprint；
8. 任一步失败，person/operation/items/link/control/exclusion/filter/queue 全回滚。

拆分没有业务 no-op。成功和 replay 必须返回同一个 `new_person_id`、operation id/revision 与记录时 filter
revision；replay 不读取当前 live 状态重建结果。

## 通用撤销

扩展现有 `/person-operations/{operation_id}/undo` dispatcher，保留 P3-03 person family 和 P3-04 face
family 的响应、错误与 replay 逐字段不变；新增 split family：

- 幂等门最先；只允许 committed/uncompensated SPLIT 且 operation revision 匹配；禁止 undo an UNDO；
- 严格校验 item family/顺序/数量，不接受混入或缺失快照；
- source/created 人物元数据、alias、redirect、有效成员或任一 selected FACE_CONTROL after snapshot 变化即
  整批 `PERSON_OPERATION_NOT_UNDOABLE`；suggestion-only/不相关实体变化不冲突；
- face/person 消失给安全具名 conflict；redirect 环按 `PERSON_REDIRECT_CYCLE`；坏 schema 走既有拒写；
- 无冲突时 selected face 恢复原 control/effective assignment/exclusion 语义，control/link/person revision
  全部向前；source 头像/成员恢复；created 不删除，清空初始头像并 redirect 到 source；
- 原 SPLIT 标 UNDONE，新 UNDO 保存同 family items/envelope；重复 undo request replay 稳定，第二个新 request
  拒绝且零写。

P3-03/P3-04 的 undo 实现和 companion 不得因 dispatcher 扩展而漂移。

## 权威到派生与读取

changed split/undo 同一事务内只推进一次 `catalog_filter_revision`，cause=`PERSON_CHANGED`；只为所选 face
资产写 `search_projection_queue`，只为当前 generation 已发布的所选 face 排 `PENDING_REPAIR`。不得调用图片
projection refresh，不写图片向量 `index_outbox`，不改 embedding/space/generation。

提交后：source/new 人物与 face 归属从 SQLite 立即正确；人物/照片计数沿用现有权威口径，asset_id 去重；
split 后新人物计入 unnamed，undo 后 created ID canonicalize 到 source。保持现有 face_summary 字段，不新增
不必要计数。

## API、错误与隐私

新增 request/response model 必须与 companion 一致且 extra forbid。唯一 split 路径以当前 session、Host/
Origin、double-submit CSRF 中间件保护。共享 undo response union 加 split family，但 P3-03/P3-04 OpenAPI
shape 不变。

实现 ADR-0008 的闭合错误集与 HTTP 映射；新增 `PERSON_SPLIT_CONFLICT=409`，其他复用现有 code。错误 details
只含安全 ID、expected/current revision、固定 reason/entity 字段。响应、错误、日志、OpenAPI 示例和诊断不得
泄露路径、name/name_key/alias、bbox、landmark、向量、confidence、相似度、payload/hash 或内部快照。

## D 级具名验证

至少覆盖 ADR-0008 §10 的 12 组，并显式包含：

- idempotency gate 早于 later revision/entity missing；
- source、control、assignment revision 三种 stale 独立零写；
- suggestion/unassigned/cross-person/MANUAL_UNASSIGNED/missing/duplicate/empty/501/source-empty；
- AUTO 与 MANUAL confirmed 输入都变为新人物 MANUAL confirmed，其他 exclusions 保留；
- source/new 头像、名字、alias、siblings 与同图他人边界；
- rename/merge/face correction/second split/new confirmed member 后的 undo conflict；
- suggestion-only 和不相关改变不阻止 undo；
- undo 后 revision forward、created redirect、重启可读、旧 created ID 可解析；
- 注入 operation/item/filter/search queue/face repair 中途失败时完整回滚；
- 图片 `index_outbox`、embedding/space/generation 前后逐项不变；
- P3-03/P3-04 operation family 的首次/重放/撤销 envelope 回归。
