## 1. 用户目标与闭环

主要瓶颈：每张照片都要点“原图细节”，增强结果还需要逐脸指定人物。交付同一条自动原图人脸处理链的两个入口：**旧图库点一次，后台补识别待归类照片；以后新建/增量建库自动从原图裁脸，合格结果自动归人**。有歧义或涉及人工保护的结果才留待确认。

沿用30万张长期规模，但本卡只做有界队列和小型验证，不声称30万性能已验。SCRFD仍640一次、ArcFace仍112、buffalo_l及现有.50/.29/.08归属规则不变。根本未检测到的脸不会因原图裁剪保证补出；不做960/1280、分块补检、换模型、调门限、全库强制重检或自动合并人物。

## 3. 一键增强已有待归类照片

1. 在“整理一下”增加“一键原图补识别”，沿用当前来源/图库范围，显示待处理照片数与范围。用户点击即授权应用处理该范围；本次实现未执行真实库。一个点击创建任务并持续补充队列，不要求每20/50张再点一次。
2. 目标从SQLite已有事实选择：机器待归组/机器建议，或SMALL且原图有更多识别像素；按asset去重，一张合照只解码/检测一次。无脸记录、不曾分析、已确认的未命名人物不是同一种失败，不能全混入补识别。纯源图模糊/低检测分数不默认反复增强。未命名分组不因没名字重跑。
3. 按输入revision与处理版本复用成功产物和任务，跳过已增强、不可读/离线、人工未归类/指定/有效排除及OPEN保护的目标脸。合照有合格机器脸可处理整张原图，但不得借同图重检修改受保护的另一张脸。已经算过但尚未发布/匹配的结果只恢复后续步骤，不再推理。
4. 复用持久jobs；任务保存范围、起始边界和进度，每次有界取候选（建议50个asset），处理串行，不把全部ID或原图留内存。重复点击复用同一未完成批次；重启后恢复已存在的工作，不重新遍历磁盘图库或纳入点击后无限新增的照片。
5. 展示总数、成功、跳过、失败、待确认；提供暂停/继续、失败重试。暂停在当前照片检查点生效，不撤销已完成结果；单图失败继续其他图，离线不忙等。关闭网页不丢队列，不要求重新点击每张照片来唤醒；恢复动作仍遵守现有lease和调度边界。

## 4. 新建／增量图库默认自动高清裁脸

- 建库界面的人脸默认策略为“原图裁脸”，可显式选择轻量模式；策略持久化到建库/处理任务，重启和重试不退回另一模式。改变默认策略仅作用于新请求，升级/启动/打开页面不自动给旧图库补跑。
- 从方向归一化原图解码一次，检测继续缩小到640画布，每张检测脸映回源帧、局部裁剪至112再识别；质量指标使用实际识别像素。直接走选定路径，不先跑完整普通识别再为所有照片追加一次增强。没有检测到脸时结束，不运行逐脸识别。
- JPEG不使用draft冒充原图；6000万像素、每图200脸、120秒预算、取消检查和既有真实设备资格保持。一次只持有一张原图，复用模型会话；与建库/补识别共用资源调度，不新增竞争GPU的无限worker。同步解码/单次ONNX检查粒度如实记录。
- 原图离线、超限、推理失败时记录原因、保留已有结果；禁止静默使用预览图并标记“原图完成”。默认策略与任务完成状态分开，不把待确认/仅成功提特征冒充自动归人成功。

## 5. 自动归人资格与人工保护

**先形成最小ADR草案，后接通自动链**；本卡规定目标和门禁，不冻结schema、API DTO或通用模型升级协议。沿用DETAIL-A §4以及ADR-0007/0010/0014；正式决定跨模块身份/协议/数据语义时，按AGENTS完整对齐两份架构/策略文档。

- 区分识别空间与处理profile。同权重/同512维不够；精确记录普通v1/v2与source-crop的允许比较组合，核对权重、模板/RGB/归一化及实际调用，补一次少量合法测试脸的真实已安装模型对照（同人旧→新/新→旧、不同人）。可用3～5张明确授权问题照补个人效果；没有样片/模型证据时保留兼容待验，不用假向量测试宣称跨profile质量已证实。
- 资格通过后接通新版outbox→确认发布→READY候选→association。代表须实际绑定artifact/generation、有效成员和质量，按canonical共享32候选/8代表上限；未知版本拒绝混算，不复制旧向量冒充新版、不因部分增强激活全库新世代。已发布详情产物可复用而不重算，是否开放自动比较是显式有版本的策略，不凭全局布尔值追认全部历史结果。
- 不改普通v2或已发布详情产物的不可变字节/身份；识别输入或配置确有变化时新建对应spec/artifact/config/face/generation身份。历史事件按保存的实际profile恢复。现有association队列按asset唯一，必须证明多profile不互相覆盖丢工作；具体最小队列方案写ADR，不借机建完整升级平台。
- 新版成为目标照片有效机器结果时，同步解决相册/整理页/封面/成员计数与同图占位的新旧重复；旧机器脸不得挡住同一物理脸新版归属，也不能放松合照两个人的冲突规则。自动结果不替换稳定person_id、不后台合并人物；照片显示数量按asset去重。
- 旧名字、人工指定/未归类、有效排除、封面与操作/撤销记录保留；新旧人工脸只经ADR-0010显式映射，唯一高匹配也不自动确认。OPEN hold、映射确认/拒绝/撤销后的requeue和人工repair按实际spec/processor/space/generation执行；零脸保留旧人工锚点/NO_CANDIDATE，撤销重新hold。
- 自动提交在权威事务内重读人工控制、排除、canonical和OPEN状态/期望revision，迟到结果不覆盖用户修改；冲突整笔拒绝。无兼容证据/保护未解除的结果留待人工处理，不自动造重复人物。本卡若只完成批量推理却没有自动归人闭环，须记录部分完成与具体未决项，不能标整体完成。

## 7. 个人项目的必要定向验证

风险级别含D数据/恢复。沿用用户“个人项目，测试不必严格”的限定例外：本卡以小型直接证据替代B/D全量最低回归，不跑所有unit/integration、历史216项、30万容量、打包或跨GPU；此例外只适用于本卡，不豁免以下关键规则。

- 一个小型合成库：机器待归类/SMALL、已增强、未命名有效成员、离线、人工锁/排除/OPEN、合照混合状态；验证选择/asset去重/跳过、重复点击及计数。
- 同一批次暂停→继续、进程重建→恢复、一次发布中断→重放；确认不重复推理、不丢其他profile、单图失败不阻塞后续。复用小夹具，不做全异常排列。
- 一次新建库实际入口到原图profile→发布→自动归属，以及轻量模式/零脸/失败状态；几何、EXIF、局部裁剪/每图一次解码检测直接复用DETAIL-A必要回归，修改默认路径需证明模式选择生效。
- 兼容白名单/未知profile拒绝，旧机器占位与新脸替代，人工迟到编辑不覆盖，映射确认→撤销重新hold。新增/既有代表能用，隔离不制造重复人物；假模型只证明控制流，真实模型对照单独记证据和结论范围。
- 实际前端JS/API最小闭环：一次点击持续处理、进度/暂停/继续/失败重试、旧响应不污染切换范围；session/CSRF及脱敏保持。可用合成浏览器补一次试用，不以无页面截图替代行为验证。
- 指定测试清单在实现报告列清，用`uv run pytest -q <实际定向文件> --junitxml=test-results/P4-PERSON-DETAIL-B-final34.xml`；`.uv-cache`/`.pytest-tmp`项目内。原targeted.xml被并行局部测试覆盖，最终完整34项证据另存，详见报告。Ruff、修改JS的Node语法、diff-check；依赖真变化才更新/核对uv.lock。只读最终计数/退出码，失败展开相关日志。
