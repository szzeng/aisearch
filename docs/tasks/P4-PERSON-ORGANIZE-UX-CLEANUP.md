## 1. 目的与范围

已有「人物 / 合集 / 待整理」一级导航，以及「未命名人物 / 未识别人脸」二级分类；目前日常整理页面仍包含冗余「查看整张照片」按钮、过多说明和工具、底部已忽略长列表。已忽略人脸混合 TEMPORARY / EXCLUDED，无筛选；人物级已忽略与人脸级已忽略入口分散，且「明确排除」未能从日常浏览中消失。

本卡目标：**保留已有功能与业务语义，把日常整理界面做减法；把已忽略集中管理，并让明确排除的内容默认不展示也不预加载。**

必须完成：

1. 删除未识别人脸及已忽略人脸卡片中独立的「查看整张照片」按钮；保留头像打开照片。
2. 「待整理」新增独立「已忽略」二级标签；移走未识别人脸页面尾部已忽略区域。
3. 已忽略区统一人物/人脸入口，并提供「暂时忽略 / 明确排除」服务端筛选；默认仅看暂时忽略。
4. TEMPORARY 人脸沿用原分组；EXCLUDED 人脸采用平铺分页，不运行无效的候选聚合。
5. 精简日常工具栏和卡片文案，高级功能保留可发现入口；明确人物级和单脸级排除的差异。
6. 保护头像预览、批量选择/Shift、归属/撤销、合集、导航历史与数据库安全。

**非目标**：不重写人物识别、聚类、匹配算法；不新增人物管理系统；不新增数据库迁移、不操作真实照片；不开展全仓测试或 30 万规模性能认证。

## 2. 页面与交互合同

### 2.1 导航结构

一级保持：`人物 / 合集 / 待整理`。

「待整理」二级调整为：`未命名人物 / 未识别人脸 / 已忽略`。三个分类只渲染当前列表，不上下堆叠，不增加概览中转页。

- **未命名人物**：保留已分组人物、命名、合并及原相册入口；默认只显示常用操作，「批量管理」后展示批量工具。
- **未识别人脸**：默认显示标题、一个整理原因下拉框、「批量整理」、「更多操作」、人脸列表及候选确认/指定人物操作；不再显示底部已忽略列表。
- **已忽略**：对象选择 `人脸 / 人物`；状态选择 `暂时忽略 / 明确排除`。对象与状态均有清晰选中态，不提供混合「全部」默认项。独立「管理」入口，仅在进入后显示批量工具。

进入规则：
- 从待整理导航正常进入已忽略：默认 **人脸 + 暂时忽略**。
- 从人物列表已有「查看已忽略」快捷入口进入：定位 **人物 + 暂时忽略**；该快捷入口只做导航，不保留第二套隐藏人物列表。
- 主动点击「明确排除」才请求 EXCLUDED 数据；切出并重新从待整理导航进入时重置为默认。
- 关闭照片弹窗、从详情返回当前已忽略页时，保留当次选择的对象/状态、合理的已加载范围及滚动位置。浏览器前进/后退尊重真实历史导航，不把关闭照片误判为切分类。
- 已忽略人物集合须覆盖原来已命名、未命名的隐藏人物；不要因 `state.organize` 或原 kind 筛选遗漏。

### 2.2 未识别人脸默认界面

只常驻：当前类别标题、整理原因筛选、批量整理、更多操作及必要反馈。

低质量显示开关、识别/补匹配、原图补识别、历史及非日常高级操作统一收进相应的「更多操作」/折叠区，不删功能、不搬出用户无法发现的位置。正在运行的识别任务状态、严重错误和可恢复操作即使折叠也必须有必要提示；折叠菜单不会停止后台处理。

把重复的大段说明改成短帮助或 tooltip，不要在每张卡片重复提示「点击头像查看照片」。

### 2.3 人脸卡片

复用 `persons-albums.js::renderInboxFace()`：

- 删除「查看整张照片」独立按钮及其事件、显隐和无用引用；未识别、已忽略同时删除。
- 人脸头像普通点击以及 Enter/Space 打开同一张原照片；保留焦点可见性、已有 hover 和照片关闭返回机制。
- **批量模式仍然头像查看照片、卡片底框/checkbox 选择、Shift 连选**；头像打开不得改变选集或 Shift 锚点。
- 候选参考头像仅用于对比，不得变成误打开照片或误选择入口。
- 有建议时保留「确认是某人 / 选其他人」；无建议时可显示更直观的「指定人物」，但不得删新建/选择人物能力。
- 明确排除的人脸不再渲染自动建议，不伪造匹配结果；人工恢复、照片浏览和原有合法操作仍可用。

不得回退 `P4-PERSON-AVATAR-CLICK-A` 和 `P4-PERSON-NAV-IMPLEMENT-A` 的现有行为。

### 2.4 批量整理

默认不展示长排批量按钮；进入「批量整理」才显示当前对象的选中数、全选/反选**已加载**、清空选择及写入操作。

未识别人脸建议把「忽略方式下拉框 + 提交」改成两个直观动作：
- `暂时忽略所选人脸` → `TEMPORARY`
- `排除所选人脸` → `EXCLUDED`

保持复用 `POST /faces/inbox/visibility` 和原确认/保护机制。其他已有「移到已有的人物」「从人物移出」「恢复自动判断」「加入合集」等能力可分组收起，但不能失去入口。

已忽略的人物、人脸分别在管理模式显示恢复所选、加入合集等**原本已有且合法**的操作，不要为了视觉统一新增不支持的动作。恢复只移除对应忽略标记，不修改照片或人工身份事实。

统一文案：
- 人物：`暂时忽略所选人物 / 排除所选人物`。
- 单脸：`暂时忽略所选人脸 / 排除所选人脸`。
- 筛选标签：`暂时忽略 / 明确排除`。

短说明必须明确：人物级 EXCLUDED 不再作为正常自动匹配人物候选；单脸 EXCLUDED **仅排除该 face_id 的自动匹配**，不永久阻止未来新图库中其他同人脸被识别。不要把单脸排除升级为全局人物黑名单。

## 3. 后端只读筛选

当前接口：
- `GET /faces/inbox/hidden`
- `GET /faces/inbox/hidden/groups`
- `GET /faces/inbox/hidden/groups/{group_key}`

增加可选 `ignore_state=TEMPORARY|EXCLUDED`，按现有 API 规范校验。

要求：
1. 新页面发请求时**必须明确传状态**；未传保持现行兼容语义，非法值 422。
2. 筛选在 SQL 层完成；禁止读取全量后在浏览器过滤。
3. TEMPORARY 仍采用原候选组/单张混合卡片；列表、候选分组、组内展开、代表人脸和分页都绑定 TEMPORARY。
4. EXCLUDED 优先读取普通平铺人脸接口及 Keyset 分页，不再触发候选组分组请求；不展示自动建议。已确认归属而不符合隐藏收件箱资格的脸仍遵守既有有效成员过滤。
5. 游标绑定 `ignore_state`、接口/分组范围和现有必要 revision；切换筛选须丢弃旧游标，跨状态重用游标安全拒绝，不能错页/漏页/混页。
6. 请求返回过期时不覆盖当前页面；恢复/写入后按当前筛选重读受影响列表，失效的游标不能继续翻页。
7. 保留 `GET /persons` 的现有 `visibility=hidden&ignore_state=...` 筛选能力；不新建重复人物接口。

不要为了一个状态筛选复制整套人脸分组 SQL，也不要改候选/归属的真值来源。

## 4. 前端状态与安全

在现有 `libraryView` 上增加 `ignored`，保留 `people / collections / unnamed / faces`。扩展 `person_view` 路由解析和必要的导航焦点/标题/返回提示；兼容原详情、旧入口和现有 URL 历史规则。

分别维护人脸/人物对象选择与忽略状态；继续复用 `selectedPeople`、`selectedInboxFaces`、`selectedHiddenFaces` 各自选择集合，不混用 `person_id` 和 `face_id`。

- 对象或状态切换时，清除不再适用的选择、Shift 锚点与游标；不在新标签中提交旧标签的选择。
- 继承写入中禁切换、`pendingWrite`、stale 请求、防重复提交及 500 项上限等现有安全保护。
- 取消/淘汰已隐藏区域的旧请求、计数与分页观察者；同一照片预览关闭不触发错误的页面重载。
- 继续复用现有 `directorySnapshots`、`syncLibraryView()`、`setLibraryView()` 等机制，不另建独立状态机。

## 5. SQL 性能与数据边界

目标规模约 30 万张照片，但本卡仅做针对性的查询设计核对，不执行规模压测。

- 只读当前可见对象与状态；默认进入已忽略**零 EXCLUDED 读取**。
- 平铺 EXCLUDED 不进行无意义的候选聚合；TEMPORARY 沿用原分页分组。
- 不为标签计数新增逐次全图库 `COUNT(*)`，无需展示昂贵精确总数。
- 按当前页批量读取必要详情，避免新增 N+1。特别关注 `inbox_hidden_group_page()` 当前按卡 `read_one` 的路径：能在小范围安全批量化则顺便优化，否则记录为已知性能风险，不扩大成本。
- 优先使用现有索引；仅有 `EXPLAIN QUERY PLAN` 等证据证明必要时再考虑最小增量索引，不提前增加 schema migration。
- 不额外重建向量索引、重跑模型、聚类或全图库扫描；不因只读筛选修改全局 revision 写入语义。

现有 `person_hidden` 与 `face_inbox_hidden` 已保存 `ignore_state`。原则上**不做数据库迁移**，不删除原人物、人脸、图片或任何人工确认、排除、合并、撤销记录。

## 7. 简单验收与交付

使用隔离合成数据，不访问真实图库。直接相关场景：

| 场景 | 必须观察 |
| --- | --- |
| 卡片 | 两类人脸无「查看整张照片」独立按钮；头像看照片，底框/checkbox/Shift 可选且互不干扰 |
| 默认筛选 | 进入已忽略只加载 TEMPORARY；EXCLUDED 只有主动点击才读取；两状态数据不混 |
| 分页 | TEMPORARY 候选组展开、EXCLUDED 平铺与多页正确；错状态/过期游标拒绝 |
| 人物/人脸 | 已命名与未命名的隐藏人物均可找到；身份、照片和隐藏脸按各自 ID 管理 |
| 恢复/归属 | 仅恢复当前选择；人工确认、排除、归属、合集及写入失败保护不回退 |
| 导航 | 二级标签、从人物快捷入口跳转、照片关闭、详情返回、前进后退和延迟响应正确 |
| SQL | 状态从 SQL 层过滤；无明显新增多余请求、N+1 或无关统计 |

完成时运行直接相关 pytest、修改 JS 的 `node --check`、修改 Python 的 Ruff、`git diff --check`。浏览器环境可用则用既有隔离合成数据做简短产品内置浏览器检查；不可用或用户自行验收时如实记为未运行，不虚报浏览器 PASS。
