## 2. 目标体验：保留一级导航，整理内部做减法

保留一级导航：`人物 / 合集 / 待整理`。

待整理二级：`未命名人物 / 未识别人脸 / 已忽略`。三个只展示当前列表，不增加概览页、重复包屑或第二套导航。

| 页面 | 日常默认显示 | 管理时显示 |
| --- | --- | --- |
| 未命名人物 | 现有分组卡片、命名及常用操作 | 原有批量管理/合并/忽略等 |
| 未识别人脸 | 整理原因筛选、人脸卡片、候选确认/指定人物、`批量整理`、`更多操作` | 选中数、选择工具、暂时忽略/排除、人工归属、合集等 |
| 已忽略 | 对象 `人脸/人物`，状态 `暂时忽略/明确排除`，当前结果与 `管理` | 仅当前对象可用的恢复、加入合集等既有合法操作 |

**已忽略默认仅显示「人脸 + 暂时忽略」。明确排除需要用户主动切换，默认不查询、不预加载、不显示排除记录。** 不提供会混合两种状态的日常「全部」入口；原 API 不带参数的兼容语义仍保留。

进入/返回合同：
- 从「待整理 → 已忽略」正常进入：默认 `人脸 + TEMPORARY`；从人物原「查看已忽略」快捷入口进入：直达 `人物 + TEMPORARY`，该按钮不再切换原人物列表为另一个隐藏模式。
- 从其他一级/二级分类**重新主动进入**已忽略时使用上述默认；仅关闭照片或从人物相册返回、浏览器历史恢复时保留当前主动选择的对象/状态及合理的列表位置。
- 未命名人物、普通人物、合集和原人物相册都保留独立筛选与返回上下文。已忽略人物须覆盖原隐藏的**已命名及未命名**人物，避免沿用当前 `state.organize` 限定导致漏项。

### 2.1 卡片、按钮与工具收敛

- 删除待整理和已忽略人脸卡中的 `查看整张照片` 按钮，包括事件、显隐、无用引用和测试旧断言；**不增加替代文字**。
- 人脸头像点击或键盘 Enter/Space 打开原照片；批量模式中头像仍打开照片，卡片底框/checkbox 仍选中，Shift 仍连选。头像预览不得修改选择或选择锚点；候选**参考头像**不能误被当成可选脸。
- 正常模式保留「确认是某人」「选其他人」「这是谁？」等原有效功能。需要时仅把「这是谁？」改成更明确的「指定人物」，必须仍可选择已有或合法创建人物。
- 未识别人脸首屏移除冗余介绍、长段合集说明和常驻高级操作。原有整理原因下拉框保留，不新造另一套筛选；低质量筛选、补匹配/原图补识别、识别更新待确认、历史和其他低频入口统一归入可发现的「更多操作」及现有折叠区；进行中的批次状态、失败/可恢复信息仍可见。
- 默认不展开批量工具；进入批量模式才出现选集及可用动作。不要为简化界面删除功能或触发额外读取。

### 2.2 已忽略的两种呈现

- **TEMPORARY 人脸**：继续按现有「候选人物分组 + 单脸」展示，保留原候选/参考、展开、逐脸确认/指定人物、管理、恢复能力。
- **EXCLUDED 人脸**：使用 `GET /faces/inbox/hidden` 的普通人脸分页，呈现单脸网格；不运行候选分组接口，也不输出自动推荐。仍可点击头像浏览照片、批量选择及恢复。不能挪用合集静态脸列表。
- **已忽略人物**：使用现有 `GET /persons?visibility=hidden&ignore_state=...` 的人物数据，保留人物卡片和原合法操作。人物/单脸保持各自 ID 和写接口。

文案按范围区分：`暂时忽略所选人物 / 排除所选人物`、`暂时忽略所选人脸 / 排除所选人脸`；状态筛选仍是 `暂时忽略 / 明确排除`。简短说明：人物级 EXCLUDED 令该人物退出正常自动匹配参考；脸级 EXCLUDED 仅保护被标记的 `face_id`，不封禁以后新图库出现的同一人。原照片依然在图库。

## 3. 后端只读接口：可选状态筛选 + 稳定分页

涉及：

- `GET /faces/inbox/hidden` → `inbox_hidden_page()`
- `GET /faces/inbox/hidden/groups` → `inbox_hidden_group_page()`
- `GET /faces/inbox/hidden/groups/{group_key}` → `inbox_hidden_group_faces()`

三者增加可选 `ignore_state: Literal["TEMPORARY","EXCLUDED"] | None`，从 FastAPI 路由准确传至 `persons/albums.py`。不带参数沿用旧读取和旧游标协议；非法状态返回 422。**UI 对已忽略人脸的每个请求都显式传状态**。

查询边界：

1. 在 `face_inbox_hidden.ignore_state` 的 SQL 条件中直接过滤；候选分组外层、代表脸二次读取、展开组内查询与过滤一致。不可在前端全部加载再筛。
2. 保持当前有效成员排除规则（`_HIDDEN_INBOX_WHERE` / `_NO_MEMBER`）及人工归属可见性，禁止将已确认有效成员因隐藏标记重新放回待整理。
3. TEMPORARY 沿用当前分组 CTE；EXCLUDED 日常 UI 只调用平铺页。兼容性需要的旧混合分组 API 无参行为继续工作，不需要为 EXCLUDED 新造候选组。
4. 所有**带 ignore_state**的 cursor 都绑定状态、接口种类、组键和当前相应的 revision；跨 TEMPORARY/EXCLUDED、跨平铺/分组、跨不同候选组重用游标应返回原项目规范的错误，不能漏项或串项。无筛选旧游标保持兼容；不要把纯展示状态写入全局 revision。
5. 恢复/隐藏后按当前筛选失效并刷新当前页，过期响应丢弃；不能在已提交后错误地继续翻旧游标。慢请求、切页及重试同样绑定当前状态。
6. 仅修改读取投影与必需的查询包装，不改 `set_inbox_visibility()` 的原有写入行为、人工判断协议或事务规则。

人物已忽略复用现有 `visibility=hidden + ignore_state` API，不新增第二套人物隐藏接口。

## 4. 前端导航与状态：尽量复用，不复制系统

现有 `libraryView` 包含 `people / collections / unnamed / faces`，本卡加 `ignored`，扩展 `person_view` 路由解析、`syncLibraryView()`、`setLibraryView()`、入口事件、目录标题/返回标签和需要的分页门禁。

核心做法：
- 将现有 `#pa-inbox-hidden-*` 控件及结果区迁出 `#pa-inbox`，放入独立 `#pa-ignored` 区，复用已有 IDs、渲染、选择和恢复逻辑；布局调整后的 CSS、显隐条件、事件绑定一并校正，不复制两份 DOM。
- 原 `loadHiddenFaces()` 拆分或参数化为「TEMPORARY 分组 / EXCLUDED 平铺」两种读取路径，不能在 EXCLUDED 模式沿用组装 `page.cards` 的代码；保持组内 `loadInboxGroup()` 的 hidden 路径显式传递状态。
- `peopleDirectoryActive()`、`inboxDirectoryActive()`、`refreshPeopleViews()`、`loadLibraryView()`、`peopleValues()`、目录快照、观察者及 `AIPersonTools` 的整理入口必须逐个核对。**切换至已忽略时不能还隐式加载普通未识别人脸、人物目录或补识别工具**。
- 保留合集列表按需加载/缓存失效、筛选控件刷新、头像预览、共享查看器历史和已有返回快照；这轮刚修好的合集版本/过期响应、首次加载合集选项、移出计数不得回退。
- 分开保存「已忽略对象人脸/人物」和「当前忽略状态」；不混 `selectedPeople`、`selectedInboxFaces`、`selectedHiddenFaces`。切换对象或状态时清选择、Shift 锚点、过期 cursor 和不可信的数据；批量上限 500。
- 写入中遵守 `writing`、`pendingWrite`、未知结果及 revision/instance 安全边界；操作成功才更新界面，失败/冲突不伪装成功。关闭照片应只关闭照片，不退回人物首页。

## 5. 数据与性能边界

数据库已有 `person_hidden.ignore_state`、`face_inbox_hidden.ignore_state`，本任务**预计无迁移**，不得重建表、迁移旧状态、批量修复历史数据、重跑模型或向量索引。此前合入的 `0032` 和 `0033` 迁移保持不动。

- 不为标签数字新加昂贵 `COUNT(*)`；首屏只读当前类型+状态，明确排除默认零请求。
- TEMPORARY 延用原分组语义；EXCLUDED 采用 Keyset 平铺、每页上限与现有接口一致。
- **N+1 关注点**：隐藏分组 `inbox_hidden_group_page()` 代表脸 `read_one` 和 `_face_view()` 每脸多次读取仍存在。新增功能不能扩大调用次数；如能在局部安全改成「当前页批量预取」则执行，若牵涉广泛共享业务，应在报告明确剩余开销并保留独立优化边界，不强制大改。
- 先复用现有索引，必要时用 `EXPLAIN QUERY PLAN` 核对状态过滤与分页；**不因新合入 `0033` 就自行追加迁移**。如索引确需新增，应说明证据、迁移兼容/回滚/拒绝路径及相应验收，再确定是否纳入同卡。
- 不改变 SQLite 数据写入真值源、全局资源 revision 或合集版本语义；不新增全量计数、扫描、自动重聚类或隐藏类别预加载。
