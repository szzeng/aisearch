## 冻结实现范围

### 1. `0006` 增量迁移：`search_documents` + FTS5 外部内容表

- 新增连续 migration（编号按届时实际序列，预期 `0006_*`），**不得修改 0001～0005**，并沿用既有
  目标 schema 校验器：单事务推进、迁移前备份、注入损坏整体回滚、缺件 `SCHEMA_INCONSISTENT`、
  过新库 `SCHEMA_TOO_NEW` 且零写入。
- `search_documents` 以 `asset_id` 为 `INTEGER PRIMARY KEY`（外键到 `assets`），字段按主架构 §4.3
  分开：`filename_text`、`user_text`、`ocr_text`、`caption_text`、`tag_text`、`place_text`，
  外加 `tokenizer_version`、`fts_generation_id`（或等价世代列）与 `updated_at`。
- FTS5 使用**外部内容表**并显式维护 `rowid = asset_id`；所有写入/更新/删除都在调用方事务内完成，
  禁止依赖「另一张表刚好 rowid 相同」。必须有 update/delete 用例（删除资产后 FTS 无残留行、
  重扫改名后只留一份词条）。
- **只写真实来源**：P2-04 只填 `filename_text` 与 `place_text`。OCR/caption/tag 属 P3-01/P2-05，
  本任务必须把这四列留空（写入 `''` 而不是伪造内容），并在报告中记录该边界；`user_text`
  在现有 API 没有备注写入入口，同样只预留列（不得临时发明备注 API）。
- `filename_text` 只放**文件名本身**（basename，含扩展名），不把目录路径或绝对路径写入 FTS 文本
  （避免把本机目录名当检索词；需要时由 SQLite 位置字段提供）。这是本卡记录在案的边界，
  变更它需要先更新架构说明。

### 2. 受控 MATCH 构造器与 tokenizer 世代

- 新增 `src/photo_search/search/**`（或等价单模块）：确定性分词 + 受控 MATCH 构造 + 查询执行，
  不引入 ORM、不引入第二套数据库。
- 每个 token 单独引号转义后再拼 MATCH；AND/OR/短语策略固定、可测试、写进报告（例如：默认按
  token 全 AND、显式带引号的短语按短语处理）；所有值参数绑定，不把用户输入直接拼进 SQL。
- 空查询、只有特殊字符（`"`、`*`、`(`、`)`、`-`、`NEAR`、`MATCH` 等）、超长输入必须是**结构化
  422**（可复用 `VALIDATION_ERROR`/`INVALID_*` 之一并在报告中写明），不得变成 500 或空结果。
- 用例必须覆盖：中文、英文、数字、文件名片段（含扩展名、`IMG_0001`、全角/半角）、中英混排、
  停用词（不能因为停用词退化成「必须全词命中」）、显式短语、FTS 特殊字符。
- `tokenizer_version` 与 `fts_generation_id` 必须能从 `search_documents` 与查询路径两边读到；
  分词配置变化只重建 FTS，不重新跑 OCR/模型推理。
- **依赖边界**：`jieba` **不在** `uv.lock`。若判断必须新增第三方分词依赖，先停下并向用户报告
  （属 §2.1 依赖决策，不由本卡自行决定，也不得顺手写入 `pyproject.toml`）；默认路径是用标准库 +
  已实测的 SQLite FTS5 tokenizer 实现确定性分词版本。

### 3. 有效地点文本投影（`place_text`）

- `place_text` 只能包含**当前有效地点**：ACTIVE `MANUAL_ASSIGNED` 的规范名 + 完整祖先链 +
  ACTIVE 别名（含 DATASET 来源别名）。
- 以下一律**不得**写入：`SUGGESTION_ONLY` 候选、被排除地点、`MANUAL_UNASSIGNED`、
  `AUTO_ALLOWED`（无有效地点）、`RETIRED` 地点、`DIRECTORY`/`ASSIGNED` 之外的状态。
  必须有一条「同一资产既有候选又无有效归属时 `place_text` 为空」的用例，以及一条「候选地名
  不出现在 FTS 命中」的用例。
- 地点条件仍由 SQLite 关系过滤（`place_ids`/`place_state`）权威判定；**文本命中不证明拍摄地**，
  命中说明必须能区分「人工指定」「有效归类」与「文字命中」。
- 库名/别名文本只进 FTS 投影；`catalog.db` 仍是唯一人工知识权威。

### 4. 改名/别名/层级变化后的重投影

- 复用 P2-03 的投影刷新入口与 outbox/`index_entries`：目录改动在**短事务**里只递增一次
  `catalog_filter_revision` 并持久记录受影响集，大批量派生**分批**执行，
  **不得**在长事务里逐图重写全库。
- 查询期间必须读 SQLite 最新名称；投影滞后时按 outbox/index_entries 识别影响集并补查，
  不允许「只删旧命中、漏掉新归类」。
- 用例：改名 / 编辑别名 / 未来层级变化（本任务可用受控目录更新模拟）后，受影响资产的新名称与新
  祖先在 FTS 中可见；无冲突改名可被既有 undo 语义补偿；**投影中断后重跑不产生重复行**。
- 位置整理不得改动 `space_id`、不得重新编码图文向量、不得改写 `created_at`/`time_desc`。

### 5. 最小检索表面（加性、可关闭）

- 允许在既有只读 `GET /assets` 上**新增可选参数**（例如 `name=` 或 `text=`），语义为「文件名/
  有效地点文本命中」，与 `source_id`/`place_ids`/`place_state`/`availability` 等条件 AND，
  **不改变既有游标空间**与既有排序；不给参数时行为与今天逐字节一致。
- 也可以只交付服务层 API + 测试，由 P2-05/06 决定对外形状；若加参数，必须在 OpenAPI/模型中
  声明、在报告中给出契约，并保持既有 P1-04/P2-03A 测试原样通过。
- 本卡**不得**实现 `POST /search`、融合/排名（RRF）、search session/游标、反馈、SearchProfile
  切换或任何语义召回；这些属于 P2-05/P2-06。不得添加搜索页面（P2-07）。

### 6. 隐私与边界

- FTS 文本中不得出现精确坐标、绝对路径、原始 EXIF、`request_id` 载荷或任何凭证。
- 坐标仍只出现在会话保护的 `/assets/{id}/geo`；通用响应只给地名摘要。
- 沿用既有 session/Host/Origin/CSRF 边界；不新增绕过写入边界的路径。

```text

```

因本任务预期新增 migration 与投影恢复路径，**必须同时完成 D 级故障注入/恢复**（在报告里逐项记录
命令、结果与未验证项）：

1. **migration**：v5→v6 正常升级（备份内 `schema_version=5` 且无新表；单事务推进；旧行逐列不变）；
   注入损坏脚本整体回滚；缺目标对象 `SCHEMA_INCONSISTENT`；过新库 `SCHEMA_TOO_NEW` 零写。
2. **FTS 内容一致性**：更新/删除后 FTS 与 `search_documents` 一致（无孤儿行、无旧词条残留）；
   删除资产后其 FTS 行消失；重扫改名后只留新名称。
3. **投影重投影**：改名 → 受影响资产集被持久记录 → 分批派生 → 中断后重跑不重复、不丢新命中；
   投影滞后期间的查询仍以 SQLite 权威状态为准并给出可识别的滞后/补查信号。
4. **候选隔离**：只有候选（无有效归属）的资产 `place_text` 为空且不出现在地点文本命中；
   人工指定后立即可见（含祖先与别名）。
5. **MATCH 边界**：特殊字符/空白/超长输入 → 结构化 422（不是 500，也不是静默空结果）；
   中英数字混排与显式短语命中符合报告写明的策略。
6. **既有不变量**：`schema_version` 之外的一切既有测试原样通过；`catalog_filter_revision`
   在一次目录改动中至多 +1；`suggestion_revision` 不受 FTS 投影影响。
