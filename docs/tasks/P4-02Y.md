# P4-02Y — 一键刷新图库：扫描变化 → 增量派生 → 可搜索

**状态：READY（未实施）。**

推荐执行：**DS-H / DeepSeek V4.1 Flash / 高推理**。  
实现完成后：独立新会话 DS-H 做**窄受影响面工程主审**；仅当实现必须改变既有 ADR、schema、既有 API 错误语义或搜索契约时再加 Sol 聚焦终审。

## 1. 目标

给个人试用版增加一个真正可日常使用的 **“刷新图库”** 能力：

> 用户登记好一个或多个照片目录后，以后只需点一次“刷新图库”，系统自动重新扫描来源，识别新增 / 删除 / 改名 / 移动 / 内容替换，并只为需要处理的当前内容补齐派生结果；已经完成且输入版本未变的资产不得重新跑 AI。

本卡解决的是**手动刷新闭环**，不是实时文件系统 watcher。

用户期望：

1. 新增一个来源目录后，不需要重建已有 30 万资产；
2. 已有来源里增加/删除/移动/替换照片后，一次刷新即可更新 catalog；
3. 新增/变更照片自动进入当前语义索引并可搜索；
4. 已完成的旧 embedding / 缩略图 / 派生任务保持复用；
5. 来源离线、单张坏图、处理器不可用时如实报告，不把旧数据误删，不假装“全部完成”。

## 2. 现有能力必须复用

不得另写第二套扫描、内容身份或索引逻辑。

直接复用现有生产入口/服务：

- CatalogService.register_source
- CatalogService.run_scan
- scanner.execute_scan
- semantic.build_index
- semantic.ensure_search_profile
- CatalogService.generate_thumbnail
- taken-time 现有 target / enqueue / run 入口
- face 现有 target / enqueue / run / association 入口
- OCR 现有 target / enqueue / run / projection 入口
- 既有 outbox / generation / jobs / projection / authority 语义

现有不变量保持：

- 原图只读；
- 完整 SHA-256 是内容身份；
- 只有完整成功扫描才可产生 MISSING；
- 来源离线不能被当成“全部删除”；
- 同内容多位置共享 asset；
- 改名/移动不改变内容身份；
- 当前 generation / processor / input revision 已完成的工作必须幂等复用。

**本卡不得为了加快刷新而用 size/mtime 代替 SHA-256 内容身份，也不得修改 ADR-0002。**

## 3. 产品入口

### Web

在“来源与扫描”页面增加一个明显的：

**刷新图库**

按钮。

保留现有每个来源的“扫描”按钮，不删除、不改变语义。

刷新期间页面至少显示当前阶段：

- 扫描来源 x/y
- 更新语义索引
- 更新缩略图
- 更新拍摄时间
- 更新人物
- 更新 OCR
- 完成 / 部分完成 / 失败

不要求复杂进度条，文本状态即可。

### API

增加一个有界的本机维护入口，例如：

POST /api/v1/library/refresh

返回 **202**，不得阻塞 HTTP 请求直到全部处理完。

再提供只读状态入口，例如：

GET /api/v1/library/refresh

或等价的单一当前刷新状态接口。

具体路径可按现有 routes 风格调整，但必须保持：

- 同一进程最多一个 active refresh；
- 重复点击时不得并发启动第二套全库刷新；
- 可返回“已在运行”的当前 refresh，而不是重复执行；
- 不新增数据库 schema 仅为了保存 UI 进度。

刷新进程若被杀，允许 UI 状态丢失；底层阶段必须依赖已有幂等性，重启后再次点击刷新可以安全继续。

## 4. 刷新流程

顺序固定为：

### A. 扫描所有登记来源

按稳定顺序逐个调用现有生产扫描。

对每个来源：

- ONLINE：正常扫描；
- SOURCE_OFFLINE / ACCESS_DENIED：记录该来源失败/阻塞，继续其他来源；
- 不得因为一个来源离线就把其未见文件标为 MISSING；
- 不得并行跑多个来源扫描。

记录每来源：

- files_seen / enumerated
- assets
- locations
- locations_missing
- scan state / error

### B. 语义索引增量补齐

扫描阶段结束后，复用当前真实模型/manifest/runtime 配置和同一 encoder 实例。

循环调用现有 semantic.build_index 的有界批次，直到当前 generation：

- targets == 0，或
- selection 明确 coverage complete。

要求：

- 已有 CONFIRMED + 当前 input_revision 的资产不重算 embedding；
- 新来源中的重复内容不得重复编码；
- 只补当前缺失/过期 generation；
- 不新建第二套向量数据库；
- 不修改当前模型、space、distance 或搜索排序；
- 全部批次完成后才调用/确认当前 search profile 可服务。

必须防止默认单批 limit=5000 导致“只刷前 5000 张就显示完成”。

### C. 缩略图增量补齐

复用现有 content-addressed media cache。

刷新当前 PRESENT 资产的 thumbnail：

- 已有当前 processor/version 的 published artifact 直接复用；
- 新内容才真正生成；
- 已知 deterministic failure 不得无限重试；
- 不自动生成全库 preview，preview 继续按现有按需策略。

### D. 轻量元数据 / 人物 / OCR

复用各自已有的 input revision + job identity，**不得 force 全量重跑**。

依次让：

- taken-time
- face
- OCR

补齐当前缺失任务。

要求：

- 同一 asset + input_revision + task_type + processor_id 已成功时不重新推理；
- 新增/替换内容产生新 input revision 时才进入新任务；
- 对已存在 30 万资产不能因为“刷新图库”而强制重新做人脸/OCR；
- face/OCR 权重或运行能力不可用时必须记录该阶段 SKIPPED_UNAVAILABLE / 等价明确状态，不得把整个 catalog 回滚，也不得伪装为已完成。

如果现有 target 选择会枚举全部资产，可以接受一次只读选择，但不得生成重复作业或重新推理已完成资产；若为了个人体验需要优化选择，只允许做**语义等价的 delta selector**，不得改 job identity。

## 5. 删除 / 改名 / 替换语义

至少验证：

### 新增
原库已有资产，再新增 N 张真新照片：

- catalog 只增加新内容；
- semantic 只新增 N 个需要的 embedding（扣除重复内容）；
- 旧 embedding 不重算。

### 重复内容
在新目录复制一张已有照片：

- assets 不增加；
- 新增一个 file_location；
- 不重新生成该资产 embedding。

### 删除
删除来源中的照片后刷新：

- 完整成功扫描后旧位置变 MISSING；
- 不物理删除原 asset / 人工事实；
- 搜索按既有 availability/authority 规则处理。

### 改名 / 移动
同内容改名或移入子目录：

- 内容 asset 身份保持；
- 不重新生成 embedding；
- 位置事实按现有 scanner 语义更新。

### 同路径内容替换
用不同图片覆盖原文件：

- 新内容必须得到新的/已有对应 asset；
- 旧 asset 不被就地篡改；
- 新内容进入增量派生；
- 旧内容的历史派生不错误继承给新内容。

## 6. No-op 刷新是关键验收

在一次完整刷新全部成功后，**不修改任何照片，立刻再点一次“刷新图库”**。

第二次必须满足：

- 扫描可以重新走现有完整扫描；
- 不新增 asset；
- 不新增 location；
- semantic 新编码数 = **0**；
- thumbnail 新生成数 = **0**；
- taken-time / face / OCR 不产生新的同 revision 工作；
- 当前 generation / profile 不发生无意义切换；
- 搜索结果前后保持一致。

注意：当前 scanner 为正确性会完整枚举并对文件做内容确认，本卡**不承诺 no-op 扫描是秒级**，也不在本卡实现 Windows watcher / USN Journal / size+mtime 快速跳 hash。

若后续真实使用认为全量 rescan 太慢，再单独评估文件监听或安全扫描加速；不得夹带进本卡。

## 7. 失败与恢复

必须验证：

- 刷新中杀进程后，重新启动再刷新可以继续，已完成派生不重复；
- 单张坏图不终止整个图库刷新；
- 一个来源离线时其他来源继续；
- 磁盘空间不足沿用现有结构化失败，不自动删除用户数据；
- semantic / face / OCR 任一处理器失败，不得破坏此前可服务的旧索引/profile；
- 搜索在刷新期间仍保持已有 P4-02V 的“可用或明确 LAGGING”语义，不因内部争用频繁 500/409。

## 8. 性能边界

本卡不追求新的性能指标，只要求没有明显退化。

做两档实测：

### 小型变更
已有库基础上：

- +100 新照片
- 删除 10
- 移动/改名 10
- 复制 10 个已有内容

执行一次刷新，证明只有真正需要的派生工作被执行。

### 30 万 no-op
复用现有 30 万夹具，仅做 no-op 刷新诊断：

重点记录：

- scan wall time；
- semantic targets / encoded；
- thumbnail generated；
- 各 processor 新 job 数；
- 搜索期间是否出现合法请求拒绝。

**不要求重新生成 30 万真实 embedding。**

## 9. 明确不做

本卡不实现：

- 实时文件系统 watcher；
- Windows USN Journal；
- 定时后台自动刷新；
- source remap；
- 模型升级 P4-03B；
- A3 / ANN / FAISS；
- 新数据库后端；
- VACUUM / 自动删除旧 artifact；
- 全库 preview 预生成；
- 40 万以上容量优化；
- 用 size/mtime 取代 SHA-256。

## 10. 最小测试

至少覆盖：

1. 一键刷新：scan → semantic → thumbnail → derived stages；
2. 新增文件只补新增内容；
3. 重复内容新增位置但不重做 embedding；
4. 删除 → MISSING；
5. rename/move 保持 asset；
6. 同路径替换不继承旧结果；
7. no-op 第二次刷新所有 AI 派生为 0 新工作；
8. 一个来源离线、另一个来源仍完成；
9. refresh 重复点击不并发启动第二个；
10. 进程中断后再次刷新幂等恢复；
11. 刷新期间搜索不出现由本功能新增的内部争用拒绝；
12. Web 按钮和状态文案真实走产品 API。

回归：

- 相关 unit / integration；
- B 级 tests/unit tests/integration 一次；
- ruff check .
- uv lock --check
- git diff --check

## 12. PASS 标准

全部满足才记 PASS：

- Web 有一个可用的“刷新图库”入口；
- 多来源扫描可以一键串行完成；
- 新增 / 删除 / 改名 / 移动 / 内容替换语义正确；
- 新增/变化内容自动补进当前语义索引；
- 已完成旧资产不重新跑 embedding；
- 缩略图和已启用派生处理器按 input revision 增量补齐；
- no-op 第二次刷新 = 0 新 AI 派生工作；
- 来源离线不会制造错误删除；
- 中断后重新刷新可安全继续；
- 刷新期间搜索没有新增内部争用拒绝；
- B 级回归通过；
- 独立 DS-H 窄主审 PASS。
