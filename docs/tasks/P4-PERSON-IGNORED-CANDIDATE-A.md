# P4-PERSON-IGNORED-CANDIDATE-A — 已忽略人物候选关系恢复与处理优化

## 背景

当前人物整理流程中，AI 人脸识别可能判断某个待整理人脸与已有人物存在相似关系。

用户选择忽略后，该人脸进入「已忽略人物」，但历史候选人物关系可能仍然存在。

当前问题：

- 已忽略列表无法展示已有候选人物；
- 用户误忽略后，没有方便恢复入口；
- 后续人物库变化后，用户无法重新确认；
- 只能重新查找照片或重新触发整理。

---

## 目标

在不改变人脸识别算法、不重新计算人物关系的情况下，为已忽略人物增加人工恢复处理能力。

本任务只使用已有候选关系数据。

---

## 功能要求

### 1. 已忽略人物展示候选关系

位置：

```
人物管理 → 待整理 → 已忽略人物
```

如果存在候选人物，需要显示：

- 候选人物头像；
- 人物名称；
- 相似度（如果已有）；
- 操作入口。

示例：

```
可能人物：张三 85%

操作：
- 确认是张三
- 选择其他人物
- 保持忽略
```

要求：

- 使用已有 candidate 数据；
- 不重新执行人脸识别；
- 不批量重新计算相似度。

---

## 2. 确认归属

用户选择：

```
确认是某人物
```

结果：

```
已忽略人脸 → 目标人物
```

要求：

- 使用现有人物归属流程；
- 不复制照片；
- 保持人物关系一致性。

---

## 3. 选择其他人物

提供人工指定入口：

```
已忽略人脸 → 选择人物 → 归属
```

支持：

- 搜索人物；
- 查看人物头像；
- 选择已有用户人物。

---

## 4. 保持忽略

继续保持当前状态。

不自动恢复，避免误匹配。

---

## 数据安全要求

禁止：

- 删除已有忽略记录；
- 删除照片；
- 删除人脸数据；
- 重新建立全部人物关系；
- 全量重新执行人脸识别。

只允许：

- 读取已有候选关系；
- 修改归属状态；
- 更新必要索引。

---

## 与忽略状态优化兼容

本任务依赖：

```
P4-PERSON-IGNORE-STATE-A
```

如果后续拆分为：

- 暂时忽略；
- 明确排除；

则：

- 暂时忽略支持候选恢复；
- 明确排除不参与推荐。

---

## 性能要求

禁止：

- 页面打开触发模型推理；
- 批量计算相似度；
- 重新聚合人物。

页面只读取已有数据。

---

## 简单验收

### 测试1：已有候选

准备一个已忽略人脸：

```
候选：张三 90%
```

检查：

- 显示张三头像；
- 显示候选信息；
- 点击确认后进入张三。

---

### 测试2：选择其他人物

选择李四。

结果：

- 人脸归属李四。

---

### 测试3：保持忽略

结果：

- 状态保持不变。

---

### 测试4：无候选

没有候选人物时：

- 页面正常显示；
- 不报错。

---

## 实现范围

本任务只处理：

- 已忽略人物展示；
- 候选关系恢复入口；
- 人工归属操作。

不涉及：

- 人脸识别算法；
- 相似度模型；
- 人物聚合算法重构。

## 推荐执行模型

中高级代码模型。

重点：小范围修改，避免重构人物系统。
