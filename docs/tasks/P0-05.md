## 必须保持的不变量与行为

1. **spawn 语义**：worker 用 `multiprocessing` 的 spawn 起点或等价方式启动同一解释器/打包后自身上下文（主架构 §3.3、§3.1）；不得依赖 fork，也不得让 worker 成为业务代码的隐式全局单例。
2. **有界消息**：单条消息上限显式配置并写入报告（建议 1 MiB）；超限必须被拒绝并返回结构化错误，不允许 OOM、静默截断或半条 JSON。
3. **大数据走文件**：图片等大输入通过临时文件路径传递，不放进消息（§3.3）。
4. **异常回传**：worker 内异常必须回主进程结构化错误（stage、exception type、message、completed steps）；父进程记录并保留 worker 的 stderr 尾部，禁止把失败当成功。
5. **退出与超时**：正常 `shutdown` 返回 0；不可恢复错误非零；父进程超时后先 terminate 再 kill，且不残留子进程（用 `psutil` 之外的最小手段或系统查询验证）。
6. **离线**：运行与打包产物启动过程不访问网络；不因缺少网络而降级为假结果。
7. **协议边界**：业务代码不写死 ONNX、512 维、224 px、tokenizer 或设备（主架构 §11.3.4）；维度、预处理、度量从 manifest 读取，返回结果携带 processor/space 标识。
8. **打包边界**：运行时不依赖 Python、Node、Docker；优先只带 ONNX Runtime 路径，`torch` 只作为开发期参考实现，不应成为打包产物的运行时依赖。
