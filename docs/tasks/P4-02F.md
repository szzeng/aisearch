# P4-02F — F2 检索延迟（候选块 / A3 决策）

本卡关闭 [P4-02B](P4-02B.md) §9 F2 与 [Sol 性能架构审查 §4](../reports/P4-02B-performance-architecture-review.md)、
[DS-H 审查 §4.5/§6](../reports/P4-02B-dsh-engineering-review.md)：30 万档暖机文字搜索
service P95 **125 174.8 ms**（3 样本，目标 ≤ 1 s），根因是 `search/retrieval.py::vector_channel`
的候选块路径（每 5 000 候选一块、每块一次引擎 pass，30 万约 60 块；查询阶段工作集峰值 2.118 GB）。
本卡分 **阶段 0 受控归因** 与 **阶段 1 决策闸门**，**未证明与 SQLite 权威候选集等价前不授权实现**
任何绕过权威候选的路径。

推荐执行模型：**DS-H / DeepSeek V4.1 Flash / 高推理**（检索语义 + 可能的 ADR 裁决）。
**Sol high 聚焦终审必选**（命中协议/ADR 裁决与 §12.2 承诺口径）。模型切换由用户在 Codex 中手动完成。

  [P4-02D 归因](../reports/P4-02D-attribution.md) §5/§7/§8/§9。
  F3 的主因已单变量证明 = `ensure_scalar_index`「见到同名索引即返回 `present`、从不重建」造成的
  **`asset_id_idx` 部分覆盖**：10 万档波次形状为 `num_indexed_rows=5000 / num_unindexed_rows=95000`，
  突发形状为 `100000 / 0`；部分覆盖对**任何**候选块都不生效（连索引覆盖的 block#1 也一样慢），
  每块退化为整代过滤扫描（每次查询读 3 852 MB vs 480 MB），同一张表上仅做 `replace` 重建即把
  service 中位从 14 897.3 ms 降到 2 444.7 ms（6.09×）且返回页不变 ⇒ **阶段 1 的修法方向已获得因果证据**。
  同时存在一个**反向**小变量：等覆盖下两种建库形状的「小连续候选集 + 索引」路径仍差约 1.9×
  （未定位到物理层，已排除 SQLite/fragment 布局/索引来源/整代扫描；下一最小变量 = 索引页/段结构与
  命中 fragment 的 row-address 对应关系，需 `pylance`）。阶段 0 仍**缺**：30 万档同形态复测、
  A3 等价性反例、真实文本塔 P95、冷 OS 缓存与 soak。

## 阶段 0：必须交付的归因事实

1. **分阶段计时**（同一 data root、同一查询、同一 `top_k`）：SQLite 候选获取、各块 Lance 检索、
   行转换/物化、融合与权威复读各自耗时与占比；给出块数、每块耗时分位、返回行数。
2. **块大小矩阵**：至少 {250, 1 000, 5 000, 20 000} 或等价梯度，证明四种块大小返回**逐项相同**的
   `(distance, asset_id)` 页（块约束是访问路径参数而非召回参数），并给出块数—耗时关系。
3. **F4 索引覆盖**（DS-H §7）：记录 `asset_id_idx` 的 `num_indexed_rows` / `num_unindexed_rows`
   与 Lance 表 fragment/version；做一次「显式 `replace` 重建索引」的对照，量化覆盖率造成的差距。
4. **每调用固定开销**：证明 `search_candidates` 每次调用重复 `lancedb.connect`/`open_table`
   的固定成本量级，并给出「一次搜索复用一个表句柄」的可省时间估算。
5. **单次 pass 对照**：不带候选约束的一次引擎查询耗时与页（**诊断下界**，不是 A3 授权、也不代表
   与权威候选集等价）。
6. **10 万突发 vs 波次**：与 [P4-02D](P4-02D.md) 对接（同一受控设计），给出两形状下分阶段耗时差，
   说明 8 317.8 ms 与 3 484.4 ms 的差异落在哪一段。

## 阶段 1：决策闸门

- **闸门 A（无契约变更，优先）**：把访问路径的常数项降下来（完整索引覆盖 + 表句柄复用 +
  块数上界），在 10 万与 30 万同夹具复测。若 30 万暖机 service P95 ≤ 1 s **且**结果页与旧路径
  逐项相同、内存峰值有界，则按无契约变更实施，走 DS-H 完整受影响面主审。
- **闸门 B（A3 策略化）**：若闸门 A 达不到，必须先形成 ADR/补遗并写清：
  ① 资格谓词（该 generation/space 的当前 `CONFIRMED`、可见、非旧 revision 的真实集合）；
  ② 并发窗口（Lance 已写未确认、待修复、离线/隐藏、并发发布与 `projection_revision` 变化）；
  ③ 回退策略（不能证明等价时回退候选块路径）；
  ④ [Sol §4](../reports/P4-02B-performance-architecture-review.md) 的 A/B 反例逐条关闭
  （未确认的 A 距离更近、已确认的 B 次近、`top_k=1` 时全局查询先取 A 再删 A 必须漏 **不** 发生）。
  **未证明等价前不授权实现**；实施后必须 **DS-H 完整受影响面主审 + Sol high 聚焦终审必选**。
- **两条路都达不到 ≤ 1 s**：停止，把性能决策交回用户（接受现状 / 改 §12.2 口径需 ADR 裁决），
  **不得**自动放宽门槛。

## 必须交付的验证证据（B + D）

1. **等价性**：新旧路径在 10 万与 30 万档的命中 ID 与逐项排序相同（含并列距离的
   `(distance, asset_id)` 全局序），且 `pending_projection` 语义不变。
2. **反例注入**：未确认 A + 已确认 B 的 `top_k=1`；`PENDING_REPAIR`；旧 `projection_revision`；
   离线/隐藏资产；并发发布窗口——每条给出前后计数与最小复现。
3. **性能**：10 万与 30 万暖机 service P95（并与 HTTP 层对照）、查询阶段内存峰值、
   后台维护同时前台 P95；未达标必须给测量、原因与决策，不得写成「通过」。
4. **不回归**：D 级五项注入、P4-01/P4-01C 的并列距离与块界用例、focused + 全量 JUnit、
   `ruff check .`、`git diff --check`、`uv lock --check`。
5. **变异测试**：至少覆盖「丢掉块内截断后的全局排序」「把引擎 limit 当作行数上限」两处变异，
   必须让对应用例失败。
