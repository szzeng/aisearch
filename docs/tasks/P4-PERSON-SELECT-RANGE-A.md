# P4-PERSON-SELECT-RANGE-A — 人物整理 Shift 连选与批量快捷选择

**状态：READY / 待实施（仅任务卡）**  
**日期：2026-10-11；仓库：`szzeng/aisearch`，master。**  
**范围：人物相册与整理页面的前端选中体验；个人项目，最少定向测试。**

## 1. 背景和现状（开工以最新 HEAD 再核对）

用户在人物相册逐脸纠错、待整理人脸、人物批量管理和人物合集移出成员时，需要频繁逐个点击头像或复选框。现有跨图/跨页选择可用，但没有 Shift 范围选择或“全选已加载 / 反选”捷径。

当前证据：
- `src/photo_search/web/persons.js`：人物相册“整理照片”由 `#pt-face-list` 列出单个 `face_id`，独立 Map 选择，分页 `/faces?person_id=…&limit=40`，最多 500 脸；`#pt-organize` 已可在“整理照片 / 完成整理”间切换。
- `src/photo_search/web/persons-albums.js`：人物列表 Set + 人物 snapshot；待整理和已忽略脸使用独立 Set、snapshot、跨页选择与批量写；待整理候选组支持按需加载组内脸；人物合集成员另有 `collectionSelectedPeople`。
- `src/photo_search/web/persons.html`：已有选择数、取消选择及批量动作入口，未设置范围选择按钮；`P4-PERSON-UX-SIMPLIFY-A` 和 `P4-PERSON-REGROUP-A` 已实施，不要重做或回退。

实施前按仓库 `AGENTS.md` → `docs/development-status.md` → 本卡 → 相关 JS/HTML/CSS、已有选择 DOM 桩/测试文件读取。核对最新 master 与本地其他任务的改动，不能覆盖并行工作。

## 2. 用户看到的行为

### A. 统一快捷交互

在**已进入整理/批量管理模式**时：
1. **普通点击头像或复选框**：切换这一人脸/人物的选中状态；现有“点击头像即可勾选”的功能保留。
2. **Shift + 点击**：以上一次明确点选的项目为锚点，在**同一个当前可见、已加载、顺序稳定的列表**中，把两端及中间项目一次**加入选中**；不清空原来其他页选中的项。选中的末端成为下次范围选择锚点。Shift 再点已选项不触发“范围反选”或意外取消。锚点不存在、已移走或上下文变化时退化为普通单项选择，不跨隐藏区域/不同列表。
3. **Ctrl/Cmd + 点击**：仍可逐项增减，与普通点击一致；无需额外提供复杂桌面文件管理器式的“单击清空其余选择”语义。
4. 显示三个简短入口：**“全选已加载” / “反选已加载” / “清空选择”**。这里“已加载”指当前操作区本次已呈现并可以直接选择的卡片，不代表后台全部照片，也不得发起全库选择/自动加载下一页。
   - 全选：仅增加当前操作区已加载项目；之前在同一操作域、较早页选中的项目继续保留。
   - 反选：仅翻转本操作区当前可见已加载项，其他未加载或暂不可见的既有选择保持不变。
   - 清空：清除当前操作域全部待提交选择，包括跨页选择；**零业务写入**。待整理与已忽略如果仍共用一套批量选择和操作，应与页面实际合并选择口径一致，避免留下看不见的选中脸。
5. 显示“已选 X / 500 张脸”或“已选 X 个人物”；提供一句“按住 Shift 连选，仅限已加载”提示，避免冗长说明。没进入整理模式时不展示这些快捷按钮。

### B. 应适用的四个区域

- **人物相册的“整理照片”**：`#pt-face-list` 的跨多张照片及多页成员脸；选择单位始终是 **face_id**，不是整张 asset；合照未选中的脸绝不受写操作影响。
- **“整理一下”人物列表**：已命名/未命名人物卡的批量管理，选择单位是 canonical `person_id`；保留原人物 snapshot 供合并/忽略/合集操作。
- **“整理一下”待整理与已忽略人脸**：常规分页卡片与展开的候选组内实际加载的人脸，选择单位是 `face_id`；候选组未展开或未加载的成员**不得被偷偷选中**。同一组内可 Shift 连选；不同组/待整理/已忽略之间不得形成隐式连续范围，跨组已明确勾选项仍保留。
- **人物合集的成员列表**：现有“选择移出”可 Shift 连选及全选/反选已加载；不改变人物合集数据的业务语义，不自动把整个合集清空。

不要扩到搜索结果、地理相册、全站快捷键、原图重新检测、人物识别算法或模型任务。

### C. 上限、状态及安全

- **保留已有单次 500 脸、人物批量相关已有限制**，不把 500 解释成相册照片数量上限；合集选择沿用其原操作上限，不在本卡擅自改后端协议。
- 全选或范围连选如果会超过本操作的有效上限：**整次新增选择不执行、原已选不丢**，明确提示超限；不悄悄只选前 500，也不逐条写服务端。若 `反选` 后超限，同样整体拒绝本次反选。
- 范围顺序只使用**当前 DOM 中同一个操作列表的稳定卡片顺序**；翻页追加后的已加载项可连续选，未加载页不会被隐式选择。列表重排、筛选、切换人物/合集、折叠候选组、重新加载、失效的人脸 revision 或跨操作域切换时，锚点按实际上下文重置；不要静默指向新顺序的另一张脸。
- **不额外触发 API**：仅用户执行原“移出 / 智能分组 / 合并 / 拆分 / 忽略 / 恢复 / 加入合集”等操作才走既有受保护写接口。选择动作只修改 UI 的 Set/Map 和样式。
- 写入中、结果未知待重试、后台可见性操作中禁止改动选择；不破坏已有 `pendingWrite` 重试同一 request_id、CAS/revision、撤销及失败提示。按现有读取保护处理 stale snapshot，不为“全选”绕开权威校验。
- 正确同步头像复选框、卡片选中样式、选择数量及按钮禁用状态；回到正常浏览/“完成整理”后选择工具隐藏。键盘 Tab + Space/Enter 原可用的勾选保持可用，不拦截浏览器常用 Ctrl+A；Shift 修饰符应从真正的 click/pointer 事件捕获，**不能假设 `change` 事件含有 `shiftKey`**。
- 多页 DOM 复用、图片缓存、人物排序/排序同分规则、分页 API 与候选组按需加载保持原状。

## 3. 技术建议（少改、易维护）

- 首选在 `src/photo_search/web/persons.js` 与 `persons-albums.js` 各复用一个轻量的范围/批量选择 helper，或以一个小型纯 JS helper 共享“锚点 + 有序 ID + 集合运算”；**不新建状态管理框架**。
- 明确区分 person / album-face / inbox-face / hidden-face / collection-person 这几种 scope，尤其避免 `selectedInboxFaces` 和 `selectedHiddenFaces` 混淆。创建/更新 DOM 时统一应用选中状态，不为了 Shift 重新创建头像节点或全列表重拉。
- 在 `persons.html` 相应工具条添加少量按钮及简短中文提示，必要时只加几条 `persons.css` 样式；不重排整张页面。
- 不改任何 API、Pydantic model、SQLite schema、face/person 服务、`FaceIndexCoordinator` 或识别阈值。若实施时发现某场景必须改变身份事实/锁/撤销语义，暂停该场景并记录，不纳入本前端卡。

## 4. 五组最小验收（隔离合成数据即可）

1. **人物相册**：至少模拟两页已加载脸，单击第 3 张 + Shift 点第 15 张 → 13 张连续选中；再追加下一页做跨已加载页选择，旧选择保留，未加载脸不选。
2. **候选组和待整理**：同组 Shift 连选、全选/反选/清空；折叠组与已忽略区不混入当前范围；已明确选择的跨页人脸仍保留。
3. **人物与合集**：人物卡和合集人物成员用 Shift + 全选已加载操作，校验选中 `person_id` 和 snapshot 仍正确；合并/移出原参数入口不变。
4. **边界**：0/1 项、锚点失效、切换筛选或人物、加载下一页/刷新、已有 499 项再尝试新增超过上限时整次拒绝且原选择保持、忙时按钮不可用。
5. **无副作用**：选择、反选、清空不发写 API；合照中未选脸不出现在提交项，完成整理不提交/不撤销已保存动作；保留已有键盘/复选框及头像直接点击行为。

**测试执行**：优先新增/调整一两个既有 DOM/Node 模拟用例或最小 `pytest` UI 驱动，按仓库约定输出 JUnit XML；`node --check` 对改动 JS、`git diff --check`，若改 Python 测试则仅需相应 Ruff/pytest。**不跑全量 pytest、GPU、真图库、端到端完整浏览器套件或大型性能测试**。可让用户自行浏览器手点 3 个场景（相册 Shift、待整理全选、超限提示）。
