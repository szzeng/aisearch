## 1. 交付范围（有限扩展）

1. **星标**：在真实照片缩略图位置展示收藏状态，并支持单击星标加入/取消。覆盖普通照片列表与时间轴、收藏列表、搜索结果、人物/合集的照片列表、地点相册照片、地图内照片列表。**人脸裁剪图、人物头像、地点文字建议行及没有真实照片缩略图的管理项不纳入。** 当前查看器的收藏按钮沿用 A 的权威实现。
2. **批量收藏**：只在「全部照片**列表**」「收藏列表」「搜索结果照片列表」新增「选择照片」模式，提供单选、Shift 连选、全选当前已呈现项、反选当前已呈现项、清空，以及「加入收藏」「取消收藏」两项真实动作。**不把普通时间轴、人物/地点/地图页面升级为新的批量业务页**；这些区域保持单张星标。
3. **收藏拍摄时间排序**：收藏页在默认「最近收藏」之外提供「按拍摄时间」。遵守现有可信 EXIF、未知时间置尾、不拿 FILE_MTIME 假冒拍摄时间的规则；由服务端有界分页，不做前端全量排序。无新时间轴。
4. 不包含收藏范围的自然语言/向量搜索、保存搜索为动态照片合集、评分、自动挑选、文件导出、写原图 EXIF。这些不是本卡的隐含验收条件。

## 2. 现有组件与新复用层

- 以 `asset_id` 为唯一照片身份。新增/复用**小型共享 favorites 前端状态工具**，集中处理已知 ID 的批量读取、单张写入、同一页面可见图标更新及只读缓存失效；不引入框架/长存全图库 Map。对当前真实展示的一页照片（一般 50 张）**一次批量状态读取**，不要逐缩略图请求。收藏列表已有真值时无需再重复查询。
- 复用 A 的独立 `favorites_revision` 与 `/favorites/states`；读请求标记页代次和 ID，筛选切换、滚动回收/重建、切图或离开页面后迟到结果不得错写图标。写入成功以 API 权威结果更新，写失败/结果不明须重读权威状态，不应长时间展示假成功。多页面重新进入应读取最新状态，不要求跨浏览器标签页的实时推送。
- 复用 `app.js::buildTile`、`timelineRenderAsset`、`photo-timeline.js::renderAsset`、搜索/人物/地点/地图既有渲染器，只加最小控件。现有时间轴 `renderAsset` 可能直接返回 `<button>`；**不得嵌套 `<button>`/`input`**，应将照片打开控件和星标置于合法兄弟元素或经过审查的包装节点中。不能破坏原 `data-asset-id`、anchor、页回收、鼠标 hover 地图高亮、照片打开、Esc/Back 或滚动位置。
- 当前共享 viewer 刚加入单照片人脸批量整理：本卡不改人脸/人物归属、face_id 控件、收藏的人物合集、地点人工确认和其 revision。不得因为加星标重构完整 viewer 状态机。

## 3. 照片批量选择的固定行为

- 照片选择模式使用独立 `Set<asset_id>`；普通模式点击照片仍打开 viewer，选择模式点击照片**只切换勾选**，星标/其他独立按钮不能意外触发卡片打开或两次选择。checkbox 有键盘标签；批量工具只在主动进入模式时显示。
- Shift 连选仅沿**同一操作域、当前实际保留并可呈现的 DOM 项**按视觉顺序选择；无锚点等同单选，不暗中请求未加载页。`PhotoScrollPager` 会回收旧 DOM：用户显式选择的旧 ID 仍可保留于 Set 并计入总数，但「全选/反选当前项」只作用于当前保留 DOM，不能把已回收的旧页误当仍呈现；退出或范围/排序/搜索会话变化时清理选择与锚点。
- 一次选中上限 **500 张**，超限整次新增拒绝、旧选择不变、提示明确；不能把 `face_id` / `person_id` 的上限当作同一个选择集合。批量加入和取消都采用**显式目标状态**，选中阶段零业务写；提交成功更新现有结果和收藏状态，失败保留选集供重试。操作写入中禁止二次提交，未知结果不能重复“切换”。
- 浏览器 Esc 优先当前 viewer/dialog，其次退出照片选择模式；不改变人物整理、地点建议、搜索页现有其他选择域的 Escape/Shift 定义。清空选择不撤销已经保存的收藏。

## 4. 后端最小扩展

`POST /api/v1/favorites/batch`：请求 `{asset_ids: [1,2], is_favorite: true|false}`，数组需 1～500 个不重复、严格正整数；同一 Catalog 短事务**先校验整批资格，再原子写入**。任意不合法/不存在/非图片资产，整个请求 4xx 且**零部分提交**；已达目标状态视为 no-op。单批存在真实变化时独立 `favorites_revision` **只加一次**，整批全 no-op 不增；对新收藏使用同一个服务器时间基准，排序由 `asset_id` 打破同毫秒并列。响应至少包含目标状态、请求数、实际变化数、未变化数和权威 revision；状态恢复复用 A 的 states 查询。session、Origin/CSRF 和结构化错误沿用既有中间件，不放宽单张权限。

收藏列表新增 `order=recent|capture_desc`；游标绑定 `favorites_revision`、排序模式和位置，切换排序或收藏成员变化须重取第一页或提示明确 409，不得混页。`capture_desc` 允许仅以收藏表候选 JOIN `asset_metadata` 排序，**不要先扫描全库资产再过滤**；用合成 `EXPLAIN QUERY PLAN` 核对，并验证收藏较多时没有显著退化。如确有排序瓶颈，只针对收藏集合增加最小索引/投影并说明维护代价，不擅改普通照片 `asset_page` 的冻结排序契约。

## 5. 实施顺序、兼容和验收

建议串行顺序：① 后端批写和拍摄时间分页 → ② 共享星标状态/事件钩子 → ③ 普通列表和时间轴 → ④ 搜索结果 → ⑤ 人物/地点/地图的真实照片缩略图 → ⑥ 三类列表的照片级选择模式。相同 JS/CSS 文件以最新 HEAD 修改，资源 cache-bust 只更新直接引用；不触碰已存在的 `0033` 索引、全局检索 revision、TopK、地图 bbox/member_revision 或人脸写协议。

### 本次性能设计与验证（2026-10-19 激活时补齐）

- **链路与风险（PERF-BOUNDED）**：收藏拍摄时间页可能为每个候选单独读 EXIF 或先扫全库；缩略图星标可能变成逐图请求；批量操作可能扩大成全库读取/写入。按收藏候选集排序、每次只读当前 DOM 已呈现项；请求最多 500 个明确选中的 `asset_id`。
- **做法与边界**：先用 `asset_favorites` 限定候选，再联接可信拍摄时间投影；未知时间置尾，稳定平局用 `asset_id`。每个已呈现照片页分批读取状态（states API 每次最多 100 IDs），收藏页已有状态不重复读；批写先整批校验，再在一个短 Catalog 事务里写入且最多推进一次 revision。星标只保留当前根节点可见 ID 状态，不建全图库缓存。
- **验证与停止**：核 EXPLAIN 与查询调用数，测试 50 项页/DOM 回收迟到状态、捕获时间可靠性、500 上限和批次原子性；用隔离合成库在内置浏览器验三类批量选择及一条其他页面星标路径。达到卡面正确性、状态安全和有界读取要求后停止，不新增 30 万延迟或发行结论。

2. 点星标不打开照片，点图正常打开；普通时间轴/搜索/人物/地点/地图及收藏列表状态一致，hover 和 Back 不回归；不合法嵌套按钮。
3. 三类列表：单选→Shift→全选/反选/清空→批量加入/取消；500/501、跨页、回收、切换筛选、Esc/弹窗隔离、错误后保持选集。

5. capture 排序：有效拍摄时间、FILE_MTIME、未知时间、时间戳并列、深翻页和成员变化 409；确认不改普通照片时间轴/搜索 TopK。
