## 为什么是这张卡（P4-02M 的结论，不是性能问题）

- `python -m photo_search`（含打包 onedir：`PhotoSearch.spec` 的 Analysis 入口同为
  `src/photo_search/__main__.py`）在 `_serve()` 里构造
  `ApiContext(dataclasses.replace(settings, session_token=bootstrap.token))`，**从不提供 `encoder_factory`**
  （`src/photo_search/__main__.py:64-78`）。
- 于是 `query_encoder()` 恒为 `None`（`src/photo_search/api/context.py:35,87-105`，模块自述
  「this build has no built-in encoder」），能力报告 `query_encoder_available=false`
  （`src/photo_search/api/routes.py:349`）。
- 文本搜索结构化拒绝：`RUNTIME_CAPABILITY_UNAVAILABLE` / `QUERY_ENCODER_UNAVAILABLE`
  （`src/photo_search/search/service.py:1004-1012`，即 `POST /api/v1/search` 传
  `encoder=context.query_encoder()`，`api/routes.py:1309`）；上传搜图 `IMAGE_ENCODER_UNAVAILABLE`
  （`api/routes.py:1386-1405`）。
- `src/photo_search` 内**没有任何 `QueryEncoder` 实现类**（`encode_queries` 只有
  `search/embedding.py:36` 的 Protocol 定义）；真实编码只存在于 AI worker：
  `workers/ai_worker.py:110-125`（`action == "encode_text"` → `ChineseClipOnnxAdapter.encode_text`）
  经 `workers/client.py::AiWorkerClient.encode_text/encode_image` 使用，当前调用方只有 `demo-search`
  与 `indexing/cli.py::_image_encoder`（建库/再执行）。
- 运行时只读核对（`create_app`/`ApiContext` 不做 I/O）：模块级 `app`、无参 `create_app()`、默认
  `ApiContext` 的 `query_encoder()` 全为 `None`。
- 该状态是既有、已被文档记录的预期行为（`docs/diagnostics/search-smoke-checklist.md:21`、
  `docs/tasks/P2-07.md:76`、`P2-08.md:152`、`P3-01.md:147`、
  `tools/diagnostics/packaged_api_smoke.py:1341,1494`）；本卡把它从「记录」变成「接线」。

用户可见后果：应用能浏览/筛选/看缩略图，但**任何文字搜索都直接 409**，个人试用无法开始 ⇒ 优先于检索加速。

## 关键不变量（逐条验证）

1. **能力诚实**：有可用编码器 ⇒ `capabilities.search.query_encoder_available=true`；无 ⇒ `false`，且文本/上传
   仍是既有结构化 409，绝不降级为静默纯文本页或替身向量。
2. **依赖方向**（ADR-0003 §7）：业务层不 import ONNX/PyTorch；重活留在 worker 子进程或既有 adapter 边界后；
   失败结构化（带失败类与路径），不能让进程起不来。
3. **一次编码、续页复用**：既有 `search/service.py` 的 `encoder`/`query_vector` 语义、会话/游标/筛选/发布资格
   形状不变；同一次搜索不得逐页重编码。
4. **无权重分支逐字不变**：没有登记权重时，启动、`GET /capabilities`、`POST /search`、`POST /search/image`
   的响应与今天一致（可复跑既有 `tests/**` 与打包 smoke 断言）。
5. **资源与代码分开**：模型准备（`tools/prepare_models/`）是独立、需用户授权的资源步骤，不写进本卡代码改动。
