## 1. 唯一用户目标

**新电脑没有 PhotoSearch 旧数据库、索引或模型。** 用户把自己的**照片原文件**放到新电脑（或可访问的本地目录）后，按下面的流程完成使用：

**下载并完整解压 A 的 Windows ZIP → 双击启动 → 按提示准备官方 AI 模型 → 添加照片目录 → 用现有建库流程生成新索引 → 浏览和搜索。**

安装过程不要求用户安装 Python、uv、Git、Visual Studio、CUDA Toolkit，也不要求回旧电脑找 `catalog.db`、向量、备份或其它项目私有文件；系统需要兼容的 NVIDIA 显卡和驱动。VC++ 等系统运行库是否另需安装，以 A 的干净机器实测结论为准，不能预先承诺。**旧人工整理、人脸归属、OCR、收藏等不会凭空恢复，新库从头生成。**

这是一张**首次准备/体验卡**，不是发行工程：继续 ZIP 便携包；不做 MSI/Inno Setup、桌面原生 UI、自动升级、云端同步、跨电脑迁移或一个新的建库引擎。

## 3. 最小产品改动

### A. 空数据根首次启动：简短准备指引

- 保持已通过的 `PhotoSearch.exe` 和浏览器式本地 UI；**只在新数据根/资源未齐时**，于现有「图库管理」区域展示简短的“首次使用”引导（不增加一个独立的大型安装向导）。依次展示：**运行环境 → 模型 → 照片目录 → 建库**，状态均来自真实现有 API/任务；页面可进入并浏览，不因尚无模型而启动失败。
- 运行环境：告诉用户是否检测到 NVIDIA CUDA/GPU、Qwen 能否运行；驱动缺失或 CUDA 不兼容时给出可理解的原因和 NVIDIA 官方驱动指引。**不静默转为 CPU 运行 Qwen，也不假装搜索已就绪**。
- 模型：区分“未安装 / 安装或下载中 / 待校验 / 已校验可用 / 校验失败 / GPU 不可用”；轻量状态查询**不可把仅存在文件**误显示为已通过 SHA 校验。首次启动**不自动下载、自动完整 hash 4GB、自动建库**。只有用户明确开始对应操作才做耗时工作，显示真实进度或明确的阶段提示。
- 照片：用户手动选择/登记一个新电脑上的原图文件夹；不能默认扫描 C 盘、用户目录或所有硬盘。没有照片目录时明确提示“请选择照片文件夹”，不报旧库损坏。

### B. Qwen 模型：最简单、可复用的官方准备流程

- **一条主路径：官方固定版本准备 Qwen。** 优先复用 A 随包依赖中已有的可靠下载组件（先核对 `huggingface_hub` 在冻结包内可用），不新写完整 HTTP Range 下载框架，不增加模型商店、插件系统或后台常驻下载服务。用户点击“下载 Qwen”并确认约 4.3 GB 下载及磁盘需要后，才读取**内置可信清单**中的 `Qwen/Qwen3-VL-Embedding-2B` 固定 commit、必要文件白名单、固定大小和 SHA；不接受任意仓库、revision、脚本或 URL，不使用 `trust_remote_code`。
- 下载到数据根下应用自有的**隔离暂存目录**，明确可取消/重试，下载完成后调用既有固定清单校验，再发布到 `<data_root>/models/qwen3_vl_embedding`；失败、取消、断网、空间不足时保持未就绪，不覆盖已校验可用的模型。不支持安全续传的环境可重新下载，**不必为首次版本单独开发断点续传状态机**。避免在服务启动线程执行长时间 IO；同时间最多一项模型准备操作，禁止重复点击造成重复下载。
- **一条备用路径：使用已经下载好的同版本模型目录。** 可通过简单本地路径导入（复用 `embedding prepare-local` 的验证与发布逻辑），或以用户可复制的、经测试的便携 EXE 命令完成；用户不必安装 Python/uv。损坏、revision 不符或缺文件要明确拒绝，不强制覆盖旧模型。
- 512D/1024D 共享一次权重下载。**不得改变**既有 Provider/Processor/Space/Generation 身份、`default()`、模型加载方式、检索阈值或激活/切换协议。模型准备成功仅表示可用于建库，**不**表示已有图像向量索引。
- **辅助模型分级处理，避免范围失控**：OCR 若冻结包内已有合规模型资源，复用现有资源/准备逻辑，检查第一次新库 OCR 能否真正工作；人脸 `buffalo_l` 优先提供受许可的**官方来源说明＋手动导入/现有准备方法**，用户选择后方可安装，不要求为其开发第二套下载器；Chinese-CLIP、地点数据集为可选高级准备，保留既有入口与清晰提示，**不阻挡 Qwen + 浏览建库主流程**。不能让下载/导入成功的标签冒充实际 OCR/人脸 GPU 验收。

### C. 新库建库：完全复用现有图库管理

- 模型已准备后，提示用户通过现有页面添加新的照片来源，并用**现有**任务执行图片解析、缩略图、Qwen 向量、OCR、人脸等已启用能力；进度使用现有真实状态。图像/文本搜索必须绑定已建好并被发布的对应 Profile/Generation；建库未结束时诚实显示待就绪/部分就绪，不能显示假“100%”。
- 首次建库可能处理很多照片，是正常的一次性工作；不为“无等待”偷偷减少图像、跳过识别，或自动改变 Qwen 512D 为 1024D。关闭/重新启动后沿用现有受控状态恢复，不能重复给同照片创建多条来源/资产。
- 不在首次启动自动全盘扫描、批量清理离线照片、创建没有用户选择的来源，或自动下载官方模型。原图始终只读，不从程序内移动或删除。

## 5. 性能设计：PERF-BOUNDED（三行）

- **链路及风险**：首次模型准备约 4.3GB、完整 SHA 校验与新图库首次建库会较慢；这些是用户主动开始的一次性任务，不能拖慢空库首屏，也不能被后台无限重复。
- **做法与边界**：不在页面打开时同步哈希大模型、不自动扫描硬盘；单次有界下载/校验，现有分批 GPU Worker/建库调度；避免重复下载同一份 Qwen 权重、重复解码/索引和新增高频 SQL。
- **验证与停止**：检查空库启动、下载失败/取消、模型就绪后的实际合成小库建库与重启；出现明显资源失控时停止并修复。**不要求 30 万实测、不承诺 GTX 1660 6GB 或所有 Windows 设备已兼容。**
