## 任务定位

P1-05 的真实浏览器 smoke 发现：P1-03 的媒体失败记录里，Pillow 抛出的消息带的是 **repr 转义**路径
（文件系统里的一个反斜杠在字符串里变成两个），而 `Redactor` 只按登记根的单反斜杠字面量做替换，
因此 `GET /api/v1/assets/{id}` 的 `media[*].message` 仍可能把本机绝对路径交给调用方。

实测证据（P1-05 报告 §6 步骤 8 / §8.1，夹具 `%TEMP%\...\corrupt.jpg`）：

```text
cache/media/catalog-thumbnail@1/…json 的 message 字段：
  cannot identify the file as an image: cannot identify image file
  'C:\\Users\\<user>\\AppData\\Local\\Temp\\...\\corrupt.jpg'
```

既有断言为什么漏掉：`tests/integration/test_api_sources_assets.py::test_asset_detail_and_unknown_ids`
只检查单反斜杠形态 `str(api_env.library) not in response.text`，而这里的泄漏是双反斜杠形态，
所以断言通过、泄漏依旧。

P1-05 已在页面侧加纵深防御（`src/photo_search/web/app.js` 的 `PATH_LIKE`：检测到盘符/UNC 形态即整条
消息替换为「错误详情包含本机路径，已省略。」）。本任务修的是**服务端**这一处根因，页面守卫**保留**。

## 用户场景

- 用户扫到一个损坏文件（或方向/格式异常的文件）后打开详情页：产物状态显示 `DECODE_FAILED` 等结构化
  code 与可读原因，但**任何地方都不出现本机绝对路径**（含 repr 转义、正斜杠、UNC、`\\?\` 等拼写）。
- 用户查看失败任务/失败清单（`GET /jobs`、`GET /stats`）时同样不会看到本机绝对路径。
- 用户看到的原因文本仍然有用：能看出「是解码失败」「是格式暂不支持」，而不是被整段抹掉。

## 必须交付

### 1. `Redactor` 覆盖同一登记根的多种拼写

- 每个登记根展开为一组变体：单反斜杠（`C:\照片 库`）、repr 双反斜杠（`C:\\照片 库`）、正斜杠
  （`C:/照片 库`）、混合分隔符、`\\?\C:\...` 扩展长度前缀；大小写仍按当前方式不敏感处理。
- 仍然「最长根优先」，替换目标不变：来源根 → `<source_root>`、数据目录 → `<data_root>`。
- `pairs` 是公开属性（`tests/unit/test_api_session.py` 之外也可能被诊断脚本读取）：若展开变体会改变它的
  含义，必须保持 `pairs` 的既有语义（逻辑根），把变体放在私有结构里；不得因为实现方便而破坏公开属性。

### 2. 兜底：未登记的本机路径也不得原样输出

- 替换完登记根后，对仍然存在的盘符绝对路径（`[A-Za-z]:\` 或 `[A-Za-z]:/`）与 UNC 路径
  （`\\server\share`、`\\?\UNC\...`）做兜底替换，占位符用稳定的 `<local_path>`。
- 兜底不得破坏非路径文本：错误 code（如 `SCHEMA_TOO_NEW`）、状态词（`RUNNING`）、数量、单位、
  相对路径（`子目录 中文\a.jpg`）必须原样保留；不得把 `[SCHEMA_TOO_NEW] ...`、`a:b` 之类的普通文本误伤。
- 兜底必须对 `Redactor.details()` 递归生效（它走 `text()`），使 `details` 里未登记的绝对路径同样被替换。

### 3. 不改动的部分（硬约束）

- 错误 code、HTTP 状态映射、错误信封形状（`code`/`message`/`request_id`/`details`）、
  `X-Request-ID` 头、404/403/409/422/416 的既有映射：**全部不变**。
- `Redactor` 之外的任何模块：**不改**（若发现确实必须改调用方，先停下来说明理由，不要顺手重构）。
- 前端 `PATH_LIKE` 守卫与其单元断言：**保留**，不得删除或削弱（纵深防御）。
- 不新增依赖、不新增表/迁移、不改 `schema_version`、不改 ADR-0002。

### 4. 测试（以新增为主；既有测试只能新增，不得修改或弱化）

- **新增单元测试文件** `tests/unit/test_api_redaction.py`（文件名不得与既有测试模块同名，
  避免 pytest 模块名冲突）：参数化覆盖
  - 单反斜杠 / repr 双反斜杠 / 正斜杠 / 混合分隔符 / 大小写不同；
  - 含空格与中文的根（`C:\照片 库 中文\子目录\a.jpg`）；
  - 嵌套根最长优先（`D:\Photos` 与 `D:\Photos\Sub` 同时登记）；
  - `\\?\C:\...` 与未登记 UNC `\\server\share\a.jpg`；
  - 未登记盘符路径（`C:\Other\b.jpg`）→ `<local_path>`；
  - 非路径文本原样保留（`[SCHEMA_TOO_NEW] catalog schema_version 2 ...`、相对路径、纯数字）；
  - `None`/空串/无 `_pairs` 时的行为与现状一致。
- **新增集成用例**（写在 `tests/integration/test_api_files.py`，**新增函数，不改既有函数**）：

  既不包含 `str(api_env.library)`，也不包含 `str(api_env.library).replace("\\", "\\\\")`；
  同时断言 `media["thumbnail"]["code"] in {"DECODE_FAILED", "FORMAT_UNSUPPORTED"}` 且
  `media["thumbnail"]["message"]` 仍非空（证明不是靠抹掉整条消息过关）。

## 正常行为 / 异常行为 / 边界情况

**正常行为**

- 损坏文件的详情仍返回 `state=failed`、`code=DECODE_FAILED`、可读 `message`，只是路径被替换为占位符。
- 正常错误（`SCHEMA_TOO_NEW`、`SOURCE_OVERLAP`、`INPUT_UNSTABLE` 等）的 `code`/`message` 语义不变。
- 页面侧守卫与单元断言继续存在（服务端修复后仍保留）。

**异常行为**

- 任何响应（含 `details`、`last_error_message`、`scan.error_message`）都不得包含本机绝对路径的
  单反斜杠、双反斜杠、正斜杠或 UNC 形态。
- 不得通过把整条 `message` 置空/置常量来「通过」测试——除路径外的可读原因必须保留。
- 不得放宽会话/CSRF/Host/Origin/受控路径边界来绕开问题。

**边界情况**

- 根目录含空格、中文、`>220` 字符；
- 路径出现在消息开头/中间/结尾，或被单引号/双引号包围；
- 同一条消息里出现多个不同路径（登记根 + 未登记路径）；
- 嵌套根场景（数据目录在来源外但与来源同前缀）；
- 消息里同时出现 `code` 字样与路径字样；
- `message` 为空、`record` 为 `None`。
