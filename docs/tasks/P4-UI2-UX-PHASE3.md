# P4-UI2-UX-PHASE3 — 全站照片与相册界面体验收口

**PH3-01～03 展示/UI 范围：SCOPED PASS（限定视口与定向测试）；阶段整体：IMPLEMENTED / ACCEPTANCE PARTIAL（2026-10-23）。智能合集排名结果/相关度排序、地图底图和中等宽度面板测量仍 PENDING；分页、人物批量选择、viewer 横竖合成比例/缩放/信息栏和地图标记返回范围已补验。**
**优先级**：P1
**执行模型建议**：GPT-6 High
**独立复核**：Luna High（如可用，使用与实施不同的审查上下文）
**前置条件**：任务 2 的修改已经完成并确认没有共享文件冲突
**目标**：统一照片浏览、时间轴、人物、合集、地点、地图和共享查看器的布局、文案、控件及视觉体验。

## 1. 核心交付要求

这是一项实际 UI 优化任务，不是单纯的 CSS 整理或设计评估。

最终界面必须满足：

1. 整体视觉与现有 UI 2.0 设计保持一致。
2. 主要内容突出，常用功能容易找到。
3. 页面间的标题、筛选、按钮、间距和卡片层级统一。
4. 桌面及窄窗口下无明显错位、遮挡、异常留白或水平溢出。
5. 提示文字清楚、精简，低频工具适当收纳。
6. 不改变现有搜索、分页、数据管理和浏览器回退逻辑。
7. 所有重要改动必须经过实际浏览器验证，不能只依赖代码审查。

**不得仅以“代码已修改、测试通过”认定 UI 优化完成。**

不得机械复制 demo 的模拟数据、布局尺寸或假功能。实际业务需求与可用性优先。

### 统一设计规则

重点保持以下一致性：

- 页面标题和工具栏的对齐方式。
- 左侧导航、顶部搜索及主内容的空间关系。
- 按钮高度、内边距、圆角、颜色和操作层级。
- 卡片的间距、封面区域、标题和辅助信息。
- 筛选器、下拉菜单和标签的密度。
- 加载、空状态、错误及禁用状态。
- 长文本省略、换行和提示方式。
- 浅色及暗色主题的可读性。

优先使用现有 CSS 变量，不新增相互矛盾的设计规范。

## 3. 施工前：真实界面审计

先检查当前 HEAD、工作树、已有任务报告和实际 HTML/CSS/JS，明确任务 2 已完成的内容。

随后使用 Codex 内置浏览器访问隔离合成图库，检查以下七类页面：

| 页面 | 必须检查的主要内容 |
|---|---|
| 照片浏览 | 时间轴、筛选栏、照片密度、日期标题 |
| 人物 | 人物卡片、相册、待整理、批量模式 |
| 普通合集 | 合集目录、详情、照片列表 |
| 智能合集 | 目录、匹配结果、刷新状态、空状态 |
| 地点 | 地点卡片、地点相册、筛选与管理 |
| 地图 | 地图与照片列表的比例、悬停和收藏 |
| 照片查看器 | 适窗、100%、信息区、横图与竖图 |

尽量准备可重复使用的合成数据：横竖照片、长文件名、人物头像、多个合集、地点照片以及有 GPS 信息的照片。

**不能只使用空页面验证布局。** 无真实结构数据的页面应补充合成数据；无法构造的状态如实记录为待验证。

形成问题清单，每项包含：

- 页面及具体位置。
- 当前表现和问题。
- 预期改善效果。
- 严重程度。
- 修改范围。
- 修改前的截图或可复核浏览器观察记录。

优先 P0、P1，不为了制造修改数量而处理无价值的小差异。

## 4. 页面实施范围

### A. 照片浏览与时间轴

- 照片为主体，减少工具栏和说明文字占用。
- 常用时间、图库及浏览模式控件组织紧凑。
- 日期分组、时间依据和跳转操作层级清楚。
- 横图、竖图、缩略图异常不破坏卡片布局。
- 保留自动分页、懒加载、DOM 资源回收及返回位置恢复。
- 不改变时间轴排序和日期语义。

### B. 人物与待整理

- 人物头像、名称、照片数量及操作入口排列一致。
- 普通浏览只突出常用功能，批量操作按模式显示。
- 人物相册与照片浏览使用一致的布局语言。
- 待整理保留现有分类和业务规则，减少多余说明。
- 忽略、明确排除、人工归属、确认、撤销等行为不变。

### C. 普通合集与智能合集

- 合集卡片更加紧凑，长名称不撑破布局。
- 封面、名称、照片数量、操作按钮保持清晰层级。
- 普通合集与智能合集的类型可辨识。
- 智能合集的匹配、刷新、排序和错误状态容易理解。
- 自动分页、人工排除及刷新机制不变。
- 不改变模型阈值、匹配算法或成员资格。

### D. 地点与地图

- 地点目录、地点相册和地图相册层级清楚。
- 地图与照片列表的空间分配合理。
- 地图标记、悬停、收藏、照片打开等操作协调。
- 不出现图层遮挡、双滚动或窄屏无法操作问题。
- 保留原有地图范围、成员查询及查看器返回行为。

### E. 共享照片查看器

- 弹窗尺寸基于浏览器可用视口，不因照片自身缩放而异常改变。
- 横图和竖图在适窗模式下完整显示。
- 预览 100% 与适窗状态明确，图片平移范围正确。
- 标题、工具栏、照片信息、OCR 及关联人物信息不互相遮挡。
- 信息栏展开和收起后布局稳定。
- 关闭、Esc、Back、Forward 和照片跳转遵守已有页面级历史规则。

不重新开发查看器，不重建缩放和导航状态机。

## 5. 下拉菜单与文案优化

逐个检查实际存在的主要控件。

- 多选项、低频操作：优先保留原生下拉框。
- 两三个常用模式：评估是否使用分段切换按钮。
- 高级工具：放入明确的折叠区域。
- 重要状态和主要操作：直接可见。
- 危险操作：保留必要的风险说明和确认。

保留键盘操作、焦点状态和可访问名称。

统一文案原则：

- 按钮写清楚动作。
- 普通提示尽量简短。
- 技术细节按需展开。
- 错误显示原因和下一步。
- 不为了简洁删除必要的状态及安全提示。

只调整确实存在问题的控件，不强制全部替换。

## 6. 视觉质量验收：本卡强制要求

这是本次任务最重要的部分。

### 6.1 修改前后对照

使用同一组合成数据、相同浏览器视口和相同页面状态，对比修改前后的产品界面。

建议视口：

- 桌面：1440×900。
- 普通笔记本：1280×800。
- 窄窗口：约 470×740。

优先覆盖七类主要页面；空状态、长文字、展开工具栏等选择确实受修改影响的代表场景。

尽可能保存真实截图。截图必须来自实际产品，而不是 demo 或重新绘制的概念图。

### 6.2 明确的检查标准

**布局正确性**

- 没有控件重叠、明显错位、截断或不必要的横向滚动。
- 同层级标题、工具栏和卡片保持一致的对齐。
- 主要内容区域没有无原因的大面积留白。
- 固定导航和顶栏不遮挡需要操作的内容。
- 长名称、无图片、空结果和错误状态不破坏布局。

**视觉一致性**

- 同类按钮和控件的尺寸、样式保持一致。
- 页面颜色、间距、字体层级符合现有设计规范。
- 照片、头像、合集封面等保持合理比例。
- 主要操作与次要操作在视觉上能明显区分。
- 文字具有足够对比度；普通正文以 WCAG AA 4.5:1 为目标，适用例外按实际语义处理。

**交互可用性**

- 常用操作容易发现，不需要反复展开隐藏菜单。
- 下拉菜单、弹窗、tooltip 不被父容器裁切。
- 鼠标、键盘、选择状态和焦点表现正常。
- 不因 CSS 修改造成点击区域偏移。
- 页面返回、照片查看和筛选流程不回归。

对于可以用浏览器测量的项目，结合 DOM 尺寸和实际观察记录结果；对于美观、密度、视觉层级等需要判断的项目，必须结合真实截图评估，不能只用自动断言代替视觉审查。

### 6.3 修复与复查循环

对确认存在的 P0、P1 问题执行：

**发现问题 → 修改 → 浏览器复查 → 回归检查。**

第一次修改仍有问题时，继续进行针对性修正，不能只留下“建议后续优化”就认定完成。

如果修复一个页面导致共享组件在其他页面回归，必须检查受影响的其他消费者并修复。

无收益的 P2 像素细节不无限迭代。

## 7. 独立视觉复核

实施者完成代码和浏览器检查后，安排一次独立只读复核。

建议由 Luna High 或另一独立 High 级别审查上下文完成。

审查内容：

1. 原设计基准与当前产品是否一致。
2. 前后截图是否证明问题得到改善。
3. 不同页面的卡片、工具栏、按钮及间距是否统一。
4. 主要内容和操作是否突出。
5. 是否存在明显视觉回归。
6. 公共 CSS 修改是否影响其他页面。
7. 浏览器回退、分页、状态更新是否存在直接相关的风险。

复核输出具体问题、位置、严重级别和修复建议。

**不能仅以“看起来不错”或“代码没有问题”作为通过结论。**

审查发现可复现的 P0、P1 问题，应修复后针对相关页面再次复核，直到关闭或明确遇到阻塞。

独立模型是辅助质量保障，不代替真实浏览器验收，也不代表用户已接受最终视觉效果。

## 8. 性能与工程边界

本项目是个人照片管理应用，以现有功能稳定和简单维护为主。

- 只修改必要的 HTML/CSS/JavaScript。
- 不更改数据库 schema、索引和搜索算法。
- 不新增无必要的 API、模型调用或后台任务。
- 不一次性拉取所有照片、人物或合集。
- 不改变分页、懒加载和资源回收策略。
- 不恢复每次提交搜索就新增浏览器历史条目的旧行为。
- 不引入新的大型前端框架。
- 不访问或修改真实图库、原图和人工整理数据。
- 公共样式修改优先使用既有 token 和局部作用域。
- 若发现需要改变业务协议才能修复，应停止该项并明确说明，不擅自扩大范围。
