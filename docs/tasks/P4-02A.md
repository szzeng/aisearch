# P4-02A — 语义 outbox 生产维护入口接线与长写事务争用边界（P4-02 前置）

本卡是 **P4-02 的前置子任务**：把 P4-01C 已经验证过的语义索引维护路径真正接进生产入口，并给出
「检查与引擎写在同一写事务内」（P4-01C 第二轮修复）在**生产并发与容量**下的争用/busy-timeout 证据。
没有这张卡，`src/` 里没有任何生产模块调用 `IndexCoordinator.process_all/process_next`
（P4-01C 主审 R5、Sol 终审 §8.2 都要求它成为 P4-02 前置项），P4-02B 的容量数字就只能是夹具数字。

推荐执行模型：**DS-H / DeepSeek V4.1 Flash / 高推理**（改生产接线与并发/提交顺序边界）。
完成后**另开独立 DS-H 会话**做全量工程主审；**C2 / GPT-5.6 Sol / high 聚焦终审必选**（V3.1 §11
「幂等键、提交顺序、outbox」），主审通过后状态先写 `ENGINEERING REVIEW PASS / SOL FOCUSED REVIEW PENDING`。
模型切换由用户在 Codex 中手动完成。

## 允许修改范围

- **生产接线（本卡核心）**：为语义 outbox 增加**一个可验证的生产维护入口**，并在报告写明「谁在什么时机、
  以什么并发口径」调用它。可选形态（择一，不要全都做）：
  - CLI 子命令（例如 `photo_search.indexing.cli` 或 `ingestion/cli.py` 下新增 `index drain` 类命令），
    由启动器/用户显式运行；或
  - 现有后台调度/进程内维护钩子里的一个受控 drain（例如 scheduler 已经驱动的维护周期）。
  **不得**新增长驻服务、守护进程框架、Redis/Celery、分布式调度、多 GPU 或第二向量后端。
- `src/photo_search/indexing/store.py`：只允许为了「入口需要的可观测性/参数（batch、limit、结果计数）」
  做最小改动；**不得**改状态机语义、确认顺序或检索参数。
- 相关测试：新增入口/并发/锁等待/崩溃恢复用例；可同步既有断言（不得削弱）。
- 诊断工具：可新增/扩展项目内诊断脚本（如 `tools/diagnostics/index_maintenance_probe.py`），产出机器可读 JSON。
- 报告 `docs/reports/P4-02A-maintenance-entry.md`、`docs/development-status.md`、下一任务卡。

## 必须保持的不变量

1. 逐事件幂等与确认顺序不变：`tests/integration/test_p2_index_submission.py`、
   `test_p2_acceptance_recovery.py`、`test_p2_search_topup.py` 与 P4-01C 专项用例全部原样通过；
2. `after_lance` 崩溃窗口＝行停在 `IN_FLIGHT`；重放后零逻辑重复、`index_entries` 与 Lance 行数一致；
3. **旧 revision 不得回滚最新状态**（P4-01C 第二轮用例
   `test_a_stale_projection_revision_can_never_land_after_a_newer_one` 继续绿），且新入口下仍成立；
4. `semantic_ready`/`index_generations` 状态机不变；`asset_id` 标量索引仍只在维护侧创建、缺失即可回退；
5. 读路径不受影响：精确路径仍是默认（不引入 ANN 主路径），检索结果与 P4-01C 修复后一致；
6. 前台写（地点/人物修正、搜索会话、扫描提交）在维护 drain 期间**不得**出现静默失败：
   `busy_timeout` 触发的拒绝必须是结构化错误且可重试，且必须在报告里给出实测数量。

## 必须交付的事实（含 D 级注入）

1. **入口接线**：入口位置、调用时机、并发口径（单维护者互斥 / 多维护者 + 逐事件幂等），以及
   「为什么这个口径能保证不变量 3」的可验证证据（不是论证文字）。
2. **争用与 busy-timeout 边界**：维护 drain 与前台写并发时，锁等待分布（P50/P95）、`busy_timeout`
   触发的拒绝次数与重试结果；给出真实命令与 JSON 证据。
3. **D 级注入（每条都要有前后状态计数）**：
   1. drain 中途中断进程后重启：零逻辑重复、零丢失，恢复后结果与中断前一致；
   2. 「Lance 已写、outbox 未确认」重放；
   3. 同 `asset_id` 内容变更后旧向量不得继续命中（含同时有新 revision 的情况）；
   4. 两个维护者同时 drain（若选择多维护者口径）：不变量 3 与不变量 1 同时成立。
4. **容量口径的诚实标注**：本卡只给入口与争用边界；正式容量/吞吐见 P4-02B，不得在本卡宣称容量 PASS。
