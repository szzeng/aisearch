# P4-FACE-NONREAL-FILTER-A — 卡通人脸识别过滤与人工恢复（个人试用版）

**状态：TODO / 任务卡已提交，待实施。** 推荐执行模型：GPT-6 High。项目：`szzeng/aisearch`。以开工时最新 `master`、`AGENTS.md`、`docs/development-status.md` 和现存工作区为准，不覆盖并行 UI 2.0 改动。

**模型基线更正（2026-10-15）：** 用户当前按 **Qwen3-VL-Embedding-2B** 使用图片语义搜索；仓库已支持 Qwen 和 Chinese-CLIP 双 provider，实际活动 provider 由所选数据根的 active SearchProfile 决定，不能从源码默认值推断。**Qwen 是图文语义 embedding 模型，不是当前的人脸检测器，也不是已经验证的真人/卡通分类器。** 当前人脸流水线仍使用 SCRFD + ArcFace。本卡以活动 Qwen 的小样本可行性试验为首选，不默认使用 Chinese-CLIP。

## 1. 问题与目标

当前 SCRFD 可把动漫、漫画、游戏插画中的面孔检测为人脸，ArcFace 又会生成特征，导致卡通脸进入人物待整理、自动建组或匹配参考池。既有 `det_score`、`face_pixels`、`blur_variance` 只是检测质量指标，不能判定真人与卡通。

**本卡要真正减少明显 2D 卡通/动漫插画人脸进入人物整理和自动归类，同时优先保护真人照片、人工确认关系和数据库。** 不把“AI 生成写实人物”“屏幕里的真人”“雕像/玩偶”直接等同于卡通；不确定时不自动排除。

完成后的体验：新识别的人脸自动获得保守判定；明显卡通脸不参与自动归人，也不成为其他人的匹配参考；在原有「人物 → 整理」中可看到“疑似卡通”并批量确认/恢复；已有图库可按需增量补判，不必重新建库。

## 2. 现有代码与边界（实施前复核）

- `src/photo_search/face/engine.py`、`face/contract.py`：SCRFD 640 检测、ArcFace 112 对齐/512 维识别；`DETECT_SCORE_THRESHOLD=0.50`，人脸 artifact、`FACE_SPEC_REVISION`、`face_id`/向量身份不可随意改变。
- `src/photo_search/face/processor.py`：检测事实保存到 `faces`、向量保存到 `face_embeddings`；复用已发布 artifact / 版本逻辑。
- `src/photo_search/face/index.py`：候选代表与 `reconcile_asset()` 自动关联，存在事务内人工控制再校验；新的“卡通排除”必须同时覆盖**候选来源、关联目标、提交时竞态**。
- `src/photo_search/persons/albums.py`、`persons/quality_policy.py`：已有清爽模式/疑似低质量展示，不能把“卡通”混作 `LOW_DETECTION_SCORE`。
- `P4-PERSON-INBOX-IGNORE-STATE-A`：`face_inbox_hidden` 的 `EXCLUDED` 仅阻止当前脸被自动匹配，仍可能让它作为其他脸的参考；所以**不能单靠既有 EXCLUDED 冒充非真人识别过滤**。
- `P4-PERSON-IGNORE-STATE-A`：已有人物级暂时忽略/明确排除；两类人工状态应维持原义。
- `src/photo_search/models/embedding/qwen3_vl.py`、`models/embedding/registry.py`、`workers/query_encoder.py`、`src/photo_search/__main__.py`：已实现 Qwen3-VL-Embedding-2B 作为可切换的图片语义 provider，按**活动 SearchProfile / 对应 manifest 和实际权重**选择；当前用户使用 Qwen，但开工仍需通过只读活动 profile/页面能力确认，不得默认断言任何数据根当前选中 Qwen。Qwen 是图文向量模型，支持图文相似度，不等于可直接输出可靠“真人概率”的视觉分类器；现有图像编码接口以路径为主，局部裁剪需在隔离临时文件/受控 worker 中完成。
- `src/photo_search/models/embedding/chinese_clip_onnx.py`：Chinese-CLIP 是另一套可选 provider，保留作**明确授权且已安装时的可选离线对照**；不因为分类需求自动切换搜索 provider、跨空间混合向量或重新下载模型。

## 3. 实现范围

### A. 保守的人脸级分类

1. 检测出脸后，基于**该脸及适量周边区域**分类；不以整张图片类别决定是否识别其中所有人。真人站在动漫海报前，应尽量只保留真人。
2. 使用独立、版本化的 `REAL / CARTOON / UNCERTAIN / ERROR` 机器判定；只允许**高可信 CARTOON** 阻止后续机器归类。`UNCERTAIN`、模型不可用、超时或读取失败不得伪装成 CARTOON；按旧流程保守继续并留诊断记录。分数是分类决策证据，不能直接当“真实性概率”。
3. **优先验证实际活动的 Qwen3-VL-Embedding-2B** 是否能基于逐脸局部裁剪和文字描述/少量对照样本，稳健区分真人照片与明显 2D 卡通（写实照片、动漫插画、手绘肖像、写实 AI、真人+海报混合）。Qwen 本身是 embedding 模型，不是带已校准类别输出的分类器；相似度、与提示词的距离或候选原型差值只作候选证据，不能叫作“真人概率”。使用少量合成/公开授权夹具，记录实际活动 provider、使用的图文模板、阈值依据、误排真人样本、模型加载/每脸推理开销；不能单看整图语义便封禁所有脸。若用户活动 provider 不是 Qwen，先记录事实而非悄悄切换。
4. 若活动 Qwen 对局部卡通分类的可靠性/速度/显存占用不足以满足保守要求，不得硬套 Qwen 相似度门限，也不得未经授权自动改用 Chinese-CLIP：本卡仍完成可用的**逐脸手动标记/过滤/恢复**，但自动部分明确标记 `BLOCKED / 需后续专用小分类器`，**不得以“自动已解决”记 PASS**。只有经小样本证据确认后才启用 Qwen 自动规则；不擅自下载新模型或改变冻结的人脸权重、搜索 embedding space。
5. 不把新增分类器直接塞进 `FACE_SPEC_REVISION` / immutable face artifact；优先作为可单独重跑的后置分类阶段。新照片需要在**自动人物关联之前**读取有效分类结果；若分类器失败/不可用，按保守回退旧流程并记录原因，不得永久卡住建库。Qwen CUDA/FP16 资源可能与图片检索/建库争用；任务必须复用既有 worker 边界或实现有界调度、幂等缓存和暂停/恢复，不得在普通 API 请求中临时批量加载第二份 Qwen 权重，不能对每次页面打开重复推理。

### B. 分类存储和优先级

1. 用最小必要的新增表/连续迁移保存 `face_id`、`asset input_revision`、`face spec_revision`、`classifier/policy_revision`、机器结果及原因、可选人工覆盖结果与更新时间；当前结果必须与当前有效 asset/face 版本匹配，不复用过期裁剪结果。表/字段以实际 schema 最简设计为准。
2. 人工标记分为“**不是现实人脸（排除）**”和“**是真人（恢复正常匹配）**”；人工决定优先于机器结果，后续刷新/升级分类器不能悄悄覆盖。恢复应真正恢复候选资格并按现有受控关联/候选修复路径生效，而不是仅取消 UI 隐藏。
3. 不改原 `face_id`、检测坐标、ArcFace 向量、人工身份/姓名/头像或已经确认的归属；不删除照片、人物、历史链接和向量。不更改现有人工 `EXCLUDED/TEMPORARY` 含义。
4. 若检测版本替换（普通检测 → source-detail）、照片内容变化或人脸映射待确认，不能把旧 `face_id` 的机器或人工结果无依据地套到另一张脸；沿用现有 redetection hold/映射与人工保护规则。

### C. 候选与存量数据

1. 对有效 `CARTOON` 排除：不能成为新自动归类**目标**，不能成为候选代表/其他人的**参考来源**；自动归类写事务中必须重查分类/人工修订状态，阻止稍早计算的结果越过新排除决定。手动认作真人后可重新参与候选。
2. 旧库里已自动归入人物的疑似卡通脸：**不自动解绑或改写人物归属**；在人物整理中提供可复查入口。用户明确确认“不是现实人脸”时，复用现有人工取消归类/排除和撤销机制处理，不影响该照片同框的真实人脸。
3. 支持对已有 `faces` 做**显式启动、可暂停/续跑、有界分页、只补缺或版本过期**的分类；按现有图库维护/继续处理入口接入，避免新增复杂管理页。不重复运行 SCRFD、ArcFace、OCR、图片语义向量建库，不扫描无脸照片。是否补查整库由用户主动触发。
4. 保持照片搜索、地点、合集、缩略图、普通图库浏览原状；人脸分类状态不应造成 30 万照片规模下普通人物页每次打开都重扫原图或全表重算。

### D. 最小 UI

复用人物整理现有卡片、批量勾选/Shift 多选和已忽略/恢复操作。只新增一个“**疑似卡通**”分类入口（显示少量计数）和三个清晰动作：

- **确认不是现实人脸**：针对已勾选的 `face_id`，永久人工排除自动归人和候选参考，可在该入口恢复。
- **确认是真人**：人工覆盖机器判定，继续正常人物整理；不自动指定此人是谁。
- **暂不处理 / 恢复自动判断**：可撤销人工覆盖并查看机器当前判断；与现有“暂时忽略”区分。

明确标注“自动疑似”与“人工确认”，不新增独立页面、不新增一排质量阈值设置。正常待整理列表对机器高可信卡通默认收起，但必须有完整可查找的恢复入口；人工已确认/人工指定的人脸不能静默消失。已忽略人脸/人物页面及原有 `EXCLUDED` 不改变原有含义。分页、组内计数、同图多脸和选择集只影响指定脸。

## 4. 个人测试为主的验收

**开发侧最低限度自检（不要求正式浏览器验收）：**

- 2～4 组有界、合成/公开夹具的定向测试即可：① 真人+卡通同图按脸隔离；② 卡通不能成为关联目标或候选参考，且提交前新发生的排除能挡住晚到自动结果；③ 人工确认真人/恢复优先且可撤销，原人物链接和其他脸不变；④ 旧脸/新脸版本隔离与迁移不丢原数据（若新增迁移）。**Qwen 分类可行性单独做少量图片试验，保留真人误排和卡通漏排实例，不将合成规则测试当作真实模型效果。**
- 执行受影响 Python 语法/Ruff、必要的 JS `node --check`、`git diff --check`；pytest 生成 JUnit XML。只记录实际测试结果。**不跑全仓测试、30 万规模/压测、全量建库、真实图库、GPU 实机矩阵、打包验收、Codex 浏览器截图**。架构策略要求的状态/身份/迁移受影响面复核仍按 `AGENTS.md` / V3.1 进行，但不扩张为全仓回归。
- 不读取、扫描、修改用户实际 `PhotoSearchData` 或真实图库；自动模型试验用隔离夹具与明确允许的已安装权重，不能擅自从用户的真实数据根加载/修改模型配置。用户自行负责真实环境试用。

**用户手工试用清单：**

1. 新增纯动漫/卡通图片：明显卡通不自动建立真人物组，能在“疑似卡通”看到并恢复。
2. 新增正常真人照片：识别、自动归人和搜索不受影响。
3. 真人站在动漫海报前：尽量只过滤海报脸；每张脸的结果独立。
4. 写实 AI 肖像、屏幕里的真人、娃娃/雕像：不应被简单误判为卡通而永久隐藏。
5. 对旧库运行“仅补卡通判定”：不重建人脸/向量，原有人物照片不丢失；旧自动归类卡通可由用户明确排除。
6. 误过滤一张真人后选择“确认是真人”：可重新参与人物整理，且刷新/重启后有效。

**交付状态：** 工程侧可标 `IMPLEMENTED / 最小定向检查通过 / 用户真实图库试用待确认`；不要标“准确率已验证”或“用户验收 PASS”。如果当前 Qwen 不适合作自动分类，应单列技术阻碍，不能把单纯隐藏 UI 说成自动识别完成；不能把 Qwen 的语义检索能力当作已校准的真人/卡通分类能力。

## 5. 禁止扩张与交接

不修改 SCRFD/ArcFace 权重、既有 immutable artifact/embedding 身份、识别阈值、照片搜索空间；不触发整库重新识别、不重写历史人物关系、不删除媒体/数据；不改 unrelated UI 2.0 页面，不增加云服务或擅自下载外部大模型。涉及持久状态及关联资格时，必须保持人工控制、并发提交、revision、redetection 和撤销不变量；需要的连续迁移/局部复核按项目策略执行。
