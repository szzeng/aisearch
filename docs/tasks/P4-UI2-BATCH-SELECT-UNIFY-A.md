## 3. 用户统一可见的交互合同（必须）

1. **模式**：已有批量/整理入口保留；未进模式时卡片按原语义打开照片/人物/详情，进入模式后点目标卡片或其**唯一复选框**切换选中。交互具有清楚选中边框/叠加 `✓`，不是仅改变背景色；不可让参考头像、候选来源文字、操作按钮意外成为批量选中目标。
2. **普通点击**：独立勾选/取消该项，记下本操作域当前锚点；在已进入模式时的非按钮卡片点击可与 checkbox 等效。checkbox 勾选必须能用 Tab + Space/Enter 操作，提供 `aria-label`；不在 `<button>` 里非法嵌套 `<input>` 或第二个 `<button>`。
3. **Shift + 点击**：从本域最近一次明确选择的锚点到当前点，按**同一操作列表当前已加载且顺序确定**的项目连续**加入选中**，含两端；不取消已选项，不扩张至未加载项，不跨人物/人脸/地点，也不跨不同候选组或隐藏/待整理列表。无有效锚点时按普通单项选择退化；末端成为新锚点。Shift 修饰符取自实际 `click` 事件，不能只看 `change` 事件。
4. **快捷项**：「全选已加载」「反选已加载」「清空选择」与已选数量状态对齐既有人物整理。全选和反选只对当前允许操作域已加载的项目生效，绝不偷偷请求更多页。保留既有「冻结全部结果快照」作为**地点特有且有独立说明**的命令，不与「全选已加载」混用。跨已加载页明确选中的项目继续保留。
5. **状态和上限**：始终以 ID Set/Map 作为真值，DOM 只是呈现；单项与 Shift、全选、反选、清空必须即时一致更新卡片、checkbox、计数、可用按钮。旧人物/人脸/合集每次最多 500 的合同保持；超限拒绝**整次新增选择**，保留原选集并显示提示，不截断或部分选择。地点依照原 `MAX_BATCH=500` 的批次提交和 `SNAPSHOT_CAP=2000` 快照规则，不能把「一批最多 500」误改成结果选择总量最多 500。
6. **锚点失效**：筛选、排序、组展开/折叠、操作域切换、人物/合集/地点切换、资源版本失效、已加载列表重新排序/重置时清除**范围锚点**。实际业务上下文不同（人物 ID、合集实例/修订、地点建议 revision、搜索 session、地图 bbox/member_version 等）时，不得把旧选择带入新范围或提交；已明确保留的跨已加载页选集不得因单纯续页丢失。
7. **退出与写入**：Esc 先交给已打开的原生 dialog/viewer；关闭弹窗后下一次 Esc 才退出底层批量模式；「清空选择」不退出、「退出批量管理／完成整理」才退出。退出仅清临时选集、锚点和相应 snapshot，不撤销已保存操作、不重新加载已经加载的列表、不跳回顶部；写入中、`pendingWrite` / 状态未知重试时沿用原禁止退出/变更选择的保护。选择操作**零业务写 API**。
8. **视觉**：沿用视觉收口的亮/暗主题、焦点、圆角、间距与卡片尺寸；仅在必要时增加带根作用域的复选框/选中态 class，复选框不遮住人像或文件名，不引起网格换列/行高抖动。窄屏和 Codex 内置浏览器可见、能点；避免全局 `.card`、`button`、`.tile` 裸规则。
