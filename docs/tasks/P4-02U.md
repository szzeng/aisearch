## 2. 问题陈述（已证实事实与未定项必须分开）

已证实：

- 30 万 → 36 万、投影队列非空、后台 drain 在场时，前台**合法**搜索 **4/9 次被拒**，错误为
  `CatalogError: CATALOG_UNREADABLE: cannot start a catalog write transaction: database is locked`（各等满 5 s busy timeout）。
- 无 drain 对照（同队列深度）**0/12 次被拒**，每轮 37.4–54.2 ms ⇒ 被拒**需要 drain 在场**。
- drain 自身计时的写事务 `write_hold_ms` p50 35.3 / p95 557.7 / **max 656.8 ms**、`write_rejections=0`，
  `lock_wait_ms`≈0 ⇒ **「drain 的长写事务占满 5 s」被证据排除**。
- 该次测量中前台已预热口径（投影已追赶）7 样本 **0 次被拒**。

未定（本卡要回答的）：

- 剩余候选：前台/后台 commit 触发的 **WAL checkpoint 持写锁时段**（不计入任何一方 `write_hold_ms`），
  或 drain 进程里**未计时**的写入路径。P4-02J 未能区分，本卡必须给出可区分证据。
- 未知：`PRAGMA wal_checkpoint` 耗时轨迹、被拒瞬间的持锁者、队列深度阈值、是否与夹具/会话状态相关。

**纪律**：归因清楚前不得写成产品缺陷、不得改产品代码；也不得把已被排除的机制重新写回结论。

## 3. 必须回答的问题（最小反例 + 四臂对照）

1. **最小反例**：固定夹具、固定投影队列深度、drain 在场 ⇒ 稳定再现被拒；记录每次尝试的样本时间线、
   busy timeout 等待时长、被拒时的错误原文与队列/后台进度。
2. **锁归属**：用**只读探测**在独立连接/进程里做 `BEGIN IMMEDIATE` 探针（失败即回滚，**不写业务数据**），
   在拒答窗口内判定写锁是否可获取；区分「drain 计时内写事务 / 未计时写路径 / checkpoint 窗口」。
3. **checkpoint 计时**：`PRAGMA wal_checkpoint(PASSIVE)`（必要时 `TRUNCATE`）耗时、`-wal`/`-shm` 大小与页数
   随时间轨迹，检查 checkpoint 是否落在 5 s 拒绝窗口内。
4. **四臂对照**（同夹具、同会话、交错采样）：(a) 无 drain（复用并复测既有 0/12 口径）；
   (b) drain 在场 + 投影已预热（既有 0/7）；(c) 队列非空 + drain 暂停/降速；(d) 队列非空 + drain 全速（反例臂）。
5. **结论与最小方案**：给出归因结论、仍未知的部分，以及**是否需要产品侧改动**（例如搜索侧对写锁的
   退避/重试策略或 checkpoint 策略）与其用户可见收益；**不在本卡实现**。
