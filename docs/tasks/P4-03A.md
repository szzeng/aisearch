# P4-03A — UpgradeRun / 目标集 / 预算 / 暂停恢复 / profile 原子激活 契约冻结

本卡是 [P4-03](P4-03.md) 拆出的**阶段 A**：把「一次升级运行」跑起来所需的**全部持久语义**先冻结成
契约——`upgrade_runs`/`upgrade_targets` 的表形态与闭集、目标集（差值集）的权威判定、预算与
暂停/恢复/取消的状态机、`search_profiles` 原子激活前的六条门禁、引用保护边界、失败分类到**既有**错误码的
映射，以及 `0017` 迁移的可实现性证明。

这是一个**只写契约、不写产品代码**的任务（A 级）：**阶段 A** 由独立 DS-H 会话草拟 ADR、机器可读 companion
与契约测试并做工程预审；**阶段 B** 必须由**独立 C2 / GPT-5.6 Sol / high** 会话聚焦终审并冻结。V3.1 §11
把「profile 原子激活、升级、回退、引用保护」列为高风险清单，V3.1 §9 的 P4-03 行要求 Sol 最终冻结 ⇒
属 §2.3 的**Sol 必选门禁，不得记 `SOL_NOT_REQUIRED`**；两阶段必须分别在两个**新会话**里完成。

推荐执行模型：**阶段 A — DS-H / DeepSeek V4.1 Flash / 高推理**；**阶段 B — C2 / GPT-5.6 Sol / high**。
模型切换始终由用户在 Codex 中手动完成；不得声称自动切换，也不得在同一会话中途换档。命中 V3.1 §2.2 六类
具名条件时才建议升 DS-MAX，且必须写明命中编号、已有证据与待回答问题。

**范围边界**：本卡**不实现**任何升级行为、不加迁移、不改 `schema_version`；实现与 D 级注入是 **P4-03B**。
本卡**不承担** §12.2 的前台性能目标（P4-02J 收口后 F2 仍未关闭），也不承担 P4-02J 收口新发现的

## 契约必须冻结的内容

以下每一条都要**逐条写进 ADR**，并在 companion 中用 `additionalProperties: false` 的公共 object 与
逐值 `oneOf`/`enum` 表达：

1. **表与列形态**：`upgrade_runs`、`upgrade_targets` 的稳定列名、类型、可空性、默认值、闭集 CHECK、
   PK/唯一键/外键（`run_id` → `upgrade_runs`、`asset_id` → `assets`、`generation_id`/`profile_id` 的引用
   形态与 `ON DELETE` 行为）、必要索引，以及 `control_revision` 的语义与自增规则。明确它与
   `index_generations`/`search_profiles` 的**权威边界**，不得形成双权威。
2. **run 状态机**：闭集 `PLANNED / RUNNING / PAUSED / CANCELLED / FAILED / SUCCEEDED` + **转换矩阵**
   （谁允许谁、每个转换的前置条件、重复请求的幂等行为），以及 `PAUSED` 的子状态
   `PAUSE_REASON ∈ {USER, BUDGET, ENVIRONMENT}` 与 `detail` 的字符/长度/禁止内容（不得含路径）。
3. **目标集（差值集）**：给出「该资产在目标 profile 的 `(space_id, processor_id, dimension)` 下**尚无当前
   revision 的 `CONFIRMED` 覆盖**」的**权威谓词**（引用既有 `index_entries`/`index_outbox`/
   `catalog_filter_revision` 口径，不得自造第二套 revision）；**plan 时快照一次**；`(run_id, asset_id)`
   唯一 + 幂等重放；`input_revision` 的来源与「目标已被更新内容取代」的判定接口（**只为 P4-04 留接口，
   本卡不实现追赶**）；目标行状态闭集 `PLANNED / IN_FLIGHT / SUCCEEDED / FAILED / CANCELLED`，
   `FAILED` 必须带冻结 `reason`；同一资产失败后重试的 revision/去重规则。
4. **预算语义**：`budget_targets`（NULL=不限）、`budget_seconds`（**墙钟**；PAUSED 期间冻结；累计
   `elapsed_ms` 的记录字段与口径）、`budget_concurrency`（一次领取目标数，不新增 worker/多 GPU）；
   「任一先到即软停」的**判定点**（批次边界）与到限后的 `state=PAUSED(reason=BUDGET)`；到限**不得**删除
   已完成目标行或产物、不得写成 `FAILED`/`CANCELLED`；可 resume 同一 run 且已完成目标跳过。
5. **暂停/恢复/取消**：暂停在**当前批次提交后**生效、在途批次保持可重放（沿用 outbox 语义）、不清产物；
   恢复从持久状态继续、`SUCCEEDED` 目标跳过、不得重复提交（幂等键）；取消保留已完成产物与人工事实、
   未处理目标转 `CANCELLED`、**不可 resume**；三个控制动作都是**单事务**（`BEGIN IMMEDIATE` + 状态谓词 +
   `control_revision` 自增），非法转换返回既有 `INVALID_STATE_TRANSITION`，控制请求可幂等重放。
6. **激活门禁与原子性（六条，失败不写任何行）**：① 目标 generation `state='READY'`；② 本次 run
   `SUCCEEDED`（或冻结的完整性策略）；③ 该空间**权威覆盖完整**（目标集逐资产 `index_entries.state='CONFIRMED'`
   且 `projection_revision` 为当前版本、`PENDING_REPAIR = 0`、该代 outbox 无未确认）；④ 引用 artifact 存在
   且可读（否则结构化 `ARTIFACT_MISSING`）；⑤ 引用保护成立；⑥ 任一条不成立 ⇒ **整体回滚、零写入**，
   返回**既有**错误码、**不新增信封字段**。六条必须写成 companion matrix + 契约用例，且「失败零写入」
   要有真实 SQLite 前后计数断言。
7. **引用保护边界**：哪些引用（活动 profile、在途查询/分页会话、UpgradeRun 目标、回退任务、备份清单）
   阻止 generation 被 retire/清理；被拒时的错误码与返回形态（用**既有**码）；不得顺带清理人工知识或原图；
   「默认仅保留前一个版本」的策略开关与空间上限字段（配置化）。
8. **失败分类映射表（零新增错误码）**：`reason` ↔ 既有错误码的**一对一或受约束组合**
   （`MODEL_WEIGHTS_MISSING`/`VRAM_INSUFFICIENT` → `RUNTIME_CAPABILITY_UNAVAILABLE{reason=…}`、
   `SOURCE_OFFLINE`（记在目标行）、`ARTIFACT_MISSING`、`LEASE_EXPIRED`/`STALE_LEASE`（可重试，takeover
   计一次失败）、`DISK_SPACE_INSUFFICIENT`、`SCHEDULER_PAUSED`、`INVALID_STATE_TRANSITION`）、
   记录位置（run 级 vs 目标行级）与可重试性；**禁止**隐式 CPU 降级或静默切换 profile。
9. **API/UI 最小契约**：只读升级状态入口（路径、字段名、分页/上限）与控制入口（暂停/恢复/取消）的请求/
   响应字段闭集；错误信封**逐字不变**（不得新增顶层字段）；UI 只展示冻结状态（完整设置页是 P4-06）。
10. **迁移与兼容契约（为 P4-03B 提供可实现性证明，本卡不实现）**：`0017` 编号、
    `SUPPORTED_SCHEMA_VERSION 16 → 17`、旧库升级路径与失败回滚、`0001`～`0016` **逐字节不变**、
    只读兼容检查（更高版本 → 既有 `SCHEMA_TOO_NEW` 行为）、以及**未使用升级功能的旧库行为逐字不变**。
11. **P4-03B 的验收前提清单**：D 级六项注入（升级中杀进程重启 / 暂停→恢复 / 预算耗尽中断 /
    激活失败原子回滚 / 旧 generation 在切换期间继续服务 / 被引用 generation 清理被拒，逐条要前后计数）、
    B 级命令、是否加 C 级（改打包资源才加）、BLOCKED 条目（真实权重、真实升级吞吐/显存、GTX 1660）的记录方式。

判定表、闭集、字段默认值与边界（NULL 预算、0/负数/超大预算、超长或含路径的 `detail`、幂等重放、
并发控制请求、目标集为空、被更新内容取代）都要在 ADR 中逐条写明。

## 契约测试与必测反例（A 级）

`tests/unit/test_p4_upgrade_contracts.py` 至少固定：

1. companion 是合法 JSON、SHA-256 与 ADR 记录一致、每个公共 object 都 `additionalProperties: false`；
2. run 状态闭集逐值接受、未知值拒绝；
3. 状态转换矩阵：允许的转换接受、**每类非法转换拒绝**（至少 6 条负例，含 `CANCELLED → RUNNING`、
   `SUCCEEDED → RUNNING`、`FAILED → RUNNING`）；
4. `PAUSE_REASON` 闭集 + `detail` 规则（超长、含路径分隔符、换行逐条拒绝）；
5. 目标行状态闭集 + `FAILED` 必须带 `reason`（缺 `reason` 拒绝）；
6. `reason` 闭集逐值接受、未知拒绝，且与错误码的映射不允许的组合被拒绝；
7. 预算判定：NULL/0/负数/超大值；「任一先到」的三组组合（目标数先到、秒数先到、并发上限）正反例；
8. 到限 ⇒ `PAUSED(BUDGET)` 且可 resume；把到限写成 `FAILED`/`CANCELLED` 的形态被拒绝；
9. 取消不可 resume；暂停后恢复只处理未 `SUCCEEDED` 的目标行；
10. 目标集差值判定：用**真实 SQLite 谓词或契约层表达式**构造「已有当前 revision 的 CONFIRMED」与
    「缺覆盖 / 陈旧 revision / `PENDING_REPAIR`」的行，断言只选后者（不得只做字符串断言）；
11. 目标集幂等：同一 plan 重复执行不产生第二行（`UNIQUE` 断言）+ `input_revision` 变更后的行为；
12. 激活六条门禁**逐条正例 + 逐条拒绝**（≥6 正 6 负），并断言拒绝路径零写入（真实 SQLite 前后计数）；
13. 引用保护：被活动 profile / 在途会话 / UpgradeRun / 回退任务引用的 generation 清理被拒；
    无引用时的行为按 ADR 明文断言；
14. API/UI 最小契约：字段名闭集 + 错误信封未新增顶层字段（对照既有 frozen companion/错误码表）；
15. 迁移契约：`0017` 编号、`16 → 17`、`0001`～`0016` 只读断言（migration 文件 sha256 列表）、
    旧库升级/回退路径的可实现性断言（纯契约，**不建表**）。

环境无第三方 JSON Schema validator 时，测试对 companion 实际使用的关键字子集执行正反例，并**不得**因此
声称已做完整 JSON Schema 校验。
