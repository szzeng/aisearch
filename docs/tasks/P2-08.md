做契约决策。不得自动切换模型、不得启动其它 Agent、不得声称已经切换。

## 用户场景

用户在图库正在被扫描、投影正在追赶、地点正在被人工整理的同时使用搜索页：他要能确定**自己看到的不是
半成品状态**——要么看到最新权威结果，要么看到可识别的过期/阻塞提示；扫描中断、程序重启、来源离线、
地名包缺失或换包都不能让他的搜索给出「看起来正常但实际错误」的答案，也不能让他的手工地点归属被自动
结果覆盖。

## 本卡范围（对抗性综合验收矩阵）

每条都必须**具名**、在 `%TEMP%` 夹具上注入真实故障（沿用 P2-03/P2-03A/P2-03B 已有的注入点，
不得为测试修改生产语义），并在报告中逐条给出实测结论：

1. **扫描中断与重启**：扫描中途终止 → 重启后继续；不出现整库误判缺失；中断期间某来源不可用时，
   资产身份与人工地点保持不变（联测 §12.4 第 1、6 条）。
2. **提交前终止**：推理完成、SQLite 事务提交前终止 → 允许重算、无半完成记录；重启后该资产在文本/
   向量通道的可见性与 `index_entries` 状态一致（§12.4 第 2 条）。
3. **LanceDB 已写、outbox 未确认**：重启重放无逻辑重复；期间查询的向量通道为空且 `pending_semantic`
   如实指名该资产（§12.4 第 3 条，联测 P2-05 §6）。
4. **旧租约/迟到结果**：过期 lease 的 worker 迟到提交被拒且零副作用；晚到的地点解析**不得**覆盖
   人工锁/排除（§12.4 第 4、31 条）。
5. **处理期间文件变化**：内容改变后旧结果（文本投影、向量条目、缩略图引用）不得附着到新内容；同一
   扫描内的观测不得继承更早执行的观测（联测 P1-02/P1-06 的窗口）。
6. **增量正确性**：新增 / 改名 / 移动 / 删除位置后，文本投影、地点有效归属、`GET /assets` 与
   `POST /search` 的可见性在同一权威版本下一致；重命名后**第一次查询**就能命中（权威补查）。
7. **过滤正确性**：祖先展开、同名地点、（`place_state` 的）无地点 / 人工未归类 / 待确认建议与
   来源、可用性 AND 组合；`place_ids` 与 `place_state=suggested` 的非法组合被结构化拒绝；
   跨来源副本去重不改变资产身份（§12.4 第 32 条）。
8. **后台竞争**：查询/续页/上传搜图与扫描、投影追赶、人工整理并发时，不出现半提交可见、不出现
   同一会话两种排序；会话在 `catalog_filter_revision`/`suggestion_revision`/profile 切换/进程重启后
   返回可识别过期码（`CATALOG_FILTER_REVISION_STALE`/`PLACE_SUGGESTION_REVISION_STALE`/
   `PROFILE_GENERATION_MISMATCH`/`SEARCH_SESSION_EXPIRED`），而不是空页或静默新排序。
9. **地名包生命周期**：缺包 / 坏包 / 换包 / 回退 + 重启后，人工地点与排除仍保留；旧建议仍可读、
   只有新解析被阻塞；`GET /places/datasets` 如实报告 `missing`/`invalid`/`active`（§12.4 第 33 条）。
10. **升级/回退边界**（只验收到当前实现已有能力）：旧 READY generation 在升级中断/取消后仍可服务；
    不宣称未实现的模型切换能力（架构 §11.3 属后续卡；本卡只做「旧 generation 继续可用」的实测）。
11. **上传搜图与上述状态的组合**：上传失败路径（超限/坏图）在任何并发状态下都不写库、不残留临时文件；
    成功路径（注入确定性假图像编码器）与文本通道共享同一权威复核。
12. **真实浏览器闭环**（必须，按 P1-05/P2-03C/P2-07 的方式记录逐步观察）：在搜索页完成一次
    「先搜索 → 期间用另一个请求/页面修改地点 → 续页/重搜 → 得到过期提示与补回结果」的闭环，并至少
    覆盖一个离线来源提示；若本构建缺编码器导致语义通道不可达，如实记录并以权威筛选/文本投影观察替代。

## 失败与升级

- 联测发现需要**新协议/新数据语义/新表**才能修的真实缺陷：保持 `VALIDATION PENDING`，停止并建议手动切
  **C2 / GPT-5.6 Sol / high**；不得自行改 ADR/冻结 schema。
- 问题落在 Windows 权限/路径、ONNX/GPU 运行库、PyInstaller 资源收集或真实模型接入：停止并建议手动切
  **C1 / GPT-5.6 Terra / medium**。
- 场景无法在 `%TEMP%` 夹具里安全注入（例如真实 USB/SMB 卷故障）：不得伪造，标记 `VALIDATION PENDING`
  并说明缺的是产品/硬件能力还是验收能力。

## 已知继承项（执行时先复核，勿静默忽略）

- 本构建的 API 进程**没有任何真实编码器**：文本查询 409 `QUERY_ENCODER_UNAVAILABLE`、上传搜图 409
  `IMAGE_ENCODER_UNAVAILABLE`，语义通道在真实浏览器里不可达（P2-06A §11.1、P2-07 §8.2/§11）。
- 搜索会话是**进程内**状态；反馈与地点操作是持久表。两者语义不同，不要混用。
- 页面、`GET /assets`、会话内复核都**不是**快照隔离读（P1-04/P2-03A/P2-06A/P2-07 记录）。
- `photo_search.geo.extract`/`geo.resolver`/`scheduler.engine` 仍不在冻结包内（无常驻调度线程）；
  若本卡改动导入图或打包资源，必须重跑 C 并复核。
- 打包 smoke 每次必须使用**新建**的工作目录；`D:\PhotoSearchSmoke\P2-06B*` 里各有一个 112 B 的
  遗留 `session.json`（旧 `(R,W)` DACL），不要擅自 takeown 或改写 ACL。
- 上传图硬限制只在 32×24 与注入的小上限夹具上验证过；真实 16 MiB / 60 MP 输入仍未测（P2-07 §11.4）。
