## 1. 唯一目标及产品决策

**统一弹窗负责日常看照片；独立完整详情页负责查看该资产的技术/诊断信息。** 用户点击任意照片后，可以通过弹窗标题栏「完整详情」直接进入以前保留的详细页面；在详情页点击「返回照片查看」，回到同一张照片及有效来源位置。

1. 所有通过 `AIPhotoInfo.open()` 创建的主照片弹窗，标题栏关闭按钮旁增加**一个**「完整详情」按钮；桌面显示文本，窄屏允许用图标+明确 `aria-label`，不能藏在需要猜测的高级菜单里。
2. 入口始终针对**当前正在显示的 `asset_id`**，包括已使用「上一张/下一张」切换到新资产的情况；请求未完成时亦不得跳向上一张的 ID。
3. 独立详情采用明确且可直达的 **`/#/asset/{asset_id}/details`**（例如 `/#/asset/123/details`）。现有 **`/#/asset/{id}` 继续代表兼容的共享弹窗**，不得直接改义或删除。
4. 详情页复用仓库中已有 `view-detail`、`renderDetail()`、`drawDetail()` 以及「更多信息与位置记录」字段，**不是另造一套详情数据 API**。保持旧详情页核心功能可用；页面以只读技术信息为主，不在本卡重写/扩展第二套图片缩放组件。原有图片区如继续保留，只做兼容维护，交互缩放的主入口仍是共享 viewer。
5. 返回后尽可能恢复：同一照片、来源相册、已验证的搜索范围和分页/滚动位置；任何会话/成员/日期规则失效时，绝不为了“强行恢复”而复活旧照片或旧 cursor。**浏览器 Back 允许回来源列表；明确点击「返回照片查看」才应尝试重新打开同一照片弹窗，二者都不能产生历史循环。**
6. 不触发原图下载、媒体重解码、人物/地点归属更改或任何数据库写入。

## 2. 仓库事实与重点风险

开始顺序：`AGENTS.md` → `docs/development-status.md` → 本卡 → `docs/reports/P4-UI2-VIEWER-UNIFY-A.md` → 下列直接相关代码及受影响测试。视觉继承 `docs/plans/P4-UI-VISUAL-TOKENS.md`，不要重读整个架构文档。

- `web/app.js` 里 `renderDetail()` / `drawDetail()` 仍完整存在，`web/index.html` 中 `#view-detail`、`#detail-body`、`#detail-back` 也未删除。高级字段由 `/assets/{id}` 等现有只读端点取得。
- 当前 `handleHash()` 只识别 `^#/asset/(\d+)$`，在 `AIPhotoInfo` 存在时打开弹窗；普通 `showDetail()` 也已改为 `AIPhotoInfo.open()`。因此**旧详情目前是保留代码，不是可直接访问的正常页面**。
- `web/photo-info.js` 的 `open()` 会为普通弹窗 `history.pushState({photoViewerKey:...}, sameURL)`；关闭后如果拥有历史标记，会调用 `history.back()`。**这是最高风险点**：不能在普通 `close()` 后立即执行 `location.hash=...`，否则可能与 popstate/关闭回调竞态，产生空白路由、退回两次或反复打开。
- 来源页面并非全在首页：搜索 `/search` 受 session/scope/revision 约束，人物/合集在 `/persons`，地点已有列表/详情精确路由，地图在 `/map`。`/#/asset/...` 的根页面不能靠当前 hash 或显示名称猜来源身份。
- `P4-UI2-VIEWER-UNIFY-A` 既有报告为功能范围通过、整体部分验收；本卡只覆盖**新增详情导航**涉及的行为，不追认旧卡未完成的长图、语义检索、性能、真实浏览器 200% 等门。

## 3. 入口与路由的确定合同

### A. 弹窗中的「完整详情」

- 按钮由共享 `AIPhotoInfo.open()` 生成，而**不是每个页面自行插入不同的详情链接**；对首页、搜索、人物、合集、地点、地图一视同仁。若某种编辑模式中 `beforeClose` 拒绝退出（`writing`、`pendingWrite`、确认弹窗），「完整详情」同样必须遵守，不得绕开写安全保护。
- 点击使用 `handle` 当前真实 `assetId`，并获取调用方提供的合法来源导航 adapter。**只允许一个**详情导航动作：连续双击、键盘重复触发或正在跳转时都不能叠加多个 history entry。
- 推荐给共享 viewer 添加小的 `onOpenFullDetails(currentAssetId, handle)` 回调（或同等窄范围 API）与 `navigateToDetails` 原因状态；保留普通 `close()` 的现有语义。由调用方在导航前捕获所需上下文，不让 viewer 掌管搜索/人物/地图业务。
- 标记“跳详情”不是 Esc/普通关闭：要先处理该 modal 当前 owned history entry，再原子导航到 `/` 的详情地址。实现可以采用经验证的专用跳转/替换路径，但**不得使用“普通关闭→无条件 history.back→立刻 location.href”**。页面切换后不能留幽灵 viewer 历史条目或重复的 popstate 回调；应单独覆盖 `options.history === false` 的旧深链模式。

### B. 两类 URL 的兼容

| URL | 必须行为 |
| --- | --- |
| `/#/asset/123` | 保持既有兼容的共享照片弹窗，旧链接可复制/直接打开/刷新 |
| `/#/asset/123/details` | 显示独立完整详情页，刷新/直接打开仍可读，不自动叠加 modal |
| `/` | 正常照片页；无详情 hash 时不无故打开 viewer |
| 非法 asset ID、资产不可用/404、请求报错 | 详情显示明确错误与安全返回操作，不无限重试、不自动展示另一个资产 |

路由匹配要先区分明确的 `details` 后缀，再匹配原旧路径；不能让宽泛正则/回调将完整详情地址误识别为普通 viewer 或直接清空 hash。应支持 Back/Forward、重复 hash、刷新和取消导航，防止路由重入。

### C. 独立详情页呈现

- **优先复用 `renderDetail/drawDetail` 的数据及字段**，保持原信息含义与结构化错误展示。若出于界面一致性减少旧页面的重复缩放控件，必须保留有用的图片预览和明确的「返回照片查看」操作；不要无声删除原页面技术字段，也不要为本卡重做图片缩放状态机。
- 标题显示真实文件名，缺失时退回资产编号；原有 `sha256`、`media` 状态、相机、时区、EXIF 墙上时间与文件时间标签不能混写。
- 保留只读状态下现有「打开原图」及文件位置功能的合法失败/离线提示，遵循同源会话和已有安全策略；不新增绕过鉴权的直链。
- 页面与当前 UI 2.0 设计 token 对齐，明确「完整详情」为技术资料页而非又一个主相册；窄屏时长路径和技术表格可折行/局部滚动，不出现不可关闭的大弹窗。

## 4. 返回与上下文：先恢复可信状态，再恢复 viewer

**主要体验**：照片列表 → 弹窗（A）→ 完整详情（A）→「返回照片查看」（A）→ 关闭弹窗 → 原照片列表。

| 进入来源 | 「返回照片查看」期望 | 安全边界 |
| --- | --- | --- |
| 首页普通列表/时间轴/单一图库 | 原资产 viewer，关闭后原来源/日期桶/合法滚动锚点 | 复用 `app.js` 既有 `browse` 返回机制，虚拟回收后用合法邻近锚点，不预载全部相册 |
| 搜索结果 | 可信原结果的同一资产，保留 q、scope chip、显式条件与已验证候选顺序 | 沿用现有搜索快照/session/revision 校验；`FILTER_ONLY` 按既有权威恢复，不重用失效 cursor，不自动重新全库搜索 |
| 人物或合集相册 | 原人物/合集合法照片，已打开位置和当前筛选尽量恢复 | 绑定人物 canonical ID、合集 instance/revision；已失效时只保留合法导航/提示，不能恢复过期成员 |
| 地点相册 | 返回精确的地点详情及合法照片范围 | 复用已实现的地点路由、成员/活动包 revision；不按同名地点重新猜测 |
| 地图相册 | 原地图中心/缩放/bbox/排序及同资产 viewer，若数据有效 | 离开 `/map` 前捕获既有 viewport 成员版本，并在恢复时校验；bbox/revision 改变不能继续旧列表 |
| 直接打开 `/#/asset/123/details` 的人 | 点击返回照片查看时打开**该资产共享 viewer**，无已知原来源则关闭后安全回首页 | **不盲目 history.back() 离站**；不得利用任意 URL 参数实现外站跳转 |

实现策略：来源页面用**一次性、会话内、最小化**的导航意图（asset ID + origin kind + 已有合法页面 route/snapshot 标识 + 必要的版本约束），优先复用当前 search/map/person/place 已建立的快照/返回方式。`sessionStorage` 仅用于恢复用户导航体验，**不是权限、范围成员或 search session 的权威**，不能存几十万 asset ID、全部搜索结果、原图路径、会话 token 或原图数据。交接 token 必须限于当前会话、一次性消费并与目标 asset ID 和允许的同源路径匹配；禁止任意 `return_url` 导致开放跳转。导航意图发生过期/被覆盖/JSON 无效/存储拒绝时，应降级为安全的查看当前资产或列表，同时明确提示，不悄悄丢失用户固定搜索范围。

浏览器 Back/Forward：从详情点 Back 可正常返回可信来源页或既有合法浏览器历史项；“返回照片查看”明确尝试重新打开同一张照片并只触发一次回源，不能形成 Back→再次打开详情→再次 Back 的循环。缺少来源时保持页内安全回退，绝不跳向外部站点。若 viewer 来源上下文发生真实过期，允许先回到列表并提示重新查询，而不是伪造照片所在位置。

### 4.1 路由与弹窗历史交接的最小状态机（新增施工约束）

**先写最小状态转换表，后改代码**；不可只依赖 `setTimeout` 或“先 close 再设置 hash”赌事件顺序。

| 起点 | 用户动作 | 目标状态 | 历史/清理约束 |
| --- | --- | --- | --- |
| 普通来源页面中的 modal（`historyOwned=true`） | 点击「完整详情」 | 独立 `details` 页面（仅一份） | 按明确的“去详情”退出原因移除本 modal 拥有的历史标记；**详情地址在浏览器历史中可正常 Back/Forward**，但不可残留空白 modal step |
| 旧 `/#/asset/id` 打开的 modal（`history:false`） | 点击「完整详情」 | 同一资产的 `/#/asset/id/details` | 不做本不存在的 modal 历史回退；独立详情可刷新 |
| 任意 modal | Esc、关闭、遮罩或浏览器 Back | 原有安全关闭 | 不触发「去详情」回调；保留现有 focus/return 逻辑 |
| 详情页面 | 点「返回照片查看」 | 同资产共享 modal | 可验证来源时沿用原上下文；无来源时原地打开该资产，不构造无依据的上一张/下一张 |
| 详情页面 | 浏览器 Back | 合法上一历史项/来源页面 | 不强制重新打开弹窗，不进入 hashchange/popstate 互相触发循环 |
| 详情页面 | 刷新/复制 URL 直达 | 只渲染详情 | 不要求 sessionStorage 中存在 origin token；未加载完不可冒出旧 modal |

明确导航过程的**一次性性**：先验证当前 `assetId` 与 `beforeClose`，标记 intent；退出 modal 并释放监听、地图、异步代际；清理其 owned history；仅进行一次路由跳转。不得在关闭回调里错误执行旧深链的“回首页”分支或旧 `history.back()`。此处是行为合同，允许实现者按真实原生 history 事件选择等效原子序列，但必须用合成 DOM 与至少一条浏览器实际行为证明。

### 4.2 资产身份、来源适配与退化策略

- 每次 `setAsset(B)` 之后，「完整详情」都必须读取 **B 的实时 asset ID**，而非打开 A 时的闭包。若 B 的详情资源尚在加载，页面可以显示 B 的加载态；不得错用 A 的信息。
- `photo-info.js` 只能传递受限导航意图，不能直接解析 `/search` 快照、`/persons` 合集版本或 `/map` bbox。跨页返回必须使用已有来源模块明确提供的 adapter 和权威恢复机制；默认 `/#/asset/id/details` 只保证**当前资产**可查看，不保证未经核实的原列表位置。
- 一次性 token / 临时 intent 应带源页面标识、asset ID、短时有效性/消费标记；避免同标签页连开 A、B 后串线。失效、重放、非法 JSON、存储拒绝与未知来源时安全降级，不伪造排序/命中或自动扩大为全库。**URL 仅携带资产 ID 和固定路径，不放敏感令牌、磁盘绝对路径或任意回跳地址。**
- 原本的「返回浏览」若被改为「返回照片查看」，只影响真正 `details` 页面；原兼容路径 `/#/asset/id` 的关闭逻辑不改变。失效时要能从详情安全返回照片主页，且与浏览器 Back 的预期分开。
- UI header 入口要有键盘可操作的语义按钮、清楚的标题、合适的焦点顺序。进入详情后聚焦标题或内容主区，返回后聚焦查看器中可见且有效的控件；不存在来源元素时不访问脱离 DOM 的旧节点。
