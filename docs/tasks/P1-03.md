## 任务定位

P1-01 建立了资产/位置/来源身份与迁移契约；P1-02 把扫描器升级为可用于真实图库的流式扫描器。P1-03 让
**已经完成 catalog 的资产第一次「能被看见」**：按 EXIF 方向归一化后生成网格缩略图与详情预览，放进可重建、
可分片的缓存目录，用原子发布保证不出现半成品，并把坏图、不支持格式、原图离线等情况与整批处理隔离开。

本任务仍然**不实现** AI（人脸/OCR/图文向量/描述）、HTTP sources/assets API、前端页面、搜索与索引、
outbox/index generation、P2 调度协议。P1-03 的解码与缩略图属于架构 §5.4 与 ADR-0002 §13 明确延后到 P1-02
之后的媒体处理范围。

## 用户场景

用户完成一次大目录扫描后：

- 打开列表/详情时能看到方向正确、尺寸合适的缩略图与预览，不必等待原图复制或重新压缩；
- 缓存目录可以整体删除或迁移，程序能按需重建，不丢失资产身份、位置关系或任何人工结论；
- 个别损坏、截断、非图片或暂不支持的 RAW/TIFF 文件只影响它自己，不会让整批缩略图任务失败；
- 原图在断盘/离线状态下，已经生成过的缩略图仍可显示，并明确提示原文件不可用；
- 生成过程中断电或被杀，重启后不会把半写文件当成可用的缩略图。

验收一律使用 `%TEMP%` 下的临时夹具，**不得**读取真实照片库。

## 必须交付

### 1. 方向归一化与尺寸契约（架构 §5.4）

- 每个输入先按 EXIF Orientation（1～8，含 3 组镜像变体）归一化，再决定缩略图、预览的像素内容；
  「方向修正后的图像」是后续所有坐标/尺寸结果的基础。
- 网格缩略图：长边 **320 px**，JPEG；WebP 仅当实测可用且作为可选目标，未验证就不得声称支持。
- 详情预览：长边 **1600 px**，**按需懒生成**，可单独清理。
- 必须给出实测的典型文件大小与生成耗时（临时夹具），不得只凭估计。
- 原图只读：绝不写回、改名、移动或删除来源目录中的任何文件。

### 2. 缓存分片与可重建（架构 §5.4、§4.4、§11.1）

- 缓存落在数据目录（`<data_root>/thumbnails/`、`<data_root>/previews/`），**不得**位于任何来源内部。
- 文件名包含 `asset_id` 或内容指纹与**处理版本**（如处理器/参数版本），目录两级分片。
- 整体删除缓存目录后必须能重建，且不改变资产身份、位置关系或人工数据（缓存优先级最低，可重建）。
- 同一资产重复请求必须幂等：不产生重复文件，不重算已有有效产物（是否重算由处理版本决定并写入报告）。

### 3. 原子发布与坏图隔离（架构 §5.4、§12.4 第 13 条）

- 临时文件写在目标分片目录内，写完后原子替换目标；**半成品绝不标记为 READY**。
- 生成中进程被杀：重启后要么重新生成，要么忽略残留临时文件；不得把不完整文件当作有效缩略图返回。
- 解码失败保留记录与原因（结构化错误码 + 简短信息），**不能阻塞整批**：一次批量生成结束后，
  成功/失败/不支持的数量必须可观测，失败原因可枚举（例如 `DECODE_FAILED`、`FORMAT_UNSUPPORTED`、
  `SOURCE_FILE_MISSING`、`DISK_SPACE_INSUFFICIENT`）。
- TIFF/RAW 等在未验证前必须显示「格式暂不支持」，**不得**把失败伪装成完成。
- 磁盘空间不足时停止提交并结构化报错，不删除人工数据或既有产物「自救」。

### 4. 离线与缺失定位（架构 §5.2、§5.4）

- 资产的所有位置都 `MISSING`（原图不可用）时：已生成的缩略图/预览仍必须可用；未生成时必须返回
  「原文件不可用」，而不是报成坏图或伪造空白图。
- 资产有多个位置时，优先使用可用位置；某个位置消失不得使整个资产不可用。

### 5. 可观测性与入口（架构 §6.3、P1-01 入口约定）

- 新增内部入口（建议 `catalog thumbnail` / `catalog preview` / `catalog media-status` 之一或多个，具体名称执行时
  按现有 CLI 风格确定），支持 `--json` 与结构化错误、非零退出码；批量模式必须可重复执行且可中断。
- 进度/失败计数若写入 `jobs.progress`，必须沿用 P1-02 的规则：同一已通过提交资格校验的事务内写入、
  0.0～1.0、单调不减；不得绕过 ADR-0002 §6.5。
- 任务记录/日志不得写入个人图片内容、OCR 原文等不必要隐私数据。

### 6. 明确不做

- 不做 HTTP API（P1-04）、不做前端页面（P1-05）、不做重复/断盘/重映射验收（P1-06）。
- 不做 AI 推理、人脸、OCR、图文向量、FTS、outbox、索引世代、search profile。
- 不引入新依赖（预期只用 Pillow + 标准库）；不加 Docker/Redis/云服务/第二个向量后端/ORM 迁移框架。
- 不提前实现 P2 全量调度协议（本任务只用 P1-01/P1-02 已冻结的最小 job 子集）。

## 正常行为 / 异常行为 / 边界情况（验收时逐条覆盖）

**正常行为**

- 批量生成 N 张（临时夹具）后，每张都有方向正确、尺寸符合契约的缩略图；`--json` 汇总成功/失败/不支持数量。
- 重复运行同一批：不重复生成、不产生重复文件，输出稳定。
- 删除缓存目录后重建：资产/位置/人工数据不变，缩略图可再次生成。

**异常行为**

- 损坏/截断 JPEG、0 字节文件、非图片扩展名内容：单个失败被隔离，整批仍然完成并报告原因。
- 生成过程中被杀/中断：没有 READY 的半成品；重跑可补齐。
- 原图在扫描后消失或来源离线：返回「原文件不可用」，已有缩略图仍可用，不产生删除结论。
- 磁盘空间不足：结构化错误 + 非零退出码，不删除既有数据。

**边界情况**

- EXIF Orientation 1～8（至少覆盖 2、3、6、8 与镜像变体）。
- 中文/空格/长路径来源；只读原文件；巨大尺寸图像；极小图像（长边 < 320 px，不得放大到失真）。
- 同内容多位置（一个 PRESENT、一个 MISSING）；跨两个来源的同内容资产。
- PNG 等非 JPEG 输入；Alpha/透明通道输入；灰度输入。
- 缓存目录已存在的旧版本产物（处理版本变化后必须可分辨，不得混用）。

7. 资产所有位置 MISSING / 来源离线 → 已有缩略图仍可用，未生成时返回「原文件不可用」。
8. 中文/空格/长路径来源 + 只读原文件 → 全部成功，原文件属性不被修改。
9. 磁盘空间不足（可注入 `disk_usage`）→ 结构化错误 + 非零退出码，既有产物不被删除。
10. 规模/性能测量：用 `tools/` 下新增的只读脚本在临时目录生成 200～1000 张真实 JPEG 夹具，记录
    生成吞吐、单张耗时、缓存占用与峰值内存；成功只保留摘要，失败才展开日志。

成功时只保留 quiet 摘要、退出码与必要计时；失败时先读失败测试名与 traceback 尾部，只重跑失败目标。
任一必需场景未真实完成，不得标记 PASS（可用 `IMPLEMENTED / VALIDATION PENDING`、`BLOCKED`、`FAIL`）。
