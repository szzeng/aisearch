ADR-0007 的冻结语义是否真的被实现、被测试、被拒绝，只在发现**确凿缺陷**时做最小修复。

执行模型：**C2（GPT-5.6 Sol / high）**。模型切换由用户在 Codex 中手动完成；不得自动切换、启动其他
Agent 或声称已切换。需要 ONNX/CUDA/DLL/Windows ACL/路径/PyInstaller 判断时，转 **C1 / GPT-5.6 Terra /
medium**；需要改变 ADR-0007 冻结语义时，停止并报告，不得自行修改冻结文件。

## 审查要点（至少逐项给出 PASS / FAIL / 无法判定 + 证据）

1. **迁移**：0012 是否只重建 `person_operations`/`person_operation_items`；`0001`～`0011` 是否逐字节未改；
   重建是否在真实 v11 库上逐列保留 operation/item/undo/alias/control/exclusion；备份、单事务、缺件、
   损坏回滚、过新拒写是否都成立；`PERSON_BUNDLE.after_revision >= 1` 与 `entity_id >= 1` 是否仍被强制。
2. **模式/排除矩阵**：ADR-0007 §3 表格逐行核对实现与拒绝；无控制行 = `AUTO_ALLOWED/revision 0`；
   `restore_auto` 是否真的保留全部排除、不采用建议；assign 回曾排除目标是只解除该目标；合并后
   canonical 等价是否生效。
3. **不变量**：每脸至多一个 CONFIRMED；`MANUAL_ASSIGNED` 恰有一个 `MANUAL/CONFIRMED`；
   `MANUAL_UNASSIGNED` 没有 CONFIRMED；一次操作是否可能把其他脸带入修改范围。
4. **幂等与批量**：门禁是否早于一切 revision 检查；同 key 异 payload 是否零写；去重前后的 500 上限、
   重复 face、单事务全量校验是否与 ADR §5 一致；payload hash 是否只含 requested 形状且顺序无关。
5. **撤销**：是否为新 `UNDO` 操作；冲突是否整批拒绝且零写；revision 是否始终向前；是否禁止 undo an UNDO；
   `FACE_OPERATION_NOT_UNDOABLE` 与 `PERSON_OPERATION_NOT_UNDOABLE` 的分派是否可解释、是否有回落漏洞。
6. **自动路径门禁**：`_control_revision_gate()` 是否真的在权威写事务内比较；`MANUAL_*` 与活动排除是否
   零覆盖；建议是否任何路径都不能被提升为 CONFIRMED；晚到结果是否零写权威关系。
7. **权威→派生**：filter revision 是否最多 +1、cause 是否复用 `PERSON_CHANGED`、队列与
   `PENDING_REPAIR` 是否只在 changed 时发生；no-op/replay 是否零副作用；是否误写图片向量 `index_outbox`。
8. **API/错误/隐私**：四条路径与 envelope 是否与 ADR-0007 §6/companion 一致；HTTP 映射、错误码闭合、
   响应字段是否与 companion 的 `additionalProperties: false` 兼容；session/Host/Origin/CSRF 与脱敏是否
   无法绕过；响应/错误/日志是否不含路径、bbox、landmark、向量、confidence/单对相似度、幂等 payload。
9. **只读计数**：四个计数口径是否与 ADR §9 一致（canonical pair 去重、未命名分组不计入待整理、
  建议不计入归属）；坏/过新 schema 是否沿用既有只读诊断边界。
10. **测试质量**：50 个新用例是否真正断言了 ADR §11 的 14 组反例，而不是复述实现；是否存在
    “只断言不报错”“断言被 try/except 吞掉”“覆盖率数字代替行为证据”的情况。

可以（并且应该）自己写**临时**探针复现怀疑点，但临时文件不得留在仓库里；不要为了“再审一遍”而复制
P3-04B 的测试文件。

## 允许修改

- 只允许修复审查中发现的确凿缺陷，且必须保持 ADR-0007 冻结语义不变。
- 允许范围：`src/photo_search/persons/**`、`src/photo_search/face/{index,processor}.py`、
  `src/photo_search/catalog/{schema,errors}.py`、`src/photo_search/scheduler/projection.py`、
  `src/photo_search/api/{models,routes,errors}.py`、新增 migration（**仅当** 0012 存在确凿缺陷时，且必须
  连续、不得修改 `0001`～`0012` 的历史语义）、`tests/**`（新增/修正用例）、本任务报告、状态与下一卡。
- 修复必须在报告中说明：缺陷、最小修复、为什么不是改冻结语义。

## 禁止修改

- ADR-0007 与 `p3-face-correction-contracts.v1.json`、ADR-0001～0006、既有 contract JSON。
- `0001`～`0011` 逐字节、`pyproject.toml`、`uv.lock`、`PhotoSearch.spec`、前端资源。
- `face_id`/`face-document.v1`、检测/质量/阈值/向量 space、候选 generation、每脸至多一个 CONFIRMED、
  P1/P2/OCR/place/search/profile/feedback 既有协议。
- 真实私人照片或真实照片库；只用 `%TEMP%` 下的合成/公共领域夹具。

## 必须保持的不变量

与 P3-04B 任务卡 §「必须保持的不变量」1～10 条完全一致（SQLite 权威、face_id 最小单位、MANUAL 两态与

## 验收

必需命令（项目内 `.uv-cache`；必须生成 JUnit XML；成功只保留 quiet 摘要）：

```text
uv run --no-sync pytest -q -p no:cacheprovider tests/unit tests/integration
uv run --no-sync ruff check .
git diff --check
uv run --no-sync uv lock --check
```

等级：**A + D 复核 + C 复核**（本任务默认不新增生产行为，因此不重复实现级 C；但**只要**改动了
`src/photo_search/**`（含 migration）就必须重跑 C 级：真实 onedir 重建 + 新建 D 盘 smoke 目录运行
`packaged_api_smoke.py`，并核对 bundle 内 `0001`～`0012` 连续且 `0012` 与源码 hash 一致）。

审查必须至少**独立复现**以下 6 组（不得只读代码）：

1. v11→v12 在含 undo/alias 引用的真实库上逐列保留；
2. 无控制行 `expected_revision=0` 首次 unassign → revision 1；错误传 1 被拒且不补建行；
3. 同 `request_id` 同 payload 在 revision 已变化后仍 replay；同 key 异 payload 零写冲突；
4. 批量第二项冲突时第一项、operation、filter revision、队列全部回滚；
5. 撤销被后续人工编辑改变的脸 → 整批 `FACE_OPERATION_NOT_UNDOABLE` 且 revision 不倒退；
6. `AUTO_ALLOWED` 且带活动排除的脸在重新关联后不回到被排除人物（含合并后的 canonical 等价）。

如需权威浏览器/打包证据：真实 smoke 使用 P3-02/P3-03 的公共领域夹具，在 `%TEMP%` 走
自动分组→命名→单脸取消→指定另一人物→恢复自动→撤销→重启查询；不得使用私人照片。
无法跑完任一必需项时不得标 PASS，写 `VALIDATION PENDING` 或 `FAIL` 并说明缺口。
