## 允许修改

- `pyproject.toml`、`uv.lock`：只新增本任务必需的 CPU 依赖（RapidOCR ONNX 运行时包；insightface 需先验证安装方式，失败则改用固定 ONNX 权重直载）。不得同时安装两个 ONNX Runtime 构建。
- `tools/prepare_models/`：下载/校验脚本与 manifest JSON。
- `tests/`：manifest 契约、预处理与权重存在性相关测试（缺权重可显式 skip，但报告要写明）。
- `docs/reports/P0-04-face-ocr-load.md`、`docs/development-status.md`、`docs/tasks/P0-05.md`。
- `.gitignore`：仅在确有必要时排除下载到仓库内的权重/缓存。

## 禁止修改

- 不修改 `src/photo_search/`，不添加 API、worker、队列、profile/generation、`indexing/` 或 `search/` 模块。
- 不把权重、ONNX 大文件或下载缓存提交进 Git；仓库只保留脚本、manifest 元数据与报告。
- 不扫描、读取、修改任何真实照片库；夹具必须脚本生成或明确授权（不得使用用户照片）。
- 不训练、不微调、不量化；不改 LanceDB/FAISS/sqlite-vec/Qdrant、Docker、Redis 或云服务；不实现动态 batch、GPU 常驻、模型切换或打包。

## 必须保持的不变量与行为

1. `GET /api/v1/health` 保持不变；业务代码不得写死 ONNX、设备、模型名或固定分辨率（§11.3.4）。
2. manifest 是模型身份的权威记录：权重可重下，但必须能由 manifest 校验（路径、字节数、SHA-256）。
3. 软件包许可不等于权重许可（§8.3）：许可证以实际仓库/权重声明为准并记录原文链接与摘录时间，不得臆造。
4. RapidOCR 必须固定检测、方向分类、识别三个权重文件，禁止依赖“最新默认模型”；OCR 与人物各用自己的预处理配置，不共用缩小后的网格缩略图（§5.4）。
5. 人脸只加载检测与识别所需文件，不启用年龄/性别/3D 等无关模型。
6. 真实推理（CPU 必测）：用脚本生成夹具跑一次 OCR 与一次人脸检测+特征提取；合成图检不到人脸不是失败，但要如实记录，正样本可用明确授权的开发图片。空白图不得崩溃。
7. 单独记录 `onnxruntime` 可用 provider、是否存在 CUDA provider、是否实际跑过；不以硬件存在推断可用。
8. 异常路径（下载失败、哈希不匹配、权重缺失、加载/推理失败）必须非零退出并输出阶段、异常类型、消息与已完成步骤，不得掩盖为 PASS。
9. 边界：只覆盖 Windows CPU、固定权重、脚本夹具与结构验证；不承诺准确率、精度、吞吐、并发、动态 batch、FP16/量化或与官方基准的对比。
10. 所有权重与缓存留在用户数据目录（主架构 §11.1），不得写入仓库或安装目录。
