## 必须交付的测量事实

1. **同一检索的证明**：两个 data root 必须由同一 `--seed 20260924`、同一夹具构造、同一替身编码器、
   同一查询 `西湖 sunset 全家福`、同一 `top_k` 构建；每轮记录返回 ID 列表与距离摘要，
   并与 `test-results/p4-02b-*.json` 的对应页比对（证明是同一检索而不是换了数据）。
2. **受控设计**：保留两个可丢弃 data root（A=一次性突发、B=有界波次），每轮按 **A / B / B / A**
   交替执行查询采样（≥20 样本/轮），并记录执行顺序与环境（是否有其他负载、OS 缓存是否为冷）。
   只允许在**复建**环节改变一个变量；查询环节不得改代码、不得改夹具。
3. **每轮必录字段**：候选数、块数、每块耗时（或每块耗时分位）、SQLite 候选 walk 耗时、
   Lance 调用次数与其固定开销、Lance 表 fragment 数/表 version/索引目录（含
   `num_indexed_rows` 与 `num_unindexed_rows`）、进程工作集峰值、磁盘读写字节、CPU 时间。
4. **F4 变量单列**：对两个 data root 分别记录 `asset_id_idx` 的覆盖率；再在同一表上做一次
   **显式 `replace` 重建索引**的对照测量（只用于归因，不改产品行为），量化「覆盖率 100% vs 部分」
   对同一查询页与耗时的影响。这是 DS-H §7 指出的、能同时解释「P4-01 的 3.6 s 与 P4-02B 的 125 s 差 35 倍」
   的候选变量。
5. **归因结论**：只允许在「阶段耗时 + 布局证据」共同指向某一层时写成根因；不得把
   「Lance 布局敏感」直接当成已证结论。若一轮内仍无法归因，给出已排除项与下一轮最小变量。
6. **成本说明**：首选与差异同规模（10 万）。若成本受限，可先用 3 万档做预筛，
   但报告中必须写明它**只是预筛**、不能代替 10 万结论。
