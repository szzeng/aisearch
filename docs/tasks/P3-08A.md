不新增 migration、不运行真实照片库**。P3-08 拆为：

### 必须冻结的问题

#### 1. 映射身份、状态与唯一性

- 明确 old/new face 的稳定键、asset identity、旧/新 processor/spec/generation、方向修正坐标系中的
  bbox/landmarks 锚点和审核状态；禁止用 ordinal、cluster id 或 person id 冒充脸映射身份。
- 定义 0/1/多候选、同脸、拆成多脸、多脸合成一脸、跨资产候选、低质量/无 landmarks、旧脸已人工控制、
  新脸又被人工编辑等情形；任何歧义不得自动转移人工知识。
- 明确 candidate 生成可自动、**确认/拒绝必须可审查**；未确认前旧人工事实继续可查询，新脸不得静默继承
  MANUAL_ASSIGNED、MANUAL_UNASSIGNED 或 exclusions。

#### 2. 确认事务与人工知识

- 冻结确认/拒绝/撤销的单事务边界、expected revision、request_id 幂等、操作日志与补偿撤销形状；不得建立
  第二套人物操作 authority。
- 明确确认后 link、control、exclusion、avatar、候选代表、旧脸可见性与派生索引/outbox 如何处理；人工肯定
  与否定冲突时不得靠覆盖解决，晚到自动结果不得改写人工选择。
- 明确重启、重复检测、检测失败/取消、旧 worker 迟到、模型升级/回退以及备份恢复时的持久状态；revision
  必须前进，不能回退版本号或丢失旧审计链。

#### 3. API、错误与隐私

- 冻结最小只读审核面与确认/拒绝/撤销写面，请求/响应字段、分页、revision、幂等和稳定错误码；
- API 不得返回 embedding、完整 landmarks/bbox、置信向量、绝对路径、原始 EXIF/GPS 或内部快照；浏览器只用
  受控 face/asset ID 获取裁剪或预览；
- 明确哪些 capability/schema 状态隐藏入口，旧 schema/无候选时诚实返回，不伪造已支持。

#### 4. P3 故障全集与跨人物/地点纠错矩阵

`p3-acceptance-matrix.v1.json` 必须给每个场景稳定 ID、上位条款、夹具、注入点、预期权威状态、允许/禁止的
副作用、现有证据或缺口、P3-08B 对应测试/浏览器步骤。至少覆盖：

- 主架构 §12.4 的人物项 8、14～22；新旧 face mapping 的生成、确认、拒绝、撤销、重启、重扫、升级失败、
  回退与晚到 worker；
- 人物 rename/merge/split/face correction/undo 与地点 assign/unassign/restore_auto/batch/undo 的交错顺序；
  每次只影响自己的 authority，但共同递增/校验 `catalog_filter_revision`，旧搜索会话必须明确 stale；
- 同图 sibling、MANUAL_UNASSIGNED、活动 exclusion、肯定/否定冲突、旧 canonical id、投影滞后补查；
- 主架构 §12.4 的地点交叉项 29～33，确保 GPS/OCR 建议不越权、人物和地点 AND 搜索不混版、不泄露坐标；
- P3-07B §6 的 merge target 高 id → undo 唯一索引冲突，列为 P3-08B **必须修复**，同时覆盖反向 id 顺序、
  多 source、控制/排除和后续编辑冲突；
- 真实浏览器闭环计划：`/persons`、`/places`、`/search` 之间完成可见的纠错→筛选→撤销/冲突→重搜，窄宽
  视口、键盘、无路径/坐标/外链泄露、访问日志边界。自动化工具未落地前只能称“记录的真实浏览器 smoke”，
  不得写 Playwright/Selenium PASS。
