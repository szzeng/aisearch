## 不变量与行为

当前唯一应用接口 `GET /api/v1/health` 保持不变。SQLite 是业务状态权威、LanceDB 是可重建投影的原则不变：本探针只证明向量侧的过滤与新增可见性，不改变任何权威数据语义。探针数据仅存于 pytest `tmp_path` 或脚本自建的临时目录，退出后不得在仓库、安装目录或用户数据目录残留 `.lance` 目录或表文件。所有命令使用 `uv run` 与 Python 3.12.10，不得使用 Python 3.14。结果必须来自真实写入与真实过滤查询，不得用固定成功 JSON、假向量或只验证 import 取代。

在 `tools/benchmarks/` 实现可直接运行的探针，输出可机读且便于报告摘录的 Python/LanceDB 版本、表 schema、使用的过滤表达式原文、每次查询的预期与实得 id 列表。正常路径必须在同一张新建落盘表上完成：

1. 建立显式 schema：`id`、固定维度向量、以及至少两个可过滤字段（例如 `space_id`、`source_id` 或布尔可见性标志），记录字段与取值。
2. 写入至少 6 条可区分记录，跨越至少两个过滤分组，且各分组内最近邻顺序可预期。
3. 执行一次带过滤条件的真实向量检索，断言返回 id 恰好是预期子集且顺序符合预期。
4. 执行第二次检索，用过滤条件排除“全表最近邻”，断言第一名变为该过滤组内的最近邻，并且被排除的 id 绝不出现在结果中。
5. 在已存在数据的情况下新增一条向量（该表不依赖任何 ANN 索引维护；若创建了索引，必须记录，并证明新增行无需重建索引即可被检索到），断言新增 id 在过滤与不过滤两种查询下都能被查到。
6. 记录每次查询使用的过滤表达式原文，便于报告核对，并说明过滤是在扫描前生效（LanceDB `where` 预过滤）。

异常路径：过滤表达式非法或引用不存在的列时，探针必须以非零退出，输出 SQLite/LanceDB 版本、异常类型与消息；**不得静默退化为无过滤查询**，也不得把“返回了结果”当成通过。回归测试覆盖成功路径、关键结果断言、以及该非法过滤器的失败路径。边界只覆盖本探针使用的固定维度、单进程、顺序写入与简单 AND 条件；不要承诺过滤下推性能、否定条件与 NULL 语义、复杂 OR/IN 组合、并发写入、ANN recall 或跨版本兼容。
