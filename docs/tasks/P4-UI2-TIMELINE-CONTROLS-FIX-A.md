## 目标

照片页面在「时间轴」模式下，必须隐藏仅属于「列表与高级日期条件」的「排序」「拍摄时间从」「到（不含）」「刷新」及列表日期说明。保留「图库筛选」和时间轴自己的「时间依据」「按日/月/年分组」「年月范围与直接定位」。切回列表时恢复全部列表控件。此修复不能改变既有查询结果、排序、过滤状态和 Timeline 数据语义。

| 控件 | 时间轴 | 列表 |
| --- | --- | --- |
| 图库筛选 | 显示 | 显示 |
| 旧列表排序 | 隐藏 | 显示 |
| 旧列表拍摄日期起止输入 | 隐藏 | 显示 |
| 旧列表刷新与日期提示 | 隐藏 | 按原逻辑显示 |
| 时间轴时间依据、分组、年份月份定位 | 显示 | 隐藏 |
| 两种视图的切换入口 | 可操作 | 可操作 |

## 已确认的代码线索

- `src/photo_search/web/index.html` 将排序、日期输入和刷新放入 `#browse-list-filters`，但 `#browse-source` 在此容器外。
- `src/photo_search/web/app.js` 的 `showBrowseMode(mode)` 已设置 `els.browseListFilters.hidden = useTimeline`，以及其他模式相关区域的可见性。
- `src/photo_search/web/photo-timeline.css` 写有 `.browse-controls #browse-list-filters { display:flex; }`，可能因 CSS 优先级覆盖浏览器对 `hidden` 的默认隐藏；这是应先验证的直接原因。
- `src/photo_search/web/styles.css` 已对 `#browse-timeline[hidden]` 写过专用规则。不要重新实现时间轴或列表过滤机制。

## 实施约束

1. 优先用最小 CSS 修复：对 `.browse-controls #browse-list-filters[hidden]` 显式设置 `display:none`，确保比原有 `display:flex` 规则优先；先核对最新代码是否已有等效规则。
2. 检查时间轴首次打开是否短暂露出列表控件。必要时在 HTML 为列表筛选容器设置初始 `hidden`，由既有模式切换逻辑在列表模式显示。不要引入依赖或重造状态管理。
3. 列表模式原有排序与起止日期数值应保留；时间轴模式既不读取这些列表筛选值作为自身过滤条件，也不应因隐藏控件而发起无关的列表加载。
4. 隐藏内容不得占位或被键盘 Tab 聚焦；保持桌面与窄屏布局正常。确认「图库筛选」、切换按钮以及时间轴自身的日期筛选与年月定位始终可用。
5. 如果 CSS/JS 文件变更，按仓库现有做法更新首页静态资源版本号，避免浏览器继续使用旧样式。
6. 优先仅改 `src/photo_search/web/photo-timeline.css`；必要时改 `index.html`；仅在查到额外事件/状态问题时触及 `app.js`。不得扩展到 API、schema、revision、时间排序契约、图库扫描、人脸、地点、搜索或数据库。
