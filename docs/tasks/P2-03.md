# P2-03 — 通用产物、outbox、幂等索引提交与修复

执行模型：**C2 / GPT-5.6 Sol / high**——先用它冻结 artifact/outbox/index_entries 的事务边界、
幂等键与恢复语义；协议冻结后的普通实现可提示用户手动切换到
**DS-H / DeepSeek V4.1 Flash / 高推理**继续。模型切换由用户在 Codex 中手动完成；本卡不启动
其他 Agent、不切换客户端，也不得声称自动切换。

`git log -1 --format=%H -- docs/reports/P2-02-persistent-scheduler-and-device-qualification.md`
取得实际 P2-02 提交，并结合 `git status --short` 复核工作树；不得从聊天历史假设。前置条件：

migration 目录只有 `0001_initial.sql` 与 `0002_scheduler_runtime.sql`。

本任务实现**通用产物落地与索引提交**：`JobResult.artifacts` 的原子发布、artifact/outbox 的
SQLite 事务、按逻辑主键幂等的 LanceDB 投影更新、`index_entries` 确认与修复、以及崩溃后的可重放。
它不实现地点表/GPS（P2-03A）、不实现 SearchProfile 原子激活（P2-06）、不做真实模型推理与 ANN 训练。

## 用户场景与完成定义

- 一次处理任务返回结构化或向量结果后，主进程先校验 lease/revision/processor/设备语义，再原子发布
  产物文件，然后在**一个** SQLite 事务里写 artifact 行、任务终态和 outbox 事件。
- indexing 按逻辑主键幂等地把向量与检索投影写入 LanceDB，读取最新 SQLite 投影；成功持久化后才在
  SQLite 确认 `index_entries` 并关闭 outbox。
- 在第 2～5 步的任意一步崩溃后重启，重放同一逻辑更新不产生第二条逻辑向量、不产生虚假 READY、
  不丢新产物；outbox 未确认的产物不被回收。
- `index_entries` 丢失或损坏时可以从现存 artifact 修复；artifact 已被回收时，同一逻辑任务可以
  **重新执行**，且"这条 job 曾经 SUCCEEDED"不构成拒绝修复的理由。
- `artifacts=[]` 的成功空结果仍是正常路径：不写 artifact、不写向量、不产生 outbox。

完成标准：`JobResult.artifacts` 的三种类型（structured/binary/embedding）都有真实落地与提交路径；
连续增量 migration、幂等重放、失败注入、`index_entries` 修复和 space 隔离全部有具名自动化用例并
通过；不产生第二向量后端，不引入新依赖，不提前实现地点或搜索。

## 冻结实现契约

### 1. 增量数据库

新增实际连续 migration（若开始时仍只有 0001/0002，应为 `0003_*`），同步 schema checker 与
`SUPPORTED_SCHEMA_VERSION`。**不得修改** `0001_initial.sql`、`0002_scheduler_runtime.sql`。
migration 至少持久化：

- **artifact 引用行**：稳定 `artifact_id`（逻辑主键 = processor_id + input_revision +
  artifact_type + artifact_revision）、`artifact_type`（embedding/structured/binary）、
  `media_type`、`checksum_sha256`、`byte_size`、受控 `storage_uri`/相对路径、可空 `space_id`、
  可空 `dimension`、`job_id` 关联、创建时间与生命周期状态（PENDING/PUBLISHED/RECLAIMED）；
  `embedding` 必须有 `space_id`/`dimension`，`structured`/`binary` 必须为空（与伴随 schema 一致）。
- **outbox 事件行**：`event_id`、逻辑主键（含 `space_id` 与 `generation_id`）、
  `projection_revision`、payload 的规范化 JSON/checksum、状态（PENDING/IN_FLIGHT/CONFIRMED）、
  `attempts`、可空 `last_error_code`、`created_at`/`updated_at`。
- **index_entries 确认行**：每个 `(space_id, asset_id, generation_id)` 至多一条，
  保存 `artifact_id`、`confirmation_revision`、确认时间与状态（CONFIRMED/STALE/PENDING_REPAIR）。
- **最小 generation 生命周期行**：作为幂等命名空间与 READY 判定的载体；本卡只要求
  "PENDING/READY/RETIRED 生命周期 + 唯一活动指针"，**不**实现 SearchProfile 组合激活。

SQLite 能表达的 NOT NULL/枚举/范围/唯一/FK/CHECK 必须下沉到 migration。v2→v3 必须先备份、事务推进、
失败回滚保持 v2、更高版本只读拒写规则不变。若需要新增列，遵循 0002 已验证的
`ALTER TABLE ADD COLUMN` 方式并证明旧行逐列不变。

### 2. 原子产物发布

- 执行器返回的 artifact payload 只允许普通 JSON 元数据与受控引用；正式产物文件由主进程在
  artifact 目录内以"同目录临时文件 + fsync + `os.replace`"发布，路径由内容 checksum 与逻辑主键
  推导，不接受执行器给定的绝对路径。
- 发布前必须校验：checksum 与 `byte_size` 一致、`space_id`/`dimension` 与 processor 契约一致、
  payload 大小在协议上限内；失败返回稳定错误码且不留下 PUBLISHED 行。
- 已存在相同 checksum 的产物文件时不重复写入；不同内容但相同逻辑主键是**冲突**，不得静默覆盖。

### 3. 提交事务与身份

- `Scheduler.submit`（或等价的单一提交入口）在同一个 SQLite 事务内完成：ADR-0002 §6.5 提交资格 →
  `resolved_device/runtime_provider/precision` 语义核对 → artifact 行 + 业务结果 + outbox 事件 +
  任务终态。任何一步失败整体回滚，且已发布的产物文件必须按 §6 的回收规则处理。
- `artifacts=[]` 仍是合法成功；`embedding` artifact 缺 `space_id`/`dimension`、或
  `structured`/`binary` 携带它们，都按契约拒绝。
- 提交路径不得改变五字段身份、七态状态机、`attempts`、lease 或迟到提交的零副作用语义。

### 4. 幂等索引提交

- `indexing` 读取 outbox 中未确认事件 → 从 SQLite 读最新投影 → 按逻辑主键幂等
  upsert/delete 到 LanceDB → 成功持久化后才在一个 SQLite 事务里确认 `index_entries` 并关闭事件。
- 同一逻辑事件重放 N 次后，LanceDB 中该 `(space_id, asset_id, generation_id)` 仍然只有一条逻辑行，
  `index_entries` 也只有一条已确认记录。
- `SEMANTIC_READY` 只在 `index_entries` 确认后可见；LanceDB 写成功但 SQLite 未确认时不显示 READY。
- 晚到的旧 `projection_revision` 事件不得回滚更新的过滤投影（按实体从 SQLite 合并，不按事件顺序覆盖）。
- 同维度不同 `space_id` 必须结构化拒绝（`SPACE_MISMATCH`），不得计算相似度、写入或复用缓存。
- 本卡允许用确定性合成向量完成 LanceDB 落地；ANN 索引构建、维护与 `fast_search` 行为不在本卡范围。

### 5. 修复与回收

- `index_entries` 缺失/损坏/被手工删除时，标记 PENDING_REPAIR 并从现存 artifact 重建；
  artifact 已回收时，允许按相同逻辑任务重新执行，不能因为旧 job 曾经 `SUCCEEDED` 而拒绝修复。
- 无向量记录不得继续显示为 SEMANTIC_READY。
- 临时文件与孤立产物的清理必须有宽限期与引用核对；outbox 未确认或被 `index_entries` 引用的产物
  必须保留；运行期的清理不得删除活动 generation 引用的内容寻址产物。

### 6. 诊断投影

- `GET /api/v1/stats` 增加 artifact/outbox/index 的**只读**计数与状态摘要（含 `pending`/`confirmed`/
  `pending_repair` 与 generation 生命周期），不得包含绝对路径、checksum 之外的私有内容或模型路径。
- `GET /api/v1/capabilities` 只增加安全的 generation/索引版本摘要；本卡**不**新增写接口、
  不实现 `POST /api/v1/index-generations`、不实现模型升级/回滚 API。
- 若新增只读端点，必须沿用现有 `/api/v1` 错误信封与 session/Origin/CSRF/Host 边界；
  higher-schema 数据库必须继续零写副作用地拒绝。

## 必须保持的不变量

- jobs 逻辑身份仍且仅为五字段；artifact/outbox/index 的唯一键不得混入 device、worker 或 generation
  以外的第六个身份字段，且不得改变既有 jobs 语义。
- lease、attempts、BLOCKED 不耗重试、迟到提交零副作用、scan_run/job 联动不回归。
- `artifacts=[]` 是正常成功空结果；没有匹配/没有结果不是失败。
- 未确认的产物不被回收；READY 只在权威确认后可见；LanceDB 始终是派生存储，SQLite 是权威。
- 同维度不同 `space_id` 永不混用；`space_id`/`dimension`/`processor_id`/`generation_id` 逐项核对。
- `schema_version` 只通过连续 migration 推进；更高版本与不一致 schema 继续先只读拒写。

D 级必须有具名自动化用例并实际执行（建议
`tests/unit/test_p2_artifacts.py`、`tests/integration/test_p2_index_submission.py`、
`tests/integration/test_p2_index_repair.py`，文件名可按现有布局调整，但报告必须逐项映射）：

1. v2→v3 正常迁移、备份、迁移中断回滚、目标 schema 缺件拒写、higher-version 无写副作用；
   旧 job/asset/位置行逐列不变。
2. 产物发布中断（临时文件残留）与 checksum/size 不符：拒绝且无 PUBLISHED 行、无 outbox、无 READY。
3. SQLite 提交前崩溃：无 artifact/outbox/终态残留；重放后恰好生成一条 artifact 与一条 outbox。
4. SQLite 提交后、LanceDB 确认前崩溃：outbox 重放 N 次后 LanceDB 与 `index_entries` 仍各一条逻辑记录。
5. LanceDB 已持久化、`index_entries` 未确认时崩溃：重启后 READY 仍不可见，重放确认后可见。
6. 同一 lease 的重复提交、迟到/过期 lease 携带 artifact 的结果：零持久副作用且不留 PUBLISHED 行。
7. `structured`/`binary`/`embedding` 三种 artifact 的正常落地；`artifacts=[]` 成功且无 artifact/outbox
   行；缺 `space_id`/`dimension` 与非法组合被拒。
8. 同维度不同 `space_id`：`SPACE_MISMATCH`，不写向量、不复用缓存。
9. `index_entries` 删除/损坏后修复成功；artifact 已回收时同一逻辑任务可重新执行，已被标记
   `VALIDATION PENDING` 的旧 SUCCEEDED job 不阻止修复。
10. 回收边界：宽限期内的临时文件不被删除；被引用或 outbox 未确认的产物在清理后仍存在。
11. 只读诊断投影的字段与脱敏；scheduler API 与 jobs 投影不回归；higher-schema 拒写。
12. 至少一次顺序重叠的重复 indexing 运行（同进程两次重放）证明幂等不靠时间窗口巧合。

若修改 `workers/**`、正式运行环境或打包入口（例如新增需要收集的包数据目录），验收自动增加 C：
实际 onedir build + 打包 API/worker smoke + 中文空格路径与离线启动；未执行不得 PASS。
