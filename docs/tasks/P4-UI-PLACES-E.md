## 20万～30万地点查询改造与性能闸门（E 卡重点）

- **当前已知瓶颈形态**：非 CN `places/albums.py::album_assets()` 调用 `_album_rows()` 和 `_group_rows()`，先遍历可能接近全库的行集合，再按 offset 切片。20万以上不能只是将此旧返回的48张按日期前端重排，也不能每加载下一页重新生成全库成员列表。
- 在保留非 CN 的原**人工指定优先、排除、有效 GPS 解析/活动包、同名父链、视频及在线资格**下，形成选中地点的**SQL 权威成员集**，在该集内以可信拍摄日期或入库日期进行 **keyset + LIMIT（约48～60）**；CN facet 优先复用其成员 SQL，绝不绕开版本和强制重建地点包。未知/待就绪桶按 `created_at DESC,asset_id DESC`，成员筛选之前不准随意少算图。
- 原自动/人工/取消/恢复归属与 CN/OSM/GeoNames 身份真值不变。对小 fixture 逐项比较**旧地点有效资产 ID 集合**与新 SQL 集合（包括人工排除、无GPS、已缺失、跨来源重复、视频、CN区县）确保完全相等且照片去重；语义不等价则不得上线优化路径。
- **20万元数据基准**：至少选择成员偏多的城市、稀疏城市、CN区县三种代表 scope；量取第一页、翻5页、跳5年前某月、当前地点年统计，≥30次暖机、记录各段 SQL `EXPLAIN QUERY PLAN` 与 P50/P95/max，**照片页 P95≤1000ms 为20万基础门槛**；30万重点复查高成员地点，不重跑模型/地图 PBF。年统计缓存按地点成员/包版本失效，每页不重扫全量。达不到性能目标则将瓶颈与 `PERF_PENDING/FAIL` 明示，不能以UI通过覆盖。
- 若 SQL 优化确需索引/Schema，不默默修改迁移。先报告最小索引、兼容、V3.1必要门槛再执行；若必须重写地点成员真值/写事务，停止并另立高风险卡。此卡不是地图地图瓦片性能、GPS重建或普遍地理重构。

## 2026-10-13 地点目录和地点相册两层规则

- **地点目录**：维持原 `places/albums.py::_sort_albums()` 的**有效照片总数降序、同数量最新入库照片时间降序，再稳定父级名称/地点键排序**；不按 EXIF 拍摄时间重新排序，不因为照片缺乏拍摄时间而从城市/区县/国家卡片扣减，也不因此改变地名归属/人工覆盖。封面资格仅由原地点照片成员与封面规则决定。
- **地点相册内部**：用户进入“深圳市”之类具体地点后，所有有**该地点权威归属**的有效唯一资产都是相册照片，即便其中有些无 EXIF 拍摄时间。进入相册才按 scope 查询有效总数和可信/未知/待就绪日期摘要；正常拍摄时间轴按真实年月，未知/待就绪各自直接入口，按入库时间倒序分页；入库轴则全数参与真实入库年月。缺 EXIF 日期**不意味着没有 GPS/地点归属**。
- **性能**：不能在打开地点目录时给几千地点逐卡执行 `COUNT(unknown)/GROUP BY(year)`；日期计数和年月分布只对选中地点异步/按需计算，并绑定活动地点包、人工覆盖及 catalog revision；旧请求不得污染另一个地点或地图 viewport。复用本卡非 CN SQL 成员改造和20万/30万性能预算，不增加永久城市×月份聚合表。人物/地点相册使用同一个 CORE 组件但成员 adapter 不交叉。
- **最小小样本**：深圳10张（可信7/未知2/待就绪1）、广州5张；深圳中有无 EXIF 但有 GPS 或人工地点的图，地点卡仍显示10、同量排序按入库、进入深圳7+2+1=10；改广州不保留深圳年份筛选；地图仍只看自己的 viewport 成员规则；不同来源重复位置资产按原去重。此小例验证所改链路；个人定向验收按下节执行，不重建真实地图包。

## 新增「搜索此地点」快捷入口（2026-10-13）

- 地点目录的「搜索地名」只负责定位城市/省/区县/国家卡；**进入某个具体地点相册**后，在该相册标题操作区有「搜索此地点」。与人物一致，点击后将**当前地点的权威身份**（`place_kind + place_key`、父级/来源用于清楚标签）交给顶部**唯一全局搜索框**，显示如「深圳市 · 广东省 ×」，聚焦等待输入；**空词不自动执行搜索**。默认查询此地点全部有效照片，不继承地点相册的年份筛选；含拍摄时间未知/待就绪照片，除非用户明确给出时间限制。
- 搜索服务现有 `place_kind/place_key` 路径可复用，但不得将深圳名称当普通关键词或将 CN/OSM/GeoNames/人工覆盖混成单个 `place_id`。必须沿用本卡优化后的**权威有效地点成员查询、人工覆盖/排除、当前包与 revision**；成员变化或地点切换会使旧 search cursor/session 失效。未知的同名地点以完整父级身份标注并通过已选择的 key 决定，不出现二次无意义消歧。
