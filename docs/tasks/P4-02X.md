# P4-02X — bounded block-size 最小产品收敛

**状态：READY（2026-09-28）。**

执行：**DS-H / DeepSeek V4.1 Flash / 高推理**。  
实现后：**独立新会话 DS-H 做窄受影响面工程主审**；无 ADR/schema/API 语义变化则 `SOL_NOT_REQUIRED`。

本卡只做一件事：

> 将 `SCOPE_BLOCK_SIZE` 从 `5000` 改为 `15000`，把 30 万档约 60 次 bounded 调用降到约 20 次，并确认结果正确、真实暖机文字搜索是否达到当前 P95 ≤ 5 s 门槛。

依据：[P4-02M bounded block-size 复测](../reports/P4-02M-bounded-block-size-retest.md)（提交 `08e012c`）。

## 1. 固定策略

上一轮已完成参数判断，不在本卡重做：

- 5000 / 60 blocks：当前产品基线；
- 15000 / 20 blocks：service 配对约 **−13.6%**；
- 30000 / 10 blocks：约 **−14.8%**；
- 50000 / 6 blocks：收益回退；
- 正常 bounded 路径六档最终结果逐项相同。

本卡固定选择 **15000**，不追求测量中最快的 30000：

1. 15000 已取得 30000 的绝大部分收益；
2. 调用数约 60 → 20；
3. `resolved=False` 时需要整块 exhaustive fallback；
4. 15000 的单块回退规模只有 30000 的一半；
5. 当前 P4-02W 暖机文字 P95 = **5076.4 ms**，只需跨过 **5000 ms** 个人试用门槛。

**不再扫 block-size 参数。**

## 2. 产品改动

原则上只改：

`src/photo_search/search/retrieval.py`

将：

```python
SCOPE_BLOCK_SIZE = 5000
```

改为：

```python
SCOPE_BLOCK_SIZE = 15000
```

允许新增/调整本次变更所需的最小测试或诊断。

禁止顺手修改：

- `search_candidates_bounded` / `resolved` / exhaustive fallback；
- SQLite authority、generation / space / revision；
- `(distance, asset_id)` 排序、RRF / BM25；
- API 信封、错误码、游标；
- schema / migration / 依赖；
- scheduler / busy timeout；
- A3 / ANN / FAISS / 第二后端 / 模型。

## 3. 最小正确性验证

不重复 P4-02M 已经证明过的全部内容，只补本次常数变化真正需要的两项。

### A. 正常 bounded 路径

复用现有 30 万夹具，`top_k=20`，确认：

- `engine_blocks ≈ 20`；
- `bounded_calls == engine_blocks`；
- `truncated=false`；
- `scanned_assets=300000`；
- 最终 `(asset_id, distance)` 与修改前 5000 基线逐项相同。

不等价 ⇒ **REVERT 到 5000，停止本卡**。

### B. 边界并列 / fallback

直接复用已有 tied-distance / block-boundary 测试或最小夹具，至少触发一次：

`resolved=False → search_candidates exhaustive fallback`

确认 fallback 后：

- 最终页面与旧路径逐项相同；
- `(distance, asset_id)` 全序不变；
- 不丢候选、不提前截断。

现有测试足够时不要另建大型夹具。

失败 ⇒ **REVERT 到 5000，停止本卡**。
