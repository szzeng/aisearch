## 1. 背景及已核对事实

用户反馈：
- 搜索 `太阳` 时被解析为 GeoNames 地点，无法顺利按图片内容搜索。
- 搜索 `深圳` 时，结果同时出现 `地点：深圳市（OpenStreetMap）/取消地点条件` 和 `地点：深圳市/取消`。
- 点击“取消地点条件”后可能依旧存在筛选、重新出现地点标签，或搜索失败。

代码事实（以开工 HEAD 再核对）：
1. `places/choices.py::choices()` 同时提供 OSM 与 GeoNames 有效来源地点的名称、别名；`places/natural_search.py::parse_place_query()` 的 `_spelling_hits()` 可以从普通输入匹配同名地点，且“纯地点”句式允许生成硬筛选。当前没有足够通用的“普通图片内容词 vs 同名地点”意图门控。
2. `search/unified_intent.py::parse_unified_intent()` 将地点候选加入统一 `intent_plan`；`search/personal_search.py::validate()` 校验计划与原始解析的一致性；`api/routes.py` 的 `POST /api/v1/search/place-aware` 处理 `place_cancelled` 和已选范围。
3. `web/search.js` 的 `renderPage()` 渲染 `place_scope`，`renderIntentChips()` 渲染 `intent_plan`，某些同一地点身份可能双重展示；`cancelPlaceScope()`、意图 chip 取消、固定 `selectedScope` 取消存在不同状态迁移。
4. **必须保留** `P4-UI2-SEARCH-SCOPE-UNIFY-A` 已有成果：页头唯一输入框旁“搜索此地点”直接执行、固定范围原子交接、连续查询保留范围、取消固定范围不自动全库重搜、相同结构化地点的部分回显去重。该卡仍为 `ACCEPTANCE PARTIAL`，新卡不得将其覆盖为未实施或声称已整体验收。
5. `P4-SEARCH-INTENT-UNIFIED-A-FIX1/FIX2` 已处理部分来源候选/父子身份消歧；`P4-SEARCH-INTENT-NL-COVERAGE-FIX-A` 已覆盖部分句式和请求竞态，不能回退。`P4-UI2-SCROLL-LOAD-A` 也可能修改同一个 `search.js`，**须串行，不要并行整文件覆盖**。
6. **未直接核验用户当前活动 GeoNames 数据包里“太阳”究竟是哪一条地点/别名**。应先使用合成候选复现机制；只有用户另行授权才读取真实数据根，不得假称扫描了真实包。

## 2. 本卡唯一目标

- **自然语言地点识别更保守：** 普通图片内容词（尤其 `太阳`）不因为命中某个 GeoNames 名称/别名就自动形成地点硬筛选；明确表示拍摄地点的语句及用户主动选择地点仍然可用。
- **一个身份、一个条件：** 相同 `place_kind + place_key` 的自动解析、服务端回显和固定范围，只显示一个可取消 chip；不同真实地点仍保留身份消歧，不按名称相同做数据合并。
- **取消必然生效：** 清理当前地点的全部镜像状态、旧游标/请求和结果；保留其他独立条件；既不重新加回该地点，也不意外执行全库空条件查询。
- **不修改权威成员语义：** 原有 OSM 优先 / GeoNames 兜底、父链消歧、GeoNames 不同真实地点保留、地点相册/人工归属和搜索权威 SQL 均保持。

## 3. 实施范围与设计合同

### A. 搜索内容与地名碰撞：小型、可解释的解析门控

1. 先区分**显式地理意图**（如 `在深圳拍的照片`、`深圳的夜景`、用户点击“搜索此地点”）与**普通视觉内容意图**（如 `太阳`、`太阳的照片`、`照片里的太阳`）。目录命中只证明“存在同名字面候选”，不证明用户想按地点筛选。
2. 明确地理上下文 / 经验证的行政层级可以形成地点硬条件；已知高置信地名（如 OSM 深圳、GeoNames 东京）应保持现有易用的一词地点搜索。对于与常用图片主题、天体、天气、色彩、物品等冲突的短词，默认保留内容搜索，不应将其全部套成地点。
3. 采用最小、可测试的冲突词保护/语境判定（可维护的小型常用视觉词集合 + 明确的句式优先级），**不要**仅凭 `GEONAMES` 来源全盘拒绝，不引入新 LLM、第三方在线词典、复杂中文分词或庞大硬编码黑名单。具体词集合只限经过用例和证据支持的范围，不宣称可穷尽所有歧义词。
4. 碰撞词确实存在于地点目录时，保留用户显式按地点搜索的能力；可沿用现有地点选择/“搜索此地点”入口。若无法判明上下文，优先可解释地询问或保留普通内容检索，不能静默错误硬过滤。
5. 人名/合集/来源同名、多地点表达、否定句、已验证父级及真实同名地点的选择规则仍按既有统一意图契约，不用本卡重新设计。严格保留 `content_query` 的有效内容，勿把 `太阳的照片` 变成空查询。

### B. 地点条件 chip 合并与身份优先级

1. 将搜索结果的有效地点视为**一个逻辑条件**，从已经解析/确认的服务端权威身份统一渲染。优先级：用户明确固定的 `selectedScope`，其次已确认 `intent_plan` / `placeAware` 的地点；`place_scope` 仅作为结果回显，不另造第二个独立的过滤条件。
2. 基于 `kind + key`（必要时连同来源/活动包版本）进行身份一致性判断；同一个地点仅有一个取消入口。UI 可显示 `深圳市 · 广东省（OpenStreetMap） ×`。不能简单按 `name` 去重或折叠台湾深圳和广东深圳等不同地点。
3. 非地点 chip（人物、合集、来源、时间、高级条件）分别保留；已存在的固定人物/合集/来源范围和 UI2.0 页头按钮不受影响。无来源证据不能捏造 OSM 或 GeoNames 标签。
4. 仅做必要的 `search.js` / 局部样式调整，保留 UI2.0 明暗色、窄屏、键盘触达及唯一顶部输入框，不恢复第二套搜索表单。

### C. 区分两种“取消”，一次原子状态更新

**C1：取消自然语言自动识别的地点（非固定相册范围）**
- 一次清掉该地点在 `placeAware`、`intentPlan`、结果回显/显示状态中的匹配字段（包括 `place_name`、`place_selection`），并明确让本次搜索不再自动重解析成同一地点。
- 如果还有真实内容词：如 `深圳的夜景` → 搜索 `夜景`，保留其它人物/时间等确认条件。
- 如果原句本身是内容与地名同形的单词：如 `太阳` 或 `深圳` → 取消地点后可以将该词作为**普通图片内容词**查询；不得因旧 `original_query` 再加回地点。
- 若原句只有明确地点框架而没有有意义的内容词：如 `在深圳拍的照片` → 清除旧结果、给出“地点条件已取消，请输入内容后搜索”，**不自动空查询全库**。
- 取消后的第一次重新检索、同条件重试、详情返回和续页均要保留“地点已被用户取消”的效果，直到用户明确输入新查询或重新选择地点。

**C2：取消主动固定的地点相册范围（`selectedScope.kind=place`）**
- 清除固定地点身份，并清理**同一身份**的意图/回显镜像；不删除无关时间、人物、合集、来源条件；不得暗中取消另外一个不同地点条件（冲突应提示）。
- 使旧 `requestGeneration`、`search_session_id`、cursor、binding、结果/计数、预览/返回快照全部过期；**不自动重新发出更宽的全库搜索**。用户手动提交后才查询。
- 对于取消后还保留的同形关键词，下一次明确的内容搜索不能又因为旧 `placeAware` / `intentPlan` 把相同地点恢复。保留原 UI2.0 “取消固定范围后等待用户提交”约定。

**C3：服务端与竞态安全**
- 优先复用现有 `place_cancelled` 和 `/search/place-aware` 计划校验；如需改变校验/规范化，必须解释纯条件时 `None` vs `""` 造成的差异，并用定向 API 回归证明取消真的成功。
- `place_cancelled` 只能取消当前有效地点限制，不允许未经原句/目录证明的新增过滤、跳过其他身份校验或绕过固定范围限制。保留其它已确认的对象身份和时间条件。
- 快速连续提交、取消时旧请求晚返回、错误响应/消歧响应晚返回，不得恢复旧地点 chip 或旧结果；不混用旧 cursor/session。失败须有可见提示。
- 不通过“先显示全库照片再过滤”、清空全部 `intent_plan`、重新创建地点记录、忽略客户端已取消状态等方式规避问题。

## 4. 最小定向测试（先复现失败，再修复）

用内存/隔离合成目录，构造 GeoNames 记录/别名 `太阳` 与其它若干冲突词，OSM 深圳、GeoNames 东京、广东/台湾两个真正不同的深圳；约 6–12 张合成照片及现有 mock encoder，**不读用户真实图库**。

| ID | 场景 | 通过标准 |
|---|---|---|
| T01 | `太阳`、`太阳的照片`、`照片里的太阳`，目录中含 GeoNames `太阳` | 走普通内容搜索，`place_kind/key` 为空，内容词未丢 |
| T02 | `在太阳拍的照片` 或显式选取目录中的“太阳”地点 | 可以选择有效真实地点；不是因为保护内容词而彻底禁用地点 |
| T03 | `深圳`、`深圳的夜景`、`东京夜景`、`朝阳区夜景` | 保留 OSM 优先、GeoNames 回退、内容词和同名区县消歧 |
| T04 | `深圳` 的结果同时含 `place_scope`、`intent_plan`（或固定相册回显） | 仅有一个地点 chip、一个取消动作，父级/来源可信 |
| T05 | 取消自动地点：`深圳的夜景`、单词 `太阳`、纯地点框架 | 夜景仍搜夜景；太阳改为内容；无内容框架不自动全库 |

| T07 | 地点 + 人物/时间，取消地点后翻页/返回 | 其它条件不丢、有效范围不扩大到未授权状态；无旧 session 混用 |
| T08 | A 请求在途，用户取消/提交 B，A 晚返回 | A 的结果、错误、chip、快照均不能覆盖 B |
