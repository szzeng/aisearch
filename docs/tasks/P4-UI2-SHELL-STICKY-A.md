## 1. 用户需求与验收边界

用户浏览照片、搜索结果、人物、地点、合集或管理长页面时，左边主导航和顶部搜索栏会随正文离开视野。要恢复 UI 2.0 已确认的视觉原型行为，且不损伤现有照片浏览链路。

**P0 必须完成：**

1. **桌面**：左侧应用导航在窗口内持续可见；照片/人物/地点/地图/图库管理入口及当前项仍能操作。顶部**唯一**全局搜索框及必要的提交/当前范围搜索按钮在纵向滚动时持续可用。
2. **正文继续使用浏览器窗口滚动**：照片普通网格、搜索结果、人物/地点长列表、时间轴不得被统一改造成 `main` 独立滚动；已有无限续页、日期定位、弹窗关闭/详情返回位置恢复不回归。
3. **不遮挡**：顶部搜索、时间轴吸顶日期标题、页面锚点、焦点、通知、当前范围 chip 与模态弹窗层级正确；大标题、冗长提示等非核心内容不应长期占屏。
4. **响应式**：桌面保留竖向导航；窄屏按既有模式退化，优先搜索可用与导航可达，不能叠两层很高的固定条造成内容几乎不可见。保留既有 200% 缩放左栏修复。
5. **地图特例**：地图页本来的地图画布与照片列表独立滚动结构保留；不牺牲地图交互或照片 hover 联动。

**P1 视觉完善（仅在不增加结构风险时实施）**：顶部固定区域尽量收紧至搜索与必要操作；标题/辅助状态正常随内容滚动。若需要较大 DOM 拆分，可先交付功能正确、视觉紧凑的页头吸顶，报告明确记录差异；不得因为追求“只剩搜索框”破坏单一表单、页面 ID 或焦点流。

**明确不做**：新增侧栏折叠/抽屉、智能隐藏顶栏、重画 UI2、重新设计搜索范围、重做分页/虚拟化、改变数据库/API/模型。

## 3. 页面行为合同

### A. 桌面公共外壳（视口宽度 >680 CSS px）

- 左栏沿用约 12–13rem 宽度，紧贴视口顶部，长列表向下滚动后仍可点击；不得因正文高度、`position:sticky` 的祖先限制或浏览器缩放突然离屏。
- 左栏内容超出窗口高度时，**仅左栏自身可纵向滚动**，导航品牌、活动项和底部管理入口仍能找到；优先 `max-height:100dvh` 配合可靠回退，不能用 `min-height:26rem` 把短窗口下面的菜单裁没。
- 搜索栏始终靠视口顶部、背景不透字、边框与阴影合理，z-index 高于正文/时间轴日期标题，低于原生 `dialog` top layer；不要采用滚动监听逐帧修改 `top`/`transform` 的动画式假固定。
- 页头拥有一个有效自然语言输入框。非搜索页全库按钮/Enter、人物/合集/地点/单图库合法范围按钮、搜索结果页范围 chip 与继续搜索的既有语义完全保留；按钮/提示换行不能压住输入或制造第二套表单。
- 原则上保留整个普通页面 **window scroll**。如果现有 Grid 第一行使页头无法独立粘附，允许五页统一引入最小右侧工作区 wrapper（页头+必要辅助区+main），并保留原 `id`、`hidden`、form、script 绑定；不为了避免 wrapper 强行把主内容改成内部滚动。
- 页内链接、跳到结果、`scrollIntoView()`、键盘 focus 和时间定位需考虑吸顶高度：使用合适的 `scroll-padding-top`、`scroll-margin-top` 或已有定位适配，避免滚完后目标内容藏在搜索栏下方；不用全页面随意增加上边距。

### B. 时间轴及无限续页

- `.photo-timeline__heading` 位于顶部搜索栏**下方**，组头互相替换时仍自然，不能盖住搜索区；定位年月/旧页面锚点不跳顶。
- 用**统一的实际页头高度变量**（例如 `--app-sticky-header-height`）给日期标题、需要的滚动定位提供偏移。优先 CSS；确需测高仅使用单个顶栏 `ResizeObserver` 在尺寸变化时更新变量，提供不支持时兜底；禁止在每次滚动时测量布局。
- 保留 `scroll-pager.js` 的 window scroll / sentinel 根、首屏续页预算、互斥和错误状态；保留 `photo-timeline.js` 的分页 cursor、回收、revision、锚点与范围合同。固定栏不得让 observer 误判进入视口而持续预取。
- 打开查看弹窗、关闭、打开旧详情并返回，需保留合法的 `asset_id` 或旧浏览位置；不能由于顶栏改高导致返回原卡片被遮住。

### C. 地图与响应式

- 地图页仍使用既有**独立布局**：桌面画布保持可见、右侧照片列表自己滚动；地图滚轮缩放、拖拽、照片 hover 高亮、照片查看不受导航/搜索顶层覆盖。必要时触发布局变更后的原地图 resize。
- 在地图 **850px** 上下切换纵向布局及公共导航 **680px** 上下切换时，分别观察滚动祖先与地图高度；不能把桌面专用 `overflow:hidden` 复制到窄屏，让地图下面照片不可到达。
- >680px 优先保留左栏，包括常见约 720 CSS px 有效宽；如果内容宽度不足，先核查可收缩项和溢出根因，不随意放宽断点。
- ≤680px 导航可改为已有顶部紧凑形态；搜索必须可见且可用，导航项可达。**不要求把整排顶部导航与搜索永久双层吸顶**：小屏高时可让非核心导航随正文离屏，避免屏幕被固定栏占满；但不能让用户失去导航入口或键盘可达性。
- 200% 浏览器真实缩放与单纯缩小 CSS 视口**不是同一份证据**；若 Codex 浏览器不能设置原生缩放，明示未验证，不以 720px 测试冒充通过。检查系统字体放大、较短窗口、浅暗主题。

### D. 弹窗、层级与无障碍

- `dialog` / viewer 仍处于顶层，Esc、遮罩点击、缩放/拖图和关闭按原行为处理；锁定背景滚动时不得改变页面根布局造成横向跳动，关闭后恢复导航/搜索与焦点。
- 确认通知、下拉面板、范围 chip、批量工具条、地图控件和时间轴吸顶组头不会被不合理的 z-index 覆盖。
- 保留 `skip-link`、`#main`、各页标题语义、`:focus-visible` 和应用导航 `aria-current`；DOM 重排不得造成空白焦点或重复标签关联。

## 4. 最小施工步骤

1. **复现与归因**：先读 `AGENTS.md` → `docs/development-status.md` → 本卡 → 上述直接相关 CSS/HTML/JS/报告；以最新 HEAD/当前工作树为准。使用隔离合成长列表，明确记录侧栏离屏时的 window scroll、Grid/包含块高度、滚动祖先、浏览器尺寸，确认为哪类 Sticky 约束。
2. **修公共布局**：优先修改 `web/styles.css` 的普通页面 Grid 高度/轨道、sidebar 和 header 的 Sticky 规则，保持正常 window scroll；使用实际浏览器连续滚动来选定方案，而不是只做 CSS 文本断言。单独限制地图特例规则，不让新样式污染它。
3. **校准紧凑搜索和吸顶偏移**：只在必要时调整五页 HTML 共用外壳；保留输入、当前范围动作及 ID/事件绑定。设置日期标题和必要锚点偏移；仅确实需要时添加极小共享测高 helper。
4. **地图/窄屏复核**：核对 850、680 两档；修直接引发的层级和高度回归。若要大规模改 map JS、scroll pager、时间轴状态机或搜索状态机，停止扩围，分离新任务。
5. **静态版本与记录**：受影响的 `index.html`、`search.html`、`persons.html`、`places.html`、`map.html` 同步更新 CSS/JS 缓存版本（按实际引用）；运行定向测试，写实施报告。

**允许修改**：`src/photo_search/web/styles.css`、`photo-timeline.css`、必要的 `map.css`、五个 HTML、极少量非业务显示 helper/定向测试。**默认不得修改**：`app.js` / `search.js` 的分页和恢复状态、`scroll-pager.js`、`photo-timeline.js` 的虚拟化、后端 API/Schema、PhotoSearchData/真实照片或第三方依赖。因真实回归需要越界时，记录理由并单独评估，勿暗中扩大。
