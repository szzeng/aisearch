# P4-PHOTO-MEMORIES-UX-A — 回忆分类浏览入口优化

- 日期：2026-10-23
- 基线：19a134b（工作树含并行未提交修改；本任务仅限回忆页相关文件）
- 状态：IMPLEMENTED / VALIDATION PENDING；已本地提交，未推送
- 用户目标：把“往年今日”和“那年这个月”拆成清楚、可直达的独立浏览入口，避免两类回忆卡片堆在同一长页面。
- 设计决定：左侧主导航仍只有“回忆”；回忆页标题下提供两个分段入口，路由分别为 /?view=memories&section=day 和 /?view=memories&section=month。列表每次只呈现一种类型，详情保留来源类型，浏览器 Back/Forward 恢复分类。
- 范围：src/photo_search/web/index.html、app.js、memories.css、本卡报告及开发状态；仅前端布局与路由状态。不改 API、日期算法、后台调度、数据库或普通合集协议。
- 必须保持：日期/月份筛选正确；精选数量语义、查看全部、保存、Viewer/详情返回不变；分类切换不重复启动生成任务；当前已生成两类卡片可复用；缩略图只为当前展示类别创建 DOM 节点，并延续 lazy loading。

## 性能设计

- 链路与风险：回忆列表年份增多后，同时渲染两类卡片会让 DOM、图片请求和页面高度增长。
- 做法与边界：复用现有有界年份批次与 API 响应缓存；前端按当前分类渲染单一列表，懒加载缩略图，不增加查询或预取。
- 验证与停止：受影响前端行为与浏览器分类切换、Back/Forward、窄屏观察；不新增规模承诺，若无明显页面负担即停止。

## 验收

- 类型入口可键盘聚焦并清楚显示当前选择，窄视口无横向溢出。
- day/month 路由直接加载、切换、Back/Forward、卡片详情返回均保留正确类别。
- 切换不同年月精选时，旧缩略图不得在新结果返回前继续显示；待加载详情 Back 回列表后，旧请求不得重开详情。
- 切换分类不触发额外后台请求；每种类别只渲染自己的卡片。
- 实际浏览器需观察回忆目录与详情关键流程；未运行的测试/浏览器范围保持 PENDING。
- 静态检查：相关 JS 语法及 git diff --check。不触发后端/数据库或30万性能测试，因为查询/API未改变。
