# P4-PLACE-CN-AUTO — 中国行政区地点自动整理

状态：**PLANNED / NOT IMPLEMENTED**。本卡只建立实施范围，不代表代码已修改或验证通过。

## 1. 背景与目标

Windows 发布包中，地图相册可以直接使用已有 GPS 坐标显示照片；中国省/市/区县地点相册则依赖独立的 OSM 行政区匹配结果。当前需要用户进入「整理地点 → 高级维护 → 更新中国地点」才会生成这批结果。

目标：**让中国行政区地点整理成为图库建库与日常刷新的自动派生阶段。正常使用不再要求用户手动点击「更新中国地点」。**

同时覆盖已经建好的图库升级到含本功能版本后的首次自动补齐，避免只对全新图库生效。

## 2. 当前实现事实

以当前 `master` 为基线，实施前重新核对 HEAD 和工作区：

- `refresh/pipeline.py::refresh_library` 已有 GPS 提取和 `place_resolver` 阶段；建库模式会按来源持续 drain，日常刷新模式使用 content delta。
- `places/cn_facets.py` 已有中国行政区解析、不可变 `cn_admin_resolutions` 写入，以及持久化的 `cn_update_runs` 进度游标。
- `cn_update_runs` 现有处理批次为每批最多 100 条有效 WGS84 GPS；进度可暂停后继续。
- `POST /places/admin/update` 及地点页按钮目前是触发中国行政区更新的主要入口。
- `places/albums.py` / `cn_facets.members_sql()` 已按活动数据包、当前 GeoFact/input revision、PRESENT 文件位置和人工控制/排除规则读取地点相册成员。

本任务应复用这些既有契约，不另建第二套地点解析或照片索引。

## 3. 目标行为

1. **全新建库**：GPS 提取阶段完成后，自动生成已有有效 GPS 照片的中国行政区结果；建库完成时，地点相册可直接显示匹配成功的中国地点，无需再点「更新中国地点」。
2. **日常新增照片**：正常图库刷新完成 GPS 提取后，只对本轮新增或内容/GPS 已变化的照片生成行政区结果。
3. **已有图库升级**：若活动中国数据包尚无 `cn_update_runs`，或此前全量补齐尚未完成，正常刷新自动启动/续接一次有界补齐；进度持久化，取消或重启后可继续。
4. **数据包切换**：活动 dataset ID 改变时，为新活动包建立独立补齐进度并生成对应结果；旧包结果不得冒充新包结果。
5. **无可用中国数据**：没有活动包、包损坏或活动包不含中国行政区边界时，明确报告跳过原因；不得阻断照片扫描、搜索索引或地图相册。

## 4. 实施方案

### 4.1 接入现有刷新流水线

- 在 `refresh/pipeline.py::_enrichment_stages()` 增加独立的 `cn_admin` 阶段。
- 阶段顺序必须在 `gps` 之后；它只依赖已经写入 catalog 的有效 GPS，不依赖附近城市 `place_resolver` 的候选结果。
- 仅在 `enrich=True` 时执行；遵循现有取消检查、阶段状态、错误隔离和 `COMPLETE/PARTIAL_FAILED` 语义。
- 不要把中国行政区匹配塞进 EXIF/GPS extractor，也不要让地图 API 承担解析工作。

### 4.2 首次全量补齐与升级补齐

- 复用 `cn_update_runs` 的活动数据包级持久游标和 `cn_facets.inputs/calculate/publish` 现有逻辑。
- 建库模式在 GPS 阶段完成后，自动开始或续接全量游标，按现有 100 条批次处理，直到完成、取消或达到既有安全停止条件。
- 已有图库升级后若没有该活动包的运行记录，自动创建全量补齐；若记录未完成则续接。日常模式每次刷新最多使用现有 `ENRICH_LIMIT` 量级的有界预算（当前为 5,000 条有效 GPS 资产），并持久化剩余进度，避免一次刷新无界占用。
- 数据包几何/边界内容应在一次阶段运行中加载并复用，不得为每个 100 条小批次重复读取、解析整份数据包。

### 4.3 完成后的增量更新

- 当活动包的全量补齐已完成，日常刷新只处理本轮 `content_delta` 中新增或内容/GPS 已变化的资产；不得每次从 asset_id=0 重跑全库。
- 增量路径按当前 `asset_id + geo_fact_id + input_revision + dataset_id + processor_id` 识别结果；已有当前版本结果应幂等跳过。
- 同一资产的 GPS/input revision 改变时，生成新派生结果；旧不可变结果保留，但不能被当前地点相册成员查询采用。
- 对超过增量阶段上限或 scan delta overflow 的情况，必须建立可恢复的补齐路径（可复用/重启持久游标），不能静默丢弃未处理资产。仅在溢出、包切换或显式修复时允许退回有界全量 catch-up；正常小批量新增不得触发全库重扫。
- 增量结果发布前，继续复核活动 dataset、当前 GeoFact/input revision；迟到结果不得覆盖新输入或新活动包。

### 4.4 手动入口与进度展示

- 保留「更新中国地点」作为手动修复/强制重查入口，不再作为正常建库和新增照片的必经步骤。
- 地点页应区分「自动整理中/待续」「已完成」「不可用/跳过」；不要再把尚未完成的自动进度单纯提示成“需要用户点击才能继续”。
- 复用现有 `/places/admin/capabilities` 和 `cn_update_runs` 状态；必要时小幅调整提示文案，不重做地点管理 UI。
- 刷新状态中增加可识别的 `cn_admin` 阶段及处理/剩余数量；进度必须反映实际处理情况，不能只显示请求已提交。

## 5. 性能与数据安全边界

- 只读取 catalog 中已经存在的有效 GPS/GeoFact 和已安装的中国行政区边界；不得重新读取照片 EXIF、扫描图片内容或重建 GPS 数据库。
- 不触发图文向量、人脸、OCR、缩略图或模型推理；不联网下载数据。
- 不写入或修改 `asset_place_assignments`、人工地点目录、人工排除、操作历史；机器结果只写既有 `cn_admin_resolutions` 派生表。
- 必须保持 `members_sql()` 的当前资格条件：活动数据包、当前资产与 GPS revision、PRESENT 位置、有效坐标基准，以及人工控制/排除保护。
- 不改变地图相册 GPS 成员、聚合、底图或地图服务商逻辑。
- 优先复用现有 schema 与持久游标；只有证明现有状态无法可靠表达增量待办时才提议新增 migration，并说明为何不能复用现有机制。
- 中国行政区数据未覆盖、边界不确定或解析结果为 UNKNOWN/UPPER_ONLY 时，遵循现有解析契约，不猜测、不补造区县。

## 6. 重点代码范围

- `src/photo_search/refresh/pipeline.py`：`refresh_library`、`_enrichment_stages`、`_drain_scope`、阶段状态与取消。
- `src/photo_search/places/cn_facets.py`：`start/inputs/calculate/publish`、增量输入与持久补齐。
- `src/photo_search/api/routes.py`：现有 capabilities/update API，仅在状态接口确有缺口时修改。
- `src/photo_search/web/places-albums.js`、`places.html`：自动进度与手动修复入口文案。
- 相关 refresh、CN facets、place albums、package activation/recovery 测试。

先阅读这些文件的直接调用者和现有测试，再确定最小改动；不要仅凭函数名假定刷新阶段的调用顺序。

## 7. 验证计划

1. **新库建库**：隔离合成图库包含超过 100 张有效中国 GPS 照片；一次完整 build 自动跨批处理，结束后省/市/区县地点相册能读取结果，无需调用手动 update API。
2. **日常增量**：全量完成后新增一张有 GPS 照片并执行普通 refresh，该照片自动进入正确地点；再次 refresh 不重复解析既有结果，也不从头扫描全库。
3. **旧图库升级**：预置已有照片和 GPS、无 CN run 的 catalog；首次普通 refresh 自动开始 catch-up，进度写入后模拟取消/重启，随后续接至 complete。
4. **GPS 变化**：同一资产的 GeoFact/input revision 改变后生成新结果；旧结果不再成为当前相册成员。
5. **数据包切换**：切换活动 dataset 后使用新 dataset 的独立结果；切换期间的迟到写入被拒绝。
6. **保护规则**：覆盖 MANUAL_ASSIGNED、MANUAL_UNASSIGNED、有效排除、无 GPS、无效 datum、非 PRESENT 位置；不得改变人工状态或把不合格照片加入相册。
7. **降级与失败**：无活动包、无 CN addon、损坏包、取消、SQL/解析异常均有准确阶段状态；核心扫描/搜索/地图可用，失败可恢复。
8. **边界与性能**：验证 100 条批次边界、5,000 条日常预算、delta overflow、重复执行幂等；确认几何数据不会按每个小批次重复加载，且 CN 阶段不读取照片文件。
9. **回归**：原 GPS 提取、附近城市解析、CN 浏览/分页/搜索、人工归属与撤销、地图 API、刷新取消/恢复及阶段状态回归。

使用隔离合成图库，不访问用户真实照片和真实 PhotoSearchData。复用已有 CN 几何与数据包证据；不重下 PBF、不重新制作地名包、不重复执行 30 万性能套件，除非新实现确实改变了相应路径并能说明理由。

## 8. Windows 手动验收

1. 用实现后的源码构建一个全新隔离图库，完成首次建库后直接打开「地点相册」；不点击「更新中国地点」，确认有 GPS 的中国照片已出现。
2. 向同一图库加入一张新的中国 GPS 照片，运行正常图库刷新；确认新照片自动出现。
3. 重启程序，确认地点相册仍可用，且没有重新全量计算。
4. 对已有图库升级，确认首次刷新会自动补齐并显示持久进度；中断后再次刷新可继续。
5. 最后点击手动入口只作为修复路径验证，不作为自动化通过的前提。
