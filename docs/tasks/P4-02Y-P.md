# P4-02Y-P — 亚洲 GeoNames 真实地名包准备

**状态：READY**

## 目标

用真实 GeoNames 数据生成一个个人使用的亚洲地名包，并导入：

```text
D:\SZ\project\PhotoSearchData\places\datasets
```

只验证现有：

```text
GPS → 附近城市建议
```

可以使用真实数据正常工作。

## 1. 数据范围

使用 GeoNames：

```text
cities500
alternateNamesV2
countryInfo
```

第一版只保留主要亚洲国家/地区：

```text
CN HK MO TW
JP KR MN
SG MY TH VN PH ID KH LA MM BN
IN NP LK BD PK BT MV
```

中国优先。

名称优先：

```text
简体中文
→ 其他中文
→ GeoNames 主名称
→ 英文
```

## 2. 实现

增加一个简单准备工具，将 GeoNames 原始文件转换成现有 PhotoSearch 地名包格式。

输出继续使用现有格式：

```text
manifest.json
places.jsonl
aliases.jsonl
hierarchy.jsonl
LICENSE.txt
```

然后复用现有：

```text
manage_dataset.py
```

完成：

```text
build / import / validate / activate
```

不修改现有地点数据结构和解析协议。

## 3. 最小验证

只做以下检查：

1. 数据包能够成功生成；
2. `validate` 通过；
3. 能成功 `activate`；
4. 检查几个已知坐标，例如：
   - 杭州；
   - 上海；
   - 东京；
   - 新加坡；
5. `nearby_cities()` 返回合理城市名称；
6. 如方便，再拿 1～3 张真实带 GPS 的个人照片确认能够产生附近城市建议。

不做大规模性能测试。

## 4. 不做

本卡不做：

- 全球 GeoNames；
- 全图库地点重算；
- RTree / GIS / 网格索引；
- 行政区边界；
- 景点 / POI；
- 地图；
- 自动确认地点；
- 地点 UI 改造；
- 打包；
- 发行资源处理。

如果真实亚洲包解析明显慢，再单独立性能优化卡。

## 5. 验收

PASS：

```text
亚洲 GeoNames 包生成成功
validate PASS
activate PASS
杭州 / 上海 / 东京 / 新加坡附近城市查询正常
```

并确认包实际位于：

```text
D:\SZ\project\PhotoSearchData\places\datasets
```
