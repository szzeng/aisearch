## 背景

当前首次建库 OCR 明显成为瓶颈：CPU 长期接近 100%，GPU 基本空闲。

已确认当前实现：

- OCR 为 `non_model + CPU_PREFERRED + cpu-only`；
- RapidOCR 正式路径未启用 CUDA；
- `max_batch_size=1`、单 worker；
- 高分辨率 OCR 最长边 2000 px，必要时切片。

P0-06 真机已有 RapidOCR 证据：CPU p50 ≈ **917.94 ms**，CUDA p50 ≈ **75.95 ms**，约 **12×** 差距。因此本卡优先解决 GPU 路径，不做其它性能优化。

## 目标

让首次建库 OCR **默认实际使用 CUDA**，并保证设备状态如实记录。

同时保留显式 CPU 路径用于诊断/对照，禁止 CUDA 初始化失败后由 RapidOCR 静默整条回退 CPU。

## 实现范围

### 1. 最小设备契约修正

当前 `p2-contracts.v1` 把 `non_model` 固定为：

`CPU_PREFERRED + ["cpu"]`

OCR 实际是模型推理，不能为了省事继续伪装 CPU。

采用**最小兼容扩展**表示“产生 structured artifact 的模型处理器”；不得把 OCR 假装成 embedding/reranker，也不得放宽 GPS / place / taken-time 等所有 `non_model` 的设备限制。

**Luna 不自行设计新的全局 processor kind / contract version。** 开始实现前，由 DS-H 明确 OCR 的最小契约表达方式。若现有冻结契约无法通过局部兼容扩展表达 GPU OCR，则停止并升级 Sol；不得通过 scheduler 特判、伪造 processor 类型，或放宽全部 `non_model` 来绕过。现有 GPS / place / taken-time 等 CPU `non_model` 行为必须保持不变。

### 2. OCR CUDA 接入

复用现有 `onnxruntime-gpu` 和 `runtime/device.py`：

- preload CUDA/cuDNN DLL；
- RapidOCR det / cls / rec 开启 CUDA；
- `auto` 默认优先 GPU；
- 显式 `cpu` 仍可运行；
- Job/result 如实记录 `resolved_device`、provider、precision。

不得新增 CUDA Toolkit、TensorRT 或新 Python 依赖。

### 3. 禁止静默 CPU 回退

GPU 路径建立后检查实际 OCR session provider。

请求 GPU 时：

- 必须实际存在 `CUDAExecutionProvider`；
- CUDA provider 创建失败时结构化失败；
- 不允许 `engine_use_cuda=true`、实际却只有 `CPUExecutionProvider` 的情况继续建库。

### 4. 保持现有 OCR 质量策略

本卡**不要修改**：

- PP-OCRv4 固定权重；
- `MAX_LONG_EDGE=2000`；
- 切片尺寸/重叠；
- OCR 阈值；
- 原文、区域、置信度与 FTS 语义；
- artifact/schema；
- batch=1；
- 单 worker；
- 并行/多进程调度。

这些优化以后有数据再决定。

## 最小验收

使用现有 OCR fixture / smoke，不扫描真实图库。

必须验证：

1. CPU 路径仍可正常 OCR；
2. GPU 路径 det/cls/rec session 实际包含 `CUDAExecutionProvider`；
3. GPU 与 CPU 的 OCR 文本、区域结果无不可接受差异；
4. GPU 请求下人为破坏 CUDA provider 时明确失败，不能静默跑 CPU；
5. 对现有 invoice / dense / blank fixture 做 warm CPU/GPU 对照，记录总耗时、单图耗时、实际 provider，以及显存占用或等价 GPU 使用证据；
6. GPU 端到端 OCR 中位耗时至少比 CPU **快 2×**；未达到则先分析，不继续做 batch/并行优化；
7. 跑一次小型 `library refresh/build` fixture，确认 OCR job 最终记录为真实 GPU device/provider。

定点测试：

```text
uv run --no-sync pytest -q -p no:cacheprovider tests/unit/test_p3_ocr_* tests/integration/test_p3_ocr_*
uv run --no-sync ruff check .
uv run --no-sync uv lock --check
git diff --check
```

若修改公共 `ProcessorSpec` / contract parser，再补相关 P2 scheduler/contract 定点回归；**不要求为了本卡跑无关全仓性能测试**。

- CPU 显式诊断路径仍可用；
- OCR 输出语义不变；
- GPS / place / taken-time 等既有 CPU `non_model` 契约不受影响；
- GPU 相对 CPU 的实际加速有测量证据。

## 明确排除

本卡不做：

- OCR batch 调优；
- 多线程/多进程 OCR；
- 多 GPU；
- OCR 模型升级；
- 分辨率/切片策略调优；
- 全库 20～30 万性能测试；
- UI 改造；
- schema / OCR 数据结构重做。

先把当前明显的 **CPU-only OCR** 修正，再根据真实吞吐决定是否需要下一轮优化。
