## 不变量与行为

当前唯一应用接口 `GET /api/v1/health` 保持不变，且不得被本探针依赖或修改。应用数据必须位于安装目录之外；探针数据仅存于 pytest `tmp_path` 或脚本自建的临时目录，退出后不得在仓库、安装目录或用户数据目录残留表目录、索引文件或 `.lance` 目录。所有命令使用 `uv run` 与 Python 3.12.10，不得使用 Python 3.14。结果必须来自真实写入与真实查询，不得用固定成功 JSON、假向量或只验证 import 取代。

在 `tools/benchmarks/` 实现可直接运行的探针，输出可机读且便于报告摘录的 Python 版本、LanceDB 实际版本、表创建结果、各步骤影响行数与查询结果。正常路径必须在一个新的落盘临时目录中：

1. 创建或打开一张固定小模式表（例如 `id`、固定维度向量、可区分标签字段），维度与字段由探针自定并在输出中记录。
2. 写入至少三条可区分记录，其中至少两条的最近邻顺序可预期。
3. 执行一次真实向量查询（最近邻），断言返回的 `id` 顺序符合预期。
4. 关闭连接并以新的进程或新的连接重新打开同一目录，重复查询并断言结果一致（证明落盘与重启可读）。
5. 重新打开后分别执行新增、更新、删除各至少一次，并在每次操作后断言行数与查询结果符合预期；更新必须能被重读确认，删除的记录不得再被查出。

异常路径：表创建或查询失败时，探针以非零退出，输出 LanceDB/Python 版本、异常类型与消息，不得掩盖为 PASS。回归测试覆盖成功路径与关键结果断言，并至少覆盖一个真实失败路径。边界只覆盖本探针使用的固定维度与单进程写入；不要承诺 ANN 索引参数、过滤下推、并发写入、跨版本兼容或性能指标。
