## 用户场景

用户发现"爸爸"里混进了一张不该属于他的脸：他要在人物页把这张脸移出（进入"待手动归类"，不得被后台
重新归回"爸爸"），把同一张合照里属于妈妈、孩子的脸保持不动；随后在待手动归类里把某张脸指定给"叔叔"
并确定它以后不被自动改回；最后可能点"恢复自动归类"，让这张脸重新参与保守关联，但**不**自动清空已有
排除。任何一步都要幂等（网络重试不会执行两次），晚到的后台结果不得覆盖人工结论。

## 本任务范围（只做冻结，不写生产实现）

以 ADR-0006 §1 的阶段边界为准，本卡必须把下面每一项**冻结成可实现的规则**，并逐条写出反例：

1. **操作词汇与记录形状**。0011 把 `person_operations.type` 冻结为
   `('RENAME','MERGE_BY_NAME','MERGE','BATCH_MERGE','UNDO')`。必须决定：单脸取消 / 手动指定 /
   恢复自动 / 批量变体新增哪些 `type`；是扩展 0011 的 `CHECK`（按 0009 范式重建表）还是在 `0012` 新增
   独立操作族；`person_operation_items.entity_type` 目前只有 `PERSON_BUNDLE`，脸级操作需要什么实体类型
   与快照形状（是否新增 `FACE_CONTROL`/`FACE_BUNDLE`，包含 mode/revision/有效链接/排除集合）。
2. **人工控制表的写入语义**。`face_assignment_controls` 的模式迁移矩阵（`AUTO_ALLOWED ↔ MANUAL_ASSIGNED
   ↔ MANUAL_UNASSIGNED`）、`revision` 递增规则、`last_operation_id`、`updated_at`、
   "无控制行 = `AUTO_ALLOWED`"的等价性；`face_exclusions` 的创建 / 解除 / 保留（取消 A 记录对 A 的排除；
   指定 B 解除对 B 的排除但保留其他人物的排除；改回 A 允许更正此前否定；"恢复自动"只解锁不清空排除）。
3. **最小单位与批量语义**。单位是 `face_id`（界面可选多张照片，但提交必须转换为明确的人脸列表）；
   批量上限、去重（同一 face 只允许出现一次）、原子性（失败全回滚）、幂等 `request_id` 的唯一性与
   载荷摘要规则、`expected_revision` 指的是哪一行（控制行还是脸级 revision）以及冲突错误码。
4. **与自动路径的边界**。人工锁下的自动建议可见但不得自动应用；后台提交时必须比较 revision 并拒绝
   覆盖晚到的人工修改；`human_controlled_face_ids()` 已生效的读取顺序如何与新的写入语义配合；
   未命名分组与"待手动归类"如何分开表达（架构 §8.3.4 第 6 条）。
5. **API 形状**。路径、方法、请求/响应字段、幂等与 revision 字段、结构化错误码（新增还是复用
   `PERSON_*`）与其 HTTP 映射；沿用既有 Host/Origin/session/double-submit CSRF 边界；响应与错误
   不得含路径、bbox、landmark、向量或单对相似度。
6. **撤销语义**。冲突检测（后续人工编辑、批量为脸的后续变化）、版本单调性、是否允许 undo an UNDO、
   `FACE_OPERATION_NOT_UNDOABLE` 之类的错误码命名与 details 形状。
7. **权威→派生提交顺序**。是否照搬 ADR-0006 §8：同一事务写权威关系与操作项 → 一次
   `catalog_filter_revision`（cause 取值）→ 受影响资产入 `search_projection_queue` → 受影响脸
   `queue_candidate()` 变 `PENDING_REPAIR`；是否需要新 cause 值（这决定 `0012` 是否要再重建队列表）。
8. **只读状态**。`face_summary` 是否新增人工锁定 / 排除 / 待手动归类的计数（名称、口径、隐私边界：
   只计数，不含姓名、坐标、相似度）。
9. **P3-02/P3-03 兼容硬约束**。不得改 `face_person_links` 的"每脸至多一个 `CONFIRMED`"形状、
   `face_id` 确定性、`face-document.v1` 产物、质量口径、校准阈值、独立候选索引的世代语义；
   不得给 `face_assignment_controls`/`face_exclusions` 增加无默认值的额外 `NOT NULL` 列（P3-02 与 P3-03
   的既有用例只写架构必需列）。
10. **迁移**。新迁移号只允许 `0012`（连续增量），遵守 ADR-0002 §7（只读预检 / 备份 / 单事务推进 /
    缺件与过新拒写）；`0001`～`0011` 逐字节不变。若结论是"不需要新迁移"，必须给出可验证的理由。

反例至少覆盖：把脸从 A 取消后又被自动归回；指定 B 后晚到的自动结果覆盖人工结论；把脸改回此前被排除的
A；恢复自动是否清空排除；同一 face 在一次批量中出现两次；批量中途失败；对已被人工作废的控制行做撤销；
`MANUAL_UNASSIGNED` 的脸在合并（P3-03 语义）与本次操作叠加时的期望结果；合照中同一人物多张脸只按明确
`face_id` 操作。

## 必须保持的不变量

1. 权威判定只看 SQLite；人脸检测事实、`face_id`、向量空间、阈值与独立候选索引世代不被本卡改动。
2. 人工结论优先：任何未来的自动任务都不得覆盖人工归属、人工未归类锁或人工排除；自动建议可显示，
   不得自动应用。
3. 每张脸最多一个 `CONFIRMED` 有效归属（现有偏唯一索引），建议不是有效归属。
4. 最小纠错单位是 `face_id`；批量必须转换为明确的人脸列表，不得用"按照片"隐式扩大范围。
5. 幂等：`request_id` 重复提交返回原操作结果；载荷不同即结构化冲突且零写入（沿用 ADR-0006 §7 范式）。
6. 撤销是新的补偿操作：版本只向前递增，不倒退；有后续冲突时整体拒绝并列出原因。
7. 隐私：API/日志/错误/诊断不得回显本地路径、坐标、向量或单对相似度明细。
8. 既有 P1/P2/P3-01/P3-02/P3-03 测试原样通过（版本耦合的机械断言除外，需在报告说明）。
