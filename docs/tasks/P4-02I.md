## 必须交付的实验闭环

1. **独立 oracle**：同一查询向量、generation/space、稳定权威视图下调用现行完整候选块精确路径，确认 `truncated=false`；合成夹具的 SQLite 权威行、Lance 行和 `projection_revision` 均可逐项检查。实验 A3 候选路径与 oracle 比较完整 `(asset_id, distance)`、全序、`top_k=1,20,200,1000`（夹具不足时记录实际 K）、空集和大量并列；不能只比较 Recall 或前 20 个 ID。
2. **机制证据**：分别为 M1 物理集等价、M2 排序前过滤等价、M3 未检查行严格停止证书建立正例和缺一前提的负例。M3 必含「A 更近但已检查失格、B 合格」以及距离下界等于第 K 行、失格判据不可证/发布前失效；M2 必含过滤结果错误却声称证明的负例。逐例记录 `C_sql`、`C_strict`、物理/过滤后行集、所选机制、证书输入、发布/回退决定和 oracle 页。
3. **五类故障与窗口**：未确认行、`PENDING_REPAIR`、旧/重复 revision、并列距离、并发发布；另覆盖 Lance 缺行、隐藏/离线/来源变化、generation/space 切换、`after_lance` 写后确认前崩溃与重启。每个注入写清事件顺序和发布前状态；证书不成立时必须走完整路径且结果逐项相同，不得只断言 HTTP 200。
4. **结果与限制**：输出机器可读逐例记录、聚合通过/回退/不可证计数、最小反例、命令、耗时与环境。明确区分真实 `vector_channel`/Lance 调用、合成候选原型、跳过/未验证项。若包含服务/融合页，对照 FTS/RRF、`pending_semantic`、会话/游标与错误；未覆盖则明确留给后续卡，不能宣称端到端等价。
