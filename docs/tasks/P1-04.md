## 任务定位

P1-01 冻结了资产/位置身份与迁移契约，P1-02 让扫描可用于真实图库，P1-03 让资产第一次「能被看见」（方向正确的
缩略图与预览、可重建缓存、坏图隔离）。三者目前只有内部 CLI 入口。P1-04 把这些已通过的能力暴露为**本机 HTTP
业务 API**，并补上两条必须同时成立的安全边界：

1. **受控文件访问**：文件接口只接受资产 ID；最终路径必须解析到自己登记来源内部的位置，越界、reparse-point 跨越、
   已变化或不可用的原图都必须被拒绝或如实报告，而不是把任意本地路径提供给调用方。
2. **本机会话保护**：默认仅监听 `127.0.0.1`，启动器生成一次性本地会话凭证，换取 `HttpOnly` 会话 cookie；
   校验 `Host`/`Origin`，变更接口要求 CSRF 令牌，不开放任意 CORS，不默认开放局域网。

本任务仍然**不实现**：搜索/以图搜图 API、人物与人脸 API、模型/索引世代/升级回退 API、outbox、FTS、调度器
pause/resume、AI 推理、P2 全量调度协议、前端页面（P1-05）、重复/断盘/重映射验收（P1-06）。

## 用户场景

- 前端（P1-05）与本地工具可以：列出/新增来源、请求扫描并观察进度、分页浏览资产、按需取缩略图与预览、
  在明确授权下取回原图字节；
- 一个本机随机进程即使知道端口，也不能在没有一次性凭证的情况下读取任何图片或元数据；
- 原图离线时，接口仍返回已生成的缩略图/预览并明确标注原文件不可用，不伪造空白图、不报「坏图」；
- 任何调用方都无法通过路径参数（`..`、绝对路径、UNC、符号链接/目录联接、盘符）读到登记来源之外的文件。

验收一律使用 `%TEMP%` 下的临时夹具，**不得**读取真实照片库。

## 必须交付

### 1. 只读业务 API（架构 §10.2，本任务最小子集）

- `GET /api/v1/health`：保持 P0-01 行为与既有测试不变（不需要会话）。
- `GET /api/v1/capabilities`：构建/契约事实（应用版本、`schema_version`、是否可写、媒体处理版本
  `catalog-thumbnail@1`/`catalog-preview@1`、支持的输入格式列表、受控读取是否启用）。**不得**返回数据目录绝对路径、
  文件清单或任何个人数据。
- `GET /api/v1/stats`：`counts()`（来源/资产/位置/缺失/待确认内容/扫描/任务）+ 每种媒体产物的
  `media_report()` 汇总（published/pending/source_missing/failed/unsupported）。
- `GET /api/v1/sources`、`POST /api/v1/sources`：`POST` 复用 `register_source`（同一套重叠/数据目录校验），
  返回 201 + 来源对象；冲突返回既有结构化错误码（`SOURCE_OVERLAP`、`DATA_ROOT_INSIDE_SOURCE`、`INVALID_PATH`）。
- `GET /api/v1/assets`：分页列表，支持 `source_id`、`availability`（`present`/`missing`/`any`）、
  `has_thumbnail`（`true`/`false`/`any`）、`limit`（默认 50，上限 200）与 `cursor`（keyset，按 `asset_id` 递增，
  不返回重复或跳过的行）。每行至少给出 `asset_id`、`sha256`、`byte_size`、`created_at`、位置计数、
  `availability`、`thumbnail_ready`、`preview_ready` 与一个「当前可用位置」摘要（`source_id` + 展示用相对路径）。
  默认排序必须稳定；不得把整个库物化到内存（keyset + 有界批次）。
- `GET /api/v1/assets/{id}`：资产详情 = `assets` 行 + 全部位置（含 `availability`、`size`、`mtime_ns`、
  展示相对路径）+ 每种媒体产物的状态（`ready`/`pending`/`source_missing`/`failed`/`unsupported` + 结构化 `code`）。
  不存在的资产返回 404 + `ASSET_NOT_FOUND`。

### 2. 受控文件访问（架构 §5.4、§10.3）

- `GET /api/v1/assets/{id}/thumbnail`、`GET /api/v1/assets/{id}/preview`：按需生成（单资产，复用
  `generate_thumbnail`/`generate_preview`），返回产物字节，`Content-Type: image/jpeg`，`Cache-Control` 明确，
  并带内容指纹/处理器版本相关的 `ETag` 或等价可校验标识（同一内容重复请求返回同一结果）。
- `GET /api/v1/assets/{id}/original`：**只有**通过受控解析才返回字节：
  - 只接受资产 ID，不接受路径参数；位置必须属于该资产且 `availability='PRESENT'`（多位置时按稳定顺序选第一个可用位置）；
  - 最终路径必须经 `path_key`/`root_key` 语义确认仍位于该来源根内部；拒绝 `..`、绝对路径、UNC、盘符注入与
    任何会把枚举带出来源树的 reparse-point；
  - 返回前校验 `size`/`mtime_ns` 与库中观测一致；不一致或不满足来源边界 → 409/404 结构化错误，绝不「尽力返回」；
  - 响应不得泄露 `root_path` 之外的任何本机路径；`Content-Disposition` 使用安全的展示文件名（含 RFC 5987 形式，
    不得出现路径分隔符）；支持 `HEAD` 与 Range（大图/断点播放），失败时不得返回半段错误内容。
- 所有文件接口在「原图不可用但产物已存在」时仍必须返回产物，并在头部或伴随结构中明确标注原文件不可用；
  未生成且原文件不可用 → 404/409 + `SOURCE_FILE_MISSING`，不得返回空白图或伪造成功。

### 3. 本机会话保护（架构 §10.3）

- 默认仅监听 `127.0.0.1`；配置成非回环地址时必须显式要求（例如 `--allow-non-loopback` 之类的显式开关），
  默认行为下拒绝，且**不实现**局域网鉴权或 CORS 白名单扩展。
- 启动时生成一次性本地会话凭证：
  - 测试/诊断可用环境变量覆盖（例如 `PHOTO_SEARCH_SESSION_TOKEN`），正常运行由应用生成随机令牌并写入
    `<data_root>/runtime/` 下的凭证文件（权限尽量收紧），**不得**写入日志；
  - 一次性交换接口（如 `GET /api/v1/session?token=...`）校验令牌后下发 `HttpOnly; SameSite=Strict; Path=/`
    会话 cookie（并用 double-submit 方式另发一个非 HttpOnly 的 CSRF cookie 或等价机制）；令牌用后失效
    （新进程重新生成），比较使用常量时间，失败不区分「不存在/已用/错误」的细节；
  - 除 `health` 与交换接口外，所有 `/api/v1/*` 都必须要求有效会话；`POST` 还必须通过 `Origin`/`Host` 校验与
    CSRF 头校验；任何失败返回结构化 JSON（无 Python traceback）。
- 统一错误信封：`{code, message, request_id}`（可选 `details`），与 catalog 结构化错误码一致；HTTP 状态映射合理
  （404 未找到、409 冲突/不支持/不可用、422 参数非法、401/403 会话与来源校验失败、400 其他）。
- Pydantic 定义请求/响应模型并保证 OpenAPI 可导出；若直接 `import pydantic`，则在 `pyproject.toml` 显式声明
  （FastAPI 已依赖的版本范围内），并同步 `uv.lock`；不引入其他新依赖。

### 4. 请求扫描（架构 §10.2「长任务返回 202 + job_id」）

- `POST /api/v1/sources/{id}/scan` 复用 `start_scan` 的语义：同一来源只有一个非终态扫描请求，重复请求返回同一个
  `scan_id`/`job_id` 并标记复用；返回 202 + `scan_id`/`job_id`/`state`，**不阻塞**请求到扫描结束。
- `GET /api/v1/jobs`（可与 `GET /api/v1/sources/{id}` 一起）暴露 job/scan 状态、`attempts`、`progress`（0.0～1.0）、
  `last_error_code`，字段来自 `jobs`/`scan_runs` 既有列，不新增表。
- 执行方式：在 API 进程内用**单个**后台执行者按 `execute_scan` 的生产路径运行（同一时刻最多一个扫描），
  必须继续走 lease/心跳/迟到提交校验与 `reset_execution_coverage`，不得出现第二个并发 `scan_run`；
  进程被杀后按 ADR-0002 §5.3 由后续执行接管同一个 `scan_run`。**不得**提前实现 P2 的调度器、worker 池、
  资源配额或 AI 任务领取。
- 若执行中发现该后台执行与冻结契约冲突（例如跨进程写者、恢复语义、状态联动无法同时成立），停止并交 **C2**，
  在报告中记录反例与最小复现。

### 5. 可观测性与隐私

- 日志与 API 响应不得包含原图内容、OCR 类文本、会话令牌或数据目录外的本机绝对路径；请求日志不得记录 cookie 值。
- 每个错误都带稳定 `code`；`request_id` 便于与报告中的证据对应。
- 内部 CLI 入口（P1-01～P1-03）保持可用与兼容，退出码语义不变；新增 API 不得改变 CLI 行为。

### 6. 明确不做

- 不做搜索/以图搜图、不做人物与人脸、不做 OCR、不做模型/索引/outbox/升级回退 API。
- 不做调度器 pause/resume、不做 P2 全量任务协议、不做前端页面（P1-05）、不做重复/断盘/重映射验收（P1-06）。
- 不新增数据表、不修改既有表/主键/唯一键/身份或缺失判定语义；不加 Docker/Redis/云服务/第二个向量后端。
- 不开放局域网、不加通配 CORS、不提供任意路径文件接口。
- 不读取、不修改、不移动、不删除任何真实照片库。

## 正常行为 / 异常行为 / 边界情况（验收时逐条覆盖）

**正常行为**

- 未带会话的任意 `/api/v1/*`（除 health/交换）→ 401 结构化错误；正确交换后 `GET` 可用，`POST` 带 CSRF 头可用。
- 新增来源 → 202/201 语义正确；请求扫描 → 202 + `scan_id`/`job_id`，重复请求复用同一扫描；扫描完成后
  `GET /api/v1/jobs`、`GET /api/v1/sources/{id}`、`GET /api/v1/stats` 与库状态一致。
- `GET /api/v1/assets` 分页遍历 N 个资产：不重不漏，`limit`/`cursor` 边界正确（首末页、空结果）。
- `GET /api/v1/assets/{id}/thumbnail|preview`：首次按需生成并返回 JPEG 字节（长边 320/1600 契约与 P1-03 一致），
  重复请求命中同一产物；`original` 返回与来源文件逐字节相同的内容（测试内直接比对 SHA-256）。

**异常行为**

- 资产/来源不存在 → 404 + 结构化 code，不返回 500。
- 原图缺失或来源离线：已生成产物仍返回；未生成时 `SOURCE_FILE_MISSING`；`GET /assets` 仍能列出该资产并标注。
- 损坏/不支持格式：文件接口返回结构化 `DECODE_FAILED`/`FORMAT_UNSUPPORTED`（沿用 P1-03 失败记录），不返回空白图。
- 请求扫描时数据库为更高 `schema_version`：读写入口一律返回 `SCHEMA_TOO_NEW` 结构化错误，且预检不产生写副作用。
- 令牌错误/已用/缺失、Origin 不匹配、`POST` 缺 CSRF 头 → 401/403；错误消息不泄露令牌内容或是否存在。

**边界情况**

- 中文、空格、超长（>220 字符）来源路径与文件名；只读原图；大小写不同的同名路径。
- 资产有多个位置：一个 `PRESENT`、一个 `MISSING`；一个来源完全离线；两个来源同内容。
- 路径穿越尝试：`../`、绝对路径、UNC、盘符、以及来源目录内的目录联接/符号链接指向来源之外（必须拒绝）。
- 扫描后原图被替换（`size`/`mtime_ns` 变化）→ 文件接口返回结构化冲突而不是返回错误内容。
- 分页上限、`limit` 非法值、重复 cursor、超大 `limit`。
- `HEAD`/Range 请求；`ETag` 或等价校验标识在不改变内容时稳定。

## 必须保持的不变量

- 资产内容身份 = 完整 SHA-256；`(source_id, path_key)` 位置唯一；`asset_id` 未确认前允许为空。
- 只有完整成功扫描才能产生缺失结论；负向事实与 `last_successful_scan` 在同一最终事务提交。
- jobs 五字段逻辑键全非空；状态迁移与迟到提交校验按 ADR-0002 §6；lease 离开 `RUNNING` 时清空。
- 正常 catalog 运行使用 WAL；更高 `schema_version` 只读诊断、拒绝写入。
- 用户原图只读；缓存/缩略图可删除重建，不得承载唯一的人工或身份信息。

1. 会话流程：无会话 401；错误/已用令牌 401；正确交换后可 `GET`；`POST` 缺 CSRF 或 Origin 不匹配 403；

6. 受控路径：`../`、绝对路径、UNC、盘符注入、来源内目录联接指向来源外，全部被拒绝且不返回字节；
