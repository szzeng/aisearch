## 实现要求

### 1. Migration 0014 与持久权威

- 新增 `face_redetection_mappings`、`face_redetection_groups` 及 ADR-0010 要求的索引、唯一性、外键、状态与
  revision 约束；稳定键、group 键和 state 闭集必须逐字段对应 ADR §2～§3。
- 按 ADR-0007 §10 / ADR-0002 §7 的既有模式重建 `person_operations` / `person_operation_items` 的闭合
  `CHECK`，只增加 `FACE_MAPPING_CONFIRM`、`FACE_MAPPING_REJECT`、`FACE_MAPPING_GROUP`；备份、单事务、
  高版本拒绝与失败回滚保持不变。
- 把 `SUPPORTED_SCHEMA_VERSION` 从 13 提到 14；`0001`～`0013` 逐字节不变。迁移必须覆盖空库连续升级、
  13→14、已有人物/地点/操作数据、失败回滚和高版本拒绝。

### 2. 候选生成、稳定身份与失效

- 在 `persist_face_document()` 的同一提交事务内，只为跨世代
  `old_spec_revision != new_spec_revision` 的新行 × 存活人工锚点生成/重算候选；同内容同 spec 重跑必须
  零新脸、零映射行、零新 group，自映射和跨资产映射永不生成。
- 严格使用 ADR §3.2 的 IoU/landmark 常量、低质量降级和四态 candidate 规则；服务端永不自动确认，
  `NO_CANDIDATE`/`AMBIGUOUS` 无默认 target。
- 判定顺序固定为：写/退休检测行 → 计算候选 → 候选失效置 `STALE`/重算 group → 计算关联保持。
  重启、重复检测、升级失败、回退、晚到 worker、备份恢复必须保持稳定 ID、forward-only revision 和旧审计链。

### 3. 临时保持与 `face_association_queue`

- 保持“检测行保留集合”与“自动关联保持集合”两个谓词分离；不得把 provisional hold 塞入
  `human_controlled_face_ids()`。
- 在 `_reconcile_asset()` 的 `BEGIN IMMEDIATE` 自动关联写事务内，与 `_manually_locked_face_ids()` / 活动
  exclusion 同一时点读取 `OPEN` group 候选并作为写门；保持脸不得获得或替换有效关联，也不得写伪人工控制。
- 保持期间保留/回写 queue 行。释放集合只有 confirm/reject（含 confirm 未选候选）；释放后仍
  `AUTO_ALLOWED` 且无有效关联的脸必须已重新排队，但决策事务不替用户选人物。
- `undo → OPEN` 不是释放：恢复保持并保留/重新排队，随后的关联遍继续跳过保持脸。失效脸不得因 hold 被当成
  不可删除的人工锚点。

### 4. 决策、幂等、revision 与补偿撤销

- 新增 `persons/mapping.py` 落实 `decide_face_mappings()` / `undo_face_mapping_operation()`；复用全局
  `request_id` 幂等门并保证它先于实体/revision 检查，同 key 同 payload replay 原结果，不同 payload 整批拒绝。
- `POST /api/v1/face-mappings/decisions` 支持 1..200 个 group、每组 1..16 targets；批量 shape、存在性、全部
  expected revision、目标合法性先验证，任一失败零写入。
- 严格实现 ADR §4 的双向继承基数、多对多保守转移、exclusion 并集、肯定/否定冲突、目标已人工编辑拒绝、
  `NO_CANDIDATE` 只允许 reject。旧脸事实保持不变并继续可查。
- operation 继续使用 `person_operations` / `person_operation_items`；只有人工事实实际变化时
  `catalog_filter_revision` 恰好 +1、cause 仍为 `PERSON_CHANGED`，更新 search projection 与 face entry repair，
  不写图片向量 `index_outbox`。
- 撤销走既有 `POST /api/v1/person-operations/{operation_id}/undo` 和 `operation_family() == "mapping"`；冲突
  整批拒绝，恢复 revision 取 `max(before, live)+1`，不允许 undo an undo。

### 5. P3-07B merge/undo 顺序缺陷

- 修复 `undo_person_operation()` 的链接恢复，使结果与 person id 顺序无关：对该 operation 快照确定的影响集合
  先统一删除有效 `CONFIRMED` 行，再按 before 快照恢复；任何语句边界每张脸至多一条有效关联。
- 不得删除未被该 operation 影响的行；revision 仍 forward-only；`MANUAL_UNASSIGNED` 恢复后无 confirmed link。
- 必须覆盖目标 id 高/低、多个 source、控制/排除、无关脸不受影响、merge 后再次人工编辑时整批
  `PERSON_OPERATION_NOT_UNDOABLE`。不得改变 ADR-0006～0008 的错误码、响应或 filter revision 语义。

### 6. API、错误、能力与隐私闭集

- 实现：
  - `GET /api/v1/face-mappings?state=open|all&limit=1..200&cursor=...`；
  - `GET /api/v1/face-mappings/{old_face_id}`；
  - `POST /api/v1/face-mappings/decisions`；
  - 复用既有 operation undo 路径。
- DTO、keyset `fm1` 游标、candidate/group 交叉约束和 12 个错误码必须与 companion 一致；错误 `details`
  严格逐码闭合，`FACE_NOT_FOUND` 至少一个 old/new ID，`INVALID_CURSOR` details 为空对象。
- 响应、错误、访问日志不得含 bbox、landmark、IoU、embedding、confidence、路径、EXIF/GPS、幂等 payload/hash
  或 before/after 快照。
- `/capabilities.face_summary` 加性增加四个映射计数；入口仅在 `schema_version >= 14` 且 schema ok 时显示，
  旧 schema、空队列和无候选必须诚实。

### 7. `/persons` 审核 UI 与真实浏览器闭环

- 在既有 `/persons` 页面增加“重检测待确认”视图：旧/新受控裁剪并排、候选强弱/状态、逐候选选择、confirm、
  reject、undo、stale/conflict/重试提示；不得渲染内部几何、路径或未冻结字段。
- 保持现有同名、待手动归类、单脸/批量纠错、split 和最近操作/undo 功能；无 capability 时隐藏新入口。
- 使用合成 `%TEMP%` 图库完成记录的真实浏览器闭环：`/persons` 确认/拒绝/撤销/冲突 → `/places` 人工纠错 →
  `/search` 人物+地点 AND 重搜/旧会话 stale。覆盖桌面宽视口、360×640、键盘可达、错误提示、访问日志与
  页面/网络响应隐私扫描；保存步骤、截图/观察和未验证项到报告。
