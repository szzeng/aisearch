# P4-SEARCH-PERF-UX-FIX — 搜索性能诊断易用性与统计修复

**优先级：** P1
**任务类型：** 已有诊断功能完善 + 最小 Bug 修复
**推荐模型：** GPT-6 High
**执行范围：** 搜索前端、诊断接口、统计与导出
**原则：** 复用现有实现、不更改搜索算法、不重建索引

## 一、任务目标

现有 `P4-QWEN-SEARCH-PERF-DIAG-A` 已实现多模型搜索性能日志，但启用流程繁琐，还存在部分统计准确性问题。

本卡将其改为应用内直接操作的功能。

目标使用流程：

**搜索页面 → 更多选项 → 开启性能诊断 → 开始标准测试 → 导出报告**

用户切换 Chinese-CLIP、Qwen 或 EXIF v2 后，可直接测试当前激活模型，无需改配置或编写命令。

## 三、一键标准性能测试

### 3.1 测试流程

用户输入搜索词后，点击「开始标准测试」。

系统自动：

1. 确认当前模型及索引可用。
2. 固定本次搜索词、条件和分页参数。
3. 执行 1 次首次观察搜索。
4. 执行 2 次预热搜索。
5. 执行 20 次正式热搜索。
6. 汇总有效样本的 P50/P95。
7. 显示结果，允许导出 JSON。

不要求用户手动点击 23 次。

自动测试必须复用真实搜索 API、结果处理和缩略图加载流程。

每轮从实际发出搜索动作时开始计时，不将两次测试之间的等待或调度时间计入搜索耗时。

### 3.2 防止自动测试干扰正常使用

- 同一时间只执行一个测试。
- 必须等待前一轮搜索和视口图片观察结束。
- 测试期间禁止重复点击开始。
- 测试期间固定搜索条件，不允许静默使用修改后的条件。
- 可随时点击「停止测试」。
- 页面关闭、导航离开或切换模型时终止测试。
- 不启动后台建库、模型切换或批量维护任务。
- 不额外生成测试图片，不强制请求视口外的缩略图。
- 遇到需要人工选择人物、地点或合集的歧义搜索时停止并说明原因。
- 不执行无限重试；失败记录保留但不计入有效统计。

正常搜索原有的索引投影追赶行为保持不变。

### 3.3 首屏测量规则

现有页面使用 `IntersectionObserver` 与异步解码。

标准测试必须确保搜索结果区实际位于可观察视口内。

可以在开始测试前自动定位结果区域，并保持每轮相同的页面位置、窗口尺寸及缩放比例。

必须区分：

- 搜索 API 执行完成
- 结果 DOM 建立完成
- 第一张缩略图解码就绪
- 当前视口缩略图全部完成、失败或超时

禁止将 DOM 创建或图片请求发出当作照片已经显示。

如当前视口没有照片，不得将“视口就绪 = 0ms”计为有效样本。

## 五、修复之前发现的统计问题

**本节为必须完成项目，不得跳过。**

### FIX-1：首屏数量统计错误

当前 `first_page_hits` 实际可能记录的是检索候选总数，而不是首页返回数量。

修复：

- `returned_candidates` 记录候选结果数量。
- `first_page_hits` 记录最终第一页实际返回的照片数量。
- 两者分开，不能混用。

例如 4265 个候选、每页 20 张，应分别记录候选数和首屏实际返回数。

### FIX-2：当前 Profile ID 读取错误

前端当前读取 `search.profile_id`，但 capabilities 真实活动字段为 `active_profile_id`。

修复：

- 正确读取 `active_profile_id`。
- 正确读取 `active_image_generation_id`。
- 统一前后端模型身份比较口径。
- 对身份缺失给出明确状态。

不能静默把缺失的 Profile 当成有效模型。

### FIX-3：空视口误判为首屏完成

如果搜索结果在屏幕下方，当前视口没有照片，诊断可能立即记录正常完成。

修复：

- 等待布局稳定后判断可见照片。
- 有结果但没有可见缩略图时，标记 `NO_VISIBLE_THUMBNAILS`。
- 不能将该情况作为有效首屏性能样本。
- 标准测试应提前统一滚动位置，保证具有可比较的视口环境。
- 无结果搜索允许记录 API 性能，但不能虚构首图显示时间。

### FIX-4：首次 Worker 冷启动判定错误

当前部分 Worker 状态在取得编码器之后才检查，可能已经发生模型加载。

修复：

- 正确区分 `first_observed`、`warmup`、`hot` 和可证实的 `worker_cold`。
- 仅在能够观察到实际 Worker 创建或模型加载时标记冷启动。
- 若模型已经由 capabilities 等流程预先加载，不能将首次点击搜索当作真正冷启动。
- 不增加额外模型调用来验证冷启动。

无法精确确认时标记 `not_measured`。

### FIX-5：缺失时间被统计为 0ms

现有统计需要避免 JavaScript `Number(null) === 0` 引发的错误。

修复：

- 只有真正的有限数值可以进入 P50/P95。
- `null`、`undefined`、缺失字段及非数字必须排除。
- 失败或超时不能被当作正常完成。
- 所有统计显示有效样本数量。

### FIX-6：预热与正式测试样本混用

修复：

- 首次观察、预热、正式热搜索分别记录。
- 手动搜索与自动标准测试分别标识。
- 自动测试的正式 P50/P95 只计算有效热样本。
- 停止、中断、失败、模型绑定异常的样本不计入正常热搜索统计。

### FIX-7：完整 HTTP 耗时口径

当前 `search_execution_ms` 主要是后端搜索执行阶段，不包含完整 HTTP 响应序列化。

修复显示和导出说明：

- `search_execution_ms`：后端搜索执行时间。
- `request_to_response_ms`：浏览器请求至响应完成并完成必要的数据读取。
- `click_to_first_image_decode_ready_ms`：首张缩略图解码就绪时间。
- `click_to_viewport_ready_ms`：当前视口缩略图就绪时间。

不得将 `search_execution_ms` 直接称为完整 HTTP 总耗时。

不要求新增复杂 ASGI 性能中间件。

### FIX-8：异步搜索串样本

检查并修复：

- 上一轮图片解码回调不能影响下一轮测试。
- 已取消搜索的旧响应不能覆盖新测试结果。
- 图片超时计时器必须及时清理。
- 手动搜索与自动测试不能共享错误的活动样本。
- 每次采样必须与唯一 request_id 对应。

## 六、后端诊断启用机制

复用已有 `Server-Timing` 和 `X-Search-Perf-Meta`。

原有环境变量开关可作为开发兼容选项保留，但通过 UI 开启时不应依赖环境变量。

对于正常会话认证的同源搜索请求，仅在携带诊断标记 `X-Search-Perf: 1` 时启用计时。

必须保持：

- 未认证请求不能访问搜索诊断数据。
- 原有会话和 CSRF 保护不变。
- 不增加全局持久化诊断开关。
- 不新增数据库迁移。
- 不返回原始搜索词、私人文件路径、Cookie、Token。
- 默认关闭时无额外模型或数据库调用。
- 不改变正常搜索返回 JSON。

如后端已有适合复用的权限及请求标记机制，优先使用，不另造配置体系。

## 八、数据安全及性能边界

禁止：

- 自动切换模型
- 自动重建图库向量
- 修改搜索阈值、top_k、排序
- 更改 Chinese-CLIP 或 Qwen 推理参数
- 修改原图、原始索引或人物记录
- 新增常驻性能采集任务
- 对普通搜索增加额外 GPU/SQL 工作

20 次正式搜索使用既有搜索流程。所有测试应在用户主动点击后执行，不允许后台定时自动触发。

## 九、最小定向测试

必须覆盖：

1. 普通搜索默认关闭诊断，行为不变。
2. UI 开关立即生效，无需环境变量或重启。
3. 一键标准测试正确执行 1 次首次观察、2 次预热、20 次正式搜索。
4. 用户停止或页面退出后，自动搜索不再继续。
5. 四种模型身份识别及绑定核验。
6. FIX-1 至 FIX-8 的对应回归测试。
7. 图片成功、失败、超时、空结果和无可见图片。
8. JSON 导出隐私检查。
9. 关闭诊断时，不增加模型和数据库工作量。

执行必要的 Ruff、Node 语法检查、定向 pytest 和 `git diff --check`。

不跑全量 pytest 或 30 万图库测试。

不要将现有未通过的旧测试静默宣称通过；只报告本任务实际验证的结果。

## 十、完成标准

用户使用正常方式启动 PhotoSearch 后，无需任何命令行操作即可：

**开启诊断 → 输入搜索词 → 开始标准测试 → 查看结果 → 导出 JSON。**

切换到 Chinese-CLIP 或 Qwen 后重复操作，即可获得独立且可比较的性能报告。

必须保证统计正确，特别是模型身份、有效样本、首屏照片数量及时间缺失值处理。
