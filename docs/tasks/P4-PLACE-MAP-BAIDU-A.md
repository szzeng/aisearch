### 2. 第一阶段：坐标兼容性验证（强制阻断）

这是整个任务最重要的部分。

未通过本阶段，不得进行完整地图迁移。

#### 2.1 使用官方 JSAPI 4.0

要求：

- 官方 HTTPS SDK。
- 动态按需加载。
- 同一页面只加载一次。
- 主地图和详情地图共用加载器。
- 不使用 JSAPI GL、2.0 等其他版本。
- 不增加不必要的构建工具和 npm 依赖。

#### 2.2 优先采用全局 WGS84 坐标模式

官方支持：

`BMAP_COORD_WGS84`

在地图实例创建之前设置全局坐标类型。

验证以下行为：

| 验证项目 | 要求 |
|---|---|
| 地图中心点输入 | 接收 WGS84 |
| 地图中心点读取 | 返回符合 WGS84 合同的结果 |
| 地图视野 bbox | 能够提供 WGS84 |
| 地图点击事件 | 返回 WGS84 |
| PointLayer GeoJSON | 能正确显示 WGS84 |
| PointLayer 点击 | 正确取得照片 ID |
| 地图深链接 | WGS84 定位正确 |
| 国内地图 | 正确显示 BD09LL 底图 |
| 海外地图 | WGS84 定位正确 |

特别注意：

百度 PointLayer 文档没有列出独立的 `coordType` 参数，因此不能直接假设它一定遵循全局坐标设置，必须实际验证。

#### 2.3 坐标转换备用方案

如果全局 WGS84 模式不能正确处理照片点，验证官方：

`BMap.Convertor.translate(points, 1, 5, callback)`

对应：

- 1：WGS84。
- 5：BD09LL（百度经纬度）。

只允许转换当前地图视野实际需要的照片点。

必须验证批量大小、请求次数、耗时、配额及失败处理。

禁止：

- 将 BD09LL bbox 直接作为 WGS84 查询条件。
- 使用未经官方支持的 BD09LL → WGS84 逆转换。
- 自行编写近似坐标偏移算法。
- 将 BD09MC 当作 BD09LL。
- 将转换后的坐标写回数据库。

**阻断条件：** 如果不能可靠获得 WGS84 视野边界，或者 PointLayer 无法满足坐标要求，停止迁移，提交 NO-GO 报告。

#### 2.4 第一阶段交付

提供一份独立验证报告：

- SDK 实际加载结果。
- WGS84 全局模式结果。

不使用真实图库 GPS 做开发阶段实验。

### 3. 第二阶段：地图引擎替换

通过第一阶段后实施。

#### 3.1 地图类型

使用百度官方原生地图类型：

- `BMAP_NORMAL_MAP`
- `BMAP_SATELLITE_MAP`
- `BMAP_HYBRID_MAP`

默认普通地图。

通过官方 `setMapType()` 切换。

不自行拼接百度瓦片地址，不使用天地图瓦片作为百度地图的底图。

#### 3.2 照片点显示

优先采用 `BMap.PointLayer`：

- GeoJSON 批量显示。
- 支持单点点击。
- 读取 `asset_id`。
- 使用有界数据集。
- 更新数据时复用图层。
- 正确释放旧数据及事件。

禁止为每张照片创建一个 DOM Marker。

#### 3.3 保留原有聚合功能

目前项目使用 MapLibre 客户端聚合，超过 5000 张时使用服务端网格。

百度 PointLayer 不应被误当成聚合引擎。

为了避免功能退化：

优先复用现有服务端网格机制，为百度地图增加一个向后兼容的可选网格展示模式。

要求：

1. 百度地图可以请求网格模式，即使当前照片数量不超过 5000。
2. 使用现有 `_grid_expression` 和 `_bounded_grid`。
3. 单次返回网格数量不超过现有上限 1000。
4. 每个网格保留 `cell_id`、`grid_zoom`、`asset_count`。
5. 单照片网格保留 `asset_id`，可以直接打开照片。
6. 多照片网格显示数量，点击后调用现有 `/assets` 查询成员。
7. 根据缩放级别调整网格密度。
8. 保留现有网格成员分页。

原有 `/points` 默认响应行为不得被破坏。

不得引入仅适用于 JSAPI GL 的聚合插件来冒充 JSAPI 4.0 能力。

如果网格显示效果或性能不合格，先解决问题，不得降低验收标准。
