## 实现要求

### 1. 人物选择必须来自权威读 API

- 通过受会话保护的 `GET /api/v1/persons?kind=all&limit=...&cursor=...` 分页读取 active canonical persons；
  不允许用户靠猜内部 ID 完成正常路径，也不把全部人物一次性物化到 DOM。
- 每个选项至少显示受控名称（未命名时用明确占位）、稳定 `person_id` 和必要的已有计数；不得显示路径、bbox、
  embedding、内部快照或重定向链。
- 提供可键盘操作的多选、加载下一页和清空选择；翻页/重绘不能丢失已选 ID。同名人物必须用 `#person_id`
  区分，不得按名称自动合并。
- schema `<13`、schema 状态异常或人物读 API 不可用时，人物筛选控件明确禁用/说明；不得伪装成“无人”。

### 2. `any` / `all` 与请求接线

- 页面提供明确的 `person_match=any|all` 控件；没有选择人物时只允许 `any`，不得发送 `all + []`。
- 普通文本/纯筛选 `POST /api/v1/search` 仅在选中人物时发送 `person_ids`；顺序稳定、去重，值为正整数；同时发送
  选定的 `person_match`。
- 人物条件与 `place_ids`、`place_state`、`include_descendants`、来源和 availability 保持既有 AND 语义；页面
  不得本地猜测命中或二次过滤后端结果。
- continuation 必须沿用首次查询绑定；用户改变人物、匹配方式或地点条件后只能发起新搜索，不得拿旧 cursor
  续页。现有 stale/expired 错误保留当前条件并提供“按当前条件重搜”。
- 上传搜图不发送人物字段，并在 UI 明确说明人物筛选只作用于普通搜索；不得扩展 multipart 后端协议。

### 3. 回显、错误与隐私

- 成功后用后端 `filters.person_ids` / `filters.person_match` 显示实际 canonical 回显；不得把原始已合并 ID 冒充
  当前 canonical。
- `INVALID_PERSON_FILTER`、`CATALOG_FILTER_REVISION_STALE`、`SEARCH_SESSION_EXPIRED`、`INVALID_CURSOR`
  必须显示结构化失败与重新搜索提示，不能降级为空结果。
- DOM、URL、错误文案和访问日志不得出现 CSRF/session 值、本地路径、bbox/landmark、向量、相似度、payload/hash
  或内部快照；不得把 person id 写入页面 URL 查询串。
- 沿用无 CDN、无第三方脚本、`textContent`/安全 DOM 构造、同源 credential 和现有 CSRF 规则。

### 4. BROW-002 记录式真实浏览器闭环

使用合成临时图库，在 Codex 内置真实浏览器完成并记录：

1. 页面分页加载至少两个 active canonical persons，选择 A/B，并分别验证 `any` 与 `all`；
2. 同时选择一个地点，证明人物条件与地点条件按 AND 组合，结果与 API 级夹具一致；
3. 保留一个有下一页的搜索会话，执行人物 rename/merge/face correction 或映射确认中的一种合法人工事实变化；
4. 旧 continuation 明确返回 `CATALOG_FILTER_REVISION_STALE`，页面保留当前人物/地点条件；
5. 点击“按当前条件重搜”，页面使用当前 canonical 回显并得到更新后的结果；
6. 验证同名人物不混淆、清空人物后恢复无人物条件、上传搜图不发送人物字段；
7. 键盘完成选择/any-all/提交/重搜，360×640 下无横向溢出；DOM、URL 和服务端访问日志隐私扫描干净。

自动化浏览器框架仍未落地时，只能称“记录的真实浏览器 smoke”，不得称 Playwright/Selenium PASS。所有素材
使用合成图片与项目临时数据目录；严禁扫描真实照片库。
