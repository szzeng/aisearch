## 用户场景

用户看到一堆「未命名人物 001/002…」，要把其中几张改成「爸爸」「妈妈」，把分错的脸从「爸爸」里移除，
把两个其实是同一人的未命名分组合并成一个，并且事后能撤销。他要求：改名不得改变 `person_id`；把某组改成
已有名字必须合并而不是留下两个同名活动人物；人工结论永远优先于自动结果；任何操作都要幂等（网络重试不会
执行两次）并在冲突时明确拒绝而不是覆盖后续的人工修正。

## 本任务范围

实现以 ADR-0006 为最终解释；若本卡概述与 ADR-0006 的精确 DDL/API/事务或阶段边界存在歧义，必须按
ADR-0006 执行，不得在 DS-H 阶段重新设计。

1. **命名与 `name_key`**：给 `persons.name` 写入显示名，并按 §8.3.2 生成版本化 `name_key`（Unicode NFC、
   去首尾空白、连续空白合一、英文大小写保留、不做拼音/繁简/近义词模糊匹配）。空名字返回校验错误；
   「未命名人物 001」只是占位文字，不参与匹配。
2. **同名合并**：保存名字时在同一 SQLite 写事务里解析活动目标（无目标=改名；目标是自己=幂等返回；
   目标是别人=合并到该目标）。源人物保留 `merged_into` 指向目标，**不得**形成环，且不得删除源人物行。
3. **显式批量合并**：多选未命名分组合并到指定人物，与同名合并调用**同一个业务用例**，不由前端循环改名
   模拟；批量原子（失败全回滚）。
4. **旧 ID 重定向**：查询入口把旧 `person_id` 解析到 canonical 目标（沿用 §8.3.3：「旧 ID 在查询入口解析
   到 canonical_person_id；all 模式中合并后的重复人物条件去重」）。
5. **操作记录与撤销**：`person_operations`（`request_id` 幂等唯一、`type`、源/目标、`state`、`undone_by`）+
   `person_operation_items`（`before_value`、`after_revision`）；撤销是**新的补偿操作**并递增 revision，
   不倒退版本号；有后续冲突时整体拒绝并列出原因。
6. **合并的数据行为**：人脸成员与别名去重（同 `face_id` 不重复）、人物页按 `asset_id` 去重计数、
   **保留来源属性**（人工仍人工、自动仍自动）、按同一模型空间重选代表样本（不混向量空间）、
   `MANUAL_UNASSIGNED` 的脸不因合并重新归类、排除按活动目标解析。
7. **投影与索引**：受影响资产在同一事务写入 `search_projection_queue`/索引预约（沿用 P2-03A/
   P3-02 的「人工优先 → 机器产物追赶」语义；人脸候选索引的受影响脸降级为 `PENDING_REPAIR` 并重新发布），
   不重算任何图文或人脸向量；不重新训练、不重扫全库。
8. **API 与状态**：至少提供改名/合并/撤销的 `/api/v1` 入口（沿用既有 session/Origin/CSRF/Host 边界与结构化
   错误），并在 `face_summary` 增加人物/别名/待确认/最近操作计数（只读、只计数，无个人信息）。
9. **幂等与并发**：同 `request_id` + 不同载荷 = 结构化冲突、零写入（沿用 P2-03A 的
   `*_IDEMPOTENCY_CONFLICT` 范式）；对人工锁定的脸显示自动建议但**不得**自动应用；提交时比较 revision，
   拒绝覆盖晚到的人工修改。

## 必须保持的不变量

1. 权威判定只看 SQLite；显示名/别名/合并只改人物知识，不改资产身份、位置、缺失判定、地点状态、OCR
   文档与人脸检测事实。
2. 迁移只在确需时新增，并遵守 ADR-0002 §7（只读预检、备份、单事务推进、缺件/过新拒写）；
   `0001`～`0010` 逐字节不变。
3. 人工结论优先：改名/合并/纠错/撤销之后，任何自动任务（含 P3-02 的保守关联）都不得覆盖人工归属、
   人工未归类锁或人工排除；自动建议可显示但不得自动应用。
4. `person_id` 稳定：改名不得改变 id；合并保留源 id 供历史与旧链接使用；旧 id 解析到 canonical 目标，
   且不得形成重定向环。
5. 同名合并只在用户提交保存时触发；后台/相似名字/相同别名都不触发合并；活动人物非空 `name_key` 唯一。
6. 人脸向量与图片向量严格分 space；本任务不重算任何向量、不触碰图片索引空间。
7. 幂等：`request_id` 重复提交返回原操作结果；载荷不同的重复 `request_id` 是结构化冲突且零写入。
8. 事实/数量一致性：人物页按 `asset_id` 去重计数；同一张照片里同一人的多张脸不重复计数。
9. 隐私：显示名只存本地数据库；API/日志/错误/诊断不得回显本地路径、坐标、向量或人脸相似度明细。
10. 既有 P1/P2/P3-01/P3-02 测试原样通过（版本耦合的机械断言除外，需在报告说明）。
