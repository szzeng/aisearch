## 4. 30 万验收口径

不要求准备或重新编码 30 万张真实个人照片。

优先复用已有可复现的 **30 万产品级夹具**；只有不兼容当前 schema / profile 时才重建。

正式性能结论必须走：

- 真实产品入口；
- 真实 HTTP API；
- 真实查询编码器；
- 当前实际 CUDA GPU；
- 当前固定模型。

合成向量、内部 service、NumPy 或单独 Lance 调用只能用于归因，不能替代端到端 PASS。

每个正式延迟场景：

- 至少 30 个正式计时样本；
- 固定版本 / 数据 / 查询；
- 记录 P50 / 样本 P95 / max / 所有失败；
- 非预期合法请求失败 ⇒ 该场景 FAIL；
- 冷启动、模型首次加载、冷缓存单列，不混入暖机统计。

样本 P95：

`sorted_samples[ceil(0.95 * N) - 1]`

每个场景允许先跑 **3～5 次 smoke** 检查入口、CUDA、数据与输出结构；smoke 不计入正式 30 样本。

## 5. 执行顺序与提前停止

按以下顺序执行：

### A. 30 万暖机普通文字搜索

真实链路：

`文本 → 真实文本编码器 → HTTP API → 检索 → 融合 → metadata → response`

门槛：

**P95 ≤ 5 秒**

记录 HTTP 总延迟；已有可观测分量可顺带记录，但不得为了埋点修改 `src/**`。

若明显 FAIL，可先记录证据；继续执行 D，用于判断是否同时存在后台争用问题。

### D. 后台建库同时普通文字搜索

后台必须：

- 通过真实产品维护 / 建库入口运行；
- 在正式样本期间真实推进；
- 每个正式样本证明与后台工作实际 overlap。

允许准备足够长的合法 backlog，不要求重新编码完整 30 万真实照片。

门槛：

**API P95 ≤ 8 秒**

且：

**合法验证请求因内部争用被拒 = 0**

记录：

- 前台延迟；
- overlap；
- background before / after progress；
- 已有 batches / applied / confirmed / lock wait / write hold；
- `search_projection.state`；
- 所有失败原文。

不得暂停后台后冒充后台场景通过。

### 阶段停止规则

如果 A 或 D 已明确 FAIL：

- 本卡允许停止尚未执行的 B / C；
- 结论记为 `PERSONAL TRIAL PERFORMANCE FAIL / PARTIAL`；
- 给出主要失败证据和一张最小修复卡建议；
- 不再为证明“已经失败”继续做昂贵测量。

只有 A 和 D **都 PASS**，才继续 B / C。

### B. 浏览器第一屏图片可见

真实浏览器入口：

`提交搜索 → 第一屏结果图片实际可见`

门槛：

**P95 ≤ 6 秒**

至少记录 API response、首张图片可见、第一屏完成。

不得以 API response 代替浏览器首屏。

不为本卡引入新的大型前端或浏览器自动化工程；优先复用现有入口和可用测量方式。

### C. 默认 CUDA 上传图片搜索

真实链路：

`上传 → 解码 → 真实图像编码器 → 检索 → response`

门槛：

**P95 ≤ 5 秒**

使用固定、受支持图片集合。

不得用预计算向量代替上传链路。

## 7. 判定

### PASS

只有以下全部成立：

1. 暖机文字 API P95 ≤ 5 s；
2. 后台建库 + 文字搜索 P95 ≤ 8 s；
3. 后台合法请求因内部争用被拒 = 0；
4. 浏览器第一屏 P95 ≤ 6 s；
5. CUDA 上传搜图 P95 ≤ 5 s；
6. 来源离线快速 smoke 无明显阻断；

才记录：

`PERSONAL TRIAL PERFORMANCE PASS`

随后：

- 结束性能专项；
- 不自动启动 P4-02I / A3；
- 不自动启动 P4-02L / ANN；
- P4-03B / P4-04 继续后置；
- 转入真实日常使用。

### FAIL

任一核心场景失败即可记录：

`PERSONAL TRIAL PERFORMANCE FAIL`

或因阶段停止而记录：

`PERSONAL TRIAL PERFORMANCE FAIL / PARTIAL`

本卡不修代码。

报告只需明确：

- 哪个场景失败；
- P50 / P95 / max；
- 失败数量；
- 距门槛差值；
- 当前可证明的主要原因；
- 下一张最小修复卡建议；
- 明确哪些方向当前不需要启动。

典型分流：

- A 失败 → 聚焦当前最大检索执行分量；
- D 失败 → 聚焦后台调度公平性 / 写锁占用；
- B 失败但 API 达标 → 聚焦首屏 / 缩略图链路；
- C 失败 → 聚焦上传解码 / 编码 / 排队链路。

不得一张卡同时启动 SQL + A3 + ANN + scheduler + model。
