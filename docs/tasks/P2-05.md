## 冻结实现范围

### 1. 双通道并行召回（不加新数据库、不加新依赖）

- 新增 `src/photo_search/search/recall.py`（或等价单模块）：一次查询同时得到
  **FTS 通道**（复用 P2-04 的 `build_match` + `search_documents_fts`）与**图文向量通道**
  （复用 P2-03 的 `LanceVectorIndex` 与 `index_entries`/`index_generations`，通过
  `EmbeddingAdapter` 只对**查询文本**编码一次）。
- 每条通道给出**有界**的初始候选（默认 `TOP_K = 200`，可配置常量并写进报告）；通道内排名必须
  确定性（向量按 `(distance, asset_id)`，FTS 按 `(bm25/rowid)` 或 SQLite 顺序 + `asset_id`）。
- **space/profile 绑定**：查询必须显式绑定 `space_id` + `generation_id` + 维度；维度或 space 不匹配
  必须**结构化拒绝**（复用既有的 `SPACE_MISMATCH`/`RUNTIME_RESOLUTION_MISMATCH` 之一并写进报告），
  不得静默换用另一维度或另一 generation；不得把不同 `space_id` 的向量混进同一排名。
- 本卡**不得**引入 ANN 索引、第二套向量后端、ORM 或新依赖（`pyproject.toml`/`uv.lock` 不得改动）；
  当前规模用暴力扫描 + 预过滤即可。

### 2. 融合：RRF，可复算、可对照

- `score = Σ_i weight_i / (60 + rank_i)`，首版权重相等；`rank_i` 从 1 开始；同一 `asset_id` 在两路
  命中时只出现一次（去重），`matched_by` 记录两路各自的名次（例如 `{"fts": 3, "vector": 11}`）。
- 排序与并列规则必须完全确定：先 `score` 降序，再**命中通道数**降序，最后 `asset_id` 升序。
  **不得**把 BM25、向量距离与人脸分数直接加权相加，**不得**把余弦值显示成百分比正确率。
- 输出必须带 `hit_reason`/`matched_text`（FTS 命中来自文件名还是有效地点，用 P2-04 的
  `filename_text`/`place_text` 判定）与 `filters`（实际生效的地点/来源/可用性条件）。
- 融合函数必须是**纯函数**（输入两路排名 + 权重，输出有序列表），以便「确定性检索对照」直接复算。

### 3. 地点候选预过滤与权威最终校验

- 权威条件（`source_id`/`availability`/`place_ids`/`include_descendants`/`place_state`）**始终**由
  SQLite 判定：先取权威候选集（或使用已验证的向量预过滤把候选集下推），再对候选做精确/受限检索；
  **禁止**「全库 Top-K 后再过滤」，也禁止把 `SUGGESTION_ONLY` 候选当成有效归类。
- 向量预过滤优先使用 P0-02 已验证的 `where()` 前置过滤；若后端能力不足，必须改为按权威候选 ID
  做受限检索或块扫描回退，并在报告中写明该回退的语义与代价。
- SQLite 侧最终校验必须按 `asset_id` 去重，且 `place_state=suggested`、`catalog_filter_revision`、
  `suggestion_revision` 的既有语义不变（含过期 revision 的结构化 409）。

### 4. 投影滞后与权威补查（本卡的核心正例）

- 文本侧：查询前复用 `search.documents.catch_up`（有界批）并在响应/结果结构里带
  `search_projection={state, queued_assets, processed_assets, tokenizer_version, fts_generation_id}`；
  仍有滞后时结果必须**明确标记**，且权威过滤结果不受影响。
- 向量侧：按 `index_outbox`/`index_entries` 的 `PENDING`/`IN_FLIGHT`/`PENDING_REPAIR` 与
  `index_generations.state` 识别「有效但尚未确认投射」的资产，用 SQLite 权威事实对这些资产做
  **补查**（不得只删旧命中而漏掉新加入/新归类的资产）。
- 必须有具名用例：**改名/新归类后第一次查询就能命中该资产**（即使其向量行尚未确认）；
  以及「旧 generation 仍可用、新 generation 未确认时不宣称新图已进入语义检索」。

### 5. 明确的非目标（本卡不得实现）

- **不得**实现 `POST /search`、请求/响应解析协议、搜索会话、跨页游标、结果缓存、显式相关性反馈、
  SearchProfile 切换或任何用户可见 API 形状（P2-06），也不得新增页面（P2-07）。
- 不得实现自然语言条件解析（年份/人物别名/显式筛选语法）——那是 P2-06 冻结 `SearchRequest` 时的内容；
  本卡的服务层接口只接受已结构化的条件（地点/来源/可用性/文本/向量）。
- 不得改动：ADR-0001～0005 与冻结 JSON schema、`0001`～`0006`、五字段 job 身份、lease/attempts/
  迟到提交、资产/位置/缺失判定、P2-03A/B 的人工锁/排除/幂等/批量/撤销语义与触发矩阵、P2-04 的
  tokenizer 世代/MATCH 策略/`place_text` 来源规则、`space_id`、`ingestion/**`、`workers/**`、
  打包入口、前端资源、依赖。

## 验收（B；涉及原子切换/恢复补 D，打包资源变化补 C）

必需命令：

```text
uv run pytest -q tests/unit tests/integration
uv run ruff check .
git diff --check
uv lock --check
```

**确定性检索对照**（本卡的核心验收，报告里逐项记录命令、结果与未验证项）：

1. **融合数学**：固定两路排名（含只在一路出现的资产、并列分数、同分不同通道数）→ 纯函数输出与
   手算 RRF 完全一致；`Σ weight/(60+rank)`、去重、`asset_id` 兜底排序逐项断言。
2. **确定性通道**：用确定性 `EmbeddingAdapter` 假实现 + 真实 LanceDB generation 构造两组已知向量，
   断言向量通道名次、FTS 通道名次与融合顺序；重复运行字节一致（同一查询两次结果完全相同）。
3. **过滤正确性**：权威地点/来源/可用性条件下候选集正确；`place_ids` OR + 其它条件 AND、
   后代展开、`place_state=suggested` 语义与 P2-03A/B 一致；**不得**出现「Top-K 后过滤」；
   非法 `where()` 列必须结构化失败（不回退为未过滤检索）。
4. **地点补查正例**：仅用地点筛选（无 GPU）→ 新归类/改名后的资产在**下一次搜索**即可命中；
   向量行尚未确认时该资产仍通过 FTS 通道与权威补查出现，且 `matched_by` 如实标注。
5. **space/generation 绑定**：维度或 `space_id` 不匹配 → 结构化拒绝；两个维度相同但 space 不同的
   generation 不得混用；旧 generation 仍可查询，未确认的新 generation 不得被宣称已覆盖新照片。
6. **既有不变量**：`schema_version` 仍为 6；既有测试原样通过；`catalog_filter_revision`/
   `suggestion_revision` 触发矩阵不变；查询不写 `created_at`、不重算向量、不改 `space_id`。
