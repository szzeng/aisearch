## 目标

让每个“来源”的正常流程变成：

> **新增来源 → 开始建库 → 可以语义搜索 → 日常快速刷新**

并支持安全删除来源。

---

## 1. 开始建库

新增来源后显示：

> **未建库**  
> `[开始建库] [删除来源]`

点击「开始建库」后，复用现有 source-scoped refresh 自动完成：

```
扫描/确认文件
→ 搜索投影
→ Semantic 建库
→ 可以语义搜索
→ 后台继续 Face / OCR / GPS / Place / Thumbnail
```

新来源没有可复用绑定，首次 fast scan 会确认全部文件；**不要再额外先跑一次 full scan**。

现有 full scan 仅保留为“完整校验扫描”维护入口。

---

## 2. 首次大来源 backlog

首次来源可能有 20～30 万照片，不能只依赖单轮 `content_delta`。

建库模式必须根据持久状态持续分批追赶：

- Semantic；
- Face；
- OCR；
- 其它需要补齐的 enrichment。

要求：

- bounded batch；
- 可中断、可重启；
- 已完成资产不重复处理；
- 不因 delta/batch 上限永久漏处理；
- 复用现有 selector / jobs / processor，不另写第二套 pipeline。

---

## 3. 来源级进度

来源卡至少显示：

```
我的照片
D:\Photos

扫描：250,318 个文件
语义索引：183,500 / 231,420
状态：正在建立语义索引

人物：处理中
OCR：处理中
地点：完成
```

只要求 **Semantic 给出精确 completed / total**；Face/OCR/GPS/Place 可显示“处理中 / 完成 / 不可用”，避免为 UI 引入昂贵全量统计。

进度必须由持久状态推导，程序重启后仍能恢复。

### 语义状态

只有该来源当前可索引图片的 Semantic backlog 清零后显示：

> **✓ 可以语义搜索**

Face / OCR / GPS / Place 不阻塞该状态。

---

## 4. 日常操作

建库完成后来源卡主要操作：

> **快速刷新此来源**

继续复用 P4-02Y 的 skip-hash + delta 流程，只处理变化。

全局“刷新图库”继续刷新全部来源。

原“扫描”改名：

> **完整校验扫描**

作为次要/高级维护操作。

---

## 5. 删除来源

每个来源增加：

> **删除来源**

含义：

> 从 PhotoSearch 取消管理该文件夹。

要求：

- 删除来源登记及该来源相关 location / scan 状态；
- 来源立即从界面消失；
- 搜索/浏览不再把它作为有效来源；
- 同一 asset 若仍存在于其他来源，必须继续保留；
- **绝不删除、移动或修改任何原始照片。**

确认文案：

> 删除来源只会移除 PhotoSearch 中的记录，不会删除文件夹中的照片。

本卡不做 orphan asset/artifact/vector 的物理 GC。

---

## 6. 验收

至少验证：

1. 新增来源后只点一次「开始建库」，无需再手动“扫描 → 刷新”；
2. Semantic 进度真实，coverage 完整后才显示「可以语义搜索」；
3. 20～30 万级来源不会因 batch/delta 上限永久漏处理；
4. 中断、重启后可以继续；
5. Face/OCR 等历史 backlog 能继续追赶；
6. 完成后不重复处理已完成资产；
7. 日常「快速刷新此来源」仍只处理变化；
8. 未建库和已建库来源均可删除；
9. 删除一个来源不破坏其他来源共享 asset；
10. 删除来源全过程原始照片 **0 修改 / 0 删除**。
