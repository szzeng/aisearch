## 实现要求

### 1. 迁移与权威表

- `0015_taken_time.sql` 只创建 ADR-0011 §2 的 `asset_metadata` 主键 + 六列、全部表级 CHECK、必要索引，并在
  `metadata` 写入库级 `taken_time_rules_version=1`；迁移本身不回填任何资产。
- 建表与 schema version 推进沿用既有受控事务；失败完整回滚到 14，重启可安全重放。旧程序打开 15 必须
  `SCHEMA_TOO_NEW` 且零写。
- 旧库已有表、数据、revision、`asset_id`/`time_desc` SQL 与游标逐字不变。最终索引列序以 30 万规模实测
  决定，但不得取消支持 `capture_desc`/时间过滤的索引。

### 2. 增量抽取与规则版本

- 来源闭集与优先级严格为 `EXIF_ORIGINAL → EXIF_DIGITIZED → EXIF_ROOT → FILE_MTIME`。Exif 子 IFD 必须通过
  `getexif().get_ifd(0x8769)` 读取；只读文件头，不解码像素。
- 按 `location_id` 升序尝试 `PRESENT` 位置；读取前后执行 `(size, mtime_ns)` 观察守卫。坏值逐级吞掉并继续，
  `FILE_MTIME` 使用全部位置（含 `MISSING`）的最小 `mtime_ns`；禁止扫描时间、当前时间和 `created_at` 兜底。
- `taken_at_sort` 只按墙上字段计算非负 civil key，偏移永不参与；无偏移不猜 UTC/本机时区。来源、置信度、
  标签、过滤资格、排序桶与隐私严格按 ADR/companion。
- 抽取任务幂等、可续跑；规则版本失配时既有行不可信、不参与过滤，公开的可信 extracted/capture 计数均归零。
  行写入与同一 `catalog_filter_revision` 的 `CAPTURE_TIME_CHANGED` 递增在一个事务内，一个事务至多 +1。

### 3. 资产列表、详情与 `capture_desc`

- `GET /api/v1/assets` 新增 `order=capture_desc`、`capture_from`、`capture_to_exclusive`；既有 `asset_id` 与
  `time_desc` 行集、SQL、游标逐字不变。
- `capture_desc` 使用独立 `c1` arity 4 游标 `[known, sort_key_or_0, asset_id, catalog_filter_revision]`，严格拒绝
  跨空间、非法 bucket、尾桶非零 sort、asset_id 0、负值、错 arity 与损坏游标。revision 变化返回既有 409
  `CATALOG_FILTER_REVISION_STALE` details 子集。
- 排序固定为有 civil key 的行按 key/asset_id 倒序，随后无 key 尾桶按 asset_id 倒序；revision 不变时分页
  不重不漏。
- 列表在给出时间边界时返回条件性 `taken_time` 四态块；详情返回闭合 `taken_time` 对象或 `null`，绝不公开
  `taken_at_raw`。

### 4. 搜索条件、会话与回显

- `POST /api/v1/search` 加性接入同一对 capture 字段；规范化为毫秒定宽墙上时间，拒绝时区后缀、坏日历、
  歧义写法与非升序区间，使用 422 `INVALID_TIME_RANGE` 和既有 details 键。
- 时间条件进入现有 scope 的同一 AND 集合，且只有 `label=capture` 行可命中；不得只靠文本/向量投影过滤。
- 会话只绑定既有 `catalog_filter_revision`；`query_hash` 为 ADR-0009 §6.2 字段集加两个规范化 capture 字段，
  不新增时间 revision、会话或第二条件表示。
- live `filters` 使用 `SearchFiltersEchoV2` 的 11+2=13 键。只扩展
  `test_the_frozen_echo_keys_are_the_implemented_echo_keys` 的 live 键集断言；P3 companion、历史 fixture 与哈希
  断言不得删除、修改或削弱。
- `search_projection` 8 键保持不变；`taken_time` 是兄弟块，不新增 FTS 字段或 projection queue cause。

### 5. 前端、错误与隐私

- 在资产浏览/搜索面提供明确的拍摄时间范围与 `capture_desc`；展示规范化墙上时间，有记录偏移才显示
  `±HH:MM`，无偏移绝不显示 UTC。`EXIF_ROOT`/`FILE_MTIME` 必须标「文件时间」。
- 对 `PENDING`/`PARTIAL`/`READY`/`NO_CAPTURE_TIME` 给出诚实提示；空结果不得把“尚未抽取”伪装成“无命中”。
- stale/expired/invalid cursor/time range 都显示结构化失败与重开/重搜路径；条件不得静默丢失。
- DOM、URL、错误、日志和反馈不得出现原始 EXIF、`taken_at_raw`、路径、坐标、设备序列号、身份标签或 instant。
  `camera` 仅详情页出现，按 ADR 规范化并限长 128。

- assets/search/detail 信封、V2 echo、单一 revision/hash、四态纯函数、错误/隐私闭集；
- P4-00A 的 39 个契约测试继续全绿，既有 companion 与 0001～0014 哈希不变。

### 记录式真实浏览器
