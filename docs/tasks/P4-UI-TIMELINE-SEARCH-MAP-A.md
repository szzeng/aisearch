## 唯一闭环

### 全站唯一搜索入口的结果状态合同（2026-10-13）

继承 A/C 的**页头单个全局自然语言输入**：SEARCH-MAP 不再生成、挂载或绑定第二个自然语言输入/提交监听，也不能恢复左侧“搜索”重复一级入口。结构化入库时间/日期未知/待就绪标签从这一份输入解析并使用已有搜索会话，取消时同一查询 scope 重算。进入搜索结果页、从人物/地点进入结果页、返回并二次编辑时只触发一次搜索；`/search` 深链/已有 session 兼容；空 q 不做模型搜索。人物/地点目录局部筛选不作为全局搜索语义。保留纯条件 SQL 与语义 TopK 分流，不为 UI 单输入进行多次编码器调用。

### 当前人物／合集／地点固定搜索范围的服务端闭环（2026-10-13）

**任务目的**：让人物标题「搜索此相册」、家庭合集「搜索此合集」、地点标题「搜索此地点」经 C 卡页头唯一输入框**真实执行当前相册成员内搜索**，而不是只显示 scope 标签。搜“海边”只限当前成员；不隐式继承先前拍摄年份或入库排序；人物/地点无 EXIF 日期仍能通过内容词命中，除非有明确时间过滤。

**权威范围与验证**：
- 人物范围采用原 `person_ids` + canonical/person revision 资格和 `person_match` 合同；不得只是将名字写入内容关键词；同一照片中的两张脸按 asset 去重。核对已有 `pa-search-photos` 的旧搜图行为与结果同义（原 legacy 保留到本卡收尾）。
- 合集范围采用既有 `collection_id` / `instance_token` / membership revision 的服务端当前有效合集成员，按 asset 去重；核对 `search` 路由现有 collection_scope 支持程度，若缺，允许最小加性**只读**入口/参数，不用任一人物 ID 代替合集。
- 地点范围优先复用 `routes.py` 中现有 `place_kind/place_key` / `_place_album_search_page` / `album_member_ids` 及 E 卡优化的地点成员 SQL；CN/OSM/GeoNames 父级身份、人工覆盖/排除、有效活动/非视频资格均与点击来源的地点相册**完全相等**。用户从选中相册进入不应让 parser 再按地名歧义挑别的同名地点。严禁客户端将已加载48张列表、地图单屏照片或手写 JSON ID 当成权威范围。
- **固定范围的解析优先级**：scope 是已选中的、经服务端复核的约束。自然语言中发现相同人/地点→去重；内容新增合法人物/地点→在双方可支持的合同下做 AND；不支持交集或明确矛盾→结构化冲突与取消 chip 提示，**不能扩大成 OR 或无声清除固定 scope**。词句解析出其它时间条件不能替代固定 scope。原无范围 `/search` 请求保持原样、历史快照兼容。
- **结果与游标**：纯条件时 SQLite 完整有界分页，有内容词才现有 FTS/向量/RRF，且先绑定权威成员再召回；语义仍遵原 TopK/候选截断，不能冒充全成员。首次请求固定 scope identity + membership/filter/place-package revisions，后续 cursor/search_session 与条件 fingerprint 必须绑定；scope 切换、标签取消、相册被合并/改名/移除、CN 地点包版本或成员变化、返回失效时返回明确过期/重新搜索，不沿用旧结果，也不展示跨相册图片。
- **上线切换门闩**：E/D 阶段可以没有新按钮，**不能有死按钮**。本卡对人、合集、地点各通过可见 chip → 正确成员 → 搜索 → 翻两页 → 预览 → 返回，并在相应前端打开 CTA，**才将旧 `persons.html#pa-search-photos` 输入框移除**（当人物新方案已通过）。未支持某类范围则该类 CTA 留后置、旧人物局部搜索照常保留；报告分别列 `PERSON_SCOPE_PASS / COLLECTION_SCOPE_PASS / PLACE_SCOPE_PASS` 或 `DEFERRED`，不以全站单框外观冒充功能完工。
- **性能**：复用20万元数据 SQLite 夹具和 E 的地点 SQL 计划，对高照片数人物、交叠合集和高成员地点各做一组纯条件/有内容词/续页、scope 变更的定向耗时与关键查询计划；按钮点击、聚焦和 chip 显示是纯前端操作，零编码器/零全量计数。保证数据库先按成员约束，再分页，不为每个候选做全量 Python member 集。无需全仓/GPU/真实 PhotoSearchData。

### 搜索结果
- 默认**相关度**排序与当前候选语义原样保留。仅在已有搜索结果 UI 上增加「按时间查看」模式；清楚显示“按时间整理**当前检索候选**”还是“纯条件完整结果按时间浏览”，避免用户误认为两个模式命中集相同。
- 对**纯权威过滤**（人物/合集/地点/时间/图库等无需语义评分）尽量沿用全量数据库成员过滤 + 时间轴服务端时间页；与原完整分页一致，不受浏览端/TopK 截断。纯地点分页与修订语义照旧。
- 对**FTS/向量/融合语义结果**：不得仅按当前前端已加载页排序后叫“整个搜索结果按时间”；先证明能用冻结且有界的 session 候选快照/游标在服务端正确分页，且清楚标记候选截断/上限。若缺该保证，**不要开放这个入口**，只维持原相关度结果并在报告记录此子项后置，不改原搜索算法补洞。
- 搜索页仅一个主输入框、可取消 intent chips、失败保留输入；范围/时间/人物取消后旧 time cursor 必须失效；搜索→照片详情→人物相册→返回恢复原模式、过滤、页面与滚动，不重复触发搜索。

### 20万图库搜索条件分流与日期语义（新增必要且有界的解析/只读扩展）

- **语义识别冻结**：沿用 `search/unified_intent.py`、`intent_plan`、`search/natural_intent.py` 现有“一次识别→一份计划”；仅增加确定性的 `time_basis=capture|added`、`capture_status=trusted|unknown|pending` 条件，名称可依现有风格调整。默认“2020年照片”按原可信拍摄时间；“2020年导入/入库/加入图库照片”仅按 `assets.created_at` 筛选；“没有拍摄日期的照片”严格匹配已提取但无可信来源，“日期待处理”匹配尚未提取/规则版本失配。**绝不在 UI/SQL 自动填拍摄日期或加入手动改日期**。
- **执行路径**：当解析后无实质内容词（如“2021年张三的照片”“2020年入库照片”“没有拍摄日期的家庭合集照片”），直接调用原权威 SQLite FILTER_ONLY/时间轴服务端全量分页；**不得调用文本图像 encoder、FTS/向量或 search_assets 的TopK排名路径**。含“海边、全家福”等剩余内容词时才走原 FTS/Vector/RRF，并在召回前通过同一权威时间/人物/来源/地点条件限制候选。
- **完整性**：纯条件不受语义 5000 上限，并可跨页取完权威匹配；语义查询保留原 TopK/截断/相关度与 `search_session_id`。若实现当前语义候选时间模式，必须使用服务端冻结候选全集与版本/游标并明确“仅当前候选”，不能浏览器排序已加载一页就冒充全库；缺安全候选快照则只保留相关度模式，报告 DEFERRED。
- **冲突与续页**：若一句话同时明确拍摄和导入年份、要求不连续 OR 等而尚无正确交集合同，返回明确 `unsupported` 说明而非吞掉任一条件；续页冻结首次解析的相对日期、时间依据、状态与 scope，人员/地点/包/修订变化返回现有冲突语义。时间范围继续左闭右开。用户取消任一标签需重算计划并抛弃旧 cursor/session 的相应范围，不能将状态词落到 FTS 搜图。
- **边界**：这属于 SEARCH-MAP 卡明确授权的**最小加性解析/只读合同**，允许核对必要 API request model/intent plan；不改旧 `capture_from/to_exclusive` API 含义、不重写全部解析器、不改向量/FTS/RRF、人工归属/自动地点确认、不建设新索引数据库。现有 source/person/collection/place 身份沿用权威资格。
- **性能**：在 CORE/E 共享的20万元数据夹具上验证拍摄年份、入库年份、可信未知、张三+年份、地点+年份等纯条件的实际 SQL/query plan、首50～60条 API 与直接下一页；至少≥30次暖机测量，结果与 SQL 全集/COUNT 在小fixture及规模集合抽样一致。纯条件**零编码器调用**可计数证明；语义路径仅做少量假向量/现有已验证搜索语义回归，不重跑30万 GPU/AI 基准。逐页不自动计算全部年月分布。不能达到 CORE/E 对应页目标，未测报告 PERF_PENDING、实测超标报告 PERF_FAIL 而非借历史向量测速宣布达标。
