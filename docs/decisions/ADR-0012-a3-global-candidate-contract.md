## 1. 术语

| 术语 | 含义 |
|---|---|
| **完整路径** | 现行 `search/retrieval.py::vector_channel` 的候选块精确路径：SQLite 权威资格决定成员，按 `asset_id` 分块调用 Lance，**未截断**（`truncated=false`）时逐块 top-k 的合并等于候选集全局 top-k |
| **`C_sql`（oracle 成员集）** | 该请求绑定的 `generation_id`/`space_id` 内，**恰好等于** `_CONFIRMED_BLOCK_SQL` 所选条目的 `asset_id` 集合（§3.1）。它定义现行完整路径（等价性 oracle）的成员 |
| **`C_strict`（证书资格集）** | `C_sql` 中那些在 Lance 侧也**行级一致**的资产：恰好一行（`record_id = generation:asset`）、space 匹配、且该行 `projection_revision` 等于该条目当前 `confirmation_revision`（§3.2）。证书（§4）只在 `C_strict` 上评估 |
| **A3** | 「无额外用户筛选时，用一次全局向量 Top-K 或等价的少候选访问取代整代候选块物化」的候选协议（P4-02G §3 的定义）。本 ADR 与 P4-02C 的同名审计幂等 A3 无关 |
| **证书** | §4 三种机制之一成立的**可验证**证明，且必须在**发布前**仍成立；没有证书就不得用 A3 发布页 |
| **回退** | 走完整路径（或按现行契约报告状态），不发布缺项页 |

## 2. 资格谓词 `A3_ELIGIBLE`（必须同时成立）

1. 请求带**完整向量绑定**：`(encoder|query_vector, space_id, generation_id, dimension)` 齐备，
   且存在语义通道（文本或图片查询）；纯筛选查询不合格。
2. **无额外权威筛选**（必须**逐字段**核对 `scope_condition`，不能只看列表是否为空）：
   `source_id is None`、`availability == "any"`、`place_ids` 为空、**`place_state == "any"`**、
   `person_ids` 为空、`capture is None` —— 即 `scope_condition` 恰好返回 `"1"`（恒真）。
   ⚠ `place_state` **独立于** `place_ids`：`places/filter.py::place_condition` 在 `place_ids=()` 时
   对 `assigned`/`unassigned`/`manual_unassigned`/`suggested` 仍返回非恒真谓词（Sol 聚焦审核 F1 的
   最小反例：`place_state=assigned` + 距离逆序时，全代 Top-1 会取到无地点资产的 B 而漏掉有
   `MANUAL_ASSIGNED` 的 A）。资格判据是**由真实谓词是否恒真**决定，而不是由列表是否为空决定。
3. 绑定的 generation 处于活动且 `state == "READY"`，其 `space_id`/维度与请求一致，
   不允许跨代、跨 space 或旧 generation。
4. 未命中上述任何一条 ⇒ **不资格**，按 §7 回退。

「无用户筛选」只表示没有额外限制，**不等于** Lance 全表都是可搜索行：资格集合始终是 §3 的 C。
带筛选（来源/地点/人物/拍摄时间）的请求**一律**走完整路径，本 ADR 不泛化到那些场景。

## 3. 两个集合：oracle 成员集 `C_sql` 与证书资格集 `C_strict`

### 3.1 `C_sql`（oracle 成员集，现行语义）

`C_sql` = `_CONFIRMED_BLOCK_SQL` 所选条目的 `asset_id` 集合，即同一 SQLite 权威视图下该绑定
generation/space 内满足 `index_entries.state = 'CONFIRMED'` **且** `scope_condition`（§2.2 成立时为
恒真）的行。它**只**比较 ID 入口，**不**比较 Lance 行的 `projection_revision`，也**不**在
`availability = "any"` 时追加可见性条件 —— 这正是现行完整路径的行为，因此 `C_sql` 就是
**等价性 oracle 的成员集**（§5.5）。

### 3.2 `C_strict`（证书资格集，A3 的更强前提）

`C_strict` = `C_sql` 中同时满足以下条件的资产：

1. 在 Lance 中恰好一行（`record_id = f"{generation_id}:{asset_id}"` 使「每代每资产一行」成为结构事实，
   不存在重复行）；
2. 该行 `space_id` 与绑定一致；
3. 该行 `projection_revision` **等于**该条目当前的 `confirmation_revision`。

Lance 侧的 `visible`、行数、计数或索引存在性**都不是**资格凭证；它们是派生数据。

### 3.3 两条集合的关系（F2 的裁决）

- A3 的**发布义务**是「与 oracle（`C_sql` 上的完整路径）逐项相同」；
- A3 的**证书义务**是在 `C_strict` 上可证，且**发布前必须同时通过**：公共门禁
  `C_strict == C_sql`（权威侧）**与按机制定义的引擎侧门禁**（下表）。引擎侧门禁**不统一**：
  要求「全物理行集 == `C_strict`」只有 M1 需要，按到 M2/M3 会与其定义冲突（Sol r3 的阻断项）。

| 机制 | 引擎侧门禁（发布前必须成立） | 说明 |
|---|---|---|
| **M1 等价快照** | 引擎对该代/空间的**全物理可返回行集**（不加任何额外谓词）== `C_strict`，即**没有多余行** | 最强：整代可查询行集与证书集逐项相等 |
| **M2 下推等价** | 引擎以**已证明与 `C_strict` 等价的谓词**过滤后的行集 == `C_strict`（其 ID 投影 == `C_sql`）；全物理集**可以**有多余行 | 资格在排序之前完成，故多余行不参与排序 |
| **M3 停止证书** | **不要求行集相等**：允许引擎有多余（未确认/不合格）行，但必须在**引擎行流**上给出严格停止证书——已取得 K 个**合格**行，且所有**未检查的潜在合格行**在 `(distance, asset_id)` 全序上都不可能排在第 K 行之前；**已检查并经同一权威视图判为不合格的行可以更近**，但该失格判据及其**发布前有效性**必须可证；第 K 行的合格性必须在**发布前**复核 | 合格性按 `C_strict` 逐行判定；证书必须可判定（例如对未检查行给出距离下界，或穷尽所有可能先于第 K 行的行），不得用固定 overfetch/重试次数代替 |

三种机制**共同**的门禁只有：公共门禁 `C_strict == C_sql` + 发布前窗口复核（§5.5、§7）。
机制与引擎侧门禁是**一对一**的：companion 的 `CertificateRule` 只接受
`M1↔M1_PHYSICAL_SET_EQUALS_C_STRICT`、`M2↔M2_PUSHDOWN_RESTRICTED_SET_EQUALS_C_STRICT`、
`M3↔M3_STOP_CERTIFICATE_OVER_ENGINE_STREAM` 三种配对，交叉组合一律拒绝（Sol r4 阻断 2）。
「引擎行集是否允许有多余行」按机制决定；**M3 的可用性不以行集相等为前提**，
否则 M3 在其本来要处理的未确认行场景里不可用（这会把三机制可行性陈述改为两机制，属于需另裁的语义变化）。
- **真实的 `after_lance` 崩溃窗口不是 `C_strict ≠ C_sql`**：任何为同一 `(space, asset, generation)`
  发布新产物的路径都会**先把条目降为 `PENDING_REPAIR`**，`process_next(failpoint="after_lance")`
  在引擎写后、确认前抛出时条目仍是 `PENDING_REPAIR` ⇒ 该资产**既不在 `C_sql` 也不在 `C_strict`**，
  两集**相等**；此时 **M1 失败**（全物理行集 ≠ `C_strict`），**M2 只有在本例已证明排序前下推等价时可用**，
  **M3 只有停止证书成立时可用**，都不成立才回退（Sol r6 修正：不是「证书一律因多余行失败」）。
  该状态由仓库自身用例与独立复跑的真实 Lance/调度器交织共同证实
  （`tests/integration/test_p2_search_topup.py` 的崩溃窗口断言 `entry_state == "PENDING_REPAIR"`；
  [独立复跑](P4-02H-independent-recheck.md) §3 的 5 步交织每步 `C_sql == C_strict`）。
- `C_sql ≠ C_strict`（**同一 `CONFIRMED` 条目的引擎行 revision 不一致**）只保留为**防御性**状态
  （越序写入、损坏或外部替换引擎文件）：现行 `IndexCoordinator` 路径不产生它，但证书不得依赖
  「它不可能发生」这一假设。该状态 ⇒ **强制回退**（§7），回退发布的正是 oracle 页。
- **本 ADR 不修改**现行完整路径的 revision-blind 行为；若要收紧它，属完整路径自身的另行裁决与立卡。

## 4. 证书：允许 A3 的三条互斥机制

| 机制 | 内容 | 引擎侧门禁 | 必须的证据 |
|---|---|---|---|
| **M1 等价快照** | 查询前存在可验证的写者栅栏/版本对，使「Lance 可查询行集及 revision」在**整个查询—发布窗口**内等于 `C_strict`（因而其 ID 投影等于 `C_sql`） | 全物理行集 == `C_strict`（无多余行） | 栅栏标识 + 同一窗口内的 ID/revision 集合相等证明（计数与采样不构成证明） |
| **M2 下推等价** | 把资格约束**推入排序之前**（引擎过滤/成员快照），并证明该谓词与 **`C_strict`** 逐项等价（其 ID 投影因而等于 `C_sql`） | 过滤后行集 == `C_strict`（全物理集可有多余行） | 谓词等价证明 + 反驳用例（不允许「引擎过滤后 SQLite 再删」两阶段替代） |
| **M3 带停止证书的迭代扩大** | 逐步扩大检索范围，直到已取得 K 个**合格**行（合格性按 **`C_strict`** 判定），且**所有未检查的潜在合格行在 `(distance, asset_id)` 全序上都不可能排在第 K 行之前**；已检查并判为不合格的行可更近，但其失格判据与发布前有效性必须可证 | **不要求行集相等**；必须给出可判定的停止证书并在发布前复核第 K 行合格性 | 停止证书（未检查行距离下界或穷尽枚举）+ 无证书即回退 |

固定倍数 overfetch、固定重试次数、全局 Top-K 后过滤、仅凭计数/采样/索引存在性**都不构成证书**。
M3 最坏情况下退化为完整候选扫描 —— 因此 A3 的收益**不是**必然保证。

## 5. 排序、并列与 `top_k`

1. 排序全序是 `(distance, asset_id)`，与完整路径完全一致。
2. **截断必须发生在全序之后**：不得让引擎先只返回 K 行再在 Python 排序（P4-01C 审查 B1）。
3. `top_k ∈ [1, 1000]`；契约要求对**每个** `top_k` 成立，不能只验证 `top_k=20`。
4. 融合、`pending_projection`、权威复读、会话/游标与错误语义保持原状。
5. **等价性 oracle 就是现行完整候选块路径的实现**（P4-02H 主审 F2）：包含它当前的
   revision-blind 窗口。任何**加强** revision 校验（例如要求引擎行的 `projection_revision`
   等于当前确认 revision）都是完整路径自身的后续工作，**不得**以 A3 为名改变基线语义；
   A3 只能被要求「不比完整路径更差」。

## 6. 状态矩阵（反例目录，冻结）

每一行都是「必须被决定」的输入状态；`A3` 列只允许在证书成立时为真，否则**回退**，
且两种情形**发布页都必须与完整路径逐项相同**（含并列距离的 `asset_id` 次序）。

| # | 反例类别 | 状态 | 决策 |
|---:|---|---|---|
| 1 | 未确认行（**含真实 `after_lance` 窗口**） | 引擎有行、oracle 无该条目：条目未 `CONFIRMED` 或已降为 `PENDING_REPAIR`（`process_next(failpoint="after_lance")` 的实际状态），此时 `C_sql == C_strict`，多余引擎行使 M1 失败 | **M1 不可用**；**M2 只在证明排序前下推等价时可用**；**M3 只在停止证书成立时可用**；都不成立则 **回退**，任何允许路径的发布页都必须与 oracle 相同 |
| 2 | 修复中 | `index_entries = PENDING_REPAIR`，引擎可能仍留该资产的行（旧向量行，或 `after_lance` 已写的新行）——**与第 1 行是同一物理状态** | **M1 不可用**；**M2 只在证明排序前下推等价时可用**；**M3 只在停止证书成立、且该多余行的失格判据（不在 `C_sql`）与发布前有效性可证时可用**；都不成立则 **回退**（F-A 裁决见 §12） |
| 3 | revision 不一致（**防御性**） | 同一 `CONFIRMED` 条目的引擎行 `projection_revision` 不一致：越序写入、损坏或外部替换引擎文件。现行 `IndexCoordinator` 路径**不产生**该状态（独立复跑 5 步交织 `C_sql == C_strict` 每步成立），仅作为证书不得依赖的假设保留 | ⇒ **回退** |
| 4 | Lance 缺行 | SQLite `CONFIRMED` 但 Lance 无对应行/旧行 | ⇒ **回退**（事后核验补不回缺失项） |
| 5 | 并列距离 | 第 K 与第 K+1 距离相同 | 全序 `(distance, asset_id)` 决定；引擎内截断一律禁止 |
| 6 | 隐藏/离线/来源变化 | 权威可见性或来源在查询窗口内变化 | 以 SQLite 权威为准 ⇒ 变化即 **回退/重搜** |
| 7 | 代/space 切换 | 绑定 generation/space 变化或不再 `READY` | ⇒ **回退** |
| 8 | 并发发布窗 | 查询与发布之间发生确认/修复/撤销/revision 变化 | 发布前按现行 revision/资格门禁复核；不能重建完整结果则 **回退/重搜** |
| 9 | 正对照（证书成立） | `C_strict == C_sql` 且**该机制的引擎侧门禁**（§3.3 表）成立，且在窗口内稳定 | 允许 A3；页必须与完整路径（oracle，`C_sql` 上）逐项相同 |
| 10 | 空 `place_ids` 但 `place_state != any`（Sol F1） | 无地点 ID 条件，`place_state ∈ {assigned, unassigned, manual_unassigned, suggested}` | **不资格**（`NOT_ELIGIBLE_EXTRA_SCOPE`）；`scope_condition` 非恒真 ⇒ 走完整路径 |
| 11 | 多余引擎行 + M3 停止证书（Sol r3/r4/r6） | 同代同 space：SQLite 仅 B `CONFIRMED`（`C_sql = C_strict = {B}`）；引擎有**已检查且经同一权威视图判为不合格**的 A(0.10 更近) 与 B(0.20)，`top_k=1`；未检查行的距离下界劣于 0.20；**本例没有已证明的排序前下推谓词** | **M3 可用**（近的 A 已检查且失格判据可证、不阻断证书；停止证书只覆盖未检查的潜在合格行）⇒ 允许 A3，页 = `{B}` = oracle。**M1 不可用**（全物理集 `{A,B}` ≠ `C_strict`）；**M2 只在本例有已证明的排序前下推等价时可用**，本例无此证明故回退。若未检查行下界更近、A 的失格判据不可证或发布前失效，或 M2 谓词未证明，则必须继续扩大或回退 |

## 12. 决策记录：F-A（`PENDING_REPAIR` 多余行的机制可用性）

r5 独立主审指出第 1/11 行（允许 M3，附停止证书）与第 2 行（无条件回退）对**同一物理状态**给出相反
决策，并把该冲突按卡面交回裁决（不自行选择）。本 ADR 采纳**方向甲**：

1. 第 2 行改为**按机制的条件回退**，与第 1/11 行一致；第 11 行写明「M1 不可用；**M2 只在本例已证明
   排序前下推等价时可用**（本例缺证明 ⇒ **该路径**回退）；M3 可用（停止证书）」，失败分支**按路径**
   分别判定（Sol r7 更正本条第 1 点的旧记录）。
2. 依据：§3.3/§4 的 M3 定义**本来就是**为「引擎有多余行」设计（不要求行集相等），而方向乙
   （把第 1/11 行限定为「多余行所属条目不是 `PENDING_REPAIR`」）会让真实 `after_lance` 窗口只剩回退，
   把已冻结的「三机制」可行性陈述退化为两机制 —— §3.3 已声明那属于需另裁的语义变化。
3. 方向甲**不放宽任何不变量**：`C_strict == C_sql`、`(distance, asset_id)` 全序、发布前窗口复核、
   「无证书即回退」全部保留；放宽的只是「哪些机制在该状态下可被考虑」，且必须附可证证书。
4. **本轮由用户在「继续修补」指令下授权 DS-H 作此统一，仍需用户在最终冻结时确认或改判方向乙**；
   若改判方向乙，必须同步改写 §3.3 的 M3 定义与 §4/§6，并如实记录为语义变化。

> **注（Sol r7 修正）**：第 11 行末句的失败分支必须**按路径**分别判定——选 **M3** 时看停止证书
> （未检查行距离下界、被排除行的失格判据是否可证且发布前仍有效）；选 **M2** 时看排序前下推谓词是否
> 已证明；**M1** 在本例不可用（全物理集 ≠ `C_strict`）。因此「本例没有已证明的 M2 谓词」只回退
> **M2 路径**，**不影响本例的 M3 正例**（允许 A3、页 = `{B}` = oracle）。

## 7. 回退义务

1. **证明不了完整 Top-K 就必须回退**：任一前提缺失、证书不成立、窗口已变或无法重建，
   一律走完整路径（或在不可能重建时按现行契约报告状态），**不得发布缺项页**。
2. 回退不改变信封：不得新增字段、错误码或状态词；回退页与完整路径页逐项相同。
3. 回退率与回退时延是**必测指标**（P4-02G §5.2）：A3 的快样本不得掩盖慢回退。

## 8. 禁止范围（本次冻结下）

  权威谓词、P1～P3 人工事实、`0001`～`0016` 迁移内容与既有 ADR 条款。
