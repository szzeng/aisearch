# ADR-0017 原图人脸自动处理与旧版本共存

状态：已实现，34项定向与公开样片真实模型对照通过；独立审查待完成。任务：P4-PERSON-DETAIL-B。[实现证据](../reports/P4-PERSON-DETAIL-B-implementation.md)。

schema19 批次原型保留原迁移；schema20 新增自动策略授权和非唯一的历史批次任务引用索引。升级沿用现有备份／迁移流程，不编辑既有迁移来修已打开的数据库。

原图模式继续使用 DETAIL-A 的不可变 source-crop.v1 产物、face_id 和 generation；自动模式仅增加独立的任务类型与 `source-detail-auto@1` 派生策略身份。处理输入及权重不变时复用已经发布的原图产物，恢复索引与归人，不重复推理。

跨版本候选只允许已验证的 buffalo_l v1、v2、source-crop.v1。每个 generation 的确定性身份、space、processor、512 维、cosine、L2 和 READY 必须全部匹配；候选仍须关联当前产物的 CONFIRMED 索引记录。原图 generation 不替换全库 active 指针。真实模型公开样片对照通过后才开放兼容桥；结果单独记录，不据此宣称真实图库准确率。

`face_detail_auto_assets` 记录每个资产当前内容及产物的自动策略授权和派生完成状态。完成后旧机器检测行保留作历史，但统一有效视图排除旧机器重复；人工链接、锁定、排除和未决映射锚点继续有效。自动归人忽略已被替代的旧机器占位，保留人工占位，并在写事务内重读人工控制。人工映射、撤销、候选修复按实际 spec 重排。

JPEG 轻量模式的 draft 帧可能小于原图帧。schema20 保存已校验产物的坐标帧；旧产物在事务外通过现有 checksum／face_id／bbox／input 校验懒恢复，不读旧照片或改变旧 face_id。仅在 source-detail 跨帧映射比较时按两轴尺寸换算，原匹配门限不变。人工锚点的旧帧无法验证时，整张照片的增强脸暂缓自动归属并留待确认，防止人工移出的人以新版本重新出现。

批次按来源和创建时资产上界分页，每页最多 50 个资产。SQLite 保存游标、任务和进度；只领取当前资产的正确模式任务。暂停阻止下一张领取，已完成推理仍恢复派生步骤。单张失败记录后继续，失败项可重试。建库选择使用现有 metadata 保存，重试同一来源集合恢复已选模式；新集合默认原图。推理使用现有单串行人脸槽、60MP/200 张脸/120 秒上限，不扩大线程并行。

验证采用定向合成/API/前端用例和公开样片真实模型对照；不扫描私人图库，不下载模型，不做全量回归或性能承诺。正式接受仍由后续独立审查完成。
